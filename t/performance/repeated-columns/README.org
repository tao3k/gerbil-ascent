* Native complete index cycle

The ASP Scheme benchmark API runs 50 alternating old/new pairs. Each call
builds the index over half the rows, extends the remaining half, computes all
lookup keys and consumes every matching bucket. Both results must equal an
independent original row sum. Input rows are outside measurement; index, keys,
buckets and result consumption are included. GC occurs before measurement;
CPU uses process user/system counters and memory uses allocated bytes.
Compilation and qualification do not overlap the timing lanes.

The repeated target is declared before execution to require >=10% CPU
improvement and >=40 faster pairs. Controls allow 110% CPU + 20 microseconds;
allocation allows 110% + 4096 bytes. No gate was relaxed.
