* Curried physical index implementation (2026-10-06)

The admitted rule analysis now supplies logical column requirements to each
engine. Pure component and actor workers derive requirements from their actual
compiled actions and build independent mutable roots. The explicit =gerbil-ascent-curried-index-provider= receiver
uses maximum bipartite matching over strict subset requirements to form chains;
each chain's permutation covers every assigned logical requirement as a prefix.
The default hash receiver, singleton requirements and arbitrary custom
Providers retain their existing representations. Requirements are planned only
when an explicit curried receiver first needs an actual physical lookup. This implements the layout-sharing mechanism discussed in
[[https://kmicinski.com/assets/byods.pdf][Provider concretization section 5.5]], rather than renaming the former cache.

A physical trie stores each input occurrence at one full-depth leaf. Ordinals
restore exact relation order when selecting a shorter prefix; ordered view
spines are cached lazily and invalidated together on extension. Existing
returned spines remain immutable. Multiple logical aliases extend one physical
entry once. All/delta and different engine/worker roots remain separate.
No general memory or application speed improvement follows from the reduced
physical root count: ordinals, trie nodes and cached view spines have costs.
The paired complete-solve fixture is observational and retains negative results;
it is not the paper's Polonius, LLVM or whole-application replication.

Native acceptance compares all 128 requirement families over three columns
with an independent chain-partition enumeration and checks actual compiled
serial/component actor solves against independent truth. Shared prefixes cover
false values, repeated row occurrences, reordered keys, immutable old views,
alias extension and owner/delta isolation. Lean proves universal prefix-coverage
lookup equality, ordered batch decomposition and exact membership; minimum
matching optimality and native trie ordinal collection are not inferred from
those theorems. Quint extends the existing root-publication model with alias and
foreign-owner mutations; it does not repeat those algebraic statements.

** Cost admission and retained negative outcomes

allocated 6,971,728 bytes per solve (median), compared with 380,768 for the

application benefit. These comparisons use the existing historical complete

* Provider concretization constructed column projection and index layout lifetime (2026-10-08)

Provider concretization section 4, printed page 264:11, requires keyed reads and ReadAll to agree
on a relation's concretization. The [[https://kmicinski.com/assets/byods.pdf][primary paper]] motivates the obligation;
the cursor algorithm below is our Scheme implementation choice. It does not
come from a new paper claim or establish all of section 4.

=table/funs.ss= now uses the existing forward cursor for public index keys as
well as ordered batch construction. Strictly increasing natural column indices
compile into gaps; after selecting a field, the next cursor begins immediately
after it. Repeated or reordered columns use direct selection. Gaps are computed
from the current caller-owned columns on each invocation. Caching them across
calls would be incorrect when that header changes. Field values retain identity.

=ProviderRouting= supplies nine additional laws. =compiled_columns_exact=
recovers arbitrary ordered columns from the generated gaps;
=cursor_columns_exact= derives the forward traversal from list-drop composition;
=stepped_projection_exact= connects both. =stepped_build_exact= and
=stepped_history_exact= derive exact ordered buckets for arbitrary finite batch
histories using the actual projection, without an assumed =keyOf= equality or
bucket-coverage premise. =ordered_check_iff= and =dispatched_projection_exact=
cover the repeated/reordered fallback. =column_key_missing_iff= and
=admitted_projection_present= state the bounds obligation explicitly. The
optional-field model distinguishes absence from a stored Boolean false. These
are mathematical list algorithms; native lawful hash/value equality and Gerbil
primitive behavior remain representation contracts.

=ComponentIndex= now carries each cache root's declared column header and an
independent frozen old-reader header. Correct extension and rebuild preserve
the layout; publication must not change a held header. Three new mutations
reverse columns during extension, overwrite a held header, or rebuild with the
wrong columns. The first and third violate =Consistent=; the second violates
=HeldStable=. TLC explores protocol interleavings, not cursor arithmetic.
The two-column, two-batch fixture limits exploration data, not runtime
arity or generation. This fixed-layout contract applies to declared engine
index roots. Raw helpers still accept caller-mutated columns between calls;
that behavior is separately tested, not claimed to preserve one root's layout.

Native qualification uses direct =list-ref= truth, shared vector identities,
96-field rows, ordered/repeated/reversed/full/empty layouts, mutable caller
headers and Boolean fields. Callback tests mutate the received column/key
headers and require the caller's headers to remain intact. The existing 256
retained-history corpus and compiled self-join controls remain independent.
Lean examples and negative controls stay under =Tests/ProviderRoutingTests.lean=.

See the [[file:../../evidence/scheme-column-projection-20261008/receipt.json][source-bound receipt]] and the updated closure matrix. This discharges the
previously named stepped-projection algebra gap. Universal native hash/trie,
ordinal and rectangle-visitor refinement, full paper applications, and matched
whole-application benefit remain separate obligations. No measured speedup,
physical-memory reduction or complete paper replication is claimed.


* Provider concretization curried collection, ordinal restoration and cached views (2026-10-08)

Provider concretization section 5.5, printed pages 264:16--17, uses nested dictionaries and adapters
so one physical chain serves multiple logical indexes. The
[[https://kmicinski.com/assets/byods.pdf][primary paper]] motivates shared lookup; Scheme additionally preserves ordered
row occurrences, including duplicates. The earlier =SharedIndex.prefix_lookup=
filter theorem did not derive the order obtained from actual trie enumeration.

=table/index-sharing.ss= now threads one tail through recursive collection.
=hash-fold= visits a node's children; leaf bucket spines append directly to the
shared tail. Ancestors never append an already collected child subtree again.
Rows and ordinal records remain borrowed. Sorting and =map cdr= still create the
ordered public result. Cache hits keep the same public spine; nonempty extension
invalidates cached aliases, while empty extension preserves them.

=ProviderRouting.collect_tail_exact= proves the accumulator transformation for
arbitrary finite binary branch descriptions and arbitrary tails. Leaves describe
last-level record enumeration; branches describe nested child traversals.
=leaf_copies_exact= counts one copied spine cell per enumerated record in this
model. =collection_copies_le= compares that count with repeated subtree appends.
This is explicit list-copy work, not physical allocation bytes or universal
native complexity. General hash traversal and its branch extraction remain
representation contracts. The native helper supports arbitrary branching.

=numberRows= models fresh increasing insertion ordinals. Lower/upper bounds,
strict order and =strict_ordinal_unique= derive unique labels without requiring
unique row values. Extension preserves order and the next-label bound;
=numbered_history_order= and =numbered_history_values= carry both through
arbitrary finite histories, including empty batches. =constructed_history_restore=
then restores the exact =replayRows= sequence from any permutation of the
constructed records. Coverage is stated for actual record occurrences, not just
set membership. Omitting a duplicate occurrence is rejected.
=constructed_prefix_restore= composes restoration with an arbitrary row
predicate, preserving exact filtered order and multiplicity across those same
histories. This connects prefix selection to the occurrence restoration law;
extraction of the native trie leaves satisfying that predicate remains explicit.

The executable Lean reference uses mergeSort with a total descending comparator.
=restored_occurrences_exact= derives the unique result. Native Scheme uses
strict greater-than comparison: =native_strict_sort_exact= proves the same unique result
under its primitive permutation/strict-order contract. The Lean theorem does
not verify Gambit's sorting implementation. Native direct-column truth and
frozen reference comparisons independently qualify that correspondence.
All examples and fault controls remain under =Tests/ProviderRoutingTests.lean=.

Quint =ComponentIndex.ReadView= adds cold all-row prefix caching. =viewValid=
means the cache may be reused, not that a previously returned reader is still
alive. =ViewConsistent= requires a reusable view to equal the committed root
and forbids reuse during private extension or failed mutation. =HeldStable=
continues to protect old returned readers independently. Correct extension and
failure revoke reuse; rebuild starts with an invalid cache. Three mutations
retain reuse during extension, retain reuse after failure, or populate a rebuilt
view from the damaged pre-rebuild cache. Each must violate =ViewConsistent=.
This finite protocol models the all-row prefix and two owners, not every key or
unbounded callback liveness. Ordinal algebra remains exclusively in Lean.

The native corpus now enumerates 64 source subsets, all six three-column
physical permutations, prefix depths zero through three, original/reversed
logical keys, absent keys, Boolean fields, duplicate insertions, cold/warm cache
identity, empty batches and held old results. Each query must agree with direct
=list-ref= filtering and the existing frozen implementation, retaining each row
object. Earlier native failure, shared alias and actor Session controls remain.
See [[file:qualification.org::*Curried collection qualification][feature qualification]].

The existing five-scenario benchmark is exposed through the ordinary Justfile
as =performance-index-sharing=. Its immutable reference remains commit

* Provider concretization constructed curried trie and prefix occurrences (2026-10-08)

Section 5.5 of the [[https://kmicinski.com/assets/byods.pdf][primary paper]] uses nested maps to serve physical prefixes.
The earlier ordinal restoration theorem accepted an occurrence permutation as
a premise. =ProviderRouting.CurriedTrie= now gives an executable, depth-indexed
dictionary construction. Depth zero is a leaf bucket; each higher level is a
key-to-child map. =trieInsert= updates exactly the selected branch and prepends
one leaf occurrence. =trieBuild= groups source occurrences by each coordinate.
=trie_insert_build= proves these constructions agree at every finite depth.
=trie_prepend_build= and =trie_replay_build= derive batch and history direction.

=trie_collect_build_count= derives exact occurrence counts by induction through
the nested maps. Its child inventory must be unique and cover every inserted
coordinate at the corresponding depth. =trie_collect_build_perm= derives the
enumeration permutation from those counts. =trie_read_build_perm= composes
selected branch descent with child collection: the result is a permutation of
the directly filtered source, including repeated equal rows. Missing branches
and overlong prefixes yield empty results in this read model.

=trieNumberedReplay= inserts actual freshly numbered batches into the trie.
=trie_numbered_replay_build= connects that execution to =replayNumbered=;
=prefix_selected_projection= connects record keys to row keys.
=trie_numbered_prefix_restore= then derives the exact ordered logical result
through arbitrary finite insertion histories. The gathered-record permutation
is no longer a caller premise in this theorem. All nine laws and positive and
negative examples are checked under =Tests/ProviderRoutingTests.lean=. Duplicate
and omitted child inventories have retained executable counterexamples.

The functional dictionary assumes coherent key equality and map lookup/update.
Collection uses one supplied finite key inventory, allowing any inventory order;
native hash nodes enumerate their own materialized children in potentially
different orders. Extracting those per-node inventories and their correspondence
to the functional branches remains a native representation obligation. This
does not verify Gambit's hash implementation or remove the sort primitive
contract. The native build requires nonempty physical columns; model depth zero
describes a leaf, not a newly admitted empty physical layout.

The Scheme qualification additionally checks depths one through five with
reversed sparse physical layouts, all prefix depths, reordered logical keys,
duplicates, row identity, warm spine identity, extensions and held old readers.
Each result is compared with independent =list-ref= filtering. Those finite
fixtures do not bound the theorem or runtime depth. Production Scheme storage
and routing are unchanged in this slice. Quint retains lifecycle ownership;
the unchanged =ComponentIndex= model is qualified separately, without adding
positional or trie algebra to its state machine. See the
[[file:qualification.org::*Trie construction qualification][feature qualification]]. No new performance samples are claimed.

* Provider concretization materialized per-node inventories (2026-10-08)

=CurriedDictionary.lean= derives distinct child keys from the actual source
rows at each path. Every node may enumerate these keys in a different order;
only a permutation of that node's constructed keys is required. Eight laws
prove unique/covered inventories, erasure to the functional trie, occurrence
counts, collection/prefix permutations and exact ordinal-restored prefix order.
This removes the earlier construction model's common global key inventory.

The tests under =Tests/CurriedDictionaryTests.lean= use independently reordered
siblings, duplicate-valued occurrences, absent/overlong prefixes and empty then
nonempty numbered history. Duplicating or omitting a child inventory fails the
occurrence specification. Native qualification separately checks heterogeneous
Scheme keys and row identity. The laws cover arbitrary natural depths and
source lists; native hash get/put/equality, enumeration and sort correspondence
remain primitive implementation obligations.
