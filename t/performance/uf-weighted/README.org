* Design and model contract
Weighted source components retain separate target rectangles and their
ordered member axes. Complete export expands the product into one owned outer
collector with a syntax-bound tuple constructor. The native =with-list-builder= owns its head and tail; no reverse traversal is
needed, and every public tuple is fresh. Visitors remain callback based
for external consumers. No mutable UF node or shared reader cursor is retained.

A uniform-schema indexed single-coordinate query with one axis owner binds
its stored selected member once, then visits its ordered descriptor bucket.
Right-axis multi-owner queries retain the previous frozen plan. Prefix keys,
repeated constraints and mixed arities retain their checked query path.

Gerbil's =std/list/list.ss= implements =push!/pop!= as scoped =defrule= syntax
and uses accumulator folds to build owned spines. Its =std/struct/dag.ss= keeps
invocation state separate from completed attributes. The product collector
uses =std/list/list-builder.ss= and the same syntax/ownership discipline, with constructor syntax bound once
instead of two higher-order callbacks per public row.

Lean =collect_right_order= and =collect_product_order= describe the actual two
accumulator loops, and =direct_product_export= proves their ordered Cartesian
result. =bind_left_order= and =bind_right_order= prove descriptor-order binding;
index ownership and schema admission remain explicit implementation refinement
obligations. =WeightedExport.qnt= executes both accumulator loops and both axis
queries, with retirement, public mutation and an independent sibling result.
Order, source aliasing, shared sibling, wrong-axis and descriptor-count mutants
must be rejected. Weighted mass is computed from both actual axes.

* Fixed native A/B admission
Baseline sources freeze =bdae4a23168c5dc0fe96b47fff81d94387849ae8= with only the
reference UF import redirected to its frozen view module. Weighted 384 SCC and
two grouped 192 SCC exports include freeze plus every public row. Left/right
queries consume complete selected results over a prepared 384 SCC cut. Dense
192 chain, sparse 128 disjoint edges and a small chain are controls.

Thirty-two operations form a sample. The original eight-operation calibration
missed the paired-win gate (14/20, then 15/20) despite a lower CPU median.
Both failures remain recorded; the larger fixed sample retains natural GC and
the identical CPU, allocation, win, heap and parent-timeout thresholds. There are 20 alternating natural-GC CPU pairs,
20 ASP admissions, and five allocation pairs with GC outside the counter.
Weighted/grouped export and both queries require CPU <=90% and >=16/20 wins.
Every scenario retains allocation <=110% +8192 bytes: public row storage already
has one outer cell and a fresh tuple per result, so this batch targets CPU rather
than claiming that required public storage can be removed. Controls retain
CPU <=110% +20us. ASP p95 <=999ms, parent timeout 90 seconds, interpreter heap
3GB. Thresholds are fixed before measurement.

Old/new complete answer sets are compared outside timing; separately allocated
UF roots do not establish the same global hash traversal order. Fixed descriptor
exports and queries within each cut are checked for exact order by native and
independent Python tests. All logs, binaries and receipts stay under ignored
=.cache/ascent/uf-weighted/=.
