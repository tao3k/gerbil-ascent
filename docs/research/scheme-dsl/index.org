* Cross-paper synthesis
:PROPERTIES:
:CUSTOM_ID: scheme-dsl-synthesis
:END:

A22 makes relation atoms, dependencies, and join planning central,
while its arrow and host forms are embedding choices rather than a
syntax requirement for our Scheme language.  F16 supplies
a formal example of functional fixed points guarded by monotonicity and
finite-height structure.  H13 shows how a small Scheme relational core
can gain a user interface through ordinary functions and macros, but its
stream search is a different evaluator.  F20 makes whole Datalog
fragments first-class values and checks the composition they form.

Our proposed =relation-view= is an inference across those sources: a
fixed, finite, pointwise Scheme function contributes rows monotonically
as *input tuples* grow.  No cited paper proves arbitrary Gerbil
procedures stable, pure, terminating, or visible to the planner.  Those
are explicit admission and test obligations in the proposal.

The deeper [[file:datafun-f16.org::#datafun-termination][Datafun reading]] separates
monotonicity from termination: one emitted row per call can generate
an infinite recursive chain.  An explicit finite-height fact domain
could support a closure claim; the current fact budget only bounds
execution through failure.  This changes the proposed view's
acceptance gate, not the current implementation's evidence status.

The other sources constrain separate boundaries: [[file:ascent-a22.org::#ascent-rule-boundary][Ascent]]
requires planner-visible bindings and dependencies;
[[file:flix-f20.org::#flix-composition-boundary][Flix]] requires checks after
fragments are assembled and has a stronger static assurance that this
repo does not implement; [[file:microkanren-h13.org::#microkanren-kernel-boundary][µKanren]]
supports a small Scheme kernel with user-level syntax while retaining
its distinct stream-search semantics.

The long-term [[file:../../scheme-relational-dsl-design.org::#scheme-dsl-architecture][architecture decision]]
now separates Scheme functions that *construct* program values from
functions evaluated *inside* a fixed point.  The former can remain
ordinary higher-order Scheme.  The latter need declared bindings,
effects, dependencies, stable captures, and a finite-height or explicit
resource-failure story.  A =relation-view= is a possible pointwise
adapter; it is not the whole language design.  [[file:datafun-s20.org][S20]]
provides a research route to higher-order delta evaluation after a
typed operator IR exists, while [[file:flix-l25.org][L25]] adds
hygienic private predicates and explicit program/solve/query stages.

#+NAME: paper-transfer-decision
| Source | Adopt as design constraint | Do not infer |
|--------+----------------------------+--------------|
| A22 | Preserve inspectable atoms, SCC/delta and join visibility | Rust arrow syntax or Rust performance transfers |
| F16 | Require stable monotone dependence and finite-height closure evidence | Arbitrary Scheme calls are statically proven |
| F20 | Check combined schema and negative cycles after composition | Gerbil fragments have row-polymorphic static safety |
| H13 | Keep a small semantic kernel beneath Scheme abstractions | Stream-search fairness equals bottom-up completion |
| S20 | Explore typed higher-order change semantics | Existing opaque closures receive a semi-naive theorem |
| L25 | Design program values, private handles and explicit solve/query | Flix syntax or static effect/type system already exists here |

* Next evidence gate

Design the new Scheme grammar and semantic IR first.  Build one native
fixture combining recursion, a scalar projection, zero/one and
multi-row views, fragment composition, and source replacement.
Record complete fact sets against an independent finite model.  Rust
comparisons are historical research, not a new-language gate.
Exercise rejection of unbound modes, arity
errors, mutable captures, and negative cycles after composition.  Then
measure the plan and SS profile against the current Scheme surface.
