#+TITLE: Projection list gate on the current Actor cut

* Source and measurement contract

The million-row projection publishes the admitted affine view as both
the source and the empty target's result. The view only needs the numeric
count, offsets and strides. =rows-of= calls the captured view's exporter.
=program/source-cut.ss= constructs each row and its outer spine directly
from those fields in public order. Its fallback source promises stay
unforced on this path. The fixtures independently retain both caller
inputs for all alternating replacements. The independent verifier reads
the delivered list after export and remains inside the native request
clock.

The existing =detached_million_list_footprints= and
=affine_views_leave_fallback_unforced= fix the fresh pair layout and
exclude a second source list on this path.
=redundant_projection_root_no_reachable_saving= applies when an owner
reference aliases the caller's live inputs. A matched native root
control varies only retention of the completed Result and Session, with
the same caller inputs and detached suffix in both arms.

The single-request diagnostic brackets replacement, publication,
delivery and independent verification. It measures GC inside each of
those intervals and accepts allocation deltas only when the collection
count is unchanged and the allocation counter is monotone. This is the
contract of =whole_list_phase_bounds= and =observed_allocation_valid=.
=whole_list_preserved_phases_limit= checks the observed schedule if its
export GC and verifier durations are kept fixed. It cannot predict a
new collector schedule. The original native gate runs independently
with its original source, settings and assertions.

* Native gate and individual request

The source baseline is =5aba102e=. The unchanged million-row suite ran
once via =gerbil test= on Gerbil with Gambit =2df89af=, one VM processor,
a 2 GiB heap, and the original 90-second watchdog. It verified all
1,000 requests and failed the strict 100 ms assertion at 105.931 ms.
The preceding 107.56 ms failure and its receipt remain available.

A separate phase build used the same input cuts, list consumer and
independent oracle and verified all 1,000 requests. Its wall P95 was
105.228 ms. At that rank, request 670 (zero-based) had the following
observations from the same request.

| Phase | Wall (ms) | GC wall inside the phase (ms) |
|-------+-----------+-------------------------------|
| Source replacement | 1.865 | 0 |
| Run and publish | 0.158 | 0 |
| Detached list delivery | 96.943 | 94.848 |
| Independent oracle | 6.176 | 0 |
| Request total | 105.228 | 94.848 |

That delivery recorded one GC with 94.671 ms GC CPU. The longest
observed request was 150.631 ms with 139.072 ms in its delivery GC.
On the 777 deliveries without GC, the allocation counter delta was
144,002,400 accounting units for each. Those deltas use a single
counter epoch and may differ from object-layout bytes. Requests
without delivery GC had 11.081 ms P95. The historical uninstrumented
failure has no individual phase marks and keeps its original receipt.

In the current trace, 20 requests reached 100 ms from delivery GC alone.
For 56 requests, delivery GC plus the separately measured oracle
reached 100 ms. Lean kernel replay checked the counts of all 1,000
observations in groups of 25 and instantiated
=whole_list_preserved_phases_limit= with the checked trace. Even with
zero other work, at most 944 requests qualify if those GC and oracle
intervals are fixed. The strict P95 requires 950. The replay used the
original Guard settings and retains the earlier failed elaborations.

* Owner-only root control

Both arms kept the same two caller lists and the same verified suffix of
a freshly returned mutable result. One arm kept the completed Session
and Result. The other closed the Session and released both. Each arm
ran in a fresh native process and recorded eight forced collections
after setup. These controls measure retained accounting and separate
pauses with a fixed root set.

| Detached rows held | Live bytes with owner | Live bytes without owner | Difference | Median GC wall with / without owner |
|--------------------+-----------------------+--------------------------+------------+--------------------------------------|
| 500000 | 486666432 | 486547248 | 119184 | 97.34 / 95.83 ms |
| 1000000 | 558949936 | 558830768 | 119168 | 112.18 / 112.31 ms |

The marginal owner accounts for about 0.114 MiB in both cases. Holding
another half-million output rows adds about 68.94 MiB in either arm.
The forced measurements do not supply a pause prediction for the timed
request schedule. The native loader's first owner-probe launches were
rejected before executing the test because the compiled interface path
was incorrect. The table uses the four naturally completed probes
from the discovered interface.

* Disposition

The measured owner lifetime and the direct exporter expose no sizable
ASCENT-owned root or removable container on the gate's path. The audit
therefore records evidence without a production change. Actor, engine
interface, condensed Session and independent oracle suites passed. The
full Lean inventory completed all 196 jobs. Existing failure receipts,
ordering, mutable list semantics and the 100 ms and 90-second limits
were retained. The conditions for pushing PR #2 remain unmet.
