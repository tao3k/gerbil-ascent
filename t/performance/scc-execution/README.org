#+TITLE: Complete engine SCC workspace and dependency admission

* One execution flow

This batch spans =program/component-plan.ss=, =program/component-worker.ss= and
=program/positive-components.ss=. A component compiles immutable dense relation
addressing from its output members and referenced input atoms. The pure plan's
relation descriptors are copied into that namespace; compiled term readers,
matchers, frame extent, action order and delta ordinals remain unchanged.
The emission boundary restores the exact original atom descriptor before owner
membership, unique-row charging, global budgets and merge credit.

A private final layout contains slots, local member/rule metadata and descriptor
restoration. Native weak identity caching retains no row, frame or physical
index state. Compilation runs outside the native primitive-operation lock.
Ready admission copies only referenced row roots and sizes into fresh compact
vectors; an assignment owns compact all/delta/version/candidate/index vectors.
Borrowed persistent row spines are not mutated. Full transferred snapshots used
by existing worker callers retain their committed output/header contract on
normal and exceptional exit; unrelated input slots keep their original roots.

The immutable SCC plan also records reverse dependency edges. Each invocation
counts only unfinished rule-owning predecessors; source-only predecessors are
already complete. Actor readiness becomes a constant-time counter lookup.
Only the coordinator decrements successors after all terminal owner merges.
Task selection order, pool lifecycle, bounded batches, credit/refusal, first
failure propagation and cancellation cleanup remain the existing actor kernel.
This improves dependency admission, not the pending-list selection algorithm.

* Gerbil source study

Installed Gerbil =1cfb032= =compiler/optimize-base.ss:334-340= constructs mutable
method state at its actual use; =compiler/optimize-top.ss:1269-1281= avoids
unneeded expression wrappers. The transferable boundary is to prepare only
referenced mutable state, rather than copying the whole program into every task.
=std/list/list-builder.ss:5-24= provides the hygienic ordered collector used
by dense slot construction. =std/make.ss:296-304,350-363= separates dependency
completion from worker lifetime and joins the pool after admission closes.
ASCENT keeps its own terminal merge-credit contract while reducing dependency
predicate work. These patterns do not prove relational semantics; native
exhaustive graph, timeout, budget and ownership tests provide that evidence.

* Full baseline and fixed scenarios

The complete baseline is =652ebddd2fee62707d72e0d92db798847dd849bc=. Four frozen
owners (=reference-evaluate=, =reference-component-plan=,
=reference-component-worker= and =reference-positive-components=) change only
imports. Reversing their relocations reproduces all four baseline blobs byte
for byte. Existing core positive traversal, physical index and Result helpers
remain shared unchanged implementations. This is a complete engine comparison,
not a direct microbenchmark of one compact helper.

=wide= evaluates 128 independent output SCCs with eight source rows and 512
unrelated empty relations. =chain= evaluates 96 dependent output SCCs with the
same padding; outputs have high global relation positions, so prefix truncation
cannot qualify as compact addressing. Both clocks include fresh engine setup,
SCC admission/closure, owner merges, commits, publication and all relation
size/row queries plus canonical sorting. Declaration and cached analysis
preparation are outside warm clocks. The independent expected answer follows
copy-rule mathematics and original declaration order, not either solver.

=indexed= closes a real recursive keyed 31-edge reachability chain against the
independent set of all ordered pairs i<j. =cold= constructs declarations and a
fresh one-row engine within every clock. =small= executes one one-row SCC.
=serial= runs the unchanged single-worker engine path. Actor scenarios use
native =##cpu-count= capacity on both sides; the pool still admits only ready
work. These are workload-specific CPU results, not evidence of multicore scale.

The native ASP fixture API generates =benchmark.ss=. Gates fixed before any
sample: targets require CPU <=90% of baseline and >=16/20 wins; controls permit
<=110% +20us; all allocations permit <=110% +8192 bytes. Each scenario includes
20 alternating natural-GC CPU pairs, 20 ASP admission samples (p95 <=999ms)
and five alternating allocation pairs. Allocation legs collect before reading
the cumulative VM counter, outside the interval; negative deltas are rejected.
ASP owns separate state and cannot alter paired inputs. A single 90-second
watchdog bounds all six scenarios. No scenario or gate may be dropped/widened.

* Audit limits and rejected directions

The baseline already commits complete SCC closure once; an extra global solver
round is not the selected bottleneck. A generic core relation-remapping API was
withdrawn: local addressing belongs to the private component workspace and
needs no new core/public expression capability. Existing unrelated core Policy
findings were not changed or claimed cleared. Optional-field construction and
an unavailable list-count import failed native compilation; the private record
uses explicit fields and dependency counts use native =for/fold/in-list=.
These failed build receipts are retained. Worker capacity and native runtime
configuration remain those of the existing caller/toolchain.
