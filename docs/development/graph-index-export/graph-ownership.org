* Index Graph reuse boundary

The earlier ASCENT integration experiment used Yuanxu =bbcb8fe9= and POO
=6cf940be=. See [[file:build-and-integration.org][Build and integration]]
for the current Release cohort. The source audit
below uses the local POO commit =261a9614=; it does not claim that the
consumer executes code from that commit.

| POO mechanism | ASCENT consumer decision |
|----------------+--------------------------|
| Explicit roots over a captured inverse index | Adopted for dense dependency closure; the caller already has relation ordinals. |
| Indexed projection from touched owners to work | Candidate for rule activation after closure; =gerbil-ascent-select-rule-plans= still scans all strata and rules. |
| Persistent base with a sparse fork | Candidate for immutable publication roots with a symbol-keyed directory; =support/index.ss= is not the row-key index. |
| SCC repair and quotient support deltas | Applicable to topology edits; replacing or appending facts in an unchanged declaration does not alter its SCCs. |

The first production experiment should target sparse activation on an
unchanged admitted program. Capture output relation ordinal to ordered
rule occurrences while constructing immutable analysis. During a source
update, use reached relation ordinals to select those occurrences, then
project heads in declaration order. Distinct rules with equal bodies
remain distinct occurrences. Multi-head rules must retain the exact
ordered subsequence of affected heads, including repeated occurrences.
Reuse the existing scan for dense cuts until the measured crossover
justifies another choice. The current admission and fallback for opaque
callbacks and providers stay in force. Neither the index nor a sparse
selection can publish partial results on cancellation or exhaustion.

Lean =SourceUpdateFrame.RuleActivation.gathered_schedule_preserves_projection=
establishes ordered occurrence and head equality for a schedule with exactly
the gathered members in strictly increasing declaration order. Repeated heads
survive the ordered projection. =gather_reads_touched_buckets= counts the
ordinal entries read from the reached buckets. The model assumes that those
buckets are already captured correctly and does not charge index construction,
deduplication, ordering, or frame activation. The Scheme selector still scans
the roster. Source correspondence must cover bucket construction, the
deduplicating scheduler, and the existing plan and frame reuse decisions.
The cost comparison must include index construction and residency,
closure, selection, frame activation and execution. In the same native
Session interface, compare sparse and dense cuts, include a deletion
with negation or aggregation downstream and check provenance. Record
visited rules and heads, cumulative allocation and wall P95 separately
for cold admission and warm updates. This is a proposed consumer
experiment; the earlier closure-only measurements do not qualify it.

The complete weighted UF export has a different cost floor: even if an
index makes discovery cheaper, the API still constructs every requested
row and independent mutable list spine. Keep that case in the original
suite and attribute its materialization and GC costs separately from
lookup or activation. No Index Graph producer timing can substitute for
that gate.

* Retain graph publications across source appends

POO's reusable unit is the admitted graph and its publication identity.
=support/index.ss= forks a shared base with sparse edits, while
=generalized-graph.ss= and =component-revision.ss= limit the revision to
affected owners and reject a stale publication. The ASCENT source consumer
is =program/view-state.ss=. It already retains a lazy ordered product graph
per cut for bounded integer histories, but =program/view-replay.ss= declines
many histories with old/old insertions before the terminal event. Those cuts
rebuild the journal's graph when enumerated, even after the storage owner has
already committed the same UF frontiers.

Use the existing UF transition as the source of ordered frontier descriptors.
In =table/trrel-uf.ss= both =gerbil-ascent-trrel-uf-insert!= and
=gerbil-ascent-trrel-uf-replay-insert!= consume the same admitted blocks.
The SCC merge assigns new member spines with =append= and reassigns node
fields. Older blocks can retain the old spines. The next implementation must
carry the admitted descriptor through the existing staged frontier and
commit boundary, including the count-only initial and append routes. Count
the descriptors and retained axes before publication. Keep a generation's
earlier descriptors shared across its appends and refuse reuse after source
replacement or failed admission. Preserve derived batch reversal separately
from the source lane and the delta suffix. Only new facts enter a new block.
Do not materialize full rows or build a second UF index during commit.

This is the publication mechanism suggested by POO and the disjoint products
of factorized query results. Ascent's delta scheduling supplies the accepted
frontiers. MiniDusa's indexed prefix work illustrates why downstream checked
consumers should enter through the affected key rather than walking unrelated
frontiers. It does not provide the provenance or UF membership semantics.

[[https://arxiv.org/html/2405.19040v3#S7.SS1][Finite-Choice Logic Programming, section 7.1]].

* Retire SCC index entries by affected owner

The POO Graph comparison is an owned update. The public report separates
cold index construction, changed buckets, and ordered output. The current
locally inspected POO source was =a682d15=, including the prior
=733e40a= affected-region work. The relevant transferable idea is to
find changed owners through retained adjacency before touching buckets.
Pearce and Kelly give a related locality criterion for DAG order repair.
ASCENT's operation here is SCC quotient and transitive-index maintenance.

In =table/trrel-uf.ss= the old merge filtered the complete root roster,
searched the entire surviving roster for forward retirement, and examined
both tables of every survivor for representation retirement. The dense
reverse branch also visited the surviving roster. The new merge begins
after missing rectangles are committed. In the resulting closure, if a
surviving root reaches a loser then it reaches the winner, and if a loser
reaches a surviving root then the winner reaches it. The converses hold
for a nonempty loser set. The winner's existing reverse and forward rows
therefore locate the exact affected owners. Drop internal keys from those
two rows before iterating them. Iterate the winner's reverse row while
changing only external forward rows, then iterate its forward row while
changing only external reverse rows. Each bucket keeps its sparse or
packed representation and is normalized only after local retirement.

The group roster remains newest first. Retire losers from the prefix
through the oldest losing birth ID and share the unaffected suffix.
The population changes by the number of losers. A whole-group collapse
releases the winner's adjacency and registry without traversing retired
arcs. Groups with no reverse index still use the existing bounded
small-group fallback. Frozen descriptors retain member spines, and the
merge only replaces a member field. Budget preflight and the exact
frontier production precede adjacency retirement.

For an indexed partial merge the owner-opening count is
=2 + external predecessors + external successors=. Key deletes, packed
word work, and the root roster prefix have separate charges. An old
loser's rank can still make that prefix long. A pure count and sparse
index checks do not predict physical allocation, GC or total latency.

* Enumerate the existing packed reach index in birth order

=table/uf-reach.ss= previously made =ordered-neighbors= choose between
scanning the live root roster and sorting the selected keys. The packed
index already knows the order. Its words name group-owned birth slots,
and =compact-reach-for-each-id= enumerates them in ascending order. Use
the existing =axis-for-each= to insert the implicit diagonal exactly once
and build the requested private spine. The packed route applies when
backing word count is at most degree. In particular, a broad historical
span after retirements can still take the established fallback.

This applies the POO Graph practice of traversing the owned bucket and
using its existing order. It shares no mutable registry between graphs
and leaves each insertion's preflight, budget and publication sequence
intact. The exact position of the diagonal matters: the traversal order
also feeds the cycle roster, union winner selection and ordered frontiers.
=gerbil-ascent-trrel-uf-validate= checks live birth IDs, diagonal exclusion,
word cardinalities, and the forward/reverse ownership invariant.

Guarded Lean =ordered_axis_both_directions= proves sequence equality
from strict birth order and identical support. The packed visit bound
counts at most =2 * degree + 1= word, selected-root and diagonal visits
under the same guard as the Scheme source. The bound excludes output
spine writes and the optional in-place reversal. The model does not
assign clock costs to these operations. Bit/registry integrity and native
publication order have their own tests.
