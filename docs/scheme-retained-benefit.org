#+TITLE: Native retained replacement benefit measurement

* Question and executable boundary

Does checked dependency reuse reduce native work and elapsed time relative to
a fresh solve of the identical prospective input? Run =just build-dsl-closure=
then =just check-retained-benefit=. The native entry uses the same compiler,
dependency prefix, DSL and evaluator for both paths. Scheme verifies source
and binary hashes and admits the artifact. The Python IO package supervises
genuine process activity; it decides no semantic truth.
The unchanged bounds are 1G heap, 5 seconds without actual output and 120
seconds for the complete measurement process. Compilation and parent artifact
finalization no longer have a 180-second total deadline, following the user's
explicit build policy correction. The build supervisor observes actual command
output and CPU-time advances in its own process group; 60 seconds with neither
signal fails the build. CPU activity is evidence of execution, not proof of
semantic progress or successful compilation. Compilation must still exit 0,
and source/owner/binary binding must pass before artifact publication. Runtime
Cases retain the five-second output and 120-second module bounds. Historical
deadline failures below remain failures under their original policy.

* Workloads and independent truth

The original receipts measure a twelve-edge chain plus an independent
singleton source and its copied output. The current entry also measures a
48-edge chain. Each condition has thirty groups of three timed arms; all six
order permutations occur five times. Batch sizes are 16 for twelve edges and
4 for 48 edges, with a distinct completed base Session for every update.
Declaration, completed initial solve/check and completed timed-arm markers
report actual work outside timers; they are not periodic heartbeat output.

| Condition | Source transaction | Expected active native plans, fresh / retained |
|-----------+--------------------+------------------------------------------------|
| independent | Change the singleton 7 to 8 | 3 / 1 |
| recursive | Remove edge 0->1 | 3 / 2 |
| all-inputs | Both changes together | 3 / 3 |

Scheme verifies completion and every row of all four relations before
publishing a sample. Its independent model checks x<y membership, rejects
duplicates and checks the complete triangular cardinality. After deletion
node 0 is isolated; the lower bound becomes 1. This establishes exact closure
without comparing one evaluator output with another as the sole oracle.

* Timing contract

Each batch opens and completes distinct base Sessions. Initial construction,
initial solves, forced GC and independent row checking are outside the timers.
Three separately named arms preserve the distinction between solve and update:

| Arm | Timed work |
|-----+------------|
| solve | evaluate-program on the preconstructed prospective program: engine admission, computation and publication |
| fresh-update | Construct a prospective source snapshot from base declarations and ready replacement rows, then full evaluate-program |
| retained | replace-sources!: snapshot, replacement admission, dependency invalidation, computation and publication |

The fresh-update snapshot preserves the base rules/providers/declarations and
overrides source rows through the same POO prototype mechanism used by Session.
Both update arms therefore start with base declarations and ready replacement
rows and include candidate construction. The solve arm remains a diagnostic
control, whose time must not be relabeled as the cost of a complete update.
The original Session setup cost is therefore excluded explicitly: these are
update measurements for an already retained session, not cold-start claims.

Raw samples report per-operation batch means for current-jiffy wall seconds,
cpu-time process CPU seconds, native allocated bytes and active-rule-count.
The result vectors, loop index lists and two-element f64 counter buffer are
allocated before timing. Gambit's native =##get-bytes-allocated!= implementation
was checked against installed compiler commit
[[https://github.com/gambit/gambit/blob/dcd677cd3e40860bdd27dfbdbf5e3ce46ab03813/lib/_kernel.scm#L4126][dcd677cd3e40860bdd27dfbdbf5e3ce46ab03813]]. Allocation is not live heap or peak RSS.
Active plans are a dependency-selection observation,
not counts of every rule invocation, join, allocation or instruction. No
speed threshold turns a slower but correct sample into an omitted result.
Shared-host interference remains possible even with counterbalancing.

* Historical solve-boundary receipts

The first accepted 60-pair run reports the following wall-time medians. CPU
medians track them closely; every raw pair is retained in the evidence receipt.
The [[file:evidence/scheme-retained-benefit-20261004/receipt.json][receipt]] binds source 004a349 and the accepted native artifact,
all raw distributions, the 125-Case rerun and five unchanged Rust differentials.

| Condition | Fresh wall median (microseconds) | Retained wall median (microseconds) | Retained / fresh median |
|-----------+---------------------------------+------------------------------------+-------------------------|
| independent | 63 | 164.5 | 2.61 |
| recursive | 54.5 | 174 | 3.19 |
| all-inputs | 55 | 182.5 | 3.32 |

A second complete 60-pair measurement on source 05a1921, integrating the
concurrent activation-cache change f01c7b0, still reports no small-chain speed
benefit. The [[file:evidence/scheme-retained-benefit-integrated-20261004/receipt.json][integrated receipt]] binds its distinct source and artifact.

| Condition | Fresh wall median (microseconds) | Retained wall median (microseconds) | Retained / fresh median |
|-----------+---------------------------------+------------------------------------+-------------------------|
| independent | 63 | 170.5 | 2.71 |
| recursive | 60 | 179.5 | 2.99 |
| all-inputs | 59 | 183 | 3.10 |

The two runs are not a controlled A/B of the activation-cache implementation:
compilation state and host conditions were not held fixed. Each run separately
counterbalances fresh versus retained update and keeps all twenty pairs.
The original pre-integration snapshot is reconstructible from published
a68d044 plus its receipt's source-snapshot.patch after the commits were rebased.

These are ratios of medians, not medians of paired ratios. On this small
workload there is no measured speed benefit, including when fewer plans are
active. Snapshot, admission and update management costs are included; their
individual contributions have not been profiled, so this result does not
attribute the regression to one particular function. Microsecond samples are
especially sensitive to host state and clock granularity. Do not extrapolate
these ratios to larger inputs.

The [[file:evidence/scheme-retained-batch-solve-20261004/receipt.json][batched solve-boundary receipt]] additionally records 120 paired groups,
17,280 independently checked measured results and native allocation counts
on source d2922ec. Its complete process finished in 108.92 seconds under the
original 120-second bound. The data contains all orders and every sample;
candidate construction remains excluded from its solve control.

* Scope and remaining acceptance

The user's build-policy correction is recorded in the
[[file:evidence/scheme-build-activity-20261004/receipt.json][activity-supervised build receipt]]. Source 99208d7 built in 297.47 seconds
with exit 0 and completed artifact binding. The process snapshot observed four
concurrent gsc processes with GERBIL_BUILD_CORES=4. This supersedes the build
gate failure for that source; it does not retroactively accept earlier killed
builds or establish a concurrency speedup. Dependency
initialization and linking include serial phases even with parallel objects.
The same artifact subsequently passed all twelve native Suites and 127 Cases,
with twelve MODULE-OK/HARNESS-OK/final OK markers and exit 0. This includes the
24 model-task native preflight Cases. The three-arm measurement then failed
the unchanged five-second output gate inside its first retained timing batch,
after the fresh arm completed; no completed group or distribution is accepted.

The [[file:evidence/scheme-retained-transition-20261004/receipt.json][latest transition receipt]] records the integration of concurrent source
7e0a060 and all rejected build/progress attempts. Its three-arm entry at that
historical source was not accepted: compilation reached the then-active 180-second
deadline. A prior pre-integration build completed in 126.06 seconds, but its
measurement subsequently failed the five-second startup progress bound. The
entry now reports only completed declarations, solves and timed arms; current
native qualification must pass before publishing its distributions or freezing
a new paid model plan. Prior 125-Case receipts bind their original sources.

On source 7103f87 the native dynamic model module completed all 24 tasks,
including the two actual function-valued fixed points (independent bitmasks
3 and 1), with NATIVE-MODULES-OK, MODULE-OK, HARNESS-OK, final OK and exit 0.
That invocation did not enforce the five-second output watchdog. A separate
direct gxi/gxtest invocation with the watchdog exited 124 before any output.
The first result establishes computation agreement only; neither invocation
replaces the accepted AOT preflight or authorizes a model accuracy claim.

The architecture must qualify a cost crossover before selecting
reuse on performance grounds. Next evidence needs larger independent and
fully affected components, batch duration above the timer resolution, separate
setup/update accounting, and profiling of admission/snapshot/native solve
allocations. Any cost-based choice must preserve the same atomic publication,
failure recovery, budgets and independent result checks. Counting fewer plans
alone cannot authorize a claim of runtime savings.

This finite chain experiment cannot establish general runtime benefit, memory
benefit, provenance cost or model reasoning gain. R5 also needs per-operation
memory/allocation distributions, larger and varied workload families and
reproducible measurements on an isolated host. R6 still requires a newly
frozen actual-source plan and explicit source-disclosure/cost authorization.
No paid model calls belong to this experiment. MRR integration remains gated.
