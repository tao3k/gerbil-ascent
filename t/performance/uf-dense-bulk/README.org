#+TITLE: Admitted dense UF axis transfer qualification

* Scope and source study

The baseline is the previously accepted word-bitmap implementation at
=c3b4da20755141fa2eaff12fe270756cee15b451=, not its earlier hash-only baseline.
=reference-trrel-uf.ss= is byte-identical to that commit's UF source. Native
closure targets compare separate historical/current kernels. Complete engine
controls retain the earlier evaluator references and share current canonical
storage helpers; they do not measure a historical whole-engine speedup.

Gerbil =1cfb032= supplies two complementary ownership patterns:
- =std/vector/extensible.ss= separates native buffer ownership from its logical
  extent and copies an owned span with =vector-copy!= /=subu8vector-move!=.
- =gerbil/runtime/util.ss= =append-reverse-until= constructs a selected axis in
  its consumer's order with =cons=, rather than selecting then copying again.
  =std/list/list.ss= =group-same= destructively reverses its own constructed
  bucket spines. That rule cannot be applied to an arbitrary =filter= result:
  the installed native filter can return the original list unchanged.

A native probe records =FILTER-SHARES=#t=. An attempted destructive reversal
failed root-population and semantic regression tests and was withdrawn. The
final implementation never destructively reverses borrowed root selections.

* One admission, traversal and commit contract

A private final =closure-axis= carries a root and its stable dense adjacency.
=axis-for-each= visits set birth IDs in ascending writer order, merging the
axis root at its correct position. =axis-weight= uses that same traversal for
weighted fact preflight. A dense fresh source/sink therefore needs no expanded
root-list spine for either preflight or commit. Sparse count selections are
constructed directly in writer order; scalar frontier selections retain their
legacy order. Count-only SCC intersection separately restores legacy root
order, including largest-component tie selection and persistent member order.

Once the budget is admitted, a fresh endpoint owns a complete new adjacency:
its opposite endpoint's already closed adjacency plus that endpoint. Copy the
native words once, set the certified missing self-axis bit, and install the
cached degree. Update only the opposite index per component. This removes
repeated sparse population, bitmap promotion and intermediate vector growth
from the newly owned index. Scalar frontier construction and count commit use
the same symmetric copy contract. Existing endpoints keep missing-pair checks.

Copy admission preserves the previous density growth bound. A distant birth
ID may extend a buffer only when its required payload is <=2 bytes per new
arc; otherwise scalar insertion remains responsible. The buffer is always
copied, never shared between mutable adjacency owners. The group registry
remains shared. Captured cuts retain persistent member spines, never this axis,
its mutable bitmap or its registry. No allocation or registry installation
moves before successful fact-budget preflight.

* Fixed experiment

The native baseline, populations, gates and sample counts were fixed before
sampling. Targets: 512 forward-chain edges (=dense=), 512 reverse-chain edges
(=reverse-dense=), and 256 forward-chain edges (=chain=). Each requires CPU
<=90% baseline, >=16/20 wins, and allocated bytes <=80% baseline +8192 bytes.
Twenty alternating process CPU pairs retain natural GC. Five alternating
allocation pairs collect outside the VM counter interval. Twenty separate ASP
=benchmark-run/result= admissions retain p95 <=999ms. All twenty scenarios
must finish in a single 90-second invocation; no timeout or failed gate is
loosened. CPU measures user+system time, not elapsed wall time or SMP scaling.

Controls retain <=110% CPU +20us and <=110% allocated bytes +8192 bytes:
=native-star/native-groups/native-small/dense-cut/cycle/unique/partitioned/
sparse/grouped/retained/capture/cold/small/packed/adjacent/large/eqrel=.
Native controls compare genuinely frozen/current UF owners. Complete engine
controls share live helpers. The fixture preserves independent closure counts,
physical component counts, exact scalar frontier comparisons in native tests,
weighted SCC behavior, grouped state and immutable cut checks.

* Reproduction

Use the repository's package prefix and its native Gerbil environment boundary:

#+begin_src sh
# GERBIL_PATH selects the standard package prefix; std/make owns all compilation.
export GERBIL_PATH="${GERBIL_PATH:-$PWD/.gerbil}"
gxi -:max-heap=3G,debug=q t/performance/uf-dense-bulk/build.ss "$GERBIL_PATH/lib"
mkdir -p .cache/ascent/uf-dense-bulk/receipts
timeout 90s gxi -:max-heap=3G,debug=q \
  -e '(add-load-path! (path-expand "lib" (gerbil-path)))' \
  :gerbil-ascent/t/performance/uf-dense-bulk/runner all \
  .cache/ascent/uf-dense-bulk/receipts
#+end_src

Tests remain in =t/qualification/ascent-uf-dense-bulk-test.ss= and the existing
UF/storage/publication suites. Build and tests use native Gerbil/ASP interfaces;
no Python harness, custom process scheduler or build-entry test logic is added.
Concurrent uncommitted interface/evidence changes in the shared workspace are
excluded from the qualification snapshot and this commit.

* Failed experiments and evidence boundary

Ignored =.cache/ascent/uf-dense-bulk/= retains every attempt separately:
- =rejected-copy-only=: CPU improved but reverse-chain allocation saved only
  about 12%, failing the fixed 20% requirement. It overlapped the initial unit
  test run and supplies no accepted timing samples.
- =rejected-borrowed-axis=: native regression tests exposed root-list mutation
  after destructively reversing a filter result. No timings are admitted.
- =rejected-list-axis=: directly constructed list axes preserved semantics but
  still failed the reverse-chain allocation gate. No samples enter the final
  medians.

VM allocation reduction is not a claim about total retained heap or peak RSS.
The closure still has quadratically many logical facts in the worst case.
The representation probe separately measures bitmap payload, excluding vector
headers, sparse hash capacity, persistent members, journals and runtime memory.
