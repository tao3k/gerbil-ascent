#+TITLE: Provider Admission: proofs

Feature owner: [[file:../index.org][feature index]]. This page retains the original
source dates and qualification boundaries. Current evidence is commit-specific.

* Provider concretization native correspondence: isolate storage injection spines (2026-10-06)

[[https://kmicinski.com/assets/byods.pdf][Provider concretization Sections 3.1 and 3.3]] express injection and concretization as operations
on abstract relation state. The Scheme implementation supplies concrete row
snapshots to a StorageProvider. An independent ownership condition is needed
so retaining those lists cannot modify source authority or previously
published facts outside the evaluator's admission and publication paths.

The unrepaired native storage suite shows both failures. A retained extension
output changes a published =((1) (2))= into =((99) (2))=. Retaining and mutating
input rows changes the original source to =((99) (99))=. Both checks reject;
a compile-only constructor arity mistake was corrected before recording this
semantic counterexample run.

=table/storage.ss= now owns a schema-selected extension function. Four native
receiver identities are privately retained and keep direct dispatch. Derived
or caller-defined receivers get copies of all/pending outer and row spines,
plus the input row spine. Equal all/pending roots reuse one private copy,
preserving this observable header identity without lending engine roots.
Field values retain identity. Returned packets must be proper lists; every
row is checked with a traversal bounded by the admitted arity before copying.
This admits the complete shape before any stored-field callback.

=program/analysis.ss= caches this dispatch with the immutable schema, so the
initial source, derived rule emission and retained append paths all use the
same boundary. Their membership, budgets, callbacks and publication owners
remain in the evaluator and admission module. Native controls cover retained
arguments and outputs, prior results, rule materialization, malformed/cyclic
rows and batches, field-callback exclusion, native receiver selection and
shared nested-field identity. Existing duplicate order, budget refusal,
Session recovery and built-in BYODS composition remain required regression
checks. See the [[file:../../evidence/scheme-storage-spines-20261006/receipt.json][source-bound receipt]].

The new custom boundary changes malformed-packet callback ordering: no stored
field callback runs before the entire shape batch is admitted. It does not
prove semantic completeness of a custom extension or roll back its private
state. Nested field stability and arbitrary closure effects remain premises.
Copying costs scale with supplied all/pending snapshots and the emitted batch.
No new Lean/TLA source, provider speedup or general refinement is claimed.


* Provider concretization native correspondence: custom state readiness through publication (2026-10-06)

[[https://kmicinski.com/assets/byods.pdf][Provider concretization Sections 3.1 and 3.3]] describe injection and represented total/delta
facts. Scheme callbacks introduce another obligation: an exception must not
leave a reusable private state that remembers a fact the evaluator never
published. No rollback operation exists in the arbitrary StorageProvider API.

A native counterexample mutates a private vector before raising. The raw
retained engine then accepts another run, despite that state being capable of
suppressing the same fact on retry. Source rows and public publication remain
unchanged, so copying their spines alone cannot close this failure boundary.

Custom engine states now have a private =storage-state-owner= containing the
Provider's original value and a readiness phase. Provider code still receives
that original value. The immutable schema shares no readiness owner between
engines. Dispatch enters =pending=; receiver or shape failure becomes =failed=.
Typed-field and budget refusal leave the owner pending. A later public run or
append requires every custom owner to be ready and otherwise requests source
replay. The original failure is propagated at its first occurrence.

Readiness is restored after a complete initial extension batch or retained
source append, and after the whole rule-round commit has published rows,
membership, versions and physical indexes. It is deliberately not restored
per successful emission: a later guard can raise after an earlier injection
mutated private state, discarding the round workspace. Pending owners may
accept additional injections inside that same round. Deadline partial results
use the existing completed round boundary. Native Provider state representation
and preflight remain unchanged; custom readiness adds owner checks, with no
performance improvement claim.

Native controls cover raised, shape, field and budget failures; unsafe raw
engine reuse refuses until a fresh source solve. Session recovery uses its
existing fresh-engine reconstruction and preserves prior results. A two-row
rule emits once before a later guard failure and proves that this entire round
still requires replay; a fresh engine recovers both independent consequences.
The [[file:../../evidence/scheme-storage-state-20261006/receipt.json][receipt]] retains exact source and rejected/accepted native run boundaries.

This closes reuse of interrupted custom engine state under independent fresh
construction and stable fields. It does not prove arbitrary concretization
completeness, rollback private state, or reverse external closure side effects.
Native extraction and those remaining Provider laws still require separate
work. No Lean/Quint source is changed by this implementation.


* Provider concretization native correspondence: graph state readiness beyond kernel preflight (2026-10-06)

[[https://kmicinski.com/assets/byods.pdf][Provider concretization Section 3.3]] requires represented facts to cross the evaluator's
appropriate total/delta frontier. A kernel's successful private injection and
a complete engine publication are separate events. The native graph Providers
have atomic budget preflight in their raw APIs, but a later field checker or
rule guard can still reject the enclosing engine update after injection.

The unrepaired native =eqrel= control admits an edge's input fields, injects
=(1,2)= privately, then rejects a returned field. A raw engine retry silently
returns zero rows: the components already regard that edge as connected,
while the engine never published its four concrete pairs. This exposes why
kernel preflight alone cannot establish callback-sensitive engine atomicity.

=program/analysis.ss= now caches engine-specific dispatch from
=table/storage.ss=. Stateful native and custom engine states have private
readiness owners. A shared call boundary marks them pending, unwraps the
original private value for the kernel and preserves raised diagnostics.
The existing complete source/round publication owner restores readiness.
Failed or pending public engine reuse requires source replay. Native kernels
retain their borrowed-row execution without custom all/pending packet copies;
Canonical Set retains direct state and procedure dispatch.

Raw =gerbil-ascent-storage-make-state=, =gerbil-ascent-storage-extend= and native
algorithm dispatch remain unchanged. Their standalone preflight/refusal laws
are tested separately from engine admission. Raw engine failure is treated
conservatively even for a kernel-only budget refusal; Session recovery handles
that refusal by reconstructing its accepted source snapshot. No exception
classification by message text or generic private-state cloning is introduced.

Native controls exercise field rejection, raw retry refusal, Session recovery
and later guard failure for =eqrel=, =trrel= and =trrel_uf=. Fresh solves compare
against explicit independent two-/three-node concrete relations. Existing
custom state/row ownership and raw native graph budget/frontier qualification
remain required regressions. The [[file:../../evidence/scheme-native-storage-state-20261006/receipt.json][receipt]] retains exact source and native log
boundaries. This closes the native graph publication gap under stable field
values and independent constructors; external effects, general lattice laws
and native-to-proof extraction remain open. No Lean/Quint source or speed claim
is changed by this implementation.
