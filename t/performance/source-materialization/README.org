#+title: Accepted source cut materialization and update evidence

* Complete production flow

=program/source-snapshot.ss= owns exact persistent base/addition roots and their
ordered materialized rows. New source-state headers cannot mutate these records.
Unchanged roots share the materialization and declaration; changed roots produce
provisional records. Session replacement, recovery and timeout replay use that
owner. The native engine source replacement/replay path uses the same protocol.
The existing caller publishes a prepared cut only after candidate execution and
acceptance succeed. There is no global cache or retained chain of old cuts.

The optional internal source cut propagates from Session through updated engine,
reuse admission and update selection. It certifies only exact source equality:
the candidate Program, original base/addition roots and candidate row root must
all match the owned materialization. Foreign/stale evidence falls back to the
original complete ordered comparison. Eligibility, every fresh engine row check,
budget charging, dependency closure and completed-result admission remain intact.
The public Session methods and root build interface are unchanged.

The local Gerbil compiler at =1cfb032= allocates invocation-owned facts in
=compiler/optimize.ss:28-35= and records facts before recursive work in
=compiler/optimize-xform.ss:108-113=. Native =std/struct/lru.ss= illustrates compact
final records and typed field access. This unit applies explicit lifetime and
identity contracts to source preparation; it does not adopt an eviction policy
or cache callback results.

The complete handoff additionally covers =program/result.ss=. Its native factory
returns Result plus a private publication capsule through =values=. Engine owns
the latest capsule; Session forwards it to reuse admission. Exact completed
Result identity admits a read-only internal row reader. Foreign/stale capsules
fall back to the public protocol. Public =rows-of= and visitors still detach
row spines; retained native seeding owns new membership tables and row-list
headers, and rechecks all seeded rows/budgets. The capsule captures only one
published snapshot vector and its existing name resolver, never mutable engine
buffers or a prior capsule. Existing clearing of completed reuse releases the
previous publication. No global registry/cache or public Session method is added.
The native engine's internal getter follows its existing analysis/schema/log
handoff pattern. One-shot results do not allocate a publication capsule.

Native seeding additionally reuses fresh initial admission for an unaffected
canonical Set relation only when the immutable rule plan has no head writing
that relation and its source occurrence count equals the matching native
publication count. Fresh row/field/budget admission has already completed.
Every written relation keeps full completed-row seeding, even if its counts
coincide with source counts. Buffered duplicate appends with a count mismatch
also keep full seeding. The derived/duplicate equal-count counterexample is
an executable Case. This avoids building membership and row spines twice for
source-only relations without accepting an unvalidated source or closure.

* Fresh admission closes the eager replay gate

The final initializer selects lattice/view/Set/custom storage once per relation.
Its private syntax has two traversal modes: a callback-free exact Set uses the
native =foldl= occurrence counter and builds one private reversed row spine;
callback paths keep =for-each= and the original shape/field/expansion/quota order.
This distinction matters when a callback changes a borrowed source list header:
=foldl= prefetches the next node, while the old native =for-each= reads it after
the callback. The executable control checks independent rows and callback traces
for both engines. No per-row checker closure is allocated on the pure Set path.
