#+title: Native physical index batch construction protocol

* Gerbil source-backed expression layer

Gerbil =1cfb032= =runtime/table.ss:439-465= expresses =__table-update!= with
=defrules=: hash/probe happens once, and the update callback is invoked directly
before storing its result. =runtime/hash.ss:580= supplies checked =HashTable=
dispatch. ASCENT canonical buckets use this synchronous native protocol.

=table/funs.ss= owns =gerbil-ascent-index-batch!= as a hygienic =defrule=. The
caller binds its row identifier and key expression; the template owns one row
slot and one prepend callback for the whole batch. It evaluates the index once
and evaluates each key before publishing the row. =table/access.ss= uses that
protocol for scalar keys, replacing separate =hash-get= and =hash-put!= calls.
The general index owner uses it for stepped and arbitrary-column projections,
removing duplicated batch loops without adding a per-row projection callback.

Every append creates a fresh bucket spine. Build reverses only newly constructed
bucket spines into source order; retained buckets and row identities remain
unchanged. Scalar keys remain scalars, composite keys retain their ordered list
representation, and custom POO providers keep their checked callback dispatch
and detached argument headers. No runtime environment option is added.

* Complete paired workflow

Baseline =3b8a2c61c3d45f1b3187c6c5b1bbb812dec720ab=. =reference-funs.ss= is exact;
=reference-access.ss= only redirects its frozen funs and current Provider imports.
Public ASP =make-benchmark-fixture= generated the fixture before measurement.
Each of seven shapes runs 50 alternating pairs with collection before timing.
Input rows, keys and independent expected buckets are prepared outside timing.
The measured interval builds the complete physical index, captures selected
buckets, appends a batch and queries them again. Every pair checks ordered
source/extended buckets, retained old buckets and stored row identity. Keys
include false, dense repeated values, unique vectors, repeated and unordered
columns. Structured scalar values contain 32 fields; source has 4096 rows.

Fixed gates: structured dense/unique require CPU <=90% baseline and >=35 wins.
Primitive, composite, arbitrary, small and empty controls permit <=105% plus
20us. Allocation is <=105% plus 4096 bytes; ASP pair p95 is <=999ms. Allocation
uses a fixed buffer with =##get-bytes-allocated!=, not retained heap. Timed
processes run alone. The interval does not include analysis or whole solving.
