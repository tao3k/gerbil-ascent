#+title: Fresh UF products and monotone replay axes

* Source learning and ownership

Gerbil =1cfb032= =std/struct/dag.ss:31-47= separates visiting state, completed
attributes and callback order inside one walk. =compiler/optimize-base.ss:63-89=
represents class/accessor premises as explicit private structure metadata.
This batch applies those ownership patterns to admission: represent a proved
state premise once, select the appropriate algorithm, and retain the original
callback/commit boundary. It introduces no global cache, environment setting or
second execution scheduler.

For a non-self injection with a fresh endpoint, every pair in Pred(a) x Succ(b)
is missing. A fresh source has no incoming arc; a fresh sink has no outgoing
arc. Native UF count-only admission therefore preflights the exact weighted
product =(sum predecessor sizes) * (sum successor sizes)= plus new diagonals.
It avoids per-pair reachability probes both during count preflight and commit.
Scalar frontiers still collect their descriptors in the original order, using
the same missing-product premise. Ordinary and self injections retain existing
membership tests. All budget decisions precede graph mutation and publication.

Packed replay keeps two private monotone flags on each node. False =inbound?=
certifies a singleton predecessor axis; false =outbound?= certifies a singleton
successor axis. Committing an external root-pair arc sets the flags on source
and target, including when output is declined for an earlier delta prefix.
SCC roots retain conservative true flags after retirement. False cannot survive
on a multi-root SCC winner because closing the SCC admits incoming/outgoing
arcs for every participating root. True merely selects the existing scan.
No counters, edge removals or new retained cut state are needed for these flags.
Fresh replay products use the same weighted count and skip pair membership
probes during writing. Journals, delta boundaries, output order and the
512-vertex capacity limit remain observable through their existing protocols.
