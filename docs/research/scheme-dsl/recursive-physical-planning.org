* Source and selection

Hangdong Zhao et al., [[https://www.vldb.org/pvldb/vol19/p361-zhao.pdf][FlowLog: Efficient and Extensible Datalog via
Incrementality]], PVLDB 19(3), 2025, presented at [[https://vldb.org/2026/program.html][VLDB 2026]];
[[https://arxiv.org/html/2511.00865][author preprint]] and [[https://github.com/flowlog-rs/vldb26-artifact][public artifact]]. The publication year is
2025 even though the conference is in 2026. It belongs in the core
reading because it directly studies the architecture of a Datalog
engine on graph and program-analysis workloads, with executable
artifacts and multiple engine baselines.

* Current code seam

[[file:../../../program/planning.ss][=program/planning.ss=]] prepares a checked plan before reading source rows;
[[file:../../../core/dependency-graph.ss][=core/dependency-graph.ss=]] and
[[file:../../../core/positive-plan.ss][=core/positive-plan.ss=]] retain dependency/delta and positive
join structure. [[file:../../../program/evaluate.ss][=program/evaluate.ss=]] owns evaluation-local buffers and
indexes, while [[file:../../../table/provider.ss][=table/provider.ss=]] lets a declared physical index
serve bound-column lookup. [[file:../../../program/session.ss][=program/session.ss=]] and
[[file:../../../program/reuse.ss][=program/reuse.ss=]] can retain completed state for supported updates;
replacement invalidates affected components or recomputes as the
[[file:../../scheme-closure-contract.org][closure contract]] states. This does not implement Differential
Dataflow, FlowLog's optimizer, or general deletion maintenance.

* Falsifiable next receipt

Freeze the same admitted recursive program and source bytes. Run a
chain, a branch-heavy graph and a real program-analysis or KG extract
through default and one custom index/eligible storage Provider. First
compare every relation against an independent oracle and each
publication after append/withdrawal against fresh recomputation. Then
record per-rule join candidates, materialized intermediate rows,
allocation, peak memory, cold solve and retained-update wall times.
Run paired plan orders only after the output oracle passes; retain
regressions and unsupported cells. This tests whether the IR/physical
boundary is useful *here*, not whether Gerbil matches FlowLog's ranking.
