* Aim and terminology
:PROPERTIES:
:CUSTOM_ID: llm-library-aim
:END:

Build two related capabilities: a Scheme-native Datalog Library for
trusted application code, and an LLM reasoning Library that accepts
bounded candidate programs and returns checkable observations.  An LLM
is a caller, not a rule engine.  Use /Agent/ only for a separately
defined multi-step controller or when discussing a paper's own term.
Serving products such as SGLang/vLLM are later adapters, not the Library
semantics.  See the [[file:scheme-relational-dsl-design.org][language overview]]
and [[file:research/agent-inference/index.org][research ledger]].
The [[file:scheme-relational-language-design.org][first Scheme language
design gate]] precedes this LLM interface work: it must decide the
program IR, higher-order composition and rule-time operator semantics.

The first operational case is finite graph reachability with two named
source snapshots.  It tests recursion, source withdrawal, mistaken rule
proposals, positive support and a complete negative answer.  It does
not stand for all model reasoning.  The implemented boundary is
=candidate/reasoning.ss=; its focused acceptance corpus is
=t/qualification/ascent-reasoning-library-test.ss=.

* Implemented first transcript
:PROPERTIES:
:CUSTOM_ID: llm-library-first-transcript
:END:

The caller creates =reasoning-source-snapshot= from a source identity,
nonnegative generation, and declarations shaped like
=(edge 2 ((1 2) (2 3)))=.  The constructor copies scalar rows and binds
them to a local SHA256 digest.  The identity and generation come from
the caller; this digest is a consistency marker, not authentication.
Each =reasoning-attempt= evaluates one inert candidate against that
snapshot.  Candidate facts are hypothetical overlays and never change
the stored snapshot.

#+begin_src scheme
(def source
  (reasoning-source-snapshot 'graph 1 '((edge 2 ((1 2) (2 3)))))
(reasoning-attempt
 source
 '(candidate
    (relation path 2)
    (rule (path ?x ?y) (edge ?x ?y))
    (rule (path ?x ?z) (path ?x ?y) (edge ?y ?z))
    (query path 1 3)
    (limits 16 32 64)))
;; => complete, ((1 3)), one source-row path witness
#+end_src

The candidate grammar accepts derived =relation= declarations,
hypothetical =fact= rows only for source relations, =rule= heads with
ordered positive atoms, checked negation, fixed =where= and =compute=
operators, and checked count/sum/min/max =reduce= clauses. It accepts
one =query= and explicit input/derived/output =limits=.
Terms are exact integers, booleans, symbols or characters; =?name=
symbols bind variables and =?_= is a wildcard.  It admits no callable
Scheme values; hypothetical facts must be ground. The fixed operator
vocabulary is =even?= and =<= for =where=, =identity= and =+= for
=compute=. Negated atoms read already bound variables; reduction
reads an admitted relation. The planner checks strata and cycles after
inspection. This surface admits no model control loop. The implementation uses the Scheme relational admission and
one-shot solve/query path.  Inspect errors contain clause/body/term
paths, including mapped planner rule locations. Planner rejection is
distinguished from solve/query failure.

The receipt status is =rejected= for structural or planner rejection,
=unknown= for resource exhaustion or an internal failure, and
=complete= only after the fixed point and query finish.  Graph evidence
is emitted only for the exact two-rule =edge/path= closure program with
a ground integer query: one shortest labelled witness for a present
pair or the reachable cut for an absent pair.  Other programs receive
=unsupported= evidence alongside a complete answer.  This is not
general provenance or general Why-Not.  The test corpus checks a wrong
recursive join as a complete but semantically wrong candidate, and
checks all 64 directed three-node graphs against an independent
Floyd-Warshall-style finite reference.

Separately, =reasoning-receipt-proof= can hold a replayable positive
derivation DAG when every rule body uses relation atoms and fixed
=where=/=compute= clauses. The verifier replays scalar operations from
earlier bindings and accepts no input node for them. The receipt keeps
complete native rows when this proof is =bounded= or =unsupported=.
Negation and reduction still have no derivation-proof claim; the
ground nonmembership certificate supports the same fixed clauses when
their finite closure fits its bounds.

A separate [[file:finite-stratified-evidence.org][finite stratified replay]]
now checks exact relation sets for inspected candidates containing checked
negation and count/sum/min/max reduction. It independently recomputes the
finite model and binds a supplied closure to the snapshot, program and
native answer. This is a full bounded replay, not a general derivation DAG
or an explanation of why a real-world fact is absent.

#+NAME: llm-library-evidence-status
| Claim | Executable evidence | Remaining boundary |
|-------+---------------------+--------------------|
| Positive derivation | Replayable proof DAG for the checked positive clauses | No complete provenance for all derivations |
| Ground positive nonmembership | Finite closed-relation certificate and independent rule-closure checker | No open-world absence or general Why-Not cause |
| Negation and reduction | Separate stratum-by-stratum finite replay and independent check against the native answer | No compact general derivation proof or reduction lineage |
| Model usefulness | Two pre-registered five-task paired pilots in POO Flow Python Testing | No general benefit, deployed result or causal explanation |

The finite verifier is independent of the native planner and solver, but its
certificate generator and verifier share the separate replay semantics. An
independently checkable *derivation* for arbitrary negated or reduced tuples
would additionally need explicit lower-stratum completeness, every reduction
input group, and support for each derived tuple. That proof format and its
checker remain unimplemented. The current certificate must keep its
snapshot-relative, inspected-candidate scope.

Candidate and source inputs now pass an iterative scalar/pair-tree
preflight before list traversal or digest. It rejects cycles,
executable leaves, excessive nesting and node-budget exhaustion while
allowing a finite shared row. An inert but structurally rejected
proposal keeps its content digest, so its diagnostic can be tied to
the exact submitted proposal; a cyclic or executable proposal has no
safe candidate digest. =reasoning-receipt-bound?= checks the current
local snapshot identity, generation and digest together with candidate
content. It does not authenticate the source, replay a proof or establish
that the candidate means what the caller intended.

The scripted transcript in
=t/qualification/ascent-reasoning-library-test.ss= exercises this
boundary end to end. A missing predicate is rejected with feedback; a
valid but wrong recursive join completes with an incorrect total; the
corrected join yields the independent finite-model total. A later
source withdrawal changes that total, while a hypothetical candidate
edge changes only its own attempt. An old receipt does not bind to the
new generation, and a mutated proposal does not bind to its receipt.
This is a fixed scripted caller, not evidence that an LLM can discover
or repair a rule. [[file:research/agent-inference/logic-lm-ll23.org][Logic-LM]] uses solver errors for formalization repair;
[[file:research/agent-inference/linc-li23.org][LINC]] distinguishes parse failures and semantic errors. Neither paper
establishes this Library's model usefulness or source authority.

* Code map and intended seam
:PROPERTIES:
:CUSTOM_ID: llm-library-code-map
:END:

#+NAME: llm-library-code-map
| Current module | Existing behavior | Next responsibility |
|----------------+-------------------+---------------------|
| =program/objects.ss=, =program/syntax.ss= | POO declarations and Scheme =ascent= lowering | Preserve the trusted Scheme authoring path; make its admitted program shape inspectable |
| =program/analysis.ss=, =program/summary.ss= | Cached schema/plan metadata and dependency SCCs | Return stable admission diagnostics with relation/rule/clause location |
| =program/evaluate.ss=, =program/session.ss= | Fixed-point results, immutable result snapshots and retained source replacement | The first candidate boundary uses one-shot admission/solve against a copied source snapshot |
| =candidate/closure.ss= | Bounded binary-closure candidates and one shortest source support | The first candidate boundary implements its own row-labelled graph witness/cut; these remain distinct APIs |
| =candidate/types.ss=, =candidate/program.ss=, =candidate/reasoning.ss= | Shared bounded data, inert inspection/lowering, snapshot execution and receipts | Keep source authority and general provenance outside the attempt boundary |
| =candidate/finite-evidence.ss= | Separate exact finite replay and verifier for checked strata | Keep this optional bounded evidence distinct from native completion and general provenance |
| =interface/request.ss= | Inert identity/bound projection for MRR handoff | Keep MRR identity authority separate from the LLM candidate contract |

The public Library boundary should wrap these modules, not replicate
their relation store or evaluator.  Its first candidate format is inert
data: declared relation names and arities, finite source rows, checked
rule bodies, a query, and budget values. It must not deserialize
an arbitrary Scheme closure from LLM output. The trusted Scheme API can
construct richer fragments with explicitly declared operators; the
untrusted LLM surface admits only a fixed, inspectable subset.

* Proposed flow and statuses
:PROPERTIES:
:CUSTOM_ID: llm-library-flow
:END:

#+begin_example
source snapshot + candidate data
    -> parse -> inspect -> admit -> solve -> query -> explain
          rejected       |       complete / partial / unknown
                         +-> detached attempt receipt
#+end_example

#+NAME: llm-library-contract
| Operation | Required input | Required output | Claim boundary |
|-----------+----------------+-----------------+----------------|
| =inspect= | Inert candidate, schema and finite domain declaration | Located syntax/schema/binding/dependency diagnostics | Acceptance is not semantic correctness |
| =solve= | Accepted program, exact source snapshot and budget | Immutable result or explicit partial/failure status | Budget exhaustion cannot be reported as a complete fixed point |
| =query= | Completed result identity and relation/tuple pattern | Rows plus completion and snapshot identity | No hidden rerun or source mutation |
| =explain-present= | Completed result and derived tuple | Bounded source/rule witness where supported | One witness is not exhaustive provenance |
| =explain-absent= | Completed result, finite declared domain and target tuple | Verified absence plus reachable-set/cut evidence for the graph case | General recursive Why-Not remains a separate research problem |

The current code uses =rejected=, =complete= and =unknown= statuses;
=unsupported= is an evidence kind for a completed query.  =partial=
is a future contract question, not an implemented success state.
A result carries source generation, program identity,
query, limits and whether the answer is complete.  An absent pair can
only be called absent after the finite fixed point completes.  A graph
cut can show that no edge crosses the reachable/unreachable partition
in the named snapshot; it does not identify which hypothetical missing
edge a user intended.

* Executed baseline and remaining scientific gate
:PROPERTIES:
:CUSTOM_ID: llm-library-gates
:END:

The following order records the bounded first implementation. Steps 1–5
have executable evidence for their stated subsets, not for the full
language inventory. The current public contract and the shared
native/candidate finite-model gate are in
[[file:native-library-acceptance.org][the native Library admission note]].

1. Settle the first Scheme language design gate and its lowering IR.
   Write the new grammar, binding/mode rules, operator tiers and native
   finite-model corpus before rewriting the current syntax module.
2. Freeze a finite graph corpus and an independent reference closure.
   Include duplicate edges, cycles, a source withdrawal, an undeclared
   relation, an unsafe binding, and a compiling wrong recursive join.
3. Make internal program construction/admission/solve/query return
   complete facts and located failures for that corpus.  Compare fresh
   and retained sessions; preserve older immutable result snapshots.
4. Add the inert candidate adapter and typed attempt receipt.  Feed the
   *same* corpus as data through this boundary.  Reject executable Scheme
   procedures and out-of-domain terms before evaluation.
5. Add bounded positive witness and finite graph absence evidence.  Test
   witness soundness by replaying its source labels, and test absence
   only when closure is complete.  Negative cases must return =unknown=
   on budget exhaustion.
6. The first deterministic transcript covers located rejection, valid
   wrong formalization, corrected finite-model result, generation change
   and hypothetical source overlay. A separate POO Flow Python Testing
   caller then pre-registered five finite tasks, source fixtures, two arms,
   three paired repeats per arm, fixed model settings, a 30-request cap
   per pilot and separate choice/boundary scores before each run. The v1
   model-only/tool choice scores were 12/15 and 15/15, while boundary
   scores were 11/15 and 9/15. The v2 old/typed observation choice scores
   were 15/15 in both arms; boundary scores were 9/15 and 12/15. All six
   v2 closed-cut responses still claimed release authority despite the
   native denial. POO Flow's Testing Runtime guard withholds that claim;
   it does not repair the model. Protocols, individual failures and
   receipts are in =packages/python-testing/docs/model-study-v{1,2}*.org=
   on [[https://github.com/tao3k/poo-flow/pull/34][POO Flow PR #34]]. These pilots did not include a separate search arm,
   repair-turn score or a deployment test. They do not establish a general
   model advantage.

Keep semantic conformance, Library protocol conformance and model
helpfulness as three different claims.  The first gate needs no model;
the final gate cannot be inferred from a green unit test.

* Decisions for discussion
:PROPERTIES:
:CUSTOM_ID: llm-library-open-decisions
:END:

#+NAME: llm-library-decisions
| Decision | Recommended first choice | Evidence that could change it |
|----------+--------------------------+-------------------------------|
| LLM candidate syntax | Inert rule data with a fixed checked operator subset | A task requires another operator that can be safely inspected and bounded |
| Program identity | Content-derived identity plus named source generation in each attempt | Collision/canonicalization or source-revision test fails |
| Explanation | One replayable positive witness; finite graph absence/cut | A use case demands complete provenance or a general Why-Not meaning |
| Feedback size | Typed error code, precise location and bounded supporting rows | Model study shows needed detail without increased unsupported claims |
| Adapter location | Scheme Library first; external serving adapter later | Measured protocol or latency bottleneck at the plain boundary |

The candidate API and bounded pilots are implemented within these bounds.
General derivation proofs for negation and reduction, broader model
usefulness and general reasoning verification remain unproved.
