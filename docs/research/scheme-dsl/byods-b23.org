* Source and question

Arash Sahebolamri, Langston Barrett, Scott Moore, and Kristopher Micinski,
[[https://kmicinski.com/assets/byods.pdf][Bring Your Own Data Structures to Datalog]], OOPSLA2 2023, Article 264.
The question for this repository is precise: when a storage Provider
implicitly adds facts, can every rule consumer observe those facts at
the right semi-naive frontier, with the same result as the provider's
declared concrete relation? This paper is a core semantic reference for
=table/=, not merely a suggestion to use faster containers.

* Paper premises

| Locator | Result | Consequence for a provider |
|---------+--------+----------------------------|
| §3, PDF pp. 5–6, Theorem 3.1 | A monotone concretization makes the immediate-consequence operator monotone; =eqrel= is a positive example, while arbitrary lattice relations do not receive a blanket guarantee. | Specify the exact rows represented by private state; a successful insertion must not retract visible rows under the positive contract. |
| §3.3, PDF pp. 7–9, Theorem 3.5 | Semi-naive and naive DLDS semantics agree under the paper's total/delta concretization conditions. A newly implied =eqrel= pair must pass through delta; reading only the old total and a raw input delta can miss a later join. | Test the *emitted* frontier as well as the final closure, especially when two producer rules meet in one component. |
| §5.1–5.4, PDF pp. 13–15 | Specialized =eqrel=, =trrel= and =trrel_uf= address equivalence and transitive relations in real analyses, including Polonius. | Compare on relation-appropriate graph workloads and record both full outputs and provider cost. Published speedups do not transfer to Scheme. |

The paper's =eqrel= and =trrel= represent distinct relation meanings.
Equivalence closure is reflexive, symmetric and transitive over known
members; transitive reachability is directed. A physical index Provider
that only changes lookup has a different obligation from a storage
Provider that changes the fact set.

The [[file:../../rust-parity.org][Rust parity matrix]] already records finite graph and
insertion-order checks, plus a minimal *pinned Rust 0.8.0 grouped
=eqrel= split-producer discrepancy*: =(alpha,1,2)= and =(alpha,2,3)=
from different producers should permit =(alpha,1,3)=, but the pinned
Rust delta path can omit it. Scheme emits it. That counterexample is a
particularly useful BYODS discriminator; it must remain a reported
upstream divergence, not be copied into the Scheme semantics.

* Next paired experiment

1. Freeze a finite directed graph, one grouped graph, provider version,
   program and source order. Use an independent graph model to compute
   equivalence or transitive closure for the selected provider.
2. Capture each Provider expansion batch and the relation seen by the
   next rule round, then compare the complete result. Include a bridge
   whose new implied pair feeds a second producer's join, not only a
   single-head materialization.
3. Repeat over append, duplicate, failed budget/retry and replacement.
   Compare the last published snapshot with a fresh solve after each
   successful update. Measure wall time, allocation and memory only
   after exact outputs and frontier visibility agree.

This protocol tests the Scheme Provider contract. It does not reproduce
the paper's Rust performance results or prove the contract for every
possible user-supplied Provider.

* Frontier verification and full-paper closure (2026-10-05)

The [[file:../../scheme-paper-closure.org][paper closure matrix]] distinguishes the entire B23 target from bounded
built-in Provider receipts. =ProviderFrontier.lean= proves three local laws;
=ProviderFrontier.tla= explores eqrel injection and delivery, rejecting raw-only
frontiers and dropped consumption. Native tests compare each expansion against
an independent graph model for all 512 three-node inputs, all three built-in
Providers and both insertion orders. These checks do not prove Theorem 3.5,
user-defined Providers, lattice concurrency or index-sharing applications.

A concrete implementation gap is recorded: =trrel_uf= currently calls the same
=trrel-extend= with reflexive mode enabled, using the same membership and
predecessor/successor tables. It is not the paper's SCC/union-find representation.
Output/frontier qualification does not close that storage or memory-cost claim.
