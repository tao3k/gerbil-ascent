* Trace the frozen Actor allocation child

The refreshed matrix failed =actor-admission/wide= with the exact same
=-10254456= byte observation as the first matrix. The native child
binary is byte-identical to the original fenced executable. The benchmark
rejects this observation before applying its allocation threshold.

Disassembly of that arm64 child shows that =___bytes_allocated= obtains
its base from a fixed native address. It does not use a caller-supplied
processor pointer. Its loads separately expose the heap and stack spans,
prior-section charge, processor still and deferred words, the rebased
double counter and VM-wide still words. This bounds the diagnosis to
the state read at one base. It does not attribute the reported loss to
one term.

The isolated LLDB trace is bound to the same executable digest and both
instruction addresses. It reads the terms after the base is established,
then compares the reconstructed value with the actual return register.
Breakpoint locations were verified against the frozen image. The trace
changes no SDK, benchmark fixture, reported byte value or acceptance
decision.

The original native child then reproduced the exact failure under LLDB
at the unchanged 1 GiB cap and exited with its original status 70.
Four complete native function calls were observed. LLDB duplicated the
callback stream. The parser coalesced only adjacent byte-identical
lines and independently matched every reconstructed value to the return
register. The two benchmark endpoints used the same thread and native
base. Their byte terms were:

| Term | After minus before (bytes) |
|------+----------------------------|
| Adjusted base counter | -10513912 |
| Current heap span | 178016 |
| Current stack span | 36864 |
| Prior section charge | -480 |
| Processor still occupancy | 22632 |
| Deferred still occupancy | -208 |
| VM still occupancy | 22632 |

Both bracketing statistics calls add 208 bytes of deferred still charge.
The cold allocation sample is the after-call value excluding its own
statistics charge minus the before-call value including that charge.
=actor_admission_counter_replay= reconstructs the observed signed
result from the frozen endpoints. The adjusted base write is the next
source attribution. No correction or acceptance claim follows from

A hardware write observation tied the drop to
=___garbage_collect_pstate=. The first in-window write changed the
adjusted base from 6,830,696 to -1,755,864. The instruction at offset
144 adds the pre-collection processor occupancy. The second in-window
write, at offset 6664, subtracts post-collection processor occupancy
and changed it to -4,043,664. A second pair of writes belongs to the
child's cleanup collection after its endpoint. The watchpoint arm
reported -10,614,904 rather than -10,254,456 and still failed the
original gate. The exact endpoint trace and the instrumented writer
trace are separate runs. The writer trace establishes the native

A breakpoint before the GC addition reproduced the exact original
=-10254456= delta and matched the computed prelude operand to register
=x0=. The heap and stack spans were +427,648 and +66,336 bytes. The
prior-section field was already -579,581 words, which made the prelude
add -8,226,112 bytes to the adjusted base. Breakpoints at the candidate

It changed 188,411 prior words to -1,110,013. In that separate diagnostic
the original signed gate also failed. The disassembly loads the old

then subtracts the new allocation cursor from the old start before

The new section's own span was 64 bytes. The exact endpoint replay,

* Actor mailbox and continuation lifetime

Gerbil's =spawn/name= initializes an actor thread and starts it with
=thread-main='s abortive handler. Local delivery ultimately uses
=thread-send=. ASCENT's round coordinator owns admission and row
publication. A worker receives an assignment through its existing
mailbox, runs it and returns a completion envelope. A monitor joins
that worker. The worker already persists across assignments, so the
scope of the abort continuation can follow the native mailbox loop.

The isolated candidate captures one landing continuation per worker.
Each task still installs its own exception handler and starts with
an empty batch and checkpoint window. A refused credit jumps out of
that handler and through dynamic cleanup. The landing point publishes
the exact task and outcome in the existing completion envelope. The
coordinator retains ownership of merge, credit, cancellation and join.

=reusable_worker_abort_preserves_envelope= verifies the modeled
assignment-to-message mapping. The capture-count bound compares the
number of used workers with the sum of their assignments. For 1,024
completed assignments on two workers this changes the modeled capture
count from 1,024 to two. The bound counts calls to =call/cc= at this
source boundary. Gambit stack bytes, mailbox latency and the effects of
stack-section accounting still require native measurements.

The candidate passed 33 native Actor, Session and credit Cases. These
include worker reuse, first-failure identity, refusal through dynamic
cleanup, caller mailbox isolation, cancellation drains and the unique
derived-row budget. The initial source Suite invocation timed out before
any Case. The same Suites were then loaded as compiled Gerbil modules
through the native Test entry, with the original 90-second deadline.

The original admission gates for =wide=, =backlog= and =small= passed

* Automatic Actor dispatch and SCC readiness

The number 64 belongs to the =backlog= fixture's explicit worker
capacity. The Actor Session now defaults to =auto=. The round owner
checks cancellation and reads any pending result or credit request
before dispatching. If a task is ready, it reuses an idle worker or
starts a Gerbil Actor, sends the assignment, and yields to the native
scheduler. If all remaining tasks are blocked, the owner waits for
active workers. The automatic path has no configured worker count.
An explicitly supplied capacity still drives the original comparison
and the existing caller option.

In an SCC round with dependency edges, the owner seeds the zero-count
components into =std/struct/pqueue=. Completion follows the final
candidate merge. It decrements only the completed component's direct
successors and queues each newly zero count. The original ordinal is
the priority, including when a newly ready component precedes an
already queued independent component. Source-only predecessors remain
complete at admission. The round's existing credit, cancellation,
monitor join and completed-publication checks also govern this path.

Lean =ScheduledExecution= checks the zero transition, equality of
minimum ready IDs, the dependency-chain probe count, and the automatic
dispatch decision. The last decision admits ready work at any modeled
active count when the mailbox is empty. Actual heap capacity and thread
scheduling time require native measurements.

Four compiled native Test Suites completed all 56 Cases using the same
2 GiB cap and 90-second per-invocation limit. The 128-task rendezvous
required 128 distinct live Actors before any could emit a row. A separate
Case checked release only after all 33 predecessor rows were merged.
The initial combined Suite command reached its deadline before emitting
Case output. The individual Suite runs preserve that failure record.

The isolated source Test resolved the newly compiled scheduler and ran
on one Gambit processor. Each chain comparison used twelve alternating
pairs and checked every published task in order. The chain uses spare
explicit capacity to isolate readiness selection from automatic growth.

|----------------+----------------------------+---------------------------|
|            512 |               131328 / 512 |             12.893 / 1.167 |
|           2048 |             2098176 / 2048 |            240.573 / 4.166 |

Automatic dispatch completed 50,000 ready tasks using two Actor
identities, with 101.866 ms CPU and 321.123 ms elapsed. It completed
1,000,000 ready tasks using three identities, with 1,891.698 ms CPU
and 7,749.315 ms elapsed. Each task emitted a row and the owner checked
each task ID for uniqueness. These measurements cover short-task
dispatch, result checking and drain. All five original component-scope
gates passed with their original 50 pairs. The complete Lean Guard

* Native mailbox comparison and completion ownership

The Gerbil Scheme Rust PR 18 port receipt reports 1,000,000 verified
completions on one VM at 995,241.29 completions/s, with 10.083 ms
planned-to-consumed P99 and 11.019 ms P99.9. That tail starts at the
original scheduled arrival for each request. The observed peak due
and unconsumed was 11,110, exceeding the original limit of 128.
The relevant Scheme implementation transfers a resident frame into
a worker, checks its identity and the immutable request ID on return,
and releases the frame after verified consumption. The local records
are =docs/10-19-design/single-vm-audit/mailbox-pr18-3477-port.json=
and =crates/gerbil-scheme-qualification/scheme/instance-mailbox-backpressure.ss=
in the Gerbil Scheme Rust checkout.

each for uniqueness in one VM. Each arm started after a collection.

The candidate gives each worker one completion vector. The native
mailbox transfers that vector in both directions. The owner writes the
task and the worker writes the result. The owner checks the run, worker
and lease identities, consumes the task and result fields, and merges
the final batch. It can send the lease again only after completion.
The identity table stores one entry per worker and the task slot records
whether that worker has an assignment. The worker accepts the exact
lease or a stop request. Checkpoint and exceptional envelopes still
carry all five fields, and batch credit stays separate.

Lean =ActorEnvelope= checks field order and vector arity, completion
custody, and the constructor-word bound. The old success path used
five pair objects for the completion and two for the assignment.
The candidate uses one vector per worker for both messages. The model
counts these constructor words. Native timing includes the mailbox
cells, task bodies, owner validation, GC and drain.

The first prototype reused the completion vector and sent a separate
assignment pair. Its million-task pairs measured 2203.899/1936.710 ms
and 2311.190/3071.113 ms for list/frame elapsed time. The direction
changed between the two pairs. Both returned the complete set of task
IDs. The raw allocation counter reported negative deltas in both arms,
so those samples cannot qualify the allocation lane. Evidence:
=/private/tmp/ascent-actor-frame.I3kiEk/frame-cost.log=.
