#+title: Complete view publication and ordered export qualification

* Source and ownership

The complete evaluator, view publication/export owner and EqRel replay kernel
freeze =3cfbb1a7e17beb98097510a07cecf2a9b2478284=. References change only import
locations. Both complete engines share current storage dispatch/initialization,
UF kernels and other unmodified execution dependencies. The reference export
owner uses its frozen EqRel replay implementation; canonical live engine
insertion uses the current kernel on both sides. This qualifies the complete
publication/export path with those shared helpers, not a historical binary of
every dependency at the baseline commit.

Installed Gerbil =1cfb032= =std/list/list.ss:365-376= collects private buckets
and applies =reverse!= to their owned headers. =compiler/optimize-top.ss:704-711=
reverses its invocation-owned keyword accumulator. These ownership patterns
support destructive order restoration only on freshly allocated collector
spines; borrowed journal/member/input spines and held frozen cuts remain intact.

EqRel has one admission kernel for both frozen engine frontiers and synchronous
ordered replay. A private continuation selects the publication representation
after full count preflight and component commit. One interleaved writer is
shared by full frontier visitation and synchronous replay. The replay writer
factory receives the entire injection count and can decline an old frontier
while still reconstructing its component state. No per-injection temporary
EqRel view, view-key validation or visitor wrapper is needed for ordered replay.
No tuple cache, cursor, replay state or graph is retained by the published cut.
The admitted width selects a two-column or grouped three-column constructor
once outside the Cartesian writer, replacing per-row generic append. One
event-owned collector is reused across its synchronous injection callbacks.

Fallback export restores derived batch order through =reverse!=/ =append!=
on its fresh collectors and returns =reverse!= of its private output. Source
versus derived order, grouped width, suffix admission and no split-injection
checks are preserved. UF's bounded packed replay and sparse fallback selection
remain unchanged; fallback collector ownership applies to both storage kinds.

* Fixed contract before sampling

ASP's native fixture API generates =benchmark.ss=. One fixed 90-second run
contains eight complete-engine scenarios. Each leg creates a fresh engine,
publishes a complete result and exports all relation rows. Retained work adds
eight source updates, publications and intermediate exports. Targets repeat
complete exports three times, which deliberately measures ordered export cost.
Declaration/analysis is warm except in the cold control. Historical exact row
order is compared with the complete reference, while an independent pair
matrix checks closure and all relation sizes before sampling. Every leg is
compared against that checked result, including completion/path/rule metadata.

| Scenario | Work | Gate |
|----------+------+------|
| eqrel | 128 chain edges, 300 duplicates, three complete exports | target |
| grouped | 32 independent nine-node EqRel groups, three exports | target |
| retained | 64 initial edges, eight source appends/publications and three final exports | target |
| cold | declaration/analysis, one EqRel edge and full export | control |
| small | warm analysis, one EqRel edge and full export | control |
| uf | 64 UF chain edges and 300 duplicates, sparse fallback export | control |
| derived | Set source, 16 rule-derived EqRel edges and three exports | control |
| native | 64 UF chain edges, bounded packed replay and three exports | control |

There are 20 alternating process-CPU pairs with natural GC, 20 separate ASP
admissions and five alternating allocation pairs. Collection precedes only
allocation legs and is outside allocation counters; negative deltas reject.
Targets require <=90% baseline CPU and >=16/20 wins. Controls allow <=110%
plus 20us. Allocation allows <=110% plus 8192 bytes. ASP p95 <=999ms retains
the 500ms target and 499ms budget. Failed controls cannot be dropped or mixed
with another attempt; the whole-run bound never widens.
