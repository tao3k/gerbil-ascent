* Scope and admission boundary

This follows [[file:execution-correspondence-20261017.org][the executable semi-naive correspondence report]].
The production changes replace duplicated term-checking branches with emitted
Scheme and Rust procedures, and emit the actual cache publication, Actor wire
and Tarjan discovery-state macros. These artifacts are imported by production
code. Formal qualification regenerates their complete contents after checking
Lean; it does not accept hashes or previously successful test receipts.

This is not complete source refinement. The attempted full source-parser proofs
were rejected; their failed sources and logs remain under
=.cache/ascent/source-refinement/rejected-parser/=. They are not enrolled in the
proved module inventory. No =sorry=, new axiom, =native_decide=, increased proof
budget or successful test sample substitutes for those missing proofs.

The compiler admission hooks, Actor credits, checkpoints, cancellation decisions,
resource charges and provenance publication rules retain their existing
semantics. The generated macros preserve evaluation order and add no runtime
controller or serialization layer. Rust Ascent remains a development dependency;

restriction are unchanged.

* LeanPoo Guard integration

The declared LeanPoo dependency is fixed to published revision
=6aae50a9867c12191abb2180fdf031b3a8f55060=. The adapter imports its existing
=tools/process_guard.py= directly and compares the installed file with that
committed source before executing it. The upstream Guard source digest is
=8a97a64c9e6f954a37835df58dc2fd63b27ff692e888a71e937cb48c116e6f0a=.
No upstream source, branch or release is modified.

The temporary 8 GiB aggregate ceiling and the duplicated local Lean process
supervisor are removed. =just check-lean-file= and =just check-lean-proofs= use
the same LeanPoo collection/cleanup implementation as formal source rendering.
The adapter keeps compiler stdout separate from diagnostics and receipts.
Each receipt records the exact command, dependency identity, original child
status, CPU/wall time, rusage RSS, direct-child reaping and additional helper
threads. The rusage number is diagnostic information, not a claimed aggregate
process-group allocation measurement.

Focused checks retain a 30-second deadline, =-j2=, =-M1024= and =-T10000000=.
The complete library phase retains a 180-second deadline and uses =-j2=.
Its previous proof budgets are retained; focused diagnostic memory/heartbeat
flags are not imposed as new library-wide limits. Dependency restoration
is a separate bounded metadata operation. An optional caller worker ceiling can
only reduce detected Quint concurrency; it changes no model, exploration bound
or obligation. Local full formal checks use two Quint workers.

The real process controls cover recursion that ignores TERM, an exited leader
whose descendant retains stdout, exact nonzero status/output, output-sink
failure, and nested outer cancellation. Cancellation first lets the adapter
clean its compiler group before ending the adapter. The nested cancellation
fixture waits for actual compiler readiness, so import latency cannot masquerade
as a cleanup failure. No timer/reader helper thread is introduced by collection.
Deliberately detached process sessions remain outside the upstream group
contract and require their own supervisor.

* Acceptance evidence

The isolated source snapshot starts from the existing PR head and overlays only
this task's files. Concurrent trajectory/clue-query changes are excluded.
The existing released SDK is used; no compiler or upstream SDK repair is part
of this change.

| Actual descriptor/cache/wire/SCC controls | 11 Cases in =ascent-compiler-certificate-test.ss=, included in the complete inventory |

| Performance | Original performance gates and thresholds remain unchanged; exact-head CI is required. No speedup is claimed from the source refactoring or local test duration |

An early Rust candidate was rejected by the existing ASP owner-import gate;
the test import was corrected through its crate path. That failure was not
suppressed. Parser memory/recursion failures and the first nested-cancellation
fixture's startup race are retained as failures, not acceptance evidence.

Local protocol exploration uses the driver's default generation bounds. CI
repeats the complete inventory with its declared generation cutoff of four.
Neither the worker ceiling nor the Guard changes those bounds.

The first remote run of =73651fc= failed in Lean: a newly added library-wide
=-M1024= diagnostic limit rejected eight existing modules on Linux. Guard
correctly retained exit 1 and reaped the compiler. Earlier warm local builds
reused Lake traces and did not establish cold acceptance under that new flag.
Narrowing imports was insufficient; those experimental edits were discarded.
The correction removes the newly imposed global diagnostic memory/heartbeat
flags, preserving the existing proof budgets and bounded Guard deadline.
After moving aside the isolated ASCENT Lean build directory, the cold library
build passed all 175 jobs in 55.6 seconds. Guard recorded exit 0, direct-child
reaping and zero additional helper threads. This supersedes the earlier warm
build as local evidence for the corrected library invocation.

Remote acceptance belongs to the current pushed commit's complete CI run in
[[https://github.com/tao3k/gerbil-ascent/pull/1][PR #1]]. Local passes, previous commits' green runs and this report do not
by themselves establish current-head remote acceptance.
