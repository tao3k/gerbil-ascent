* Actual execution changes

** Keep producer ownership in private row views

Source projection and private source-snapshot replacement previously created
ordinary row-only prototype views and lost the factory's controlled shape
marker. Root validation therefore re-entered the expensive generic protocol.
The new relation-with-rows helper retains that field-specification marker only
when the producer is still a current owned relation. It never caches payload
membership. Every ordinary program root still checks the current rows.

POO's existing prototype dependency graph increments child revisions on
supported parent edits. Both ancestor edits and direct view edits revoke the
marker. Arbitrary caller objects and lattice objects keep their original
protocol. Actor's deferred mutable pending-row getter is deliberately unchanged.
The helper does not eagerly evaluate arbitrary caller getters.

A native 32-construction diagnostic measured 691001024 allocated bytes for
unmarked views and 113483000 for marked views, with typed observations equal.
This diagnostic uses Gambit's time counters. It does not establish complete
request allocation, transitive allocator source refinement or an end-to-end
throughput gain.

** Rank once, sort compact rows, then decode

The previous publication path decoded every row and then repeatedly compared
owned Values while sorting the result. Stack evidence shows actual Value
comparison among the remaining large-workload costs. The new private ordering
owner constructs a rank vector from actual Value::cmp, sorts encoded tuples
using those ranks, and decodes once. Its private ordered handoff avoids repeating
the full-value sort at publication.

Interning order is never treated as value order. A rank table is only built
when a derived relation has at least 8192 rows and at least twice as many rows
as distinct interned values. Small outputs retain their previous path. Source
rows retain their original representations, occurrence multiplicities and
ordinary full-value sort. Aggregate evaluation/witness ordering is unchanged.
The caller-owned Rayon pool and advisory fanout policy remain in use; sort and
decode each recheck fanout at their own boundary. All original decoder polls,
final deadline checks, admission counters and transactional rejection remain.

* Remaining boundaries

Neither a source rendering nor a finite model proves the complete Rust sorting
implementation, Vec/HashMap allocator, Scheme compiler, or upstream POO
invalidation implementation. The rank-construction order-embedding premise has
native comparisons; full compiler/container source refinement remains open.
Actual cumulative allocation for an entire request is not closed by the local
construction diagnostic or ranking-table size.

The pure Rust-owned Rayon workload does not call the VM. Bridge revision
alignment does not automatically route the external ProcessPool through the
upstream in-process short-request dispatcher. Scheme checkpoint/IPC cost,
three-CPU oversubscription and the failed one-VM large workload remain separate
performance obligations. Neither full CI nor a local allocation reduction is
accepted as latency closure. Current candidate speed and all-scenario admission
require its own original matrix and matched control artifacts.

* Rejection of the initializer-only candidate

The matched three-CPU ABBA experiment 39879073086 compared 5777852b with
41b8a1db using all eight original arms, five fixed samples and thirty-second
soaks. All answers and executable identities matched. Twelve-thread sustained
throughput improved only 1.67%; candidate maximum latencies were 781.331 and
493.609 ms versus reference 417.119 and 303.737 ms. One-thread fixed-work P95
regressed 21.87%. The initializer-only change is therefore withdrawn; its
historical successful semantic/CI receipts are not performance acceptance.

The 41b8a1db and 5777852b original matrices each attempted all 24 rows with
23 structurally valid rows. Neither complete matrix is admitted. The large
single-VM row failed in both: 41b8a1db returned a request timeout; 5777852b made
progress through three samples before the unchanged 240-second case watchdog.
Each of those samples took about 56--59 seconds. This is not evidence of a
native deadlock. In the first 5777852b sample, 24 requests made 144 native calls,
accumulating 628.961 seconds of queue time and 56.966 seconds of native service
with 2,217,595 checkpoints. Request budgets and publication checks remain intact.

The diagnostic baseline's twelve-thread bindings prerequisite passed all 72
cases in 101.563 seconds. Its empty-input mean proof took 413.030 ms; the final
projection took 356.961 ms, including 285.017 ms of GC wall and 64.597 ms of GC
CPU. These measurements locate a real cost but do not establish the cause of
the earlier 343c8c7c one-second failure. That cause remains open.

The shared diagnostic baseline adds request IDs and rejected queue-admission
observations without changing accepted-call counters or controller decisions.
After all original matrix rows finish, a failed VM case gets at most one
instrumented reproduction using its original work and limits. Such runs are
explicitly inadmissible, saved separately and cannot promote an original
failure. Complete structural evidence with tracing enabled is rejected too.

The mean diagnostic exercises the original aggregate constructor across twelve
resident single-thread VM processes and twelve Rust workers, with sixteen

384 proofs retain their original one-second deadline. Archive publication runs

run completed all 384 checks; this is neither three-CPU reproduction nor a fix.
The diagnostic runs after the original matrix, saves binary hashes and complete
traces, and never admits its timings as performance.

* Borrowed binding traversal candidate

The next candidate retains the original initializer and changes the build-only
Scheme-generated Rust matcher to borrow one owned slot state through each term.
A conflict short-circuits pure matching and drops the private partial slots.
Row work accounting, cancellation polling, source admission and publication are
unchanged. The plain-vector oracle covers 1,440 matching combinations plus empty
inputs, including inline and spilled widths, literals and pre-bound conflicts.

Guarded Lean proves rejection absorption and equivalence of borrowed traversal
to the old absorbing fold. Exact source-region obligations bind both the Rust
host and Scheme IR producer. The additional Quint model checks slot results and
state-move costs with six fault controls. All 63 models, 78 positive and 462
negative obligations passed locally, as did 93 Rayon workspace tests, 72 Scheme
binding tests at twelve test threads and strict Rust/PyO3 Clippy. These proofs do
not close Rust compiler, SmallVec implementation or full mutable-runtime source
refinement. A move-count model is not cumulative allocation measurement.

The matched comparison uses 2bfb6407 as the shared baseline: native bridge,
controller, Scheme runtime, benchmark inputs and diagnostics are identical. The
only Scheme-input exception is the build-only Rust kernel IR producer, which is
not part of the VM frontend library. All other Scheme and bridge inputs remain
strictly equal. Remote performance and exact-head CI are required before this
candidate can claim a latency or throughput improvement.
