* BYODS baseline and replication

The built-in Provider/frontier/shared-index mainline has Scheme implementations,
independent native/Rust controls, Lean laws and Quint protocols. Its current
engineering regression gates passed in revision =92475f6=, including all three
oracle jobs and Scheme performance/source/native checks
([[https://github.com/tao3k/gerbil-ascent/actions/runs/37915327136][completed CI]]). Preserve this accepted baseline rather than repeatedly treating
its mechanisms as absent implementation. Later revisions require their own CI.

Full Steensgaard input/partition correspondence is accepted. Complete upstream
Polonius reference observations and native complete-rule fixtures are accepted;
the full =clap-rs= native Scheme application comparison remains open. PageRank,
LLVM/index-sharing application replication, matched whole-application benefits
and universal native extraction remain distinct research work. The feature
[[file:../features/steensgaard/acceptance.org][Steensgaard]] and [[file:../features/polonius/acceptance.org][Polonius]] pages specify those source-bound limits.

* Connected work and remaining head-paper gates

IRIS supplies finite path specifications; candidate execution feedback supplies frozen-proposal full-row
feedback; BRINK adds whole-batch incomplete-source construction and preserved
original answers. Scheme snapshot/receipt owners connect these transfers. Lean
states semantic laws; Quint states completion, binding and publication premises.
The dedicated feature pages record their executable native controls.

scoped witness execution now has an executable gold/proposal comparison gate in the same feedback
owner: both receipts independently bind and complete against one source, and
full query identity precedes exact set differences. Frozen scope controls,
Lean premises and Quint fault exploration qualify this finite transfer.
One shared corpus now links the current Quint transition evaluator, a
kernel-checked executable Lean grader and production Scheme receipt replay,
with automatic regeneration and comparison in CI.
The scoped-witness Program now addresses witness loss before projection with
a separate 256-input three-language corpus, general Lean scope laws and four
named filtering/evidence faults. Its two-hop scope and independent direct
branch are explicit; arbitrary EEC plans and matrix propagation remain open.

Remaining head-paper experiments include scoped witness execution raw model proposal/specification
comparison and BRINK released mined-rule groundings with versioned real-KG
answers and retrieval metrics. candidate execution feedback model synthesis/Souffle corpus and IRIS Java
extraction/CodeQL/CWE-Bench-Java remain separate. The existing Wikidata scoped exclusion gold executor
is a finite real-KG baseline, not closure of those model experiments.
