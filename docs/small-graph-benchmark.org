* Method

Run =just small-graph-benchmark= after =just build=. The native Gerbil
script [[file:../t/performance/small-graph-benchmark.ss][small-graph-benchmark.ss]]
uses the ASP =testing-benchmark-run/result= API and its
[[file:../t/performance/small-graph/benchmark.ss][scenario fixture]]. Each
phase has 20 samples and records p50, p95, max, and one selected sample's
runtime memory delta. Three directed graphs on vertices 0, 1 and 2 have
0, 3, or 6 edges. An independent Floyd–Warshall closure supplies the exact
expected row set outside timed code. The selected result from every phase is
checked; the replacement phase alternates two distinct input states and
checks every sample inside its timed operation. The duplicate append phase
checks that adding an existing edge leaves the closure unchanged.

=reference= is the operator interpreter. =compile= lowers an operator graph
to a Core program. =admit= prepares the engine from an already compiled
program. =admit-solve= makes a fresh admission and runs inference; a second
solve on the same admission is a cached result. =fragment= composes, admits,
runs, and queries a named fragment. =retained-open= builds and opens a
retained operator session. =retained-replace= updates an existing session.
=retained-duplicate= appends a row already in an existing session. These
phases overlap by design and must not be added together.

The later =native-core= phase reuses immutable schema and rule analysis
from a prebuilt engine, then builds a fresh state and executes the full
semi-naive evaluator. It bypasses the public admission copy and is an
attribution probe, not a replacement public API.

The fixture's 1 ms =target_total= is an aspirational p95 target for each
phase. Its 999 ms =max_total= is a permissive research guard, not a CI
performance promise. =targetMet= in receipts compares each phase's p95
against 1 ms. The =gcDelta= value is the ASP API's memory-counter delta
for its selected sample, not total allocations across all 20 samples.

* Interpretation

The independent closure is microsecond scale on all three graphs. The
program-facing lifecycle is tens to hundreds of milliseconds even at this
size. Graph size therefore does not explain most of the end-to-end cost.
The general semi-naive evaluator and public POO-backed construction,
validation, lowering, and admission all need separate attribution before
changing the algorithm. The run-to-run and p95 spread also forbids claiming
an optimization from one sample.

This benchmark covers one positive transitive-closure program and three
input shapes. It is not evidence about arbitrary recursive Datalog,
stratified negation, reducers, larger graphs, multicore throughput, or
deployed latency. A future change should rerun the same fixture, compare
matched distributions, and retain semantic equality with the independent
closure and the 64-mask qualification corpus.

* Operator lowering experiment

The before code was commit =f587d91= with only the =native-core= phase
added to the benchmark script. The after code fused =project(join(...))=
into one projected rule and directed =fix(union(...))= branches into the
fixed-point relation. The latter transformation removes a materialized
union and its copy rule. For this reachability graph, the Core program
changed from five relations and five rules to three relations and three
rules. The 64 graph shapes in =scheme-operator-test.ss= and its nested,
retained, and budget cases passed after the change.

Two separate runs before and after used the same three masks, 20 samples
per phase, machine, and ASP fixture. The receipts are
[[file:../t/performance/small-graph/receipts/2026-10-01-optimization-before-1.txt][before 1]],
[[file:../t/performance/small-graph/receipts/2026-10-01-optimization-before-2.txt][before 2]],
[[file:../t/performance/small-graph/receipts/2026-10-01-optimization-after-1.txt][after 1]], and
[[file:../t/performance/small-graph/receipts/2026-10-01-optimization-after-2.txt][after 2]].
The table gives the median of the six p50 values (three masks times two
runs), in milliseconds. The last column counts mask/run pairs whose after
p50 was smaller. It is an indicative local comparison, not a CI gate.

The two fusions reduced public-path cost in these matched runs. The
independent reference stayed microsecond scale and native-core did not
show a matched speedup, so the main gain is fewer intermediate POO
declarations and admission work. Public operations still miss the 1 ms
research target by a wide margin. Removing intermediate relations also
reduces consumption of =max-derived-facts=, which is a resource budget:
programs at a very tight budget may complete after this optimization where
the prior lowering was bounded. Exact row-set semantics are unchanged when
both versions complete. Another optimization should target the remaining
snapshot and validation cost directly, with the same qualified boundaries.
