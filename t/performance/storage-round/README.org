#+title: Complete custom storage round and readiness qualification

* Source study and ownership

The complete evaluator and workspace freeze
=252706d119b798072f521a9321e42111804a9f9f=. The reference evaluator changes
only import locations and imports its frozen workspace. Storage dispatch and
source initialization are shared current helpers, preserving canonical provider
identity and private owner types. The reference passes no readiness summary;
it retains individual owner scans and its original workspace eligibility.
This comparison qualifies the complete evaluator/workspace change with shared
helpers, not a historical binary of all dependencies at the baseline commit.

Installed Gerbil =1cfb032= supplies the primary source patterns:
=src/std/struct/lru.ss:19-32,45-67= uses private final records and typed =using=
projections for affected-owner mutation; =src/std/make.ss:296-304,350-363=
reports successful dependency completion after owner work and keeps the
coordinator completion barrier separate. =src/std/list/list-builder.ss:5-24=
provides ordered selection and =src/std/iter/macros.ss:289-297= native folds.

Each stateful storage owner attaches to one engine-local readiness summary.
Its phase transition maintains an unready count and a pending-owner list.
Repeated extensions do not repeatedly register an already pending owner.
Pending-to-failed preserves the replay requirement. Individual source admission
restores its owner after publication; complete round admission restores touched
owners only after every required row/index/view commit succeeds. Zero unready
owners clears the list. Engine preflight is constant-time, including cached
reads and source appends, without a global registry or new environment option.

Custom storage with exact native hash indexes now uses the same retained
frontier and invocation write set as native storage. Ordered commit covers old
deltas plus actual writes; successful custom source publication registers newly
nonempty deltas. Custom callbacks retain copied row spines, all/pending aliasing,
duplicate order, field and budget checks. A derived/custom index retains full
version traversal. Single-relation engines retain direct traversal. Native
build scheduling remains upstream =std/make=; no upstream compiler is rebuilt.

* Fixed admission before measurements

The native ASP fixture API generates =benchmark.ss=. Every scenario compares
complete relation names, sizes, rows, completion, path and rule count against
independent expected truth in every leg. One fixed 90-second invocation runs
all eight scenarios. There are 20 alternating process-CPU pairs with natural
GC, 20 separate ASP consumer admissions and five alternating allocation pairs.
Allocation collection occurs before each allocation leg, outside its counters;
negative allocation deltas reject. Target CPU requires at most 90% of baseline
and at least 16/20 wins. Controls allow 110% plus 20 microseconds. Allocation
allows 110% plus 8192 bytes. ASP p95 must be at most 999ms (500ms target plus
499ms budget). No failed control is dropped or combined with another attempt.

| Scenario | Complete work | Gate |
|----------+---------------+------|
| wide | 128 custom recursion steps, 512 empty custom owners | target |
| retained | 64 custom source appends/runs, 256 cached reads, 512 empty owners | target |
| mixed | 64 custom steps and native UF publication, 384 mixed empty owners | target |
| cold | declaration, analysis, custom one-step execution | control |
| small | warm analysis, custom one-step execution | control |
| dense | 32 input rows, 40 custom multihead destinations | control |
| index | 16 custom steps with a derived custom index | control |
| native | native UF closure with 512 empty view owners | control |

Readiness tests include no-output callbacks, multiple pending/failed owners,
individual admission with stale registration, isolated engine summaries,
timeout cuts, later source frontier membership, immutable old snapshots,
callback row poisoning and complete custom-index callback traces.

build, with stable 57-entry source/SSI/contract fingerprints. CPU figures are
paired process-CPU medians in microseconds; allocation figures are separate

minimum-win gate. Every ASP receipt passes its original 20-sample p95 gate.

its small median difference is not a separate speedup claim. This evidence
does not qualify historical storage helpers, remote CI or multicore scaling.
