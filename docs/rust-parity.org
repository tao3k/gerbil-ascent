* Authority and completion rule

The first target is behavioral parity with the pinned =ascent 0.8.0= oracle,
interpreted through Scheme and Gerbil modules. The [[https://s-arash.github.io/ascent/cc22main-p95-seamless-deductive-inference-via-macros.pdf][CC 2022 paper]],
[[https://kmicinski.com/assets/byods.pdf][BYODS paper]], and [[https://github.com/s-arash/ascent][Rust implementation]] define the baseline.
Where Rust 0.8.0 exposes raw same-key lattice source rows or retained-run
artifacts that disagree with the paper's lattice fixed-point semantics,
the Scheme result follows the fixed point and records the Rust difference
with a pinned probe and an independent semilattice model.
Rust-specific surface syntax and ownership rules need equivalent Scheme APIs
and macro behavior; copying Rust syntax is not a requirement. Each row closes
only with a matching Rust fixture, Scheme result comparison, invalid-program
test where relevant, and a measured performance receipt. Until then, this
repository is a partial implementation, and Agent extensions are research
proposals rather than core parity claims.

* Whole-program closure gates

The rows below are evidence for four joint gates, not independent reasons to
declare the replication complete. A gate stays open while any listed
interaction lacks executable evidence.

* POO Flow programming style in the Scheme implementation

ASCENT declarations are POO values admitted by Core =define-type=
contracts. Clause planning has one independently extensible receiver family,
so its public dispatch is the slot generic =gerbil-ascent-clause-plan=.
Relation indexing is a separate one-receiver Provider family with slot
generics for build and lookup. A downstream index Provider extends
=gerbil-ascent-hash-index-provider= with native =.o= inheritance and overrides
the relevant method slots; the alist qualification fixture exercises this
surface. Public Provider construction does not require a positional pair of
callback functions.

Index construction, equivalence closure and rule evaluation remain named Scheme algorithms. The
tagged vectors inside the evaluator are private lowered plans, not a second
public declaration language. There is currently no independently growing
Provider-by-Profile crossing, so adding CLOS methods here would not satisfy
the POO Flow two-axis rule. The current BYODS storage Provider has a separate
semantic contract and selected Rust parity fixtures; its broader merge and
scale behavior remain open. Pure transitive algorithms live in
=table/funs.ss=; =table/eqrel.ss= owns an evaluation-local component index;
=table/trrel.ss= owns evaluation-local predecessor and successor indexes;
=table/storage.ss= owns the POO storage Provider contract and method selection.
The Provider's =.make-state= slot creates one private state per relation and
evaluation. Its =.extend-rows= slot receives that state, the current rows,
the incoming row and the remaining fact budget. This separation allows Gerbil
and its Standard Library to determine the implementation instead of copying
Rust's data-structure layout.
The evaluator resolves each storage Provider method slot once when it
initializes a relation, then invokes the selected Scheme function in the row
loop. This preserves the public POO extension point without repeated slot
dispatch for every fact.
For a retained session, a rejected update or run rebuilds evaluation-local
Provider state from the last accepted source snapshot. This covers a Provider
that mutates its private state before returning an invalid batch. Providers
that mutate external shared state must manage that state themselves.
Input budgets count declared source rows; total output budgets count
materialized source rows after BYODS expansion plus derived rows. A
qualification case checks that a two-edge =eqrel= source cannot materialize
nine rows and then derive nine more under a twelve-row output limit.
Dependency stratification, delta-position planning, lattice row operations
and rule binding live in =program/funs.ss= as named Scheme functions. The
evaluator retains session-local fact buffers, pending deltas and rule
execution state. Validated relation schema and immutable lowered rules and
strata are cached by the identity of the declared POO program with weak keys;
cache access is serialized, while every evaluation checks its current source
rows and builds separate fact buffers, indexes, BYODS state and budgets.
When the first round of a stratum starts with =delta= equal to =all=, one full rule
evaluation covers every atom position. Later rounds still use each selected
delta position. This removes duplicate first-round joins without changing
the semi-naive fixed point; the full Rust/Scheme corpus exercises this path.
POO refinement creates a new program identity and
therefore receives its own analysis. A retained session's source-only
replacement preserves declarations and rules, so its fresh fixed-point
evaluation reuses the session's immutable rule plan; rows, indexes, Provider
state and budgets are still rebuilt. This is Scheme planning inside the
evaluator, not a separate source or runtime language. Its public
=GerbilAscentSessionContract= exposes
=.append-source!=, =.replace-source!= and =.run= procedures. =gerbil-ascent-open-session= creates
one session; the one-shot API executes that session once. Results contain
stable row snapshots. A second run without new materialized rows reuses its
result, while positive relation-atom rules consume appended source deltas.
The BYODS invariant corpus now checks all 256 subsets of eight directed
edges across four nodes, including loops, a reverse bridge and two paths
between components. Scheme =eqrel=, =trrel= and =trrel_uf= Providers match an
independent graph-closure model in both insertion orders. Pinned Rust
=ascent-byods-rels 0.8.0= matches the same model for the same 256 source
snapshots. Wider producer partitions and larger graphs remain open.
The four-node eight-edge graph is also partitioned exhaustively between two
independent producer rules in all 256 ways. Scheme =eqrel=, =trrel= and
=trrel_uf= downstream joins match the independent graph-closure model for
every partition. The pinned Rust =eqrel= split-producer counterexample remains
documented; this Scheme/model receipt does not assert Rust parity for all
partitions.
An eight-node graph with a directed cycle and four cross links adds 260
selected source subsets and 260 two-producer partitions. Rust and Scheme
=eqrel=, =trrel= and =trrel_uf= each match an independent closure model on
the subsets; Scheme checks both insertion orders and all selected partitions.
Five source snapshots compare complete Rust/Scheme output directly, and four
grouped partitions compare the downstream join with Rust, using the recorded
Rust =eqrel= split-producer difference as the adjudication boundary. The
standard 1000-sample SS transitive-provider scenario now includes the full
eight-node cycle under its unchanged 1 ms hard gate. These receipts do not
cover arbitrary producer graphs or 1,000- to 10,000-node closure scale.

When a rule projects a lattice value into an ordinary relation, Scheme
finishes the lattice stratum before evaluating that projection. A recursive
=8 -> 4 -> 2 -> 1= minimum example therefore publishes only =1=, matching
the pinned Rust fresh program. A retained Rust 0.8.0 run after a later
source refinement keeps the previous ordinary row; the Scheme session
recomputes from its accepted source snapshot and matches the fresh fixed
point. The 50-key indexed session checks this with both hash and alist index
Providers, while the fresh index differential checks 50 and 1,000 keys.
Repeated zero-budget timeout calls across the recursive lattice and ordinary
projection strata publish no obsolete value, then finish with the same
fixed-point rows and preserve the first partial snapshot.

The pinned Rust =#![measure_rule_times]= attribute and Scheme's
=measure-rule-times?: #t= evaluator option produce the same rows for empty,
single and duplicate sources. Scheme returns per-rule nanoseconds in
declaration order; Rust exposes durations by SCC/rule fields. A retained
Scheme Session keeps timing enabled across positive appends and whole-source
replacement. Exact clock values are not compared. Result POO
=relation-sizes= counts the immutable rows of each relation on demand; its
empty, single and duplicate-source counts match Rust's generated
=relation_sizes_summary()=, and earlier Session snapshots retain their own
sizes after updates. Rust's generated SCC iteration and duration fields
remain a separate diagnostics gap. Rust's
=generate_run_timeout= has a selected recursive-chain partial and final
receipt. A second zero-budget call exposes a Rust 0.8.0 restart behavior;
Scheme advances its retained round cursor to preserve fixed-point progress.
=run-timeout= after a nonpositive source update currently starts a fresh
resumable engine after eager update validation. A local 1000-sample probe
that added zero-budget timeout and completion to the existing source-update
SS case measured 8.539 ms p95 against its unchanged 1 ms limit, while the
original source-update case passed at 380 us p95 in a separate local run.
The probe was not admitted as a performance gate; removing the duplicate
evaluation is open work before claiming timeout scale parity.
=inter_rule_parallelism= remains open execution-policy work.

Derived lattice batches now stage the last value per key in a Scheme hash

accepted rows in one pass. Direct lattice sources also join through the hash
table and materialize their rows once after input validation. On one local
1,000-key single-candidate derived input,
three before/after evaluations had median evaluator times of 186,270 us and

row at 1,000 and 10,000 keys. This is a selected scale and local timing

The retained lattice scale case exercises source append and replacement with

It compares complete output rows at each of three phases with an independent

For the same 64-node chain, a local three-run before/after probe evaluated

The syntax differential compares body argument expressions that read an
earlier column in the same atom or a binding from a preceding atom. It also
compares a negated atom whose second argument is an expression over its bound
first argument, across empty, duplicate, branching, anchor-hit and
anchor-miss sources. These bounded cases close the selected body-expression
positions, not arbitrary expression types or diagnostic parity.
The derived-aggregation differential lets =path= reach its recursive fixed
point before =reach-count= counts paths for selected roots in the next stratum.
Empty, chain, cycle and duplicate-edge inputs match Rust, including a zero
count for a root without paths. This is aggregation over a recursive input,
not a recursive aggregate dependency: pinned =ascent_macro 0.8.0=
rejects a cycle through an aggregate with its
="use of aggregated relation ... cannot be stratified"= diagnostic in
=ascent_mir.rs=, and the Scheme qualification rejects the same dependency.
The invalid-program differential uses a positive Rust macro compilation as
the compiler-probe control, then requires the pinned Rust 0.8.0 compiler to
reject seventeen source programs for the expected diagnostic reason. The Scheme
counterparts must reject in the matching dependency, binding, relation, or
arity class. Three negative cycles include a direct self-edge, two
negative edges, and one negative edge with positive feedback. The Scheme
planner locates a strict edge within a dependency cycle only on the error
path, so unrelated aggregate declarations do not relabel a negation cycle.
The added cases cover an unbound head variable, unknown relation, wrong body
and head arity, an unbound guard variable, binding inputs to =let= and =for=,
an unknown aggregate source, negation before its variable is bound, and source
and derived field type failures. Rust diagnoses the latter at compile time;
Scheme predicates reject them before publishing a result.

* Implementation order

1. Freeze a representative Rust 0.8.0 fixture corpus and error corpus for
   each matrix row; keep it under =rust/ascent-oracle/=.
2. Generalize relation columns and rule bindings in =program/=,
   retaining POO Core and standard-library operations as the substrate.
3. Implement and compare stratification, negation, generators, aggregation,
   and generic lattice behavior. Preserve explicit bounds and typed failures.
4. Add the BYODS provider boundary, repeated-run semantics, then serial and
   parallel execution parity.
5. Qualify Gerbil module and macro embedding plus performance against the
   corresponding Rust fixtures. Only then admit Agent-specific extensions as
   a separate research track.
