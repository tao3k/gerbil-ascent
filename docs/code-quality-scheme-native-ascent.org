#+title: Code Quality: Scheme-native Ascent

* Source picture

#+begin_example
syntax                   declaration analysis         execution
program/syntax.ss ------> program/planning.ss -------> program/evaluate.ss
program/scheme-language.ss       |                            |
         |                        v                            v
         +----------------> program/funs.ss              table/funs.ss
                           strata and terms             row indexes
#+end_example

The two syntax surfaces have different contracts. The historical
=ascent= form admits general Scheme expressions and patterns and is
kept for the Rust-oracle qualification path. It is not re-exported by
=program/interface.ss=. The native public =relational-program= form has
a checked scalar grammar and an admission boundary. Shared machinery
must preserve that distinction. =program/analysis.ss= caches immutable
declaration plans, while =program/evaluate.ss= owns mutable relation
state and retained-session behavior.

* Feature: lattice rows and term binding

=program/funs.ss= extracted a lattice key with two reversals and a
lattice value with another reversal. It now uses =butlast= and =last=,
with an explicit nonempty check for the private key helper. The
evaluator also calls key and value separately in some paths, so a
single extraction at the caller is a possible later measurement target
without adding a new public helper.

=gerbil-ascent-bind-row= is a compact state machine. Its invariants are
repeated-variable equality, pattern result arity, and shadowing order
of newly bound variables. A =match= rewrite is desirable only if those
invariants become easier to see and the errors stay stable.

Relevant qualification: repeated-variable, lattice, pattern, rule,
and invalid-program fixtures. Record values, row order, and errors.

* Feature: indexed relations

=table/funs.ss= builds bucket order by reversing the current relation
snapshot once and then prepending each row. This is intentional.
=hash-update!= with an empty-list default passed the index qualification
but was reverted after a broader test hit a time budget. The same
time budget failed after the revert, so that test does not attribute
the anomaly to either hash implementation. The existing standard
=hash-ensure-modify!= remains the clearer bounded choice here.
=gerbil-ascent-index-key= uses =list-ref= for each selected column;
its cost grows with both row width and selected columns. A single
pass over the row could help wide composite keys, but arbitrary
column order must be preserved. Use the existing index-program and
BYODS cases plus a matched wide-row probe before choosing an algorithm.

* Feature: stratification and dependency cycles

=program/funs.ss= performs stratum relaxation and, on an invalid
strict cycle, searches dependency edges repeatedly to classify the
error. This search is mainly a diagnostic path. =program/summary.ss=
already uses =append-map= and =delete-duplicates/hash= for static SCC
metadata and implements Tarjan because =:std/struct/dag= rejects
cyclic input. The two graphs have different output contracts.

A shared adjacency or SCC representation is justified only if it
reduces conceptual state while retaining minimum strata and the
aggregate, negation, and lattice-projection error classification and
current encountered-edge ordering of diagnostics.
Benchmark it on the same rule graphs; do not turn an error-path cost
into an unsupported runtime speedup claim.

* Feature: finite selection and admission

=program/operator.ss= lowers =select-eq= into a singleton source relation
plus an equality join. A direct literal term in the body and head was
tried locally. It removed one relation and allowed a smaller source
budget, and it passed the finite selection and operator qualifications.
A paired native probe then compared the original declaration order and
source handles with the literal version, under equal budgets and with
independent expected-row checks. At 64 and 256 source rows, most
alternating admission-plus-solve samples for the literal version were
much slower, despite noisy host timing. The experiment was reverted;
the singleton join remains the implementation. Do not infer a runtime
gain from the smaller rule shape.

=program/scheme-admission.ss= used to copy Core relation rows before
calling =relational-source=, which checks and copies them again. The
snapshot now delegates that single copy to =relational-source=. A
mutable Core input-row test changes the caller's list after admission
and confirms the admitted result stays unchanged. Retained replacement
and append paths had the same duplicate =relational-source= validation
after =relational-copy-rows= had already checked scalar values, arity,
and copied the row lists. They now send that checked copy directly to
the native session. Append uses the existing single-row validator and
copier directly, without building a temporary one-element list.
Existing replacement rollback and isolation cases,
plus a new append isolation and non-scalar case, protect the contract.
These are fewer copies at the boundaries; their runtime benefit still
needs a matched measurement rather than an inference from shorter
source.

The reproducible boundary probe is =just admission-copy-benchmark=. It
runs the old and new operations in one Gerbil process, checks equal
rows and independent list spines after every sample, warms both paths,
and alternates their order for eight pairs per case. Bulk admission
and replacement use 512 two-column rows, 20 repetitions per timed
sample; single-row append uses 1000 repetitions. Timing starts inside
the loaded process, so Gerbil startup is excluded. This measures row
copy and validation work only; it does not measure a complete retained
solve, rollback, or application latency.

* Feature: syntax boundaries

=program/syntax.ss= and =program/scheme-language.ss= both lower atoms,
negation, and reducers. Their generated objects and error paths must
be compared production by production before sharing code. Keep
lexical fragment handles hygienic, preserve source locations and
diagnostics, and never broaden the public checked scalar grammar
to accept arbitrary callbacks. An extra macro that hides one runtime
call would make the layer harder to read.

The current =relational-atom= and =relational-atom/lexical= expansions
look alike but quote a relation spelling versus evaluate a lexical
handle. That difference is the ownership boundary, so a common
expander would need to keep it visible. =relational-copy-row= and the
operator project constructor use =map identity= to copy list spines
before retention; these are intentional copies, not redundant maps.
The contract in =docs/native-library-acceptance.org= also keeps the
historical =ascent= syntax on the test path, so deleting or folding it
into the native language would be a separate interface change.
The same snapshot-copy pattern appears in =candidate/reasoning.ss= and
=program/scheme-admission.ss=. Its presence across those boundaries
is evidence of an isolation rule, not a reason for a blanket rewrite.

* Feature: execution and evidence

The stateful engine is in =program/evaluate.ss=; =program/analysis.ss=
owns immutable declaration caches. A change that crosses this boundary
needs retained-session source replacement, cache invalidation,
provider dispatch, and stale-receipt tests together.

For each code change, record the old and new invariant, the exact
v0.19 source operation used, a qualifying example including edge
cases, and the smallest relevant =just test-file= result. A complete
slice also needs =just test=, =just check-policy=, and =just build=.
The =justfile= harness requires =MODULE-OK=, =HARNESS-OK=, final =OK=,
and no error or overflow markers. For a performance claim, compare
matched runs from =just small-graph-benchmark= and the existing
scenario recipes, including timing spread and semantic equivalence.

The current code-review reference is PR #1, branch =feature/ascent-scheme-syntax=.
The published
small-graph receipts in =docs/small-graph-benchmark.org= include earlier
source states; rerun the exact head for performance comparisons. They
cover one positive-closure workload and do not establish general
Datalog speed.
