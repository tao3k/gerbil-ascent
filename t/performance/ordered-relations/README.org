#+TITLE: Ordered publication across bounded relation kernels

* Shared representation

Projection, composition and delta composition, bounded/unbounded closure, and
shortest-distance publication now use the same private occupied-word bitmap
when appropriate. Each sixteen-pair word is a u16; its mask and encoded offset
fit fixnums even on 32-bit Gambit. Admission records a word only on its first
transition from zero. Sorting occupied word indices in descending order and
consing set bits in descending order produces the exact ascending pair list.
The result costs O(k + b log b) for k pairs in b occupied words, rather than
comparison-sorting every pair. Empty/unoccupied words are never scanned during
publication. Membership storage shrinks from one byte to one bit per pair.

The public POO projections still expose ordinary sorted lists and read-only
membership/distance closures. Each expression owns its prepared source and
result containers. Sparse radix >512 keeps hash membership and ordinary list
sorting; external neighbor callbacks retain their invocation order. No global
cache or scheduling/profile/budget changes.

Closure uses one admission operation per candidate. Its private bit is admitted
before checking the pair budget; an exceeded budget throws before counting,
frontier insertion or any public result can escape. The externally observed
budget failure and callback trace remain unchanged.

Distance storage already determines membership, so a second bitmap is created
only once discovered cardinality reaches max(16, radix squared /64). Earlier
rows migrate once, and their temporary list is released. Smaller outputs keep
ordinary list publication, avoiding an extra domain-sized allocation for empty
or sparse distance results. Existing frontier propagation and distance joins
are unchanged.

* Exact baseline and complete consumption

baseline.txt pins the preceding commit cb67c4d. reference.ss is its exact
production table/expression.ss with only two exported names alpha renamed.
=t/performance/ordered-relations/qualify.ss= reconstructs and checks it before each qualification. Both modules
compile together into an isolated library. dependency-verification.json also
checks the 299 installed dependency artifact hashes against the preceding and
subsequent full production snapshots. The probe checks actual .ssi import
paths inside the measuring process, and saves source/native artifact hashes.

Each of two runs uses 20 warmups and 1000 alternating old/new pairs. Every timer
includes expression creation and the demanded final rows; complete graph cases
also demand projection, closure, distance rows and every returned distance.
Semantic equality is checked outside each timed attempt. Gambit cumulative
allocation counter slot 7 is used without forced per-sample GC.

The five primary workloads retain the earlier classification and require a
strict median allocation decrease and at least 900 strict paired allocation
wins in both runs. Controls additionally cover sparse radix 513, external-left
composition, index-only access, and empty/sparse distances at radix 512.
Control costs are reported without declaring uniform non-regression. Timing
claims require lower medians and at least 900 strict paired time wins in BOTH
runs; report.py enforces the allocation gate and records timing classifications.

* Collector failure excluded from qualification

The first functional-suite collection started while the long parent exclusive
performance lease was held. Twenty-four workers exceeded their 120s admission
wait before entering Cases. That collection was stopped, and the complete suite
was restarted after all performance gates had finished. failed-concurrent-*.log
retains this orchestration failure; it is not a solver semantic result. Final
suite coverage is extracted only from a complete, zero-failure suite receipt.

A subsequent complete run finished all 48 modules with one failure in the
unchanged observability Case expecting a duration interruption during a 100ms
sleep. Its completed suite receipt and module error remain in
failed-observability-*. An immediate isolated recheck passed both Cases without
source/profile/dependency changes. This establishes intermittent test behavior,
not its cause or an upstream monitor fix. The inspected dependency package source checks elapsed
time in the sampler but has no final elapsed check on normal completion; that
is a possible race path, not a trace of the failing attempt. The final full
suite passed all 48 modules and 373 native Cases after this recheck, with the
earlier failure preserved. collect-suite.py verifies every Case/Module/Harness
and final OK marker and rejects native exit-zero errors. All 41 production
source hashes, paired native artifacts, and the production snapshot still
match after completion.
