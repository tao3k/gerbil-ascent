Gerbil =1cfb032= =compiler/optimize.ss:28-35= owns lookup facts per invocation.

Apply these concrete contracts to one declaration preparation flow:

- Fragment export admission checks associations in original order, retaining
  only immutable label/handle symbols in one private identity table. The table
  stops changing before its resolver is published. Input pair mutation cannot
  rewrite the resolver; lookup and duplicate detection no longer rescan lists.
- Source handle admission owns a seen-symbol table and a lazy declaration-name
  predicate. The cursor advances only as far as each requested handle needs;
  cached slot values retain the original first-force order. It does not eagerly
  force names past a satisfied request or an earlier duplicate/type error.
- The returned source-handle list preserves input order and owns its spine.
  Declaration lookup indexes are local to one construction; later constructions
  observe the current declarations and refined POO objects.

The original public validation/extension axes remain with POO. No validation
cache, private inert shortcut or engine update policy is added here.

* Complete consumers and fixed gates

Relations and export inputs are prepared outside clocks. Every timed call uses
a fresh public Program or Fragment, validates its complete declaration tree and
forces the ordered handles plus every relation name/arity/source-row field.
Fragment calls additionally resolve every export; cold calls create a fresh
public Program, execute native evaluation and force all source results.
Independent input/export/set-truth checks run outside performance clocks.

| Scenario | Relations | Exports | Consumer |
| program | 512 | 512 prepared | Program construction and ordered publication |
| fragment | 64 | 2048 | Fragment construction and all export resolution |
| cold | 64 | 64 prepared | Public Program construction, native cold solve and all rows |
| small | 2 | 2 | Full Fragment consumer |
| empty | 0 | 0 | Full empty Fragment consumer |

Input/derived/output budgets are 4096. Targets require <=90% baseline CPU and
>=16/20 wins; cold/small/empty controls allow <=110% plus 20 microseconds.
All allocation gates allow <=110% plus 4096 bytes. Gates were fixed before
sampling. Twenty alternating CPU pairs retain natural GC; ASP
=benchmark-run/result= separately admits twenty optimized complete consumers.
Five forced-GC allocation pairs use monotone cumulative VM statistic 16. Every
observation matches the frozen complete consumer projection.

* Reproduction and evidence boundaries

Use existing repository Gerbil package/load paths and Darwin OpenSSL library path.
=gxi t/performance/declaration-names/build.ss <absolute .gerbil/lib> <binary>=
builds the runner; append =qualify= to link native Suites. Run the runner
=<scenario> <receipt-path>= sequentially. Qualification uses independent native
processes, capacity =min(cpu-count,suite-count)=, ordered Cases per Suite, and
joins every child before propagating failure. No test behavior enters build.ss.

An initial frozen-reference build rejected its relative types import; the next
whole-workspace artifact guard correctly rejected concurrent application edits.
The accepted build binds the actual program/core/table/candidate source closure,
these native fixtures and their Candidate reference imports. Unrelated concurrent
application/proof/workflow changes stay outside this closure. Canonical production
artifact admission is unchanged. Logs, executables, failures and raw samples stay
under ignored =.cache/ascent/declaration-names/=; these receipts are local native
evidence, not remote CI qualification.

* Allocation counter qualification boundary (2026-10-10)

The historical allocation pairs above sampled process-statistics slot 16 at
forced-GC boundaries. The lattice-frontier study observed negative differences
in a fully static executable, both with that recipe and with Gambit's dedicated
=##get-bytes-allocated!= counter. Historical byte counts and allocation gates
are therefore withdrawn pending a corrected gxi receipt. Historical CPU and
semantic receipts remain separate evidence. The runner now samples the dedicated
cumulative counter directly around the complete consumer and rejects a negative
difference. This change does not inherit the preceding allocation PASS.
