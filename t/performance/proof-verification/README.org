#+title: Complete positive proof verification with local binding plans

* Production ownership

Baseline =7bb4ba0cfe372357d5a30cef644407fb77582a57=. The complete frozen
=candidate/provenance.ss= is copied byte-for-byte into =reference.ss=;
both Git blobs are =5ad5410081f196d67fa96f03d5329674ff5476dd=.
The two sides have independent proof record types and independent producers.
Both use the same snapshot validity, digest, schema and scalar semantics.

=candidate/provenance.ss= owns external DAG admission and ordered predecessor
replay. =candidate/proof-frame.ss= owns invocation-local syntax classification,
variable slots and fixed scalar expressions. A fresh private frame belongs to
one rule node; failed prefixes discard all partial writes. False is a bound
scalar distinct from the private absent marker. First bindings, repeated terms,
computed outputs, wildcard and literal terms retain their distinct operations.
Only fixed pure guards can reuse a successful equal guard in that linear prefix.
No producer indexes, verdicts or values survive between verifications.

Gerbil =1cfb032= =compiler/optimize-call.ss:45-63= chooses a known operation
before execution; =compiler/optimize.ss:28-35= scopes its facts per invocation.
The existing =core/expression-plan.ss= resolves ordered inputs to frame slots.
Apply these patterns to a complete proof-check flow rather than introducing a
general dispatch framework. Public candidate, snapshot and proof formats retain
their owners. Producer probe accounting and verifier node limits do not change.

* Fixed measurement contract

ASP's =make-benchmark-fixture= generates =benchmark.ss= before compilation and
sampling. Each complete consumer invokes the public verifier, including snapshot
shape/content authentication, metadata preparation, all source/candidate/rule
nodes, input references, head rows, query roots and full native answer equality.
Inputs and independent scalar expected answers are prepared outside timing;
cold additionally produces a fresh proof inside every timed call. Forged changes
the last derivation row so the verifier must reject after checking its prefix.

|----------+--------------+-------------+-----------------+----------|
| wide | 32 | 512 | Complete wide-binding verification | <=90% old, >=16/20 wins |
| mixed | 16 | 256 | Two positive atoms and scalar guards/computations | <=90% old, >=16/20 wins |

Twenty alternating CPU pairs include natural GC; twenty separate ASP admissions
time the optimized complete operation. Five alternating allocation pairs use

<=110% old +8192 bytes; ASP p95 cap is 999ms. Heap is 3G and the complete
six-scenario process has a 90-second watchdog. No gates changed after sampling.

* Rejected attempts and reproduction

The syntax-only/alist variant fails the wide CPU gate (5524 ->5300us, 12 wins).
The static frame executable reports a negative allocation delta (-298216 bytes)
and is rejected. The existing lattice-frontier study records the same runtime
qualification boundary; this does not establish an SDK root cause. Direct gxi
loads the same compiled project libraries and qualifies the counter.
The first dense-frame variant fails mixed (3423 ->3258us). Prefix specialization
still fails mixed (1644 ->1510us), despite 20 wins. Direct term continuations and
eliminating duplicate pure-guard actions complete this same production unit.
Those rejected batches are not promoted through their individually passing
wide receipts. A new forged-predecessor test initially expected a complete proof
for an empty answer; the producer correctly returned unsupported. The repaired
test changes a reference to another valid source node and checks exact rejection.
