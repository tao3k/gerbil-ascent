* Architecture implications
:PROPERTIES:
:CUSTOM_ID: flix-l25-architecture
:END:

Flix makes a Datalog program a value that can be built, passed,
returned, and composed.  Its =inject= takes ordinary collections to
facts, while =query= computes a minimal model and extracts a relation.
The proposed Scheme API should likewise keep construction separate
from execution and expose a stable immutable result snapshot.  This
is a lifecycle contract; it does not require identical keywords.

Rho abstraction is particularly relevant for higher-order Scheme
fragment constructors.  If the same function is invoked twice, its
private =path= relation must receive a fresh identity for each result.
Otherwise two fragments can accidentally share a predicate and cause
arity conflicts, type conflicts, or recursive coupling.  Renaming only
once at macro definition is insufficient when the function can produce
fragments with different types on later invocations (§3.7, PDF p. 9).
The public interface should reveal only declared inputs/outputs, while
the planner retains the private dependency graph internally.

The paper also makes an important limit explicit: Flix's effect system
can require pure head and guard expressions, but does not prove that
they terminate (§3.8.3, PDF p. 10).  A Scheme closure accepted merely
as =procedure?= offers still less assurance.  A first implementation
can document a trusted pure/total procedure contract and qualify it
with tests; a stronger language needs a restricted analyzable
expression/operator representation.

Finally, Flix separates =solve= from =query= because solving during
every composition changes meaning when later constraints affect
negation and wastes work across multiple queries (§4.2, PDF p. 17).
In Gerbil, fragment assembly should therefore remain inert; program
admission, evaluation, and reading a snapshot are separate operations.

* Discriminating fixtures

1. Call one fragment constructor twice with different captured types;
   private relation identities must not collide.  Assemble both and
   query their public outputs independently.
2. Assemble two fragments in both orders where one supplies facts read
   by a negated rule.  Do not solve the first fragment early; check the
   complete assembled semantics and negative-cycle admission.
3. Pass a pure terminating function through a functional predicate,
   then test a mutable capture and a diverging function separately.
   Only the first has an evident safe operational story; an effect
   check alone cannot discharge termination.
4. Inject a finite source collection once and query two outputs from
   one solved snapshot.  Verify that neither query restarts evaluation.

* Current implementation reconciliation (2026-10-04)

Fresh private identities and explicit construct/admit/solve/query boundaries are implemented in the checked subset. The earlier statement that name-based includes lack generativity is historical; the general static typing/effect and compiler-refinement obligations remain open.

See the [[file:../../scheme-research-proof-audit.org][research/proof audit]] for the current transfer obligations and ordered exit gates. Earlier experiments retain their original source and cost boundaries.
