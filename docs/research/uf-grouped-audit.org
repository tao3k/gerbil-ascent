#+title: UF complete-key dispatch and independent Scheme CI qualification

* Failure and scope

Linux CI 38945117936 at bdfaa72 rejected the existing compact-query grouped
control: median CPU 1045 -> 1221 microseconds per eight-consumer sample,
with 1148544 bytes in both arms. The unchanged gate is ratio <= 1.10 plus
20 microseconds; its failure is retained. It ran before complete Scheme
qualification, so the later semantic steps were skipped, not passed.

The affected materializer checked canonical complete columns before its
compact-layout admission. Thus an ordered complete key bypassed the compact
publisher already used for repeated and reordered keys. It re-entered general
route selection, bucket costing and validation instead of the captured group's
single-descriptor publisher. This control had no structural improvement over
its reference on that route. A timing sample alone cannot attribute the entire
Linux regression to a particular compiler layout or GC event.

* Implementation and work accounting

Select compact layouts first. Their existing checked admission validates the
complete key before publication, preserves first bound key tails, and checks
invalid later coordinates even after conflicts or absent groups. The existing
owner publisher retains stored representatives, captured descriptor ordering,
empty axes and duplicate owner occurrences. Tiny, mixed and wider layouts keep
their established fallback. No new query cache, evaluator, namespace or builder
is added.

On an instrumented fixed source, the unchanged grouped input returned 2048 rows
in both arms. Actual routed-rectangles calls fell from 2048 to zero. Temporary
counters were excluded from production source and the native timing binaries.
On uninstrumented native binaries, allocation fell by 98304 bytes per sample,
exactly 48 bytes for each of 2048 queries.

* Independent CI lanes

Scheme is a two-entry matrix: semantics and performance. Both depend only on
repository hygiene; fail-fast is false. The semantic lane includes complete
standard Scheme tests, independent source consumers and the original native
source/DSL/closure qualifications. The performance lane retains every original
performance command and production-rebuild rejection. Each lane uses a distinct
content-bound native artifact cache key.

A performance failure cannot cancel or skip the semantic lane. The existing
always-run native-and-oracle job still requires the combined Scheme matrix,
Rust/PyO3, all oracle shards and formal qualification to succeed. This preserves
failure admission rather than masking a failed benchmark with successful tests.

The authorized integration includes the existing owner-plan constructor repair:
for k selected descriptors among n captured descriptors, dense selections
(k * integer-length(k) >= n) publish through an n-slot ordinal workspace;
sparse selections retain gather/sort. Every occupied slot is cleared before
reuse for another key. Only immutable descriptor selections enter the frozen
plan; the workspace never becomes query state. This removes dense repeated
sorting while preserving owner occurrences, stored representatives and order.

The 11 original owner-plan scenarios retain their exact fixture behavior and
contract bytes. One sparse-routing control is added. Local runs pass all 12
original-policy scenarios; their process inventories include unrelated work, so
these timings are exploratory and excluded from isolated performance claims.
Exact-head CI on its dedicated performance runner is the final measurement gate.

The integration adds a stale-workspace native regression and expands the Python
independent ordered-product oracle to 742 inputs across three Scheme consumers.
Lean proves bounded slot clearing and ordered publication independence. Quint
checks workspace reuse and requires owner-buffer-stale to violate exactly
OwnerWorkspaceReuseExact with exit 12. These local checks and all five formal
registry tests pass. The complete current-head Lean/Quint corpus remains required
in CI; a focused model pass is not a full-system or native extraction proof.

* Cargo cache and wheel source identity

The intervening aa12353 CI failed before its Python interface corpus:
runtime_identity rejected _sources/rust/ascent/src/data.rs/source.bin. The wheel
step reused a release product in 0.08 seconds while the shared staged source
inventory had been refreshed by other Cargo feature/profile invocations. Its
cache allowed a source-key miss to restore a different commit's rust/target.
Overlapping jobs can save artifacts newer than the next checkout's source mtimes;
Cargo's timestamp freshness therefore cannot establish this cache's source identity.

Rust dependency downloads now have a separate reusable cache. Project products
have no prefix restore key and bind the exact immutable checkout revision plus
recorded Rust/Python compiler and SDK identities. This covers all tracked inputs
without duplicating the library-owned source inventory in workflow globs.
The target tree, frozen Python _sources data and .gerbil-resources.json ownership
marker are cached together: a skipped Cargo publisher must not leave the matching
wheel data missing, and a later publication must retain its ownership proof.
Runtime identity verification and every original interface test remain mandatory.
No application source or verifier is weakened, no Cargo clean/retry is used, and
the earlier mismatched wheel failure remains part of the audit record.
