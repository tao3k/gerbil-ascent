* Acceptance rule

Advance one usable native lifecycle across admission, solve, source updates,
publication and evidence, then qualify its application costs. Current ASCENT
library closure covers R1--R5. R6 remains a separate model-comprehension study;
R7 consumer integration is deferred outside this library acceptance scope.

This matrix defines the scope of design closure. An implemented interface,
a semantic argument, a passing discriminator and measured application benefit
are separate obligations. A row closes only the claim stated in that row.
The [[file:scheme-closure-contract.org][closure contract]] supplies the semantic limits; the
[[file:native-library-acceptance.org][Library acceptance contract]] supplies the general execution gates.
Historical receipts bind their own sources and do not certify later commits.

* Model interface policy

Why might an invocation contain text? Actual source, the user's task and a
transport request identify the computation being evaluated. They are not
permission to provide prewritten semantic explanations, expected answers,
few-shot examples or hidden correction rules. This work adds no such prompts.
A guard must expose the actual computation/status at response time rather
than teach a predetermined solution. The evaluation target is the model's
understanding of Scheme logic and its own reasoning ability. Any transport
format acceptance failure must remain visible separately from semantic accuracy.
A post hoc extraction result cannot replace the raw-interface acceptance rate.
Native correctness cannot establish R6 model comprehension. R6 and future
MR/MRR integration do not replace the library semantic and release gates.
