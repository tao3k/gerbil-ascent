#+title: SDK compiler output reuse across executable build phases

* Scope

Reuse the existing released SDK, compiler executor and compiled Reader SHA-256
implementation. No SDK, upstream source, runtime, resource limit, cancellation,
provenance rule, semantic deadline or existing performance threshold changes.
Build-only helpers stay in bindings/build-entry.ss; the C ABI runtime does not
import this module. Unrelated feature edits are outside the commit.

* Actual duplicate work

The preceding build's 96 repeated static object compilations comprise 89
ASCENT objects and seven dependency objects. The SDK registers the ASCENT
runtime C producers, but closes their executor at each make boundary. The next
make therefore lacks those producer records and translates Scheme again.

Capture the SDK's actual producer predicate before the first make. After its
successful drain, observe only those registered outputs and their SHA-256
values. Register digest-validation jobs with the SDK in the next executor.
Its existing dependency barrier prevents link preparation until validation
succeeds, and propagates a changed or missing output as a build error. This is
scoped to one single-writer build invocation; it is not a persistent cache,
filesystem-existence shortcut, GSC wrapper or replacement scheduler.

The first executor is explicitly drained even when synchronous make or a warm
build submitted no jobs. Each executable still has a separate completed make
call, retaining isolation of shared C writers. Dependency files not registered
by the SDK remain on the original path; no producer evidence is invented.

* Validation and remaining scope

A cold diagnostic using the released SDK observes 126 admitted output paths.
Actual GSC invocations fall from 573 to 484, and invocations triggering C
compilation from 445 to 356. Repeated object paths fall from 96 to seven, all
in dependencies. The shared-host diagnostic wall time is not speedup evidence.

Two added artifact Cases use the real SDK executor: only registered outputs
cross a completed executor boundary; changed or missing bytes prevent the
dependent consumer from running. Every pre-existing semantic Case is retained.
The compiled artifact-test closure declares its build-only helper explicitly.

A separate hosted macOS 26 runner supplies uncontaminated timing controls.
The released binary requires macOS 26 or later; its SDK and declared dependency
seed are fixed for all controls. The predeclared order is baseline, candidate,
candidate, baseline. Each control starts with zero ASCENT artifacts, executes
the same policy-enabled build and test preparation, and rejects unrelated
compiler activity or production recompilation during preparation. Binary
receipts and common program source hashes are checked before retaining each
result. All controls are preserved; there is no fastest-run selection.

The complete macOS semantic and exact pushed-commit CI results, together with
the hosted control receipts, are recorded in PR #1 after execution. Compiler
output re-admission is not a new production source-refinement proof.

The Linux Release lacks the producer registry API; it admits no outputs and
retains its original build path. The same Cases check this fail-closed fallback.
The remaining seven dependency recompilations need a separate SDK producer
contract before they can be reused safely through this interface.

* Darwin CPU-counter units

A native calibration found an independent measurement defect in build
supervision: proc_pid_rusage CPU fields are Mach absolute ticks. Treating
them as nanoseconds underreports CPU time by 125/3 on this ARM host. A
one-second process-CPU workload produced approximately 24 million ticks;
mach_timebase_info converted that to 1.00005 seconds. The supervisor now
uses the host timebase for both self and reaped-child CPU. Positive advance
remains the activity criterion; no startup, idle, heap or acceptance deadline
changes. Linux accounting is unchanged. Raw ticks, rather than previously
mislabelled supervisor seconds, must be used for historical Darwin logs.
RUSAGE_CHILDREN CPU measurements and monotonic wall measurements in the
hosted controls already use seconds and are unaffected by this correction.
This unit error does not explain the historical 40.3% wall regression.

and zero GSC jobs on an unchanged warm preparation. This identifies source

thresholds, semantic deadlines and heap limits remain unchanged. Cost coverage

allocator source-work refinement has been proved.

** Native source correspondence and its boundary

The pinned Gerbil expander/module.ss core-import-module import-source path
reads the module, acquires its prelude, creates a module context, completes
core-expand-module-begin, quotes and assigns code, then registers the context
under its normalized path and module id. Library lookup can add another alias.
The observer snapshots distinct module-context identities after successful
outermost imports and primes its identity index before installation. Thus path,
id and library aliases do not inflate completion counts. A newly registered
string-path context records a completed module expansion at this boundary;
it does not count individual macro invocations, failed expansions, or work
before observer installation. Nested and prelude contexts discovered through
native recursion are included when they reach this registry boundary.

The returned-context identity is checked before the snapshot update. This
records native normalized-path reuse even if the raw request key missed.
A real SDK probe imports a temporary source, imports its /./ path alias, then
explicitly reloads it. The alias reuses its identity; reloading records another
identity with the same path. The source probe is now an executable test when
the released SDK is available. The decoder rejects incomplete outermost
observations and truncated context records. Old traces retain their explicit
absence of context observations rather than inventing expansion counts.

The SDK occupancy-based allocation counter remains unsuitable as a cumulative
allocation stream even when every interval is nonnegative. Summaries now expose
cumulative_allocation_observed=false and cumulative_allocation_bytes=null.
No positive interval, cache hit or reduced RSS fills that gap. Lean checks
identity filtering and empty resident scans, and distinguishes occupancy from
cumulative event metrics. Quint retains all previous controls and adds an
occupancy-as-cumulative counterexample. These statements do not prove the
native hash implementation or the full observer decoder equivalent to Lean.
