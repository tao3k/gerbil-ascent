* Stateful numeric writer qualification

The numeric product writer now uses standard Scheme =do= loops, with an
outer stride equal to twice the right-axis length. Both axes are validated
before the buffer is allocated. The private span reverser likewise uses =do=
and swaps whole binary rows without reversing columns. These are stateful
buffer writes, not allocating list transformations.

The generic row packer's next-cell increment uses =fx+= only after its full
positive rectangular allocation size has passed =fixnum?=. The new Lean
=cell_increment_within_capacity= lemma proves that a position strictly inside
the admitted size has its next position at most that size and the native
limit. This is an arithmetic precondition proof; native fixnum and buffer
implementation correctness are still premises, not discharged compiler
refinement obligations.

* Separate spine and tuple allocation

The forward builder interleaves fresh tuples with their outer cells. Two
isolated source controls change the placement while keeping the same ordered
mutable result. The first uses standard =make-list= to allocate the full
private outer spine, then fills it in left-major order. The second places
fresh tuples in a flat vector, builds the spine right to left, and clears
each vector slot as ownership passes to the result. Both use the ordinary
forward builder for unsupported shapes. The vector control limits its
experiment to at most 262,144 rows.

Lean =PrivateSpine= proves the ordered fill and drain, the common three-cell
count, and the live-pair comparison during construction. After =k= tuples,
the skeleton holds =n + 2k= pairs and the interleaved builder holds =3k=.
Any skeleton win must therefore come from placement or less bookkeeping.
The vector control holds =2k= pairs during tuple construction and adds a
vector of =n= pointer slots. During drain, the result owns the acquired
rows and all other rows remain rooted in the vector. The model does not
establish GC cost from these counts. The staged native Suite checks result
order and post-GC mutation, including adjacent rows and independent exports.
The LeanPoo Guard passed. Native =gerbil build= compiled all three controls
against the same frozen SDK and package prefix. Each native =gerbil test=
semantic run confirmed the resolved module and passed both Cases, including
unequal axes, grouped and multi-block fallback, malformed axes, and mutation
after collection. Source and object hashes were rechecked after measurement.

Each timed process validated every row at both widths before taking twelve
collected-start samples per width. Each sample consumed 32 complete exports.
