#+title: Semi-naive execution: frontier partition, scheduling and completion

* Contract and audit boundary

This audit separates least-fixed-point completeness from avoided join work.
The production implementation already uses frozen rounds and deltas; an earlier
informal description of first-call expansion did not establish either property.

The audited paths are program/evaluate.ss (serial and Actor round execution),
program/component-worker.ss (Actor SCC workspace), and
rust/ascent/src/execution/kernels.rs (Rust-owned serial/Rayon execution).
They drain rule work before committing a new frontier. Newly admitted facts feed
another round; SCC successors are admitted after predecessor completion. No new
mailbox-based scheduler or Scheme evaluator is introduced.

* Exact delta partition

For a positive Set rule, pivot i reads Old at earlier body occurrences, Delta at
i, and All at later occurrences. All = Old union Delta. Initial execution is a
single full traversal. The first fresh occurrence owns each concrete body witness;
different witnesses may still project to the same fact and require head dedup.

Scheme supplies an optional old-row lane only to already admitted pure,
canonical Set plans. Exact delta membership is cached by relation/delta version,
not by count. Actor SCC workers own their own index/cache state. Lazy membership
allocation leaves linear rules without an extra membership vector. Building
membership and traversing the old lane checkpoint real work, including excluded
rows. Failure never publishes a partially built membership cache.

Rust prefix reads exclude exact Delta membership before binding. Delta publication
now populates that membership using existing query-owned Fact digests and complete
typed-row equality. Candidate work/cancellation is still charged before filtering.
Counters used for qualification compile only under cfg(test), including Rayon.

Compact UF views keep their existing parts visitors and overlapping delta
pivots: they already exclude all-old rule joins, while expanding an old prefix
would destroy compactness. Disjoint witness ownership is applied to canonical
Set storage, not claimed for these virtual views. Lattice and observable-callback
execution retain their existing admission and traversal contracts. A lattice refinement is not ordinary set insertion. These
paths are regression-tested, not justified by a positive Set theorem. Provenance
construction and source/replacement ownership are unchanged.

* Completeness and completion

The independent Scheme and Rust oracles implement naive synchronous immediate
consequences over alists/maps. They import no production matcher, indexes, SCC
analysis, delta machinery or old evaluator. The fixture contains nonlinear and
mutual recursion, with the source producer ordered after initially empty consumers.
It includes every directed three-node graph, including cycles and self-loops,
with both rule orders on every graph: Scheme workers 1/2/4 and Rust serial plus
Rayon pools 1/2/4. This is 3072 Scheme and 4096 Rust solve/oracle comparisons.

The runtime completion audit retains the existing full-round/worker-drain barrier.
Rust rechecks Budget.result before progressing/returning; failed publication is an
error, not a successful empty round. Scheme marks an invocation finished only
after its admitted rounds close; cancellation/refusal unwinds the assigned work.
No timeout, heap bound, source/derived/output limit or provenance limit is widened.

* Formal evidence

SemiNaive.lean adds arbitrary positive-body disjoint partition, first-fresh
uniqueness and exclusion of all-old witnesses. Disjoint iteration equals naive
iteration at every natural-number round. Equality of consecutive admitted rounds
implies closure, and every round is below every seed-containing closed database:
a settled execution therefore yields the least fixed point. Monotone views and
Set semantics are explicit premises, not claims about arbitrary host effects.

DeltaClosure.qnt explores out-of-order task dispatch/completion and frozen-round
commit, frontier exactness, fail-closed resource/cancellation refusal, and complete
publication. Independent finite transitive closure is the result oracle. Faults
for omitted rescheduling, premature completion, all-old work and overlapping delta
ownership must produce counterexamples. The model is finite safety evidence; it
does not establish native extraction, general liveness or arbitrary lattices.

The formal registry retains all previous 339 obligations and adds five (one
positive exploration and four required faults), for 53 models / 344 obligations.

* Measurements and receipts

The actual two-occurrence Scheme kernel produces 3 complete body witnesses where
overlapping delta pivots produce 4. The same two pivots are independently dispatched
through Actor workers and must also produce 3. A same-size delta replacement checks
version invalidation, and interruption during old-lane construction must raise.

The Rust complete solve produces 30 successful partial/body matches versus 63,
and 21 complete body witnesses versus 51 from the independent naive oracle,
with identical facts; serial and Rayon agree. The late-support regression checks
all nonlinear provenance alternatives even when the head fact already exists;
removing one alternative must fail independent provenance verification. These are
connection/work counts, not an end-to-end wall-clock speedup claim. No isolated
runtime benchmark was performed while compiler/formal processes were active.

Raw local build/test logs and preserved failed attempts are under
.cache/ascent/delta-audit/. Final receipt binds source bytes and actual exit codes;
a partial run, compiler failure or counterexample with the wrong property is not
accepted. Other tasks' pre-existing changes and concurrent commits are excluded
from the owned implementation diff.
