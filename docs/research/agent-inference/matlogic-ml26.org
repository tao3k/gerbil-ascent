* Source and why it is core

Dezhuang Miao et al., [[https://proceedings.mlr.press/v306/miao26e.html][LLM-MatLogic: Executable Exchange Contracts for
Knowledge-Graph Query Answering with Scoped Negation]], ICML 2026;
[[https://raw.githubusercontent.com/mlresearch/v306/main/assets/miao26e/miao26e.pdf][paper PDF]]. It studies an AI specifier paired with a deterministic
graph executor on knowledge-graph tasks. The problem is central to
ASCENT: a model can specify the wrong graph logic even when the engine
executes that logic correctly, and a returned entity may need a
checkable witness with exclusion scope intact.

The paper's matrix executor and exchange contract are *not* Datalog
semantics. Its result still directly informs the candidate-program,
snapshot, query and evidence boundary in this repository.

* Executable transfer

The [[file:wikidata-scope-wd26.org][WD26 fixture]] already checks branch-scoped exclusion on pinned finite
Wikidata claims. The [[file:../../features/candidate-feedback/acceptance.org][candidate feedback contract]] now adds
=reasoning-compare-attempts=: compare submitted and gold program receipts only
after independent same-source/content binding, completion and exact full query
agreement. Frozen scope controls produce exact missing/extra rows under the
same native executor, with Lean qualification premises and Quint fault controls.
This makes gold-versus-proposal grading available without rerunning execution.
The feedback transfer now has a shared 1,024-state finite corpus: Quint's actual
transition evaluator exports it, Lean checks current/frozen results against a
kernel-checked executable grader, and Scheme replays public APIs with real
native receipts while checking the input abstraction premises. CI rejects
regeneration or native result drift. This strengthens result correspondence;
it does not change the model-experiment or arbitrary-source proof boundary.
It does not supply a model proposal, certify gold intent, implement MatLogic's
matrix schedule or reproduce its benchmark. Raw response capture, model/request
identity, retrieval provenance and the actual model study remain open.

* Concrete discriminator

Choose one frozen Freebase-derived or similarly licensed real KG
snapshot with known entity/relation mappings and independently
constructed structured queries. Include (a) a positive multi-hop
query, (b) two branches where an exclusion applies to only one branch,
(c) a witness that disappears if negation is delayed until after
projection, and (d) a source triple withdrawal. Keep retrieved-subgraph
membership separate from the complete source snapshot.

For each query, record the raw model proposal before feedback, the
admitted Scheme program, full answer relation, per-answer witness,
typed rejection/unsupported/budget status, source generation and the
gold query's result under the same finite snapshot. Score proposal
validity, exact answer sets, exclusion-scope fidelity, witness replay,
and natural-language answer separately. Compare a gold structured
request with the model-generated request under the same executor to
measure specification loss. Repeat eligible positive paths through
Set and =trrel= storage only after both are independently proved to
denote the same relation on that fixture.

This is a proposed test, not a claim that ASCENT already runs the
paper's benchmark. Full KG truth, NL intent, and incomplete-subgraph
answers remain distinct from finite Datalog closure.
