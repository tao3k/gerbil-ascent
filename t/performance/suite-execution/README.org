* Scope

Baseline: 2b3d172, clean feature/ascent-scheme-syntax checkout. This slice
optimizes the whole qualification execution pipeline: admission, scheduling,
worker lifecycle, isolation, native failure validation, and complete receipts.
Production evaluator code and dependency pins are unchanged in this slice.

* Admission and isolation

The previous suite admitted 7 semantic modules and ran 36 modules sequentially.
The new inventory admits 33 modules in separate processes and runs 10 exclusive
modules after that phase finishes. admission.json records the full inventory
and individual exclusion reasons. Unknown modules remain exclusive by default.

Admitted modules assert values, identities, callback traces, or bounded semantic
outcomes under unchanged Core default Case policies. Mutation stays inside each
module's process. Zero-timeout differential controls compare their final fixed
points, without requiring equal partial prefixes. Explicit timeout behavior,
per-rule timing, custom duration/GC profiles, internally threaded cases, and the
large exhaustive reasoning/operator/library corpora remain exclusive.

Native std/test owns suite and Case execution inside each worker; this change
does not introduce concurrent Cases or shared native interpreter state.
GERBIL_BUILD_CORES continues to select capacity through ASP's native builder
API, with its host fallback. Explicit test jobs override only this capacity.
There is no fixed four-process cap. With capacity 12 and 33 admitted modules,
the measured parallel phase uses 12 workers. Each process retains its 1 GiB
heap fence, native Case profiles and test timeout.

Both phases now use the same worker lifecycle and receipt code. Worker failures
are retained while remaining discovered modules execute. Completion is checked
against the exact discovered inventory. Cancellation stops queued work, sends
TERM to all tracked active workers, then reaps or kills them under a shared
five-second grace deadline. The inherited exclusive command path also uses
managed child cleanup. Native receipts reject MODULE errors and require an
exact MODULE-OK line, even if the native process exits zero.
