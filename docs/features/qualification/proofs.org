* Formal execution cost and parallel scheduling (2026-10-07)

The previous GitHub formal job took 170 seconds: environment installation
used 22 seconds and the combined Lean/TLA step 135 seconds. The CI command
serialized nine independent recipe groups. Lake already tracks proof inputs
and builds incrementally; the optimization does not skip kernel compilation
for changed dependencies or cache admission decisions.

At this historical snapshot, =just check-formal= verified the pinned TLC artifact\nbefore launching two
independent lanes. The contracts lane builds Lean once, then checks actor,
Session and SCC gates. The other checks ready components, indices, concrete
frontiers and frozen views. Each leaf recipe retains its configurations,
properties, mutations, worker count, heap policy and exploration bounds.
The aggregate waits for both lanes and fails if either fails; synthetic exit
41 and 42 controls check the join behavior without representing model receipts.
TLC transcripts and counterexamples are recomputed on every invocation.

A same-environment incremental-build probe measured 94 seconds serial,
68 seconds with the initial split and 67 seconds with the balanced split.
The last reduction is 28.72 percent. All 23 positive distinct-state counts
and 45 negative-control markers match the serial baseline; the complete
90-job Lean build passes. These sequential single-run observations qualify
execution scheduling in this environment, not an intrinsic Lean theorem or
TLC search speedup, statistical result, or a cold GitHub benchmark. Concurrent
processes use additional resources. The separate native Scheme CI lane remains
the complete workflow's dominant cost. See [[file:../../evidence/scheme-provider-views-20261007/formal-execution-cost.json][the cost and equivalence receipt]].


* Isolated TLC standard module extraction (2026-10-07)

The exact =bef6caf= GitHub formal job failed with exit 150 after the complete
90-job Lean build passed. =PositiveNonmembershipSession= reported an unexpected
EOF while parsing =/tmp/TLC.tla=. The concurrent lanes were sharing the JVM's
default temporary directory. The pinned checker's =SimpleFilenameToStream.read=
extracts standard modules to =TMPDIR/module-name= with =FileOutputStream= and
=deleteOnExit=; =FilenameToStream.TMPDIR= reads =java.io.tmpdir=. Concurrent JVMs
can therefore truncate or delete each other's extracted modules. Source:
[[https://raw.githubusercontent.com/tlaplus/tlaplus/v1.7.4/tlatools/org.lamport.tlatools/src/util/SimpleFilenameToStream.java][pinned upstream resolver]], verified against the exact pinned jar bytecode.

The repaired historical JVM-backed TLA leaf gates set =java.io.tmpdir= to its existing
private temporary directory. Its configurations, state directories and standard
module extraction consequently belong to the same invocation. Sequential JVMs
inside a leaf share that directory only after the preceding JVM has exited.
The two verification lanes remain concurrent and their failure join remains
strict. Historical external =TLC_BIN= implementations retained their own temporary-directory
responsibility; the standard launcher uses the pinned jar. This changes no
model, bound, property, worker count, timeout or heap setting.

The [[file:../../evidence/scheme-provider-views-20261007/tlc-extraction-isolation.json][isolation receipt]] binds the observed remote failure, resolver mechanism,
private extraction paths and complete positive/negative gate results. Earlier
parallel timing probes are historical measurements and do not establish
collision-free execution for their old launcher.


* Transport soundness behind BYODS acceptance (2026-10-07)

A complete 7abd3d6 CI run exposed a transport failure in the 10,000-pair other
oracle test, while Scheme, BYODS, scale and formal checks passed. The reader join
reported Any rather than the original read error. Current evidence proves that
the transport failed; it does not diagnose EINTR or a Scheme semantic mismatch.

PipeCapture owns universal byte-order/prefix and terminal admission properties.
OracleTransport owns independent reader/process/request completion and rejects
early admission, swallowed errors, dropped tail bytes and interruption failures.
Rust scripted read controls and the actual parallel other-shard rerun connect
the model to the test adapter. No synthetic progress, widened deadline, retry of
failed model calls or relaxation of row truth is introduced. Native OS/thread
extraction and historical failure causality remain explicit boundaries. See
[[file:../../evidence/scheme-provider-views-20261007/oracle-byte-admission.json][the receipt]].
