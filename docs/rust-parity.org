#+DATE: 2026-09-26
#+STATUS: incomplete implementation matrix

* Authority and completion rule

The first target is behavioral parity with the pinned =ascent 0.8.0= oracle,
interpreted through Scheme and Gerbil modules. The [[https://s-arash.github.io/ascent/cc22main-p95-seamless-deductive-inference-via-macros.pdf][CC 2022 paper]],
[[https://kmicinski.com/assets/byods.pdf][BYODS paper]], and [[https://github.com/s-arash/ascent][Rust implementation]] define the baseline.
Rust-specific surface syntax and ownership rules need equivalent Scheme APIs
and macro behavior; copying Rust syntax is not a requirement. Each row closes
only with a matching Rust fixture, Scheme result comparison, invalid-program
test where relevant, and a measured performance receipt. Until then, this
repository is a partial implementation, and Agent extensions are research
proposals rather than core parity claims.

* Feature matrix

| Rust Ascent 0.8.0 feature | Scheme namespace | Current state | Required closing evidence |
|---------------------------+------------------+---------------+---------------------------|
| Relation declaration, arbitrary arity and column types | =program/= | positive generic path handles unary through four-column mixed rows; binary fast path remains | broader column types and scale/performance receipts |
| Multiple heads, relation clauses, repeated variables, joins | =program/= | positive generic multi-head rules, joins and repeated-variable equality pass selected Rust oracle fixtures | arbitrary body shape, invalid-program corpus and performance receipts |
| Semi-naive least fixed point, dependencies and strata | =program/=, =core/= | generic recursive path supports positive and negative strata; binary fast path remains | recursive SCCs, rule order and termination parity |
| Conditions, bindings and generators | =program/=, =core/= | generic POO guard, =let= binding and finite list generator clauses with ordered binding checks | broader iterator/pattern shapes and scale receipts |
| Stratified negation | =program/= | 3-level negated relation fixture and negative-cycle rejection pass selected Rust oracle comparison | broader safe/unsafe programs and performance receipts |
| Aggregation and custom aggregators | =program/= | count, sum, min, max, mean and custom iterator aggregators pass empty, duplicate-input and grouped Rust fixtures | recursive aggregate corpus, broader type behavior and performance receipts |
| Lattice declarations and recursive joins | =program/=, =table/= | POO lattice declaration with user join; selected recursive shortest-path and duplicate-key snapshots match Rust | broader join families, lattice/negation composition, invalid join laws and scale receipts |
| Relation indexes and selected physical plan | =table/= | private dense/sparse binary adjacency | index selection and relation access parity across arities |
| BYODS data structure provider protocol | =table/= | absent | default provider, equivalence, transitive relation and user provider fixtures |
| Parallel execution | =core/=, =table/= | absent | deterministic serial/parallel parity and contention benchmark |
| Gerbil module and macro embedding | =core/=, =interface/= | callable Scheme functions, no full declaration surface | module reuse, local bindings, generated declarations and diagnostics |

The current Rust oracle in =rust/ascent-oracle/= covers positive binary
closure, guarded filter/copy/join, shortest source support, and selected
arbitrary-column rules, =if= guards, =let= bindings, =for= generators, stratified negation, selected aggregation and shortest-path lattice joins across
source snapshots. Scheme generators currently return finite lists and name
their input variables explicitly. These fixtures do
not close the rows above. =candidate/= and
=interface/= hold existing experimental projections; their MRR or Agent use
cannot substitute for Rust feature parity.

The standard =ascent-rule-clauses= SS scenario measures evaluation of one
predeclared program over three ternary edges. Isolated 20-sample runs after
bounding stratum traversal measured 493 and 573 us p95, but two runs after
lattice support measured 1.689 and 1.515 ms p95 with a few long-tail samples
amid approximately 0.5 ms medians. The 1 ms ceiling is not stable. This is
not a scale or cross-platform claim.
Declaration construction is outside this timing window and remains a separate
cost.

* Implementation order

1. Freeze a representative Rust 0.8.0 fixture corpus and error corpus for
   each matrix row; keep it under =rust/ascent-oracle/=.
2. Generalize relation columns and rule bindings in =program/=,
   retaining POO Foundation and standard-library operations as the substrate.
3. Implement and compare stratification, negation, generators, aggregation,
   and generic lattice behavior. Preserve explicit bounds and typed failures.
4. Add the BYODS provider boundary, then serial and parallel execution parity.
5. Qualify Gerbil module and macro embedding plus performance against the
   corresponding Rust fixtures. Only then admit Agent-specific extensions as
   a separate research track.
