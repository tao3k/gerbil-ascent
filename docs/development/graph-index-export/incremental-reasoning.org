* Index rule occurrences by their admitted output relation

POO PR #17 at =7d68b830= resolves membership requests against the partition
owned by the same publication. It avoids rebuilding the input membership
index for a rejected edit. Accepted topology edits still rebuild their
required support. In ASCENT, source replacement retains the declaration
and its dependency analysis. The corresponding reusable unit is the
lowered stratum roster, including repeated rule occurrences and ordered
multi-head projections. The production dependency pin remains
Yuanxu =bbcb8fe9= and POO =6cf940be=. The experiment transfers the
ownership and lookup algorithm from the inspected POO revision.

=program/planning.ss= attaches a lazy output index to declarations with at
least 256 rules. =program/update-selection.ss= builds one ordinal entry per
stratum occurrence. Each output relation owns a bucket of occurrence
references; a repeated head enters the bucket once but stays repeated in
the rule. A selection checks roster identity and relation count. It reads
the affected bitmap and sums the lengths of the reached buckets. The
sparse path gathers those entries, sorts a private spine by descending
ordinal, skips adjacent duplicates, and prepends into the original strata.
The same projection function preserves ordered heads and lowered slots in
both paths. If =hits * integer-length(hits)= exceeds the number of
occurrences, the selector uses the ordered full scan. The cutoff and
256-rule admission threshold are implementation choices. They are not
performance thresholds or a measured universal crossover.

The native work consists of an initial roster/head traversal and index
storage, a subsequent affected-bitmap scan and bucket probes, a sort of the
gathered entries, and head projection for the selected occurrences. The
bounded sort estimate excludes physical allocation, GC and the cost of
creating the affected bitmap. Dense fallback pays the preliminary bucket
probes as well as the ordered scan. Source rows, rule frames, and
provenance are excluded from the index. The per-cut engine continues to own
them. Lean =SourceUpdateFrame.RuleActivation.sorted_gather_preserves_projection=
proves ordered output and deduplication for exact buckets. The native
Suite exercises dense fallback, mismatched roster identity, repeated
heads, the same rule object occurring twice, and separate stratum order.
The guarded Lean file passed without warnings. The strict SysML structural
check passed. Neither result is a proof of native allocation or collector
behavior.

The production comparison separates the compiled index from the cost of
running the query. The local MiniDusa Racket
=private/runtime.rkt:find-facts= filters its database. The published Dusa
compiler =src/language/compile.ts= generates keyed indices for binarized
prefix predicates. The ASCENT output index applies the same general
restriction of work to matching keys at the scheduler boundary. The Ascent paper's delta
transformation continues to control which rows participate in recursion.
[[https://arxiv.org/abs/2405.19040][Finite-Choice Logic Programming]]
and [[https://s-arash.github.io/ascent/cc22main-p95-seamless-deductive-inference-via-macros.pdf][Seamless Deductive Inference via Macros]].

* Checked source membership and relation-owned replacement

The reference POO Graph revision implementation was inspected at local
=67cfc17=, including =7d68b83= for partition membership preflight. Its
=owned-component-revision= edits the predecessor's owned component source,
uses the partition's inverse ownership, and rebuilds code only for edited
groups unless support is explicitly complete. The published =d43578f=
benchmark measured 0.061--0.096 ms CPU for a prepared million-owner edit,
with one owner check, two opened buckets and two rank writes. It excludes
cold SCC construction and later order enumeration. The corresponding
full-owner scan cost 552.426--604.882 ms. The frozen ASCENT native comparison
uses the same POO artifact in both arms, =424e5250=.

An ASCENT source edit ordinarily preserves rule topology. Reusing POO's
dynamic topological repair for an unchanged dependency graph would duplicate
work. The relevant operation is selecting the affected relation closure and
retaining the admitted state of every untouched relation. The rule output
index already does the former for activation. On 1,000 real rules, the old
control measured 48.893 ms scan P95 and 48.772 ms indexed P95 for a full
replacement. The timed path still rebuilt source and relation state. The
selector-only timings expose the cost of one operation inside that path.

base with =member= whenever the relation had a field checker. For =B= base
rows and =U= distinct completed rows this can make up to =B*U= equality
comparisons. Each absent row incurs =B= comparisons, even when the relation
was untouched by the edit. The Set initialization path already inserts the
same admitted base rows into its exact =equal?= membership index. A privately
recaptured checked Session now reads that table after the original per-row
check. The fresh table for completed membership stays separate. Every source
occurrence still consumes its original budget, and the first occurrence of a
completed fact consumes derived budget only if it is absent from the base.
The rule/provider eligibility check, rollback and final publication retain
their existing order. Caller-owned declarations keep the original fallback.

=SourceUpdateFrame.SeedMembership.indexed_derived_rows= checks the exact
classifier correspondence and =indexed_seed_probe_saving= states the

The next owner boundary is the completed relation cut. A prepared sparse
source edit should carry the exact changed slots and read the existing SCC
successor index. Outside the transitive cut, immutable ordered rows, membership
and index version belong to the predecessor. Any first write needs a fresh
engine-local owner. Inside the cut, maintain source multiplicity and use the
existing semi-naive evaluator for additions. Deletion needs exact rederivation
or a specialized checked delta algorithm with alternate supports. A naive
support decrement can retain self-supporting cycles. Source and derived counts,
completedness, occurrence identity and provenance must all agree before one
atomic publication. Dense edits require a full-cost fallback. Qualification
must include both kinds of edit, cold construction, sparse fan-out, a dense
SCC, skewed joins and result consumption, with requests large enough to expose
allocation and GC tails.

The Ascent paper gives the semi-naive delta and indexing baseline. Dusa's
published implementation generates keyed prefix indices after binarization;
the local MiniDusa Racket =find-facts= is an independent scan reference. The
resulting ASCENT design should index checked stable prefixes when both fact
and prefix arrivals can drive work. Cyclic multiway joins warrant a separate
comparison with a worst-case-optimal join. Complete mutable list export still
charges the full output size. It has its own GC and allocation acceptance.
