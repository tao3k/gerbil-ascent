* Native complete-planning A/B

The ASP Scheme benchmark API executes 50 alternating baseline/candidate pairs.
Each measured call constructs both invalidation successors and strict strata,
then consumes their results. Inputs are prepared outside measurement. Both
checksums must equal the independent edge-count and stratum sum. GC occurs
outside the measured call; CPU uses process user/system statistics and memory
uses allocated-byte counters. Compilation and tests do not overlap timing.

The mixed target is declared before execution to require >=10% CPU improvement
and >=40 faster pairs. Controls allow <=110% baseline CPU + 20 microseconds;
allocation allows <=110% + 4096 bytes. No gates were relaxed.

All declared gates pass. Microsecond control CPU differences are not promoted

not complete program compilation, evaluation or wall-clock performance.
