** Ancestry cache root-cause experiment

Core's native responsibility checks repeatedly call POO ancestry lookup.
At the pinned POO commit =099b381588360a8a49fd772f666a1a00351366f5=,
=compute-precedence-list!= creates an active hash table before examining
its cached precedence list. A local upstream candidate moves the valid-heads
cache hit before that allocation and leaves cold traversal unchanged.
The patch, review snapshots, hashes, both raw 1000-pair runs, and logs are
[[file:../../t/performance/poo-cache/README.org][retained in the POO cache receipt index]].
ASCENT's dependency pin and the original installed dependency are unchanged.

Both matched runs qualify 3.2--3.9x median cached-path gains and about
0.9 percent cold median regression, within the prespecified 5 percent
cold allowance. All 1536 three-node graph/root comparisons, cache identity,
malformed heads, and explicit slot uninstantiation pass. This establishes
the ancestry-function boundary, not full solve latency or source authority.

The unchanged indexed-joins SS gate still fails with the candidate:
1000 samples, median 0.547 ms, p95 14.889 ms, 2 ms p95 limit.
The earlier 28.703 ms failure used a different experimental source state;
there is no matched end-to-end speedup claim from these two values.
Core's forced-collection profile also shows long pauses in the clock/memory
probe; =:std/time/precise= and the existing jiffy clock agree on those spans.
No timing or memory budget was relaxed. The final-source rule-program
module fails its unchanged duration Cases in both concurrent and serial
repeats. An earlier candidate pass does not establish stable integration
closure. Existing POO object/MOP suites and all three ASCENT responsibility
admission Cases pass under the final candidate library.

** Empty second-atom frontier pruning

first atom even when the second atom's selected delta was empty.
=program/evaluate.ss= now skips that single branch when the first two
clauses are atoms, the first has no index columns or non-variable terms,
and delta position 1 has zero rows. The old branch dispatches no Provider
callback and cannot reach subsequent clauses or emit rows. Other prefix
forms retain their existing path. Ordinary cardinality maintenance is
unchanged; its separate candidate failed paired admission and was removed.

** Multiple empty-frontier pivots

After committing the earlier slices as =98a96ca=, the next evaluator
candidate generalizes pruning across contiguous variable-only atoms without
index columns. An empty pivot uses the raw-row path. Any indexed atom,
non-variable term or other clause ends the safely bypassable prefix.
Each engine precomputes relation-index metadata in local active-rule copies;
the shared immutable analysis retains its original layout. This avoids
repeated per-round term checks and preserves old/new analysis cache sharing
and retained-session replacement behavior.
