* Closure conclusions and criteria

Deliver a usable native reasoning lifecycle, then assess architectural benefits
on the same library scenarios. Model comprehension is separately qualified
research, and MR/MRR consumer integration is deferred. This matrix retains every
obligation for full replication; passing finite scenarios does not establish
complete coverage of a paper.

The objective remains complete ASCENT behavior and BYODS design coverage.
Overall completion has not yet been established. Native cases, finite Rust
comparisons, abstract Lean theorems and finite TLC exploration answer distinct
questions. Case counts or passing CI cannot replace missing functionality or
proofs. This matrix aligns the original scope, recent actor implementation and
proof catalog. Unimplemented or unproved items remain visible.

An item closes only when all of the following evidence agrees:
1. Identify its paper location, admitted Scheme behavior and implementation owner.
2. Cover the item and its interactions with independent truth, Rust comparison
   or explicitly recorded upstream differences.
3. Connect Lean/TLA+ statements to the actual implementation and distinguish
   premises from conclusions.
4. Bind positive and negative controls, failure/timeout behavior and resource
   constraints to execution results for the current source.
5. Support claimed performance benefits with identical inputs and semantics,
   alternating measurement order, and retained negative results.
6. Verify ASCENT CI and pinned reference versions against the final GitHub
   commit. External consumer integration and consumer pins are separate work.

Sources: [[https://thomas.gilray.org/pdf/seamless-deductive.pdf][A22]] and [[https://kmicinski.com/assets/byods.pdf][B23]], reread on 2026-10-05.
A22 presents parallelization as future work; the current actor architecture adds
engineering obligations. B23's custom data structure interface and application
experiments require separate acceptance. Published performance numbers do not
constitute Scheme performance evidence.

* Integrated acceptance of the current Runtime mainline

The 2026-10-06 audit found that =SnapshotClosure.Agrees= required current owned
facts to equal the earlier snapshot. The actual owner has already received
credited batches, so this premise cannot apply directly to the live frontier at
completion. The revised proof uses an external read frame and containment of
published owned facts in the completed closure. =credited_terminal_closed=
connects the credited prefix to the terminal tail.
=GroundedBinding.credited_compiled_closed= combines row/binder/index validity,
constructed grounding, snapshot framing and actual terminal completeness into
one compiled-rule closure conclusion. Intermediate publication soundness and
completed closure have separate obligations.
=GroundedBinding.completed_compiled_least= combines seed coverage, sound
publication and closure under every compiled rule to establish that the whole
result equals the least model.

* Implementation order and final acceptance gates

1. Connect admitted DSL, native row/binder/index/rule steps and the consequence
   operator through refinement, composing the existing local statements.
   Align input capabilities, exit status and semantic budgets.
2. Connect built-in Provider gamma, stepwise emitted frontiers and arbitrary
   bodies/iterations to complete the semi-naive/naive equivalence chain.
   Define lattice and ordinary relation semantics separately.
3. Complete native refinement and scale benefits for the implemented trrel_uf
   SCC/union-find representation. Implement and verify index sharing and user
   Provider concurrency protocols, preserving ownership, cancellation and
   publication isolation. Restricted test scale cannot replace implementation.
4. Complete paper applications, interaction cases, datasets and performance/
   memory comparisons, retaining upstream differences.
5. Once every closure item has current source, native/Rust/Lean/TLA+ evidence,
   negative controls and evidence for each claimed benefit, verify ASCENT
   final-head CI before declaring complete ASCENT/BYODS library closure.
   MR/MRR integration is outside this acceptance decision.

* Positive body / frontier joint progress (2026-10-05)

B23 section 3.2, especially Lemmas 3.2-3.4 and Theorem 3.5 (pages 8-9), was
reread. The paper separates single-step decomposition, historical coverage of
old facts, abstract data structure gamma contracts and iteration equivalence.
The implementation must retain all four obligations.

The [[file:evidence/scheme-body-frontier-20261005/receipt.json][joint acceptance receipt]] records the following distinct responsibilities:

- Lean =ProviderFrontier.body_partition= proves full = old union single-delta
  pivots for finite positive bodies of arbitrary length. Environment passing
  permits shared variables and repeated relation keys.
  =projected_partition= / =projected_frontier= establish projected results and
  exact output delta for arbitrary pure head projection. Pivots may overlap;
  a new witness need not produce a new head.
- =new_consequence_pivot= requires every all-old head to belong to the known
  database before omitting the all-old body. Establishing this premise requires
  iteration history; Provider frontier completeness alone does not establish it.
  Empty bodies preserve seeds; initial full execution remains necessary.
- TLA+ =ProviderFrontier= checks consumption from private pending frontier to
  committed total and downstream publication through three atoms.
  =ConsumerSnapshot= holds in both pending and idle states. Premature publication
  and consumption of stale total are rejected by mutation controls.
- The native Scheme suite enumerates 27 three-edge input/producer partitions
  for each of eqrel, trrel and trrel-uf, yielding 81 complete programs. A relay
  delays the second producer; three reads of the same closure relation share
  variables. Independent graph closure and three-edge witness enumeration
  supply truth independently of the evaluator under test.

This establishes a single-step semantic chain for positive concrete bodies.
General lattices, negation, aggregation and arbitrary host callback delta
decomposition remain unproved; no native extraction is claimed.

* Concrete positive Set iteration history (2026-10-06)

[[file:../packages/proofs/lean/SemiNaive.lean][SemiNaive]] extends rule-body decomposition to complete synchronous iteration
for a finite rule set:

1. =consequences_partition= proves full/old/pivot decomposition of all rule outputs.
2. =pivot_after_full= derives all-old head coverage from the preceding fullStep
   definition, without caller-provided coverage or completed-solving premises.
3. =iterations_equal= proves corresponding naive and semiNaive snapshots equal
   for every Nat round. The initial round uses fullStep; empty-body facts remain
   included.

Exact scope: concrete Set databases, finitely many rules, finite positive
body environment transitions, pure fixed head projections, and views monotone
under Set inclusion. Delta is the exact difference between adjacent concrete
views. Repeated keys and shared variables retain ProviderFrontier semantics.
The rule set and rule bodies may be empty; round numbers have no upper bound.

The theorem assumes neither successful native results nor termination.
Equality at every round alone does not imply finite convergence. Termination
still requires FiniteHeight's finite-height/progress premises and descriptor
correspondence. B23's general abstract lattice join, gamma/injection and
gamma-total/delta contracts need separate connections; arbitrary caller
Providers are not assumed to satisfy them.

TLA+ retains protocol responsibilities. ProviderFrontier checks both empty and
seeded initial cuts and rejects the mutation that only runs pivots while
omitting initial full consumer publication. This finite safety check establishes
neither Lean's iteration algebra nor unbounded temporal theorems.

The [[file:evidence/scheme-seminaive-history-20261006/receipt.json][iteration receipt]] binds rebased source and actual checks. Earlier sections
and receipts describing unproved iteration history refer to the 2026-10-05
source. This section updates the conclusion for concrete Sets. Remaining
mainline obligations include composed native slot/binder/index/pivot
correspondence, general Provider gamma contracts and unbounded TLA/native trace
refinement.

* B23 active-domain eqrel concretization (2026-10-06)

The [[https://kmicinski.com/assets/byods.pdf][B23 primary paper]] sections 3.1 and 3.3 motivate a representation-specific
closure/frontier instance, rather than assuming arbitrary Providers satisfy
Set semantics. =EquivalenceComponents= constructs active-domain reflexivity,
symmetry and transitivity after each injection, least closure after every
finite input sequence, exact newly emitted facts and isolated group updates.
The corresponding native suite checks exact per-insertion deltas against
independent Floyd closure, including rejected budget and retry on the actual
state. The [[file:evidence/scheme-eqrel-frontier-20261006/receipt.json][qualification receipt]] separates general algebra from bounded native
observations and lists the remaining representation extraction boundary.

This advances eqrel's semantic instance. General gamma/join/injection laws,
other non-Set/custom lattice instances, universal Scheme equality/component
extraction and native actor trace refinement remain distinct work. Existing
TLA+ publication/credit/failure models are unchanged; Lean owns these algebraic
laws. Published B23 performance does not establish a Scheme speedup.
