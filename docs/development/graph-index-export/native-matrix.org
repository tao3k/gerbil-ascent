** Finite mapping row construction

The checked finite mapping constructor now validates a bounded row extent
before scalar reads. It appends checked values to one private STD list
builder and constructs singleton pairs directly. Input validation still
precedes output validation. The result owns both halves independently of
the caller, including repeated entries with the same source pair. Lean
checks bounded extent for proper lists and the ordered concatenation and
pair-count equations. The native semantic Cases exercise the improper and
cyclic boundaries and mutations of caller and returned pairs.

The isolated compiled candidate passed nine semantic Cases and four of
the five original finite mapping gates. Each performance Case ran all
100 pairs. Reference and candidate CPU medians were 10.2/1.2 microseconds
for =narrow-rows= and 27.5/16.5 microseconds for =wide-rows=. The wide
reference in =wide-view= still reported a negative median allocation delta
of -10,767,144 bytes; its performance gate failed. The source-control and
canonical-provider Cases passed. The initial forward-only candidate and
all final logs are retained under =.cache/ascent/yuanxu-v0.1.0/=. This
candidate has not run through the full matrix.

The finite mapping source and its mutation test were also copied into
an isolated snapshot of the frozen release source. Standard =just build=
completed with both ABI products. Standard =just test 2G= then passed
185 modules and 1,532 Cases in 98 batches using the existing worker
configuration. The test stage took 228 seconds. The first semantic
invocation stopped in the process supervisor because the sandbox denied
=ps=. The accepted invocation used the same command with local process
inspection permitted. Build, denied invocation and acceptance logs are
under =.cache/ascent/yuanxu-v0.1.0/finite-mapping-integrated/=.

A separate native observer used Gambit's processor and VM
occupancy fields around the same alternating 100 pairs of ten wide-view
constructions. It checked every pair's rows. The reference reported
83 negative totals and the current implementation 23. Of these,
44 reference intervals and 21 current intervals had no collection.
All 65 no-collection negatives had a falling prior-section term and
an unchanged rebased counter. In reference sample 68 the prior-section
term fell by 37,189,311 words and the stack span by 21,868 words. The
other terms were unchanged. Lean reconstructs the resulting
-595,378,864 byte delta with the frozen semispace accounting formula.
This localizes the signed result to native section and stack accounting.
The separate Actor trace identifies a cross-section cursor write. The
wide-view observer does not trace the exact write instruction in this
workload. The original performance receipt remains failing. Evidence:
=.cache/ascent/yuanxu-v0.1.0/finite-mapping-counter/=.

** Stratified proof node capacity

when independent finite replay established four rows. It now reserves the
smaller of the verified closure row count and the existing 4,096-node cap.
Every node is admitted only after its relation/row key is found in that
closure and ruled out as a duplicate. Neither node numbering, source
occurrence labels, proof-search work nor independent checker replay changes.

Lean Guard checked =stratified_node_reservation_fits= and
=stratified_next_node_has_slot=. They model unique reserved keys as a
subset of verified closure keys, and prove that any accepted next key
fits under both capacity bounds. The 13 native semantic Cases include
80 work budgets compared against the frozen producer and checker, 64
finite graphs, duplicate source occurrences, exact reduction groups and
stale proof rejection. The original five native performance gates each
