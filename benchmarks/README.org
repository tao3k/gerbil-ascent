#+TITLE: ASCENT benchmarks

* Single VM Actor components

Run the source Suite through the native test entry; it does not create another
runner or another VM. The installed production library supplies the Session.

#+begin_src sh
timeout --signal=KILL 90s gerbil -:max-heap=2G,debug=q test -v 5 \
  benchmarks/actor-mailbox-test.ss
#+end_src

The first Case sends one million ordered fixnums to one persistent mailbox and
waits for the receiver to drain. The second measures 10000 public Session state
requests on one VM processor. It reports Session opening, the first request,
aggregate throughput, P50, P95, maximum latency and natural collections. The
request Case requires P95 below 100 ms and checks caller-mailbox isolation.
There is no logging inside the measured loop. No build is required for the Suite
itself. These component measurements exclude Rust/Scheme value conversion,
process IPC, rule evaluation and full relation export; their throughput units
must not be substituted for those production operations.

* Concurrent native requesters

The current single-VM Suite also exercises 1, 3 and 12 native calling Actors
against the same one-worker Session. Each profile completes exactly 1,200,000
independently checked state requests. This is mailbox/Session-state admission,
not a relation-query or Rust transport result. All calling Actors join before
Session retirement, including failure paths. The original 100 ms P95 check
still applies to every client and the complete profile.

* Matched recursive production transport

The existing Rust =process_throughput= benchmark retains its complete row oracle
and changing source values. Set =ASCENT_BENCH_DSL=ascent= to load the original
closure DSL through =Engine.load_sources= and require an Actor receipt from
every Scheme query. The default =typed= fixture retains its ordinary Session
and requires that receipt instead. Rayon uses the same selected source after
owned projection. A receipt mismatch fails, including stale compiled carriers.

Set =ASCENT_BENCH_CLIENTS=1= for an isolated requester or specify the population
for a matched saturation experiment. Omission uses the machine's available
parallelism. This does not impose an Actor protocol capacity. The historical
33-row experiment explicitly retains its original 12 callers and typed DSL.

The grouped recursive case uses 256 chains of width 16, 3,840 input edges,
30,720 exported rows and at least 1,000 verified changed-source requests.
Keep finite resource prechecks when comparing the Rust interface. They include
an independent Rust budget execution before the native query and replacement;
the resulting measurements are not pure Scheme kernel timings. Keep encoding,
native calls, decoding/release, queueing and client oracle costs separate.

* Rejected reply-channel candidate (historical experiment)

The original implementation creates a private reply Actor for each synchronous
Session request, preserving the caller's mailbox. A candidate replaced that
Actor with a one-reply =std/sync/channel= channel, leaving owner-only state
mutation and generation/publication logic intact.

A declared 10000-pair alternating source-entry comparison checked identical
responses and caller-mailbox isolation. Both arms had P50 3 us and P95 4 us.
The accumulated individual request times were 120.487 ms for reply Actors and
170.859 ms for reply channels. The maxima were 33.148 ms and 46.802 ms. No GC
occurred in the paired loop. The study kept the existing reply Actor. These are historical measurements
from the isolated experiment. The native Suite above measures the installed
current Session on the same request shape.

* Provider index and Session phases

#+begin_src sh
timeout --signal=KILL 90s gerbil -:max-heap=2G,debug=q test -v 5 \
  benchmarks/provider-index-test.ss
#+end_src

Use the installed production library. The Suite compares 4096 wide rows,
16384 narrow rows, and a 4096-row wide relation with a 16-row exact match.
It records the intervals between the physical owner and actual provider
callbacks, including cold creation, warm lookup and returned-packet admission.
The cold interval before the build callback includes index-owner setup, witness
construction and outbound copying. A separate call prices the same outbound
copy primitive and checks the exact number of fresh pairs. Keep that interval
separate from the inclusive cold interval.

The structural hash diagnostic counts native structural hashes and equality
calls during member-table construction and lookup of equal copied rows. It
compares the same native table operations at the default initial capacity and
with an explicit size hint. Counter wrappers are excluded from CPU comparison.
The Session case records provider build, extension and lookup counts around
the one-shot solve, first and repeated Session reads, append and replacement.
Every result is checked against its expected complete ordered ID set outside
the measured interval. The first publication is checked again after updates.

Each phase reports CPU, wall time, collections, the live bytes observed at the
most recent GC, and an allocation-counter delta. The delta can include the
observation overhead and a false value denotes a backward counter reading.
The outbound copy also reports the two raw endpoints of the collector charge.
These observations guide optimization; the existing provider packet performance
gates still run with their original fixtures and thresholds.

* Shared-prefix cache

#+begin_src sh
timeout --signal=KILL 90s gerbil -:max-heap=2G,debug=q test -v 5 \
  benchmarks/prefix-sharing-test.ss
#+end_src

The Scheme DSL fixture derives a delta of 128 targets. Two rules share the
same edge and label reads before testing those targets. The sparse chain and
16-way graph each start with 16384 edges. Run without retention, with 32
retention units, and with enough capacity to keep the measured prefix.
The oracle computes every answer by inverting the fixture's arithmetic
and all three runs must also agree on output order.

Report matcher input rows, slots stored during a retained match, cached
rows replayed, slots restored, physical probes, and complete witnesses.
The timed pass excludes the counter instrumentation. Report direct allocation
counter deltas only for monotone samples without a collection in the interval.
The scoped retention budget is separate from the fact and heap limits.

In these rules the label atom reads the middle node and writes the target.
Different incoming source nodes that reach the same middle node can share
the ordered label matches. Each replay keeps the incoming bindings and
support, then restores only the label atom's writes. The index owner reuses a
stamp only for the same total and delta versions. The =PrefixCacheKey=
theorems in =IndexedPositiveTraversal.lean= cover both compiled bucket keys
and the retained row and slot payload.

* Actor source admission and physical index

#+begin_src sh
timeout --signal=KILL 90s gerbil -:max-heap=2G,debug=q test -v 5 \
  benchmarks/actor-source-test.ss
#+end_src

The preparation case calls =gerbil-ascent-source-cut-update= directly
for one-row append, whole-cut restoration after append, and whole-cut
replacement with every input target changed. Each arm uses 1000
samples. The retained result must have the incoming values in newest-first
order, detach each incoming tuple, and share the old suffix only on append.
Report CPU, collections, the collector charge endpoints and live heap.
For 16384 two-column rows, the owned snapshot makes 16384 outer pairs and
32768 tuple pairs. The source count in =program/source-cut.ss= now shares
the width validation traversal and checks for an empty tail at exactly the
declared arity. The proper-list check still rejects cyclic outer spines
and all validation still precedes duplicate and budget checks.
=SourceUpdateFrame.lean= gives the exact row-count and snapshot-pair laws.

Two native repetitions of each implementation bracketed the candidate.
The separate whole-cut restoration phase averaged 1.259 s before and
0.879 s after per 1000 calls. Changed whole-cut preparation averaged
1.292 s before and 0.894 s after. Each measured whole-cut preparation
arm had 13 natural collections. In the public Session, mixed replacement
averaged 3.241 s before and 2.746 s after. Full change averaged 3.168 s
before and 2.781 s after. CPU improved in both pairs for both replacement
workloads. Mixed-replacement wall P95 varied from 3.722 to 39.143 ms
across the two reference repetitions and from 2.911 to 3.217 ms across
the two candidate repetitions. The separate traced repetitions had
44 replacement transactions dominated by GC in each implementation
across 2000 requests. Append latency remains open.

A separate direct-singleton consumption candidate eliminated the
temporary lookup pair but increased the CPU of the fully changed
replacement transaction from 2.329 s to 2.531 s. The ordered bucket
traversal remains in production.

Append one edge to the 16384-edge chain and observe the native admission
buffers before building the canonical keyed index. Compare the ordinary
initializer with the exact owned source cut across 1000 paired samples.
Check the borrowed spine by identity, the duplicate-preserving count, and the absence of a membership
table for a relation with no writer. Report source spine and membership
work separately from the cold bucket build and the warm probe. The
operation counts come from the admitted edge-slot shape and native index
counters. The final count pass uses the four-rule production fixture. It
compares a cold appended cut, an exact append extension, and an unchanged
read. Compare the emitted rows in order and report physical build and
extension inputs. The allocation calibration addresses the runtime byte counters separately.

The Actor borrows the newest-first lane for current canonical Program and
relation declarations on scalar sources. Mixed source and derived relations
retain membership for every initial row. Foreign POO getters still see the
staged declaration. =SourceUpdateFrame.lean= relates the append fold,
writer mask, budgets, and source-loop work to these branches.

A single-worker Session can keep one physical index per read-only source
slot shared across its components. Extend the native index only when the
new cut has the exact prior suffix. For comparably sized replacements,
revoke the old version and clear its native table before refilling it.
Release storage on large size changes. Compact a refilled table when its
key count falls below half the former count. Drain the evaluation before
discarding indexes from a canceled or failed cut. Held results retain row
spines independently of bucket tables. =PhysicalBuckets.lean= proves the
suffix scan, ordered extension, refill and copy of occupied buckets.
