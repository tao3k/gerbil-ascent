#+TITLE: Invocation-owned positive grounding expressions

* Coherent production boundary

=candidate/grounding-plan.ss= prepares private final rule/clause records and
expression closures once per synchronous invocation. An atom matcher classifies
wildcards, variables and literals before row probing; a head renderer resolves
only its prepared getters. Rule and query plans own no rows or mutable bindings.
Native =foldr= composes ordered matcher continuations, =with= destructures the
inspected rule vector, and typed =using= exposes private clause fields.

Gerbil =1cfb032= =compiler/optimize-call.ss:89-125= guards substitution using
arity/mutation facts and preserves ordered operand bindings. Its
=core/contract.ss:401-445= supplies typed expression binding through =using=.
The application is preparation of admitted expressions followed by execution,
not a new evaluator for arbitrary user code. At this qualification's revision,
fixed scalar clauses retained the existing evaluator; the subsequent
[[file:../finite-plan/README.org][finite evidence unit]] prepares their admitted operators with matched interpreter
controls. Plans are rebuilt for each call; no validation or producer
result is cached across mutable source/proposal boundaries.

The plan is used by positive proof saturation, final query matching and complete
grounded alternative enumeration. Independent positive proof verification keeps
its original direct binding/head evaluation. Graph verification still reconstructs
the entire expected graph, and public opening still verifies before copying state.
Unsuccessful row probes, scalar evaluations, completed-round visibility, IDs,
labels, duplicate choices, material caps and exact work boundaries are unchanged.
There is no semi-naive probe skipping or reduction of verification boundaries.

Only imports are redirected: frozen graph uses frozen proof and maintenance;

The proof consumer generates the complete DAG, independently verifies it and
projects every ordered node field and root. The graph consumer produces every
alternative, opens through full reconstruction verification, copies retained
state, reads complete heights and detached rows, and projects the full witness
and alternatives. Snapshot/spec/expected rows are prepared outside timing;
every plan construction and evidence operation is inside timing. Independently
specified chain rows and heights must agree with both complete consumers.

Fixed gates preceded timing: 20 alternating CPU pairs, 20 ASP Scheme API
admissions and five dedicated allocation pairs. Large arms require <=90% CPU
and >=16 wins. Small permits <=110% CPU +20 us. Allocation permits <=110%
baseline +8192 bytes. CPU includes natural GC; cumulative allocator samples use
native =##get-bytes-allocated!= and reject negative differences. All arms run
sequentially without tests or compilation alongside them.
