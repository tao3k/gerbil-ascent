#+title: Single-VM resident Actor runtime and performance acceptance

* Decision

The primary target is one resident Gerbil VM serving multiple concurrent
Actors. The VM is the ownership boundary for Scheme values and continuations.
Gerbil schedules green threads and mailbox waits, and can run another ready
Actor while one waits for asynchronous I/O. Processor count is a separate
property of the runtime configuration. A one-processor benchmark still runs
multiple green threads in the same VM.

ASCENT coordinator Actors own ready SCCs, delta rounds, Session cuts and
completed publication. The Session owner is an Actor, and evaluation and
monitoring run in separate Gerbil green threads. Evaluator worker capacity is
separate from the number of Actors or callers. Rayon executes only pure work
over Rust-owned data. Scheme roots, continuations and mutable indexes stay
within their VM. Multiple VMs remain a separate isolation and scale-out
experiment.

This supersedes the historical test-carrier direction in
[[file:../scheme-actor-runtime-design.org][the Actor protocol history]]. Its ownership, cancellation and publication
obligations remain. Do not add another evaluator, loader, runner or scheduler
for Scheme threads. Keep the Scheme package manifest independent of the Rust
bridge's package namespace.

An ingress queue alone is not a resident service. Accepted Scheme work must
receive native execution opportunities while Rust input, output or clients
wait. Native readiness, host recovery and client consumption are separate
events. Cancellation must remain admissible under full data credits. Close
joins accepted work before releasing roots. Only complete current cuts publish.

* Resident terminal evaluator

The Session coordinator admits at most one run. It hands a certified
terminal computation to one lazily started Gerbil worker through the
worker's native mailbox. That worker remains on the existing VM. A single
monitor joins the worker at retirement. Calls with an execution authority,
deadline, rule-cost observer or conditional acceptance use the ordinary
per-run worker and monitor.

The resident worker can return a complete terminal result, decline the
optimized path, or report failure. Only the coordinator may publish. It
checks the original epoch and worker identity and calls the existing
publication admission. A current decline starts ordinary evaluation with
the same admitted cut, token and epoch. Cancellation fences off both
publication and a late decline. Retirement discards the worker and rejects
its active run. Close drains the active job and joins the idle worker
before replying to the closing callers. The worker receives the existing
resource and cancellation token. It does not take ownership of provenance
or modify the certified planner's result.

=ActorStateCost.lean= checks the disposition of stale generations, retired
workers and current declines. =ActorResidentWorker.qnt= checks admission,
fallback, worker loss and close, and includes mutations of each of those
boundaries. The original dispatcher and result admission remain the
source authority for requests routed to ordinary evaluation.

* Measurement contract

completion on one monotonic clock. Queue, execution and publication spans sum
to end-to-end latency. Full-export timing includes materialization/conversion;
a lazy run result does not establish full export. Report preparation and first
call separately. Do not add inclusive GC or CPU spans twice.

Reuse =benchmarks/*-test.ss= with native =gerbil test= and existing Justfile
entries. Source Suites require no preliminary build. Keep independent oracles,
fixed workloads, complete counts, at least 1,000 distribution samples, elapsed
and CPU costs, GC observations, P50/P95/P99/max and resource limits. Smaller
diagnostics remain diagnostic. Keep the current 100 ms Session request gate
and the tighter relation gates. Count verified completions for throughput;
report rejection, failure and cancellation separately.

Mailbox messages, Session state requests, runs, updates and full exports have
different units. A mailbox throughput result cannot qualify a query SLO.

* Completed-engine ownership candidate

A fresh Actor run currently rebuilds membership, indexes and the fixed point
for an unchanged source cut. The proposed reuse retains the private run closure,
not a public Result or a validation receipt. It applies only to one worker,
current canonical declaration trees, immutable scalar source cuts and the existing
=gerbil-ascent-update-eligible?= rule/literal/provider predicate. Mutable nested
keys, foreign getters, changed POO contracts and source updates keep fresh
construction. Program fact ceilings remain the same immutable declarations.

Every request still installs its own execution authority. The retained engine's
cancellation probe reads the current run token through an owner-private cell;
the old token is never reused. Only an authorized, epoch-current completion can
retain the candidate. Failure and cancellation discard it and restore the
committed cut. A changed source cut retires it before new computation.
An admission checker running on the coordinator cannot synchronously request
that coordinator's own mailbox. Such reentry fails before allocating a reply
Actor; final acceptance then follows the ordinary failure/rollback path.

Retained derived row pairs must remain private. The evaluator therefore creates
a fresh public Result and detaches every exported row spine for this mode.
Reusing a caller-editable Result or borrowing derived rows would be incorrect.
The native controls compare unchanged work counts, mutated exported spines,
mutable keys, source changes, refusal and cancellation. Lean states the
same-cut/elegibility/publication obligations; Quint explores their violations.
Neither alone proves the Scheme heap or the eligibility predicates.

The source cost partition is eligibility plus seeding, index construction,
rule traversal and publication. Reuse removes the middle three terms, while
eligibility and fresh outward spines remain. The unchanged-run work counter
control checks that no new traversal is charged; source changes still traverse.
This algebra does not bound scheduler pauses, GC or wall-clock tails.

* Scalar component merge

The single-worker Actor path can reuse worker novelty when the unchanged-cut
retention predicate has admitted immutable scalar operands and a canonical
positive program. =program/component-plan.ss= groups every head by the SCC
that owns its relation. =program/component-worker.ss= seeds output membership
from the admitted snapshot and admits a candidate once before emitting it.
The coordinator's same-slot seed therefore agrees with the assigned worker.
Only the coordinator calls the evaluator merge, charges fact budgets and
applies completion credits. Worker novelty replaces one coordinator
membership table for the eligible path. Other paths keep that table.

=ScalarComponentMerge.unique_worker_merge= in =ActorEnvelope.lean= proves
ordered merge equality from worker novelty. =ActorRoundCredits.qnt= retains
its delivery, credit, and drain obligations. The Lean premise still needs
source evidence for each worker's membership keys and the ordered envelopes.

The evaluator's pending membership is also redundant for this same cut. The
novelty premise covers the union of already completed and staged rows, while
the existing evaluator still validates row shape, admits each staged row and
checks derived and output limits before commit. =unique_worker_staging= proves
the same ordered pending rows under this premise. The negative control
=original_staging_drops_repeats= retains the earlier semantics for inputs
outside the worker guarantee. Keep the scheduler admission and drain
invariants in =ActorRoundCredits.qnt=.

The hosted Actor path attaches authority to each call. The membership change
preserves the row stream entering =emit-row!= and its leading work
checkpoint. =unique_worker_charge_prefix= proves that every prefix of this
stream charges the same pending facts, including the first rejection.
=run-task= still issues worker checkpoints and waits for merge credit. The
owner's publication check still receives the current request authority.
This permits removing redundant membership under host authority, while the
separate cached source-index path keeps its existing authority guard.

The typed wire Session preserves separate replacement and query
transactions, generation updates, result lifetime and proof lookup. Its
batch replacement evaluates eagerly and publishes only a complete cut.
A query can return and resume an incomplete result at a committed round

* Deadline and partial Actor delivery

The local query duration starts when the evaluator is ready to compute.
The host's separate deadline and cancellation authority continue to cover
admission, service and delivery. =program/evaluate.ss= checks the query
duration at complete delta-round boundaries. A complete SCC solve can
bypass those boundaries, so a timed or suspended run uses the standard
round executor. A later untimed request must resume those same rounds.

In =program/actor-session.ss= the worker hands the owner one joined outcome.
The owner checks the epoch and the current request before returning any rows.
An incomplete outcome leaves the committed cut and last completed Result
intact. Its private workspace may be resumed on the same owned scalar cut
with a fresh request authority. Source edits retire that workspace. A stale
or denied outcome restores the committed cut and discards the workspace.
The result handle and provenance of an incomplete query remain distinct
from committed publication when the typed Session is wired to this path.

=TimedSession= in =ActorEnvelope.lean= checks partial delivery, commitment
and resume eligibility. =ActorSession.qnt= explores suspension, cancellation,

* Process transport and native scheduler progress

The original exec worker blocked on =Connection.receive= before entering
=Runtime.call=. Its PID and one active
VM processor can be correct while a runnable Scheme thread still gets no
execution opportunity. A production API probe starts a Scheme thread through
=Module.call= and waits for an external marker without entering the VM again.
The thread writes the marker only after the next call rejoins it. A native
Gerbil control uses =device-wait-input!= from =:std/os/device= on an empty pipe.
In that control the scheduled Actor processes its mailbox and makes the
descriptor readable. Closing the writer independently wakes the reader at EOF.
The pipe wait also succeeds inside a real =Module.call=. Native scheduling
through the C ABI is therefore available when the VM stays entered.

The process worker sets its socket to nonblocking once. Its request reader
and outer reply writer use the same connection in
=rust/ascent-scheme/src/process_wire.rs=. The
existing Rust codec owns source bytes, partial offsets and errors. When a
syscall would block, the Rust connection borrow ends before the owner calls
the Gerbil wait procedure. =interface/hybrid.ss= gives that procedure one
close-on-exec duplicate descriptor and closes it before VM retirement. The
device wakes on readiness or EOF while the Rust connection reads and writes
the bytes. A native pipe control confirms that the duplicate preserves the
original file status flags and lifetime.

In =rust/ascent-scheme/src/process_worker.rs= the request lease starts after
the =Entered= frame and ends before writing =Reply=. A resumed Actor can use
its own scheduling state while this transport waits. The active execution
checkpoint waits in Rust's =poll= and exchanges its decision under the
caller's existing authority.
=ResidentTransport= in =ActorEnvelope.lean= proves byte and terminal-error
preservation across retry traces. =CheckpointTransport.qnt= checks the
scope and cursor rules and rejects entering the scheduler with an active
transport lease or advancing the cursor on a readiness signal.

The process test releases an Actor through a file created after =Module.call=
returns. The Actor's external marker must appear before the next VM call.
The Rust wire tests cover fragmented headers and bodies, buffered subsequent
frames, EOF in a partial frame and writes under backpressure. Progress during
an active publication checkpoint requires its own source and runtime evidence.
