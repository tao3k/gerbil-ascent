#+title: Dense UF storage and unique-input resource qualification

* Primary-source learning and storage contract

Gerbil =1cfb032= =std/vector/extensible.ss= defines a buffer owner separately
from its fill pointer, doubles capacity during growth, copies only owned data,
and implements bit membership with vector access and fixnum masks. The initial
segmented hash/mask implementation saved allocation but failed CPU admission;
its complete failed attempt is retained under
=.cache/ascent/uf-dense/rejected-segmented/=. The candidate applies
native word-vector access to the same admission/commit ownership contract.
No upstream rebuild, environment switch, process scheduler or test logic is
added to the package build entry.

One private adjacency protocol owns length, membership, iteration, insertion,
removal and retirement. Sparse adjacency remains an eq-hash. At geometric
cardinality boundaries starting at 32 arcs, it promotes only when the required
=u32vector= payload is at most two bytes per arc. A group shares one birth-order
registry using Gerbil's native =ExtensibleVector=, created only after successful
admission and populated only with current roots.
Each bitmap bit identifies an immutable node birth order, not a user value.

A committed new birth registers its slot once. The reserved initialized span
grows geometrically; =ExtensibleVector-fill-pointer-set!= runs only at span
boundaries. Its =let/cc= would otherwise capture a continuation for every birth,
even without buffer growth. Native sparse controls exposed that allocation cost.
The explicit positive extension argument requests one slot beyond the reserved
span; it does not change machine scheduling or add a configuration setting. Dense growth copies
an owned word vector geometrically; growth is declined when the required
payload exceeds two bytes per newly admitted degree, returning to a sparse
map. Geometric spare capacity can reach four bytes per arc at growth. Thus a
remote historical birth ID cannot request an unbounded dense matrix. A partial
SCC retires forward and reverse bits before clearing absorbed registry slots;
then adjacency with excessive retained bitmap capacity returns to sparse form.
Complete SCC collapse releases both indexes and the shared registry. Existing
value-to-node ownership remains necessary for resolving absorbed input values.

Count-only commit selects a single-target writer with =match= when possible,
avoiding a newly captured inner writer for every source root. General products
retain the nested writer; both keep the original reversed axis commit order.

Missing-arc admission is established before commit, including reverse-index
construction. Word writes increment the cached degree once per certified new

Qualification audits cached degrees, registry ownership/population, live roots,
reverse correspondence and transitive closure. Scalar frontier order retains
the ordered-neighbor contract. Freeze builds one temporary member-record array bounded by existing bitmap
span. It resolves dense IDs directly to persistent member rectangles, omitting
per-arc registry and member-map lookups. Sparse later births do not enlarge it.
The published cut retains no array, bitmap, parent link or mutable registry.

* Scope boundary

The root DAG still represents a quadratic number of reachability facts in the
worst case. This changes their physical representation and allocation cost;
it does not claim subquadratic closure maintenance. Snapshot rectangles remain
one per live root pair plus diagonals. Resource observations separate sparse
hash entries, occupied words, packed arcs, live registry keys and exact bitmap
payload bytes and registry backing-vector slots (including cleared holes).
Shared registry capacity is geometric in historical births; cleared slots retain
no absorbed nodes. They do not count hash backing capacity, object headers, member
spines, source journals or whole-engine heap usage.
