* Workload

** Replaying unaffected frontier segments

The next isolated candidate retains the accepted child interval of each
prefix occurrence in a committed compact solve. A single detached prepend
whose tail is the exact prior source spine can invalidate its old weak
component if both endpoints already belong to that same component. The
worker builds the tentative output in ordinary prefix order. For dirty
prefixes it expands and deduplicates their source bucket. For an unaffected
prefix it copies its accepted interval and transfers occurrence ordinals.
The global round remains ordered even when dirty and unchanged prefixes
interleave. The two regions have disjoint novelty by row identity.

The saveable cut binds its source occurrence count, exact source root,
unchanged region map and immutable arena. A replacement, merged or unknown
component, duplicate input or capacity refusal keeps the complete evaluator.
The owner can adopt the new cache only alongside the matching completed
terminal result. Appends never mutate an earlier cut's view or its index.
The worker must observe cancellation while replaying both retained and fresh
work. =regional_candidates_exact= and =replay_children_in_prefix_order=
state the ordered projection and merge properties with their locality and
first-witness premises. The existing Actor terminal models check stale
results, fallback and joins, and the compact-result model checks count and
resource refusal. Native controls must independently compare the two routes.

Gerbil executes these workloads in one VM. The measured build reported one
VM processor. The Session owner, resident evaluator, monitor and callers are
Gerbil green threads with separate mailboxes and lifetimes. The serial Rust
macro uses one execution thread for the rules. The benchmark measures
query work and delivery without an async I/O workload. A separate state
contention Case measures multiple concurrent green-thread requesters inside
the same VM; it does not infer parallel joins or I/O performance.

* Million-row visitor

The native list and visitor workloads alternate the same two million-row
source cuts for 1,000 requests each. An independent arithmetic sequence
checks the exact count, value and order of every delivered row. The same
consumer runs in both arms. Request time includes replacement, evaluation
and consuming the row stream. First-row time is taken at first consumer
entry. The existing bitmap-oracle list benchmark remains an independent
gate with its original workload and measurements.

For a packed cut, the existing public =visit-rows= can scan the contiguous
integer cells in ascending ordinal order when no columns are supplied.
The captured vector is read-only. Each consumer call owns its two row
pairs, even when it retains a row or reenters the Session. A callback that
exits early leaves only the prefix it received. Selected visits continue
to use the existing column and key checks and ordered origin lookup.

* Exact packed source reuse

Gambit's emitted code builds an outer pair and two field pairs per binary
row. Width-two result lists remain mutable and fully detached. Integer
vector reads of admitted fixnums do not need bignum boxes. This leaves
packed *input* allocation as an independent reduction available to both
list and field consumers.

projection can reuse a packed backing vector only if every occurrence
and both of its fields match exactly. Compare fixnum fields in order

* Direct publication from a closed identity rule

The compact integration derives its eligibility from the admitted positive
plan. There are exactly two width-two relations and one rule. Its only
body action introduces the two fields, and its only head writes those
same fields in order to the other relation. The existing Actor admission
establishes canonical Set storage, hash indexes and the absence of field
callbacks. Packed capture additionally requires unique, strictly ordered
fixnum origins. Its source slot owns the vector before any result can
borrow it.

For an untimed, unobserved call with an empty target seed and sufficient
input, derived and total fact room, the evaluation worker creates the
ordinary published result from the same frozen row view in both slots.
Names, sizes, explicit representation observations and active rule
counts match the list evaluator. The worker keeps no reusable engine
for this result. The owner alone checks its generation and commits the
publication through the normal terminal message. A later timed or
authority-bearing invocation builds through the ordinary evaluator on
the lazy source rows. This also preserves per-occurrence proof or cost
observation and the ordinary budget failure order.

* Ranked functional component

The recursive fast path uses the admitted binary plan for exactly the
base rule =reach(x,y) <- edge(x,y)= and the recursive rule
=reach(x,z) <- reach(x,y), edge(y,z)=. The variables are checked through
their compiled fresh and bound slots. The recursive pivot is the
target relation, and the other read stays in the frozen source cut.
The target has no seed. Authority, deadlines and plan-cost observers
select ordinary evaluation.

The component captures one successor per nonnegative fixnum origin and
checks that every edge increases its value. A successor can merge with
another trail. It cannot branch or revisit a vertex. Count the lengths
of trails with memoized suffixes before publishing. The full derived
count must fit both the derived and remaining total budget. Build and
count checkpoints consult the current Actor cancellation token. The
Session owner commits through the same terminal-message boundary.

The existing ordinal-run writer traverses adjacent uniform successor
runs in semi-naive delta order. Other admitted functional cuts use
stable compaction of live origins in that same order. The output view
owns its ordinal vectors and index. Each list result still owns outer
and row pairs. Refusing plan shape, rank, unique origin or resource
room leaves the ordinary solver responsible for the cut.

The separate native control retained two disjoint million-row caller
lists throughout 1,000 materializations. It allocated each ordered result
directly with three fresh pairs per row and verified all fields and the
terminal spine independently. The three distinct cells for each row
correspond to =detached_binary_pair_slot= and =detached_binary_pair_extent=
in =MillionQueryWorkload.lean=. That counts three billion cons cells across
the window by construction. The count does not depend on the GC allocation
counter. The control had no Session, relation
index, source replacement or rule evaluation. It used the same processor
count and heap ceiling. The timed loop took 29.90 s wall and 29.16 s
CPU. Its oracle-inclusive P95 was 109.57 ms, and its export GC P95 was
103.88 ms. The VM counted 249 collections, and all recorded GC wall
fell within export brackets. There were 142 requests with at least
100 ms of GC wall in export alone.

The =bounded_phase_misses_p95= theorem connects the measured GC brackets
to the production percentile rule. At most 858 of 1,000 requests in this
control could be below the bound with the recorded GC durations fixed.
The rule requires 950. This is evidence for the two-root mutable-list
shape on this Gambit release. The control does not exercise ASCENT
semantics or bound the pauses of a different allocation strategy.

** Deferred linking of private output blocks

The native binary-source exporter builds a backward outer chain with
two fresh field pairs per row. The alternative held independent block
spines in private vectors and linked their tails only after construction.
Every tail write targeted a new outer pair. =detached_block_splice_order=
uses Lean's =List.map_flatten= to establish the order of the completed

** Direct allocation of the nonmoving spine

The frozen SDK exposes =___make_pair= and =___release_scmobj=. Gambit's
[[https://github.com/gambit/gambit/blob/master/lib/mem.c#L1646][allocator contract]]
requires nonmoving inputs during foreign allocation. The probe uses
=std/ffi= to allocate an empty outer pair with immediate fields. It
releases the temporary foreign reference after the last allocating C
call, then attaches the row and the suffix from Scheme. The generated
foreign wrapper returns the new pair before Scheme writes either field.
The two inner pairs remain ordinary Scheme pairs. Failure follows
Gambit's heap-overflow signaling path. No runtime patch was used.

The native controls forced collection with the returned object rooted,
verified that a discarded blank pair was reclaimed, and verified that
mutating an exported pair left the input and another result unchanged.
The allocation probe used the same 1,000 independently verified
million-row results with both inputs retained, one VM processor, the
2 GiB heap ceiling and the 90-second watchdog.

| Outer pair allocator | Measured wall | Measured CPU | Result P95 | Export GC CPU P95 |
|----------------------+---------------+--------------+------------+-------------------|
| Ordinary Scheme allocation | 30.44 s | 29.90 s | 111.10 ms | 104.19 ms |
| Direct nonmoving allocation | 66.03 s | 65.45 s | 188.84 ms | 160.18 ms |

Both arms finished. Direct allocation removed the extra moving pair
from the =still-copy= route, while GC CPU and end-to-end cost remained

The production exporter remains unchanged. Its measured mutable-list

=PreparationWork= remains a local proposal. The original model passed

** Read recursive packed sources without materializing their row lane

The recursive terminal route forced =source-slot-newest-first= to build
the functional successor index, even when the same slot had an exact
numeric view. =packed-source-lane= allocates three pairs per input row
and the forced promise keeps the pairs reachable from its source cut.
Read the numeric view into the existing index arrays and write the
forward visit ordinals into descending slots. Lean's
=forward_cursor_preserves_newest_first_slot= ties each index slot to the
old newest-first lane. Integer validation, checkpoints, and the output
limit remain in the functional evaluator. The branching replay and
ordinary fallback still use the original lane when they need it. The
direct projection still returns the same fresh mutable list.

Both recursive arms loaded the same compiled Gerbil benchmark and
verified 1,000 results of 1,040,384 rows. The cursor overlay passed 53
focused native Cases including round order, cancellation, limits and
detached mutation. These were separate from the timed windows.

| Recursive input path | Run CPU | Total timed CPU | Total GC wall | Requests/s | Result P95 |
|----------------------+---------+-----------------+---------------+------------+------------|
| Materialized lane | 3.80 s | 44.80 s | 16.25 s | 21.45 | 94.88 ms |
| Numeric cursor | 3.19 s | 44.14 s | 18.93 s | 19.26 | 104.06 ms |

The first overlay had a shorter evaluator CPU window, but its ownership
probe still observed one forced lane retained after collection. The
actual workload orders each chain backward before stepping to the next
chain, so the existing strictly monotone source capture did not produce
a numeric view. The timing does not establish an allocation saving.
The complete Case failed the original strict 100 ms bound. The separate
unchanged projection shape under
the overlay verified 1,000 million-row results at 141.19 ms P95 and
also failed the original assertion. Both timed runs with the overlay
reported collections. The raw allocation readings are not evidence of
cumulative allocation savings.

The next candidate admits an unordered numeric lane only for the
already selected recursive terminal source. This representation supports
an internal ordinal read and keeps the deferred ordinary row lane.
It cannot publish the source as a unique indexed relation. The evaluator
still validates distinct origins and forward edges before using its
successor index. Ordinary initialization, branching replay, source
order, and resource and cancellation checks retain their existing paths.
After that validation, a scalar source view can publish and scan the
same cells in caller order. It exposes no binary-search claim for an
unordered capture. Source list and field entries remain detached from
the stored cells.

The separate native ownership probe observed one terminal evaluation,
