* Architecture decision

Actor/thread scheduling belongs in the Scheme runtime architecture. Test
preparation and source binding remain in =t/harness/run.ss=; immutable registry
construction lives in =t/harness/native-entry.ss= and test admission, output
credits, monitoring and draining live in =t/harness/actor-pool.ss=. The shell
=xargs= pool and timer-only RUNNING output have been removed.

The carrier implements the test boundary; the positive Set worker slice below
now implements one solver stratum round. Session/SCC scheduling remains a
separate implementation obligation. A test module
child runs its original =std/test= Suites and setup/cleanup in an isolated native
process. It does not execute parallel Cases or parallelize the solver.

The preferred pool carrier is one immutable AOT executable containing a frozen
module registry, original Suites and original setup/cleanup callbacks. Build and
link it once for the frozen source set; dispatch a checked registry key to each
isolated child. The receipt binds source set, registry, carrier and selected
module. Per-module immutable executables remain an alternative for smaller
qualification slices. Compiling and linking a full runtime for every dispatch
would defeat the intended preparation amortization. Reusing the mutable
=single-test= name across concurrent preparations is inadmissible for either
route. Measure preparation cost and steady execution separately.

Gerbil's [[https://gerbil.scheme.org/reference/std/actor.html][actor API]] supplies envelopes, request/reply, shutdown reactions and
actor monitors. The inspected 2591dcd SDK routes local envelopes through
=thread-send=; =spawn/name= creates an actor thread. Local messages do not by
themselves establish deep immutability of the payload. Admitted source rows,
captures, plans and indexes must retain their ownership rules when transferred.
Green-thread concurrency and CPU parallelism are separately qualified against
the captured Gambit backend. No multicore speedup follows from actor count.

* Execution owners and protocol

| Owner | Exclusive mutable state | Reads and emitted messages |
|-------+-------------------------+----------------------------|
| Preparation actor | Compiler jobs, artifact registry, generated module entries | Frozen source manifest; emits immutable source-bound carriers and registry keys; live generations cannot overwrite each other |
| Test coordinator actor | Admission queue, worker registry, lifecycle outcomes | Dispatches ready native modules; records genuine Case output and child exits; preserves exclusive lane and runtime budgets |
| Session actor | Pending/committed cuts, generation, cancellation and publication | Accepts append/replace/run/cancel requests; freezes the admitted input cut before dispatch |
| Round coordinator | Frozen total/delta frontier, assigned tasks, accepted replies, merge budget | Dispatches explicit rule/partition tasks; owns merge and the next-round barrier |
| Evaluation worker | Private variable frame and candidate output batch | Reads a frozen frontier and immutable index view; emits candidates and terminal completion for its assigned task |

Every work envelope binds session identity, generation, stratum/SCC, round,
task identity, program/source identity and frontier/index version. Natural
generations and rounds have no protocol maximum. Mailbox capacity and task size
are configurable resource controls, not semantic bounds on generations.

1. Admit and own the cut. Schedule ready independent SCCs from the dependency
   DAG. Keep lower strata frozen before negation or aggregation reads them.
2. Within an admitted positive SCC, freeze total and delta for the round.
   Partition work into bounded batches with private frames. A worker cannot
   mutate shared row buffers, canonical tables or public results.
3. Validate each candidate batch, including its origin and domain. Record a
   completion once for the assigned task; reject duplicate, stale and cross-round
   replies. A custom Provider must meet the snapshot and delta contracts or run
   on its exclusive owner. Thread-safety is not implied by its POO interface.
4. Merge completed batches under the coordinator's ownership. Set union is
   commutative/idempotent for the positive set subset. Admission counts unique
   derived rows at the actual merge boundary; duplicate derivations cannot race
   a budget or become an unreported budget bypass. Lattice joins and ordered
   source occurrences retain separate semantics.
5. Advance only after all assigned work is terminal and all accepted batches
   have been merged. An empty mailbox or one empty worker batch is insufficient
   for quiescence. New facts form the next delta; no new facts closes the SCC.
6. Publish only after every required SCC closes for the same generation and cut.
   Merge-owner serialization is measured separately from worker parallelism;
   independent Sessions and ready SCCs can overlap without weakening this cut.

* Cancellation, failure and backpressure

Cancellation advances the generation, disables acceptance for old work, and
enters a draining state. Workers cooperatively check cancellation at bounded
work boundaries, discard private candidates and issue one terminal outcome.
Actor monitors detect abnormal exits. The coordinator waits for every assigned
task to terminate or acknowledge cancellation before releasing its resources or
reusing its worker slot. Queued late replies are discarded; the last completed
source/result pair stays visible. A bounded or failed run cannot publish a
partial result as completed.

A cancellation request is not a guarantee that a noncooperative host callback
will stop. Such callbacks need a stated isolation boundary and failure outcome;
reclamation or liveness cannot be claimed from a mailbox acknowledgement alone.
The current protocol model checks safety, not worker termination or fairness.

Bound dispatch and in-flight batches with credits. Release a credit only on
terminal acceptance/drop/ack according to its task ownership. Feed control
messages independently of data credits so cancellation cannot deadlock behind
a full data mailbox. Cooperative yielding must correspond to completed real
work; ticker messages do not satisfy the test progress gate.

The scheduling protocol is our synthesis. None of these papers proves the
Gerbil actor implementation, cancellation protocol or performance claim.

* Executable safety model and next gates

=packages/proofs/tla/ActorRound.tla= models two positive producers over a tiny
finite source domain, frozen rounds, out-of-order replies, replay, generation
invalidation, cancellation draining and atomic publication. Independent closure
is {1,2,3} for seed {1}, and {2,3} for seed {2}. Fault controls disable the
barrier, admit stale completion, or publish during cancellation. TLC cutoffs
constrain enumeration only; the transition specification uses unbounded naturals.

Native implementation gates:

- Immutable precompiled carrier and module registry; actors coordinate isolated native test
  children, preserving each original std/test Suite, setup/cleanup and verdict.
- Scheme-owned protocol transitions and worker lifecycle with native shuffled,
  duplicate, late, canceled, failed-worker and full-mailbox discriminators.
- Positive SCC worker results equal the independent serial truth after every
  round and at publication, including provider expansion and skewed partitions.
- Lean refinement links actual coordinator transitions to unbounded safety
  laws. Existing Session publication proofs do not certify this new scheduler.
- Matched 1/2/4-worker measurements report queue delay, work, merge time, CPU,
  allocations, throughput and latency, including regressions and backend limits.

This decision adds no native concurrent solver or measured parallel benefit.
MRR Rust integration retains its later acceptance gate.

=RoundAdmission.lean= supplies the current unbounded work-key laws: a reply
with any different key/generation leaves the state unchanged; terminal task
acceptance is idempotent; receive/cancel preserve publication; re-enabling
acceptance after cancellation still rejects the old generation. The planned
native coordinator must implement these transitions before inheriting those
claims. Draining, credits and worker liveness are not proved by that module.

* Native test carrier implementation boundary

The pool generates one immutable AOT registry for the selected source set.
Exports are discovered during preparation; aliases bind each original Suite and
module callback without collisions. Selection accepts exactly one known source
path. Sources, generated entry and executable are checked before/after execution
under the existing lane lock. Fixture and independent reference modules are
compiled into the native library rather than recovered through runtime source
loading. The temporal Suite follows the native path in the registry; its legacy
incremental import wrapper remains available to interpreted invocations. The
syntax diagnostic module initializes the real Gerbil interpreter/expander before
its original eval-based Cases; the default AOT minimal evaluator is insufficient.

Each invocation starts a private coordinator actor, protecting the caller's
mailbox and nested invocations. It admits at most =jobs= isolated children.
Workers relay actual child output with one outstanding line each and wait for
credit. Coordinator failure of the output sink returns credit, stops further
admission, drains assigned workers, and returns failure. Monitors join workers;
uncaught worker failure becomes exit 70. Child verdicts retain their exit codes;
the first observed failure stops pending admission. Already completed successes
may release capacity before a later failure is observed. No claim of eager
cancellation of every assigned child is made: they drain under their original
5-second startup/idle output gates, 120-second deadline and 1G heap limit.
Exclusive modules start only after the successful parallel lane is fully drained.

The native qualification uses an explicit two-worker rendezvous to demonstrate
actual overlap without comparing wall-clock samples. Additional Cases check
failure admission, output failure draining, caller mailbox isolation, monitored
worker exceptions, serial line ordering and empty inventory. =ActorTestPool.tla=
checks the abstract task partition, bounded active/output credits, stopped
admission and complete return for exploration capacities 1, 2 and 3; an early
return mutation must violate =CompleteReturn=. Exploration sizes are not runtime
caps. The existing unbounded Lean round-key laws remain solver protocol laws,
not a refinement proof for this test scheduler. Liveness of arbitrary callbacks,
external cancellation and source-to-model refinement remain open obligations.

No speedup is inferred from two-worker overlap. Matched preparation, queue,
worker execution and throughput measurements remain the performance gate.

The [[file:evidence/scheme-actor-pool-20261005/receipt.json][native actor pool receipt]] retains the initial macro diagnostic failure and
separately binds full-suite and control snapshots. The full Suite passed 63
modules/560 Cases. The affected mode-reset and registry gates passed alongside
the six actor lifecycle Cases. GitHub exact-head CI is a separate publication

* Native positive Set solver rounds (2026-10-05)

=program/actor-round.ss= now coordinates actual solver tasks, independently of
=t/harness/actor-pool.ss=. =gerbil-ascent-evaluate-program= accepts =workers:=;
the default 1 retains serial evaluation. For >1, an entire active stratum must
have compiled pure positive plans; all relations must use canonical Set storage
and hash indexing, without lattice joins or field checker callbacks. Otherwise
that stratum uses its original serial path. Rule timing and retained Session
engines reject the parallel option rather than silently changing ownership.

The owner freezes total/delta row roots, size and version vectors for a round.
Each assigned rule owns a fresh slot frame and its own mutable physical index
cache. It executes the existing =core/positive-plan.ss= evaluator. Canonical
plans continue to share the existing rule-binding compilation; no second
callback interpreter was added. No shared mutable index cache is passed to a
worker. This assumes the admitted caller values are not mutated concurrently;
it does not deep-freeze arbitrary Scheme values.

One fresh coordinator mailbox and key bind program, stratum, round and frozen
frontier within the invocation. Sender identity and assigned task identity are
checked before accepting messages. A worker buffers at most 32 candidates and
waits for owner credit before continuing. Every 64 candidate traversal steps it
also requests checkpoint credit, including non-emitting scans. Only the owner
runs existing row validation, deduplication and unique-row budget charging into
tentative pending storage. It returns only after every assigned worker and its
joining monitor have terminated; the engine then commits the completed round.
The round barrier is a semantic condition, not a serial rule execution loop.

Merge failure, worker failure or the coordinator's cancellation predicate stops
pending admission. Outstanding requests receive stop credit; later batches are
refused, private candidates discarded, assigned workers drained, then the
original failure is raised in the caller. Tagged exception outcomes prevent
Gerbil's actor default error printer from polluting native acceptance output.
The generic coordinator's merge function must write tentative state; it provides
no rollback for arbitrary caller side effects. The engine's merge targets pending
rows, never a public result.

Output set membership is preserved; opt-in parallel row enumeration order is
arrival-dependent. Tests canonicalize sets rather than require serial ordering.
Callback trace/order remains serial through the eligibility gate. A single large
rule is still one task: skew partitioning, persistent worker reuse, ready-SCC
scheduling, Session actor generation/cancel publication and custom Provider
concretization are outstanding. This slice must not be called whole-runtime
closure or native refinement of all =ActorRound.tla= actions.

** Paper obligations mapped to this slice

[[https://thomas.gilray.org/pdf/seamless-deductive.pdf][A22]], §4, printed pp.82–83, derives SCC dependency ordering and partitions
new/delta/total before semi-naive traversal. Frozen round views and the complete
merge barrier preserve that separation. This implementation still schedules the
existing stratum, not the paper's SCC DAG independently; SCC scheduling therefore
remains an explicit next obligation.

[[https://kmicinski.com/assets/byods.pdf][B23]], §3.3, printed pp.264:8–9, requires total/delta concretizations to expose
all implied facts; a new implied tuple may not bypass delta. Canonical Set is the
first admitted parallel subset. Custom Provider/lattice paths retain serial
execution until their concretization and ordering contracts have a native
worker-safe representation. Plain concurrent tuple union does not establish it.

** Formal/evidence boundary

=RoundAdmission.lean= now distinguishes queued admission from assigned work:
stop preserves assigned work, assigned membership forbids return, and terminal
ack removes that task. Naturals remain unbounded. =ActorRoundCredits.tla= checks
assignment capacity, one outstanding credit per worker and return only after
drain at exploration capacities 1/2/3. An injected early return must produce a
=CompleteReturn= counterexample. These are safety abstractions, without scheduler
fairness, arbitrary callback termination or a proven Scheme/VM refinement.

The native Suite covers real two-worker rendezvous; multi-batch order; stop and
join after merge failure; non-emitting cancellation; recursive graph truth for
1/2/4 workers (including an indexed 33-edge chain); independent candidates at
each frozen toy round; unchanged callback traces; unique-row budgets and private
caller mailbox preservation. =docs/evidence/scheme-actor-round-20261005/receipt.json=
binds the qualified source and verification results. No speedup, multicore VM
scaling or model accuracy gain is inferred from worker count. Model calls: 0;
MRR Rust integration remains deferred.
