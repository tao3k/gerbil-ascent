* Architecture
The weighted rectangle view now carries a private final specialization of the
checked/admitted visitor protocol. Selected materialization uses the same key
admission and descriptor index, then expands each selected Cartesian product
directly into an invocation-owned =with-list-builder=. The product loop uses
Gerbil pattern matching and a scoped =defrule=; tuple construction stays standard
=list=. This removes the per-row callback while preserving descriptor and member
order. Generic and custom visitors retain their callback contract; one-argument
complete export retains its custom exporter. The public view structure is unchanged.

The design follows Gerbil's =std/list/list-builder.ss= owned head/tail collector
and =std/cache.ss= private final specialization. Frozen axes are borrowed; public
tuples and outer spines are fresh. There is no view cursor, tuple cache or retained
materialization. Large complete answers still require allocation proportional to
their public row count.

* Library timeout root cause
The failed direct =gxi build.ss= invocation omitted =GERBIL_BUILD_CORES=.
The installed Gerbil =std/make= defaults that variable to zero and disables
parallel compilation. =just build= already supplies the native machine count.
For a direct build, explicitly supply that upstream variable, for example:

#+begin_src sh
GERBIL_BUILD_CORES="$(getconf _NPROCESSORS_ONLN 2>/dev/null || getconf NPROCESSORS_ONLN)" gxi build.ss
#+end_src

On this Darwin host the native count is 12. The corrected cold production build
passes in 103.64/120 seconds; package/API pass in 0.94/15 and 2.54/45 seconds.
The active Homebrew OpenSSL search path is supplied with normal linker settings.
Earlier missing-library and serial-timeout logs remain failed records. No timeout
budget, source currentness check or test was weakened, and no Gerbil/Gambit source
was rebuilt. These local receipts do not qualify downstream consumers or a
portable wheel; remote exact-commit CI is a separate gate.
