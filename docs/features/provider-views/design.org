* Provider-owned relation views: architecture review (2026-10-07)
:PROPERTIES:
:CUSTOM_ID: provider-owned-views
:END:

** Finding and source boundary

This review reads implementation =93e81c1c3645197578073fd5481bf7195f16fd0b=.
It reopens Provider concretization sections 3.3, 4 and 5.1 and higher-order change sections 6.3 and 7. The
following design is a proposal; no relation-view implementation, new theorem,
Quint trace refinement or measured benefit is delivered by this review.

Provider concretization section 4 queries relation representations through logical indexes and
iterators. Section 3.3 requires total/delta coverage of the joined concrete
relation and inclusion of every newly implied fact in delta. Section 5.1's
space argument relies on retaining equivalence classes without retaining every
pair. These premises explain why a compressed private kernel alone cannot
supply the paper's whole-engine space result.

The native implementation has four concrete materialization seams:

| Owner | Current action | Consequence for compressed storage |
|-------+----------------+------------------------------------|
| [[file:../../../table/storage.ss][storage dispatch]] | =.extend-rows= returns a proper list; custom output is checked and copied | An implicit frontier is expanded before the evaluator consumes it |
| [[file:../../../program/initialization.ss][source initialization]] / [[file:../../../program/admission.ss][row admission]] | Every admitted expansion enters =all= and =present=; =delta= initially shares =all= | Provider compression does not remove engine row or membership retention |
| [[file:../../../program/evaluate.ss][evaluation]] | Derived and appended expansions update row buffers, sizes, membership and index versions | Changing only initialization cannot remove later materialization |
| [[file:../../../program/result.ss][result publication]] | Promises capture persistent row roots and defer their reversal; size observation forces those rows | Lazy ordering is not a lazy concretization of Provider state |

For a completed strongly connected active domain of n nodes, the UF view has
n squared concrete pairs. The engine retains those pairs even when the private
Provider has one SCC. This is a code-derived representation bound, not a heap
measurement. Outputting all pairs also takes at least n squared enumeration
steps; changing internal storage cannot remove that output cost. A sparse query
and a full result export must therefore be separate measurement conditions.

** Proposed ownership and semantic contract

A relation owner should retain a committed representation and issue immutable
views for the compiler's actual lookup requirements. Each view binds the
relation identity, source generation, representation revision and total/delta
lane. All keyed and full enumerators for that view must denote the same concrete
relation. Iterator progress belongs to an invocation, never to a shared mutable
cursor. The existing physical index receiver remains appropriate for explicit
Set rows; it cannot gain compressed semantics by omitting rows from its supplied
snapshot. That would violate its current complete-lookup admission contract.

For one completed positive cut, let O be the old concrete relation and N the
next concrete relation, with O contained in N. Require total union delta to
represent N, and require delta to include N minus O. Exact delta is the preferred
built-in contract because current graph kernels already satisfy it. Provider concretization permits
some overlap; any future overlapping view must preserve authoritative head
deduplication and must not count overlapping enumeration as distinct facts.
Initial evaluation still needs full seed visibility, including empty-body
rules. Returning only injected edges does not satisfy this contract.

A UF frontier may be represented by component-member rectangles rather than a
list of pairs. A rectangle must retain the member snapshots from its own cut.
Closing a cursor over mutable parent links or current root membership is unsafe:
a later merge can change the meaning of an outstanding delta or old result.
Overlapping rectangles need either a proved disjoint partition or deduplication
with an explicitly accounted space cost. Compression of delta is therefore a
separate obligation from compression of total storage.

Keep logical fact limits distinct from physical allocation. A single compressed
rectangle may imply many facts; its small descriptor cannot bypass the existing
logical limit. Preflight must compute its exact new cardinality before mutation.
Source duplicates retain their existing input-count semantics. Derived facts
retain unique admission semantics. Changing those observable budget rules would
require a separate contract decision, not an incidental iterator optimization.

** Actors, failure and observation

Use one mutation owner per relation representation initially. Pure consumers
may receive frozen views through the existing actor scheduling path; each
consumer gets its own iterator. Readiness and reply credits must bind the view
revision as well as the existing work identity. Concurrent graph mutation is a
later capability requiring its own publication protocol and lawful Provider
implementation; Scheme green threads alone do not make mutable graph state safe.

Cancellation must drain users of a staged view before its backing state can be
retired. Failure cannot publish some new rows with old membership or sizes.
Source replay remains the recovery authority for a poisoned owner. Rebuilding
from a materialized closure would turn derived facts into sources. A published
result must retain a frozen representation or an owned snapshot independently
of later merges, replacement and actor cancellation. Full row export remains
explicitly materializing; keyed observations should not force that export.

higher-order change's function-change translation has a different obligation: changes depend on
both a discrete base argument and its change. A compressed relation delta is
not a function derivative. Keep the higher-order descriptor/compiler bridge
separate while reusing only the established typed algebra where its premises
are met.

** One implementation sequence and exit gates

| Stage | Concrete deliverable | Required discriminator |
|-------+----------------------+------------------------|
| Representation boundary | Private relation-view carrier and explicit Set implementation; compiler metadata chooses keyed/full reads | Same rows, duplicate/order contract, budgets and errors as the current explicit path |
| Built-in compressed instance | UF frozen total views and exact rectangle delta with separate cardinality | Every insertion prefix against independent reachability; bridge joins, repeated atoms, explicit self inputs and grouped isolation |
| Evaluator and publication | Initialization, derived admission, append, indexes, result ownership and recovery consume the same view contract | Old result after SCC merge/replacement; exact-budget refusal/retry; interrupted publication; no hidden fallback retaining all UF pairs |
| Formal correspondence | Lean enumeration/key filtering and rectangle partition/cardinality connect to existing frontier and indexed iteration laws | Native decoding/representation premises remain explicit; tests and axiom reports belong under =Tests/= |
| Temporal correspondence | Quint view revision, reader retirement, stale reply, cancel/drain and staged publication actions | Mutations for mutable old views, early retirement and partial publication must fail; no semantic generation maximum |
| Benefit acceptance | Matched current explicit engine versus compressed engine, on identical logical inputs and budgets | Sparse keyed query and full export measured separately; include DAG/cycle, grouped joins, retained updates, peak live memory, allocation and time |

Implement the representation boundary and one UF instance together before
broadening custom Provider or lattice concurrency. Existing semantic tests stay
as controls throughout the migration. Acceptance requires both exact observations
and measured whole-engine cost; neither additional abstract theorems nor private
component counts alone closes this architecture gate.

** One production path

=core/relation-view.ss= supplies immutable relation identity, source generation,
representation revision, total/delta lane, logical cardinality, keyed/full
visitation and membership. Invocation-local visitors own traversal progress.
Explicit snapshots detach public list and row spines and retain duplicate order.
Nested field values retain the existing stable-value premise.

=table/trrel-uf.ss= freezes copied component-member spines and component reach
rectangles. Captured views contain no mutable parent pointers or reach tables.
Exact insertion delta captures the pre-merge member lists; missing rectangles
are disjoint, and their Cartesian sizes are counted before mutation. The old
explicit kernel extension still exports its original ordered frontier.

=program/view-state.ss= coordinates staged graph admission and publication of
frozen total/delta, logical sizes and representation revision. Initialization,
derived heads, append, private index dispatch, size observation and retained
results consume this representation. No expanded UF tuple membership or tuple
index is installed on this path. Compiled slot consumers bind the captured
prefix/from/to fields directly, avoiding one temporary Cartesian row per join
candidate. General row consumers retain the ordinary detached row visitor; both
interfaces traverse the same rectangles and keyed member selection. Zero logical
frontiers do not add retained union wrappers. Full =rows-of= export replays frozen injections and allocates public rows on
demand. Result size observation reads cached logical cardinality.

The compressed path is admitted for the exact built-in UF storage and canonical
hash index. Custom storage/index receivers continue using their checked explicit
protocol. This is a private representation seam; it does not publish a new
extensible Provider API. Explicit Set execution keeps its direct row loop and
existing physical index receiver. Component scheduling and closure reuse retain
their Set eligibility restrictions.

Pure actor tasks can read frozen UF cuts. The fresh round identity contains the
frozen total/delta vectors; task/worker assignments and reply credits use that
identity. The coordinator drains readers before committing staged owners.
Cancellation and failure preserve existing drain and source-replay behavior.
Callbacks, custom Providers and lattices retain serial eligibility rules.

** Contracts and limits

UF denotes a relation of facts. Engine visitors follow the captured component
rectangles; explicit Set occurrence order and the UF kernel frontier order are
retained. Public UF export replays a frozen injection journal, with separate
source/append and derived-round orientation. That journal stores injected rows,
not closure pairs or frontier rectangles. It is distinct from authoritative
Session source recovery. Old results retain their own journal root. Tests check
exact legacy public order for matched source, append and derived injections,
and compare logical facts for actor and repeated-join execution. Pure canonical
programs can change internal operational emission order. Programs containing
callbacks, field predicates, custom receivers or lattice joins now use ordered
total/delta expansion across every rule, including otherwise pure producers.
Matched fixtures check callback/key-expression traces and first failures against
the explicit evaluator. They establish bounded correspondence; a universal
callback-trace refinement theorem remains open.

Logical input/output/derived limits remain independent of descriptor counts.
Budget rejection precedes graph mutation; later callback failures quarantine the
staged owner and require source reconstruction. Old result cuts survive merge,
source replacement and failed admission. No timeout or generation ceiling is
introduced.

DAG reachability and exact frontier descriptors can remain quadratic. Bound
coordinate selection filters captured blocks before creating rows. Frozen totals
own coordinate routing buckets when bound variables can request multiple keys;
buckets retain member spines and descriptor references.
Indexed lookups choose the smallest bucket and retain captured descriptor order. Delta
frontiers still scan their descriptors. Member selection within a component is
linear and multi-bucket results require ordering; this is not an asymptotically
optimal keyed UF index. Structural
observation reports total member cells plus rectangle descriptors, excluding
closure/header/routing/index/journal/engine costs. It is not a byte or peak-memory
measurement. Derived injection journals can themselves be quadratic on dense
programs; replay allocates a temporary UF owner and every exported pair, so full
ordered export is a separate measured cost.
Full export must still emit every logical pair. Native tests establish bounded
correspondence; the separate Lean/Quint thread owns formal view and lifecycle
refinement, and its obligations are not closed by these tests.

** Acceptance sequence

The five implementation stages are one representation change: explicit carrier,
UF total/delta, evaluator/publication/recovery, actor consumption, then matched
whole-engine qualification. Qualification freezes all Scheme sources including
new files, runs the native regression suite and policy gate, and records the
comparison evaluator's identity. Sparse observation and full export are separate
conditions. Warmed alternating pairs cover DAG/cycle, grouped repeated joins and
retained updates. CPU, elapsed time, cumulative allocation and sampled post-GC
live memory have separate evidence boundaries. A sampled post-GC peak is not a
continuous process high-water mark. Negative measurements remain in the receipt.

* Component ownership, frontier union and shared readers (2026-10-07)

This follow-up is based on =9fd161f=, which carries frozen UF views through the
engine. Earlier migration proposals describe their stated revisions; the current
engine already admits canonical frozen UF execution. This unit strengthens its
mathematical and concurrency obligations, without changing Scheme execution.

** Component plan refinement

=ProviderRectangles.Components= represents captured member lists, their owner
mapping, ownership consistency and member uniqueness. =component_pair_owned=
recovers the ordered root pair of every emitted tuple. Distinct root pairs
therefore imply =component_plan_separate=; together with unique members they
imply =component_plan_nodup=. =component_plan_uniform= derives the old-membership
uniformity needed for whole-rectangle selection. =component_plan_reach_uniform=
connects that condition to =TransitiveComponents.quotient_exact= under the SCC
root-equivalence and transitivity premises.

Component membership and distinct root pairs are separate checks. The new Lean
negative examples show repeated root-pair descriptors and repeated members
both inflate cardinality despite preserving membership. Native roots/member
extraction and completeness of the candidate root-pair list remain source
refinement obligations; this record does not make the mutable Scheme parent
map a Lean value or prove its extraction automatically.

** Additive frontier union

=core/relation-view.ss= states that =gerbil-ascent-view-union= requires disjoint
facts; it is not a deduplicating Set union. Per-insertion uniqueness alone does
not justify this across an accumulated delta. =successive_frontiers_disjoint=
derives disjointness from consecutive exact frontiers through the intermediate
relation. =successive_union_exact= proves that concatenation is the exact
old-to-final frontier under both monotone steps; =successive_union_nodup=
preserves unique enumeration. Existing =count_exact= then makes additive counts
sound for these frontiers. Source occurrence counting remains a separate rule.

** Shared-reader defect discovery

=ReaderLifetime= now supports a parameterized finite =Readers= set. Each reader
has its own captured rows, current-compatibility bit, semantic validity bit and
cancellation status. =credits= counts active reader ownership, not batch/row
backpressure acknowledgements. Every release removes exactly one owner; backing
retirement is allowed only after the last owner releases. Every publication
invalidates active reads regardless of whether row content is equal.

The accepted two-reader model uses per-reader weak fairness of =Finish(r)=.
There is no numeric generation variable, generation maximum, state/action
constraint or timer. The same global completion fairness passes the one-reader
control but fails the two-reader control: one reader can remain canceled forever
while the other repeatedly borrows and completes. This is a design counterexample
to inferring individual progress from aggregate progress, not evidence that the
current Scheme actor pool has this defect.

Additional faulty variants are checked independently: =retire= makes backing
inaccessible when the first of two readers exits; =credit= releases a reader
without decrementing ownership; =aba= treats matching row contents as revision
compatibility and accepts an invalid reply. Safety controls require exit 12 and
the expected invariant; liveness controls require exit 13 and a temporal
violation. Concrete TLC state traces are recorded as structured JSON witnesses.

** Current implementation correspondence and limits

The native round owns a fresh cut identity, tracks active worker/task assignments,
refuses stale reply identities, and drains/join workers before owner publication.
Those mechanisms are the correspondence points for =valid=, ownership and last
release. Captured view spines are separate from mutable UF nodes, with nested
fields retaining the stable-value premise. =alive= abstracts accessibility of all
captured backing, not byte accounting or a native explicit reference-count API.
The model allows more publish/read interleavings than the current drain-before-
commit coordinator; injected failures are prospective protocol discriminators.

The abstraction does not prove Gambit scheduling fairness, termination of host
callbacks, multi-key actor source extraction or journal replay ordering. Lean
owns component/fact algebra; Quint owns reader lifecycle and publication. Existing
native controls and cost receipts remain separate evidence, including negative
full-export and grouped-join measurements.

* Group encoding and frozen journal correspondence (2026-10-07)

The next representation boundary is now qualified separately from SCC merging.
The native two-column carrier uses no prefix; the three-column carrier owns one
group value. The state key is =(width, group)=, so an ungrouped row and a row
in the =#f= group must not alias. =ProviderEncoding.encode= models these cases
as =Option.none= and =Option.some group= and emits ordinary two/three-element
lists. =decode_encode= and =encode_injective= derive reversible encoding and
=scopes_disjoint= separation.
=encoded_member=, =encoded_nodup= and =encoded_count= preserve membership,
unique-fact counts and budgets. =root_plan_encoded_exact= composes this boundary
with the constructed root/member frontier proof; it assumes component coverage
and SCC equivalence, not an exact-candidate or exact-frontier premise.

The presentation journal is a separate Library contract. BYODS Section 3.3,
Theorem 3.5 requires new implied facts to enter delta before consumers can miss
them; it does not prescribe Scheme export order. =orient_member=,
=orient_count= and =orient_nodup= prove that reversing a derived batch changes
presentation while preserving concretization, count and uniqueness.
=program/view-state.ss= stores detached event rows newest first, replays events
chronologically, and reverses the complete derived batch rather than reversing
each input's frontier independently. Source/append batches keep arrival order.
An export cut captures the old event list; a later publication must not substitute
the owner's latest journal. This journal is not the authoritative source log and
is not a crash-recovery, arbitrary deletion or arbitrary lattice proof.

=ProviderReplay= models private staging, commit, refusal and one held export cut.
Its =Step= constructs the new scope-local closure from current predecessor and
successor reach and endpoint diagonals. The independent =Expected= input closure
appears only in =PublishedExact=. =Replay= reconstructs a newest-first journal;
=JournalExact=, =OrderExact=, =HeldExact= and =RefusalAtomic= check completeness,
orientation, stable cuts and rejected work. Six seeded faults merge scopes,
publish a staged event early, omit an event, erase derived kind, read the latest
journal for an old cut or append on refusal. Each must fail the named invariant
with TLC exit 12. The correct model explores 23,972 distinct states.

The configuration has two nodes and two scope identities (ungrouped and a false
group); each of four non-self input edges can be admitted once. This is an
explicit finite exploration population, not a semantic generation or history
limit. Provider enumeration is abstracted by a deterministic row order; the
model does not prove the precise UF iteration order or multi-injection batching.
Native tests supply those discriminators using literal expected public exports.
One cut is explored here; multi-reader lifetimes remain owned by =ProviderViews=.

Native qualification now has nine cases. It retains all 512 graphs and adds:
- Simultaneous ungrouped, =#f= and =#t= rows; rejection and a cycle in =#f=
  preserve the other scopes and the old cut (six nodes, five SCCs, two arcs).
- Source/derived/source journal replay with a later SCC merge; public ordering
  and old cut survive caller input and returned row-spine mutation.
- A derived batch with two inputs; all seven new rows reverse as one batch.

The ordered assertions invoke =gerbil-ascent-view-rows=, which uses the journal
export callback. The generic row visitor intentionally uses descriptor order;
its order is not the public presentation contract. An initial test incorrectly
used that visitor, and failed despite identical facts; the test was corrected

in these controls. The negative model traces are design discriminators, not

* Export and grouped-consumer cost repair (2026-10-07)

** Ordered export without a second retained owner

=program/view-replay.ss= reconstructs only an invocation-local ordered cut.
Each width/group scope admits at most 256 journal injections into the packed
path, bounding its vertex population by 512 and temporary flags by 32 KiB.
Larger histories retain the existing adjacency-based UF replay. This dispatch
bound is an implementation choice; it is not a convergence or semantic limit.
Neither replay flags nor expanded output rows become part of a frozen view.

The packed path stores first-observed vertex values and reproduces UF root
and component member order. Admission counts a whole injection before writing
its missing component blocks. Component blocks partition the matrix by
pre-merge roots, so writing one missing block cannot invalidate the remaining
block tests. SCC members merge only after writing. Source and derived batches
retain their distinct legacy total/delta orientations. Output and batch list
spines are private to the invocation, permitting destructive reversal without
mutating journal histories, component members or held results.

Native controls compare exact replay sequences with the UF frontier reference
for all 512 three-node graph masks, opposite injection orders, derived batches,
false/true groups and delta cut boundaries. Separate controls reject split
frontiers and insufficient budgets, and exercise both sides of the packed
dispatch boundary. These are executable representation discriminators; they
do not establish a universal native matrix/hash extraction theorem.

** Synchronous field traversal and captured identities

Pure canonical plans can consume indexed frozen fields synchronously through
their engine or worker's private index owner. This avoids allocating a row
stream for each repeated lookup. Declined access falls through to existing
row lookup; candidate checkpoints and repeated-variable matching remain in
the compiled runner. Ordered callbacks, custom receivers and field checks use
the existing observable-order path.

Routing buckets retain descriptor references and stored singleton member
spines. Equal query objects select the actual captured member in each group.
They do not replace it with the caller's equal query object. Parts traversal
uses direct member loops instead of a fresh callback per left member. Routing
metadata contains no Cartesian pair tuples and is constructed before view
publication. Native controls compare streamed and synchronous field access
for reordered/repeated columns, missing keys and captured host-object identity.

Admitted compiled columns and the key builder establish nonnegative range,
arity and key-length checks before repeated access. The private canonical
index owner passes that admission to built-in parts visitors; ordinary public
visitors still validate arbitrary columns/keys and per-block widths. Both
visitor modes are compared across the complete valid-key control corpus.

Common pure coordinate layouts compile their slot actions once. The exact
canonical selected path can omit a prior-bound comparison only when that
coordinate is present in the compiled key with the same slot action. Generic
row access, including overselected custom candidates, keeps the full matcher.
Controls compare exact selected parts, ordinary selected rows and deliberately
overselected rows; all must admit the same matching outputs. Repeated-variable
failures, false values and rejected-frame checks retain independent controls.

The immutable parts-visitor record separates checked public access from
compiled canonical access with fixed argument protocols. Single-descriptor
prefix routing drops only the group constraint already established by that
bucket; repeated constraints and multi-descriptor buckets retain their checks.
Terminal parts outputs carry a compiled slot getter with each head. Projection
shares the same output identities and getters, preserving duplicate/multiple
head order while avoiding repeated head-action interpretation.
