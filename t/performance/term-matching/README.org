* Matched native A/B

The ASP Scheme benchmark API runs 50 alternating old/new pairs. Each call
binds candidate rows, constructs heads and consumes all results; the checksum
must equal both the baseline and an independent input sum. Process CPU and
allocated bytes are measured with GC outside each measured call. No native
build or qualification overlaps the timing lanes.

All scenarios were declared regression controls before measurement:
CPU <= 110% baseline + 20 microseconds; allocation <= 110% + 4096 bytes.
There is no predeclared speedup target for this expression refactor.

| Scenario | Iterations | Old CPU us | New CPU us | Old bytes | New bytes |

All three gates passed. The pattern control is about 3.5% slower in this run;
allocation is unchanged. These results support retaining the abstraction within
the declared regression budget, not a speedup or whole-solve performance claim.
