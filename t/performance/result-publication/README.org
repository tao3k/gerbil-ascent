#+TITLE: Demand-driven persistent result publication

* One publication lifecycle

Retained engines publish an independent vector of row promises. Each promise
closes only its persistent row root; forcing it creates the ordered public list.
Unchanged roots share the same promise across publications. Unread intermediate
snapshots avoid copying entire relations, and demanded unchanged relations reuse
their ordered list. A new engine owns a new cache; no global cache is introduced.

This delays row-header materialization, not derivation, validation, storage
expansion, lattice admission or budget enforcement. The public rows-of and
relation-sizes methods return the same ordinary lists/counts and memoize the
row view on demand. Changed roots use new promises. Engine commits prepend new
owned prefixes or replace lattice roots, so historical promises remain stable.
Published result vectors and private mutable cache vectors are distinct.

One-shot evaluation retains its original eager representation and object
construction. The existing private invocation argument carries either the
one-shot deadline or a retained context with deadline/root/promise vectors.
This avoids introducing an additional captured engine variable or run parameter
into the one-shot path. Timeout validation and round-boundary admission remain
unchanged. A normal retained run resets its context deadline before resuming.

* Complete-output measurement

The probe reuses the nine preceding execution-workspace workloads and adds a
complete retained workload with 4096 static facts and eight appends to a second
relation. Every measured call reads all relations of its final result inside
the timer. Both old and new therefore pay final row materialization and name
projection before the timing sample ends; semantic checks remain outside timing.
These consumption costs were outside the earlier probes' timers, so timing and
allocation numbers are not transferred from those earlier receipts.

Seven one-shot workloads are non-regression controls requiring non-increasing
median allocation. The two retained append workloads and the new retained-static
workload require lower median allocation and at least 900 strict paired byte
wins. This primary/control classification is specific to retained publication;
the old benchmark recipes and original SS classifications are unchanged.

Each final run uses 20 warmups and 1000 alternating old/new pairs, identical
inputs and expected outcomes, Gambit cumulative allocation counter slot 7,
and no forced per-sample GC. Timing claims require a lower median and at least
900 strict paired time wins in both final runs. Raw samples retain p95 and all
wins; no uniform tail-latency claim follows from a median improvement.

* Functional publication checks

Five new native Cases cover persistent historical snapshots across 16 updates;
unchanged-row sharing, duplicate append and source replacement; independent
engines sharing analysis; exact unknown-relation errors and rule-time metadata;
and late demand of a timed-out partial snapshot after resuming to completion.
The earlier focused run passed all five Cases. The final full suite checks
the corrected shared-analysis fixture and requires all Case completions and
native module, harness and final OK markers, rejecting native exit-zero errors.

* Rejected attempts and cause boundary

A retention probe on the original engine drops the weakly observed index after
GC while its result remains readable. It does not reproduce an index leak;
this change does not claim to fix one. The installed Case profile's periodic
sampler defaults to collect-before-sample? false; that sampler is not evidence
of periodic forced GC. ASP itself reconditions groups outside timed attempts,
and automatic GC remains part of an attempt. No profile or dependency changes.

The first source/test fixtures had missing closing parentheses; their failed
native logs remain. Moving result-object construction outside the evaluator
increased one-shot allocation and was rejected. An eager cache in the engine
scope added captured-variable cost; a separate run parameter still added cost.
Those samples remain diagnostic failures, excluded from the final claims.
The first passing representation exceeded the production module line limit.
Snapshot query helpers were moved into the publication module; pre-extraction
receipts remain separate and are excluded from exact final-source claims.
The final representation uses the existing private invocation context, retains
one-shot construction, and makes retained row views demand-driven.
