The Graph support index is not POO's complete indexing API. The correlated
=table-indexes= API accepts declared key backends, pure projections and
unique/grouped recipes. Its =.apply-delta= checks every primary expectation
before atomically retracting old memberships and inserting final memberships;
=.index-ref/opt=, =.index-fold= and deferred index cursors retain source
stamps and origin refusal. This broader API must be evaluated through the
existing ASCENT Index Provider; a symbol-only conclusion about all POO
indices would be incorrect.

The narrower support index's changed-key comparator is
=%compare-symbol-identity=. A relation key can be an integer, tuple, complex
value or a structural projection. Its =equal?=/occurrence semantics cannot be
changed to symbol identity by replacing all hash tables with this index.
The existing =table/provider.ss= already supplies the POO receiver axis and
validated build/extend/lookup boundary. Improve physical implementations
through that owner, rather than adding a second provider protocol.

POO's report =doc/graph-benchmark.org= records a million-owner owned edit at
0.061--0.096 ms CPU. That window checks one owner, opens two search buckets,
writes two ranks, copies no complete index and enumerates no output order.
Cold preparation and explicit output are separate windows. This is evidence
for affected-only work and retained ownership; it is not a universal hash,
full SCC, cold graph or complete million-row export timing. Those are upstream
reported measurements, not reproduced ASCENT performance acceptance.

* Actual redundant work in ASCENT

=program/view-state.ss:gerbil-ascent-view-export-cut= binds an immutable view
and detached injection events. Each ordinary export calls =export-events=;
the bounded journal route calls
=program/view-replay.ss:gerbil-ascent-small-journal-export= again.
=prepare= rebuilds population maps, node/value slots and a bounded V-squared
bitmap. Insertion reconstructs predecessor/successor selections, missing
component products and SCC merges before producing the same ordered cut.
The direct integer projection also enters that replay route.

This is repeated graph preparation on repeated reads, not a proof that a
single hash probe is slow. The existing UF owner already maintains forward
and predecessor reachability in =table/trrel-uf.ss= and freezes disjoint
component rectangles. However, its final rectangles alone do not encode the
journal's observable insertion/derived-round order. Replacing journal replay
with arbitrary SCC order would therefore change the existing interface.

The migrated terminal optimization avoids writes that have no later reader,
and uses population counts for the full singleton terminal mask. It does not
remove nonterminal reconstruction. The numeric writer removes intermediate
row spines on its supported path; it does not establish the requested full
production latency target. Neither is the final algorithmic solution.

GraphAr is a storage/interchange format. Its adjacency representation is
relevant; this does not call it a general query optimizer. Relational joins
are represented by query hypergraphs, while SCCs concern directed graphs.
Do not collapse these different algorithmic problems into one Graph API.

* Next implementation boundary

Capture a private ordered factorized export graph from the admitted cut,
retaining products/concatenations and per-derived-event reversal. It must not
retain live UF parents, mutable reach tables or caller-owned row spines.
Capture has an explicit capacity limit and an exact fallback. Charge its
first read/capture, retained representation, invalidation and full output.
A public ordinary =rows-of= still returns independently owned ordinary rows;
a typed request may write directly into an owned buffer. No full tuple cache,
user DSL compilation, new loader or cached admission is introduced.

The implementation must preserve duplicates, column order, empty trailing
events, grouped relation keys, delta slicing and the source generation.
Keep cancellation/publication checkpoints and existing output resource
checks; no partially captured graph may become an accepted answer. Set
answer equality does not establish provenance equivalence: derivation
identity and alternative supports remain independent obligations.

For the indexed route, sum build and probe costs on one unchanged cut
and compare with the sum of scan costs for those same requests. Identical
result enumeration cancels in the inequality. If a different route
changes enumeration, allocation or GC, measure that difference and
include it in the total. An incremental route may pay an edit instead
of a rebuild only after its cache/version correspondence is established.
The theorem gives a decision rule with supplied costs. It chooses no
cardinality cutoff or default route by itself.

Maintain two sets of quantities. Count semantic work as admitted delta
rows, prefix firings, index builds/extends/probes, captured descriptors,
emitted cells, allocated bytes and collector renewals. Time each
relevant phase over the same sample and separate GC wall from the other
elapsed intervals. Record the source revision, product hashes, sample
ordinal, request, generation, output cardinality, and resource limits.
Replay the aligned bounds and exact percentile in Lean. Compare complete
results and refusal behavior using the existing native Test cases.
Work counts support a claim about the algorithm. The measured time and
phase alignment support the wall-clock claim.

** Joint cost budget for choosing an application

For a prepared complete-list batch, bound the maximum GC saving and the
maximum outside-GC saving independently. For each matched observation,
subtract the two allowances from their respective measured durations,
clamp each remainder to zero, add them, and deduct the observer skew
allowance once. =candidate_wall_floor_sound= proves this is a floor on
candidate wall time if both saving bounds and the phase correspondence
hold. =candidate_needs_95_joint_budgets= proves that fewer than 95 floors
below 100 ms rules out a strict pass. A surviving floor permits further
qualification. It supplies no upper bound on candidate elapsed time.
