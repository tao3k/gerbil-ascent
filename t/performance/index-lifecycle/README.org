#+TITLE: Complete built-in index lifecycle qualification

* Production scope

The rule engine uses one physical access boundary for index build, incremental
extension and lookup. Only the exact canonical built-in hash provider enters
the trusted path. All other providers retain generic dispatch, lookup result
validation and callback order. Proper-list bucket validation is avoided only
for indexes constructed internally from admitted row snapshots.

Index keys for strictly increasing columns are projected with a single forward
row cursor, replacing repeated list-ref traversal from the row head. The
selection is computed once per build/extension batch. Unordered and duplicate
columns keep the original arbitrary-column projection. Bucket updates use
hash-get/hash-put directly rather than allocating two update closures per row.
Row order, append order, index versioning and the engine's admission boundary
remain intact. No cache, size threshold, fact budget or provider contract changes.

Physical access is in table/access.ss, registered as a production build module;
the evaluator owns versions and relation state. Public provider APIs and source
values retain their existing protocols.

* Frozen reference and evidence boundaries

The reference commit is recorded in baseline.txt. table/funs is an exact source
copy. The reference provider changes only its default export name and physical
algorithm import; its generic provider interface is unchanged. The evaluator
changes export names and relative module imports, and redirects canonical
built-in build/extension calls to that frozen provider through the original
generic dispatcher. This keeps canonical provider identity for engine policy.
Common analysis and positive-rule execution use unchanged shared production
modules. Custom receivers delegate to their existing slots.

verify-reference.py reconstructs and checks these transformations. Both
versions are compiled natively into the same private library; each paired run
records five verified .ssi module paths and source hashes. qualified.sources
also pins the unchanged common modules and production build entrypoints.

* Qualification method

The seven complete-solve workloads retain the previous positive-plan probe's
inputs, golden semantics, 20 warmups, 1000 alternating paired samples and gate
classification. All workloads require non-increasing median allocation; primary
ones require at least 900 strict paired allocation wins. A speed claim requires
lower median time and at least 900 strict time wins in both final runs.
Gambit cumulative process-statistics slot 7 measures allocated bytes. There is
no forced per-sample GC. Samples, p95, win counts and raw receipts are retained.

Four new native Cases check all 256 ordered subsets of eight columns plus
unordered/duplicate columns and exact buckets after extension; crossing the
31/32-row indexing threshold and retaining snapshots; exact build/extend/lookup
traces from a custom superset provider; and the exact malformed-row error.

* Full functional suite and original SS outcome

The exact frozen production source passes 47 modules and 367 native Cases.
collect-suite.py checks complete discovered-module coverage, every native Case,
module and harness completion, final OK and absence of error/overflow markers.
All per-module logs and the suite receipt are retained. Final production policy
checks 40 modules with zero findings and zero errors.

The original uninterrupted SS batch fails its first BYODS trrel time gate.
The continuation executes all 16 unexecuted entries independently, yielding
8 passed and 9 failed entries across the 17-entry inventory. All observed
failures are time-budget errors after the scenario's semantic checks. No
fixture, threshold, sample count, GC profile or heap fence is changed. This
is not complete original SS closure. original-ss-summary.json records each

* Intermediate diagnostics

initial.sexp is excluded from final claims: its baseline adapter called frozen
build/extend functions directly. The final reference retains the original
generic dispatch through a frozen default provider. Initial benchmark input
and classification were unchanged.

focused.log retains a missing closing parenthesis in the new test fixture.
focused-fixed.log ran only two Cases because the last two were accidentally
nested. Both defects were fixed, and focused-complete.log verifies all four
named native Cases, module/harness markers and final OK. The initial policy
rejected an evaluator larger than 1000 lines; extracting the physical boundary
into table/access.ss leaves final production policy with zero findings/errors.
