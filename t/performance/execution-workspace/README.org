#+TITLE: Complete fixed-point execution workspace qualification

* One execution lifecycle change

Baseline =674c68c= already compiled supported complete positive rules into slot
plans. This change addresses the whole fixed-point round loop: pending vectors,
lattice key events, deduplication tables and interpreter/admission closures are
created once per dirty fixed-point invocation and reused across rounds and
strata. Each engine also owns its numeric variable frames and reuses them across
pivots and Session updates. Mutable frames remain outside all shared caches.

This removes allocation proportional to recursive round count, rather than
adding another per-row special case. Empty/clean invocations do not construct
the round workspace. Compiled and generic rules share the same admission and
commit logic, including custom storage and indexes, lattice refinement,
budgets, timeout/resume, stratification and rule timing.

* Lifetime and safety argument

Every admitted slot read follows a fresh write on its candidate path; failed
candidates and later invocations cannot read a stale slot. Immutable analysis
and plan caches retain their original layout. Engine-local active rules alone
carry a seventh slot containing the frame. Distinct engines never share it.

After each nonempty commit, pending vector slots and lattice key events are
cleared and the private deduplication table is reset. Delta keeps the committed
row list, and custom Provider callbacks retain their original all/pending row
spines. No list spine or published snapshot is mutated. Empty commits avoid
redundant clearing. Each invocation's workspace is lexical: exceptions discard
uncommitted workspace automatically; timeout returns only after commit, with
resume position retained. An aborted invocation cannot publish its pending rows
in a later invocation.

* Matched complete workloads

The seven preceding complete-solve workloads remain, with two complete retained
Session workloads added: initialize, append-and-run 16 or 64 times, then check
an independent ordered closure. Each workload has 20 warmups and 1000
alternating old/new pairs. Both use the same heap and no forced per-sample GC.
Allocation uses Gambit process-statistics slot 7 cumulative allocated bytes.
All workloads require non-increasing median allocation; primary workloads also
require at least 900 strict paired byte wins. The preceding timing claim gate
is retained: a lower median and at least 900 strict paired time wins.
