* Completed snapshot rebasing

=SnapshotClosure= proves the pure frame/merge obligation for completed worker
results. Relevance is derived from owned rule bodies and ownership, not an
opaque callback premise. Local iteration respects this frame; merging owned
completed facts into the current database equals current local evaluation,
and snapshot stability yields current closure. Writes by another component
with no read edge derive the frame via =iterate_frame=. Changed predecessor
reads are a negative control, even if the old empty snapshot was stable.
Lean contains no temporal protocol replica. Existing Quint ready/credit models
check terminal delivery and admission; the native concurrent fixture completes
right while left retains an older snapshot and verifies both results survive.
This closes completed-result semantic rebasing under the explicit frame. It
does not prove every native execution trace, arbitrary intermediate chunks,
cancellation or mutable row encoding. See [[file:../../evidence/scheme-snapshot-closure-20261006/receipt.json][source-bound receipt]].


* Batch publication and completed closure

=SnapshotClosure.publish_exact= establishes the Set semantics of incremental
owned batch admission. Chunk boundaries, duplicate candidates and output order
are observationally irrelevant to membership (=publish_ext=). Sound partial
publication follows from local evaluation soundness; it does not imply closure.
Complete terminal membership, including retained seed facts, connects the batch
fold to current local evaluation and stable closure through the prior snapshot
frame theorem. A missing candidate rejects the delivery premise in Lean.
The native 65-candidate/17-value fixture crosses two credit batches and a
terminal tail and checks successor admission after complete owner observation.
Existing Quint credit/terminal controls retain temporal ownership. This closes
batch algebra under candidate origin and complete-delivery premises; native
trace extraction and cancellation semantics remain outstanding. See [[file:../../evidence/scheme-batch-closure-20261006/receipt.json][receipt]].

** Actor Session admission after expression-plan compilation

The 2026-10-06 rebase exposed an admission regression: a compiled positive plan
may now contain callbacks. Plan existence therefore no longer establishes
worker purity. Actor Session admission now uses the explicit
=gerbil-ascent-pure-positive-plan?= predicate, matching component dispatch.
The existing callback-rejection control detects the old behavior. This check
preserves the native boundary required by the actor protocol assumptions.

* Buffered append recovery includes cross-relation index publication (2026-10-07)

At base =85afa3f= the final native control accepted two distinct Set source
rows, then forced a budget-triggered flush. Its custom index cleared its
physical table and raised once. Both the custom-index target and a different
native-index target reported the original append error, then failed the next

classification must include every relation its buffered flush can publish.

buffered Set owner has a canonical hash IndexProvider. Otherwise its existing

programs retain direct append; lattice eager candidates retain their existing
classification. Raw index publication quarantine and physical cache ownership
are unchanged.
