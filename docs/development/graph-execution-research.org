delivery. Each has a different size parameter and a different
correctness obligation.

* Rule SCCs and scheduling

[[https://www.cs.cmu.edu/~cdm/resources/Tarjan1972-sccs.pdf][Tarjan]] partitions a directed graph with linear work in vertices and
edges. ASCENT already has this traversal, using dense IDs and explicit
DFS frames. The [[https://s-arash.github.io/ascent/cc22main-p95-seamless-deductive-inference-via-macros.pdf][Ascent paper]] then combines SCC-local evaluation with
delta, total, and indexed relation access. Graph partition and task
admission are distinct. A low ordinal blocked on a worker can remain
in the owner list while many independent tasks complete. Reexamining
the blocked suffix for each free slot gives quadratic admission work
on a chain beside an independent frontier.

Seed an ordered Gerbil STD priority queue with zero-credit tasks.
The owner consumes credits on distinct outgoing component edges after
the terminal merge and offers a successor when its last credit is
consumed. The queue selects the minimum ready ordinal, preserving the
old first-ready choice for the same completion sequence. Admission
still snapshots the current frontier. Worker checkout, cancellation,
batch credit, terminal merge, and joined return use the same envelope
path. Source-only components are complete before worker admission.

With S scheduled components and E distinct dependency edges,
readiness management uses O(S + E + S log S) work and O(S) queue
storage. These bounds exclude frontier snapshots and evaluation.
=ComponentClosure.lean= checks the final-credit transition and the
equivalence of minimum-ready and first-ready selection in ordinal
order. Ownership across the worker protocol is exercised by Gerbil
cases. The lemmas do not verify the STD heap or the Scheme compiler.

A deterministic native =gerbil test= control holds the root of a
chain in one worker while the other drains independent siblings. It
checks the exact admission sequence and every terminal completion.
The table records predicate calls and process CPU inside the Actor
round on the fixed Gerbil release. It excludes module load and queue
setup. This workload exposes coordinator overhead and does not
measure relational closure latency.

* Fact-graph SCCs and factored transitive closure

[[https://www.cs.ox.ac.uk/people/boris.motik/pubs/hmh18modular-materialisation.pdf][Hu, Motik and Horrocks]] specialize the evaluation of recursive
modules, including transitivity, using a proof obligation for each
module interface. This applies after recognizing the exact positive
binary transitive rule and its seed. It does not apply to arbitrary
rules in a recursive SCC. A fact-graph vertex is a data value and an
edge is an admitted input fact. Internal SCCs can be represented by
vertex ranges and reachability between those ranges can be evaluated
on the condensation DAG.

The core binary closure currently extends each new pair across
its middle vertex's adjacency list, using dense bit rows in a bounded
canonical case and a duplicate check in the general pair frontier.
On a complete directed graph without self edges, the pair frontier
reaches N squared pairs and visits N squared times (N - 1)
extensions. A factored representation for this graph has one
component. Discovery reads N times (N - 1) edges and complete detached
delivery still emits N squared pairs. This family distinguishes skipped
derivations from skipped output. A sparse DAG, a bow-tie with a narrow
cut, and a large SCC with a long sparse tail separate index construction
from propagation and expansion. The dense bit-row case needs its own
comparison. Measure work counts alongside process CPU, P95, and GC.

An isolated native prototype uses the existing binary adjacency and
Tarjan traversal, followed by one union per distinct condensation
edge in reverse topological order. It charges the sum of group
products before expanding the sorted row list. Each arm starts from
the same admitted trie set and produces a full sorted list of encoded
rows. The baseline is =gerbil-ascent-relation-closure-bounded=. The
test also checks the entire list against a closed-form independent
oracle and checks that a one-row-short budget is refused.

The largest fixture consists of 26 complete directed groups with
64 vertices each, joined by 25 forward bridges. On this graph the
current pair frontier visits 90,595,648 extensions, by counting
63 internal outgoing edges for each reachable pair and the separate
bridge extensions. The prototype inspects 104,857 edges in its
condensation pass in addition to its input build and SCC traversal.
It still expands and checks all 1,437,696 output rows. The CPU ratio
was 24.8 on this fixture. Each entry is a native feasibility sample.
This tests a binary kernel, outside the Session query and publication
path. It does not establish production cancellation, provenance,
latency percentiles, or a general speedup across graph shapes.

[[https://www.cs.hut.fi/~enu/thesis.pdf][Nuutila's stack closure and interval representations]] give two
choices for the next stage. Process groups in reverse topological
order, and compute each group's reachable set by adding its direct
successors and unioning their completed sets. Start with exact sparse
sets. Compare interval unions on long chains and on shuffled dense
DAGs where intervals fragment. Count group-level set operations and
stored intervals before expanding member pairs. A keyed reachability
query may also use [[https://www.cs.rpi.edu/~zaki/PaperDir/VLDBJ12.pdf][GRAIL]] labels to reject impossible targets. A positive
label test still requires exact graph search or an exact index. This
filter has no role in the full output-size bound.

Lean checks both directions of the cross-component correspondence and
the criterion for diagonal results. The proofs take exact component
ownership and witnessed cross edges as premises. Integration still
requires validating these premises against the admitted dense graph
and mapping factored rows to versioned evidence. In particular:

- A singleton without a self-loop does not yield a diagonal fact just
  from its component membership. A multi-vertex cycle yields reachable
  diagonals through a nonempty path.
- Charge the same logical unique-row limits before publication even
  when a component product represents many rows. Preserve the order
  of observable failure and cancellation checks.
- Witness expansion needs concrete, version-checked input paths.
  Inter-component reachability alone cannot fill the existing
  provenance payload or establish its completeness.
- Insert-only SCC maintenance, as in [[https://arxiv.org/abs/1105.2397][Haeupler et al.]], applies to
  an admitted insertion stream. A source replacement can remove a
  bridge and split a component. Compare local affected-region rebuild
  with a full fresh or existing grounded rederivation, including
  duplicate supports, last-support removal, and canceled publication.
  [[https://arxiv.org/abs/2203.16684][DBSP]] supplies a distinct alternative for signed changes through
  recursive operators. A trial of affected-region rebuilding would
  not qualify as a DBSP implementation.

Use the same condensed layout to evaluate keyed and full queries
separately. The local POO =strong-components.ss= already has compact
offset and target vectors for traversal. [[https://graphar.apache.org/docs/overview/concepts/][GraphAr]] likewise separates
adjacency offsets from edge properties. Both motivate measuring a
private dense layout with witness edges separate from traversal
offsets. Retain existing Provider semantics and exact version
ownership when changing any physical index layout.

* Cyclic joins and finite choice

[[https://openproceedings.org/2014/conf/icdt/Veldhuizen14.pdf][Leapfrog Triejoin]] intersects ordered key ranges across a join,
avoiding the cost of materializing a large binary intermediate on
skewed cyclic rules. Compare a triangle or multiway rule with a large
binary prefix and few answers against the current indexed,
left-to-right delta joins. An admissible optimizer needs stable
equality and ordering for every participating key. Prove that each
delta occurrence contributes exactly the sanctioned substitutions
and preserve the rule's exception and provenance behavior.

[[https://arxiv.org/abs/2405.19040][Finite-choice logic programming]] separates deterministic deductions
from branching decisions. The local Dusa forward engine stores an
attribute's known or possible values and advances the agenda on new
facts or narrowed support. The miniDUSA Racket runtime makes the
search state explicit. Compare those mechanisms against the existing
ASCENT Candidate scheduler for repeated matching and branch-local
support. A finite-choice agenda has different state and certificates
from a positive reachability index.

* Session integration

=gerbil-ascent-open-condensed-actor-session= uses the existing Actor
owner, source replacement, publication and close operations. This
entry selects the condensed view for the admitted two-relation
positive reachability rule and cyclic fixnum data. The existing
Session entry preserves the execution order of its result lists.
The condensed view orders full export by numeric origin and target.
Both entries return independently mutable lists. An unsupported
shape, executor authority, or deadline goes through the existing
evaluator and its budget and observation protocol.

The index owns one admitted source slot, its key-to-ordinal map, the
inverse label vector, exact adjacency buckets, SCC owners and group
reachability masks. The direct build checks the validity and
multiplicity of its input before it can publish a source view.
Traversal walks existing Tarjan frames with Actor cancellation
checkpoints. Group products charge exact logical rows before the view
is published. A refusal goes through the ordinary evaluator so the
public failure and rollback contract is preserved.

The unchanged source slot reuses the index. An append can consume
one delta when its row spine has the previous owned rows as its exact
tail and both endpoints have dense slots. The group update applies
old predecessors of the origin crossed with old successors of the
target, including the endpoints. A cross-edge with a return path
rebuilds because it can merge SCCs. Replacement rebuilds from the
new adjacency so a deleted bridge can split a component. Only the
Session owner installs the index after successful publication.

=closure-witness= searches the same immutable adjacency for one
nonempty path, under a caller-provided edge-inspection budget.
=verify-closure-witness= checks both the exact source-slot identity
and the publication epoch before replaying concrete edges. Old
results can still replay their own witnesses. The path witness is
separate from the general Candidate proof DAG and its evidence
completeness contract.

=ComponentClosure.lean= relates distinct labels and dense ordinals
to keyed lookup, proves the exact single-edge delta, and states the
source-slot and epoch replay condition. These are refinement lemmas
under the stated representation invariants. The native Session
suite checks the actual hash lookup and repeated key coordinates,
delta selection, stale-proof refusal, delete/split, rollback and
independently mutable results against an independent oracle.
The cancellation and close regressions also cover the ordinary
Session while the evaluator is held at its first charged step. The
hold makes the in-flight assertion independent of how quickly a
packed chain reaches completion. The join and supervisory deadlines
are unchanged. Separate state-reply tests exercise abandoned and
queued readers against the shared Session owner.

** Scanning cost by held-root control

The 62.85 percent running-thread sample share above identifies
instructions. It does not identify the objects those instructions
visited. This experiment changes the held roots in separate native
test processes. All processes load the same native benchmark,
declaration and Session objects. An additional step imports the
locked benchmark interface through the same Gerbil expander call as
test discovery. Only that step differs in the metadata control.
No registry entries or files are cleared.

The input control holds zero, one or two of the original million-row
lists. It calls the locked benchmark's native input constructor with
the original offsets. It verifies every retained input row both
before and after collection. The output control uses the locked
affine view exporter to create a separate list with zero, 500,000,
or one million retained rows. The production loop visits ordinals
backwards and prepends each row. Consequently its partial accumulator
is a suffix of the final output, as checked by
=MillionQueryWorkload.projection_accumulator_order=. The 500,000-row
control builds that suffix without holding its own source input.
It matches the contents and cell shape of the accumulator. It does
not recreate the interrupted export's allocation history or stack.

* Indexed double-bound SCC queries

The published condensed view already defines pair membership by
resolving both fixnum labels and testing the destination owner's bit
in the origin owner's reachability mask. The view's target lists
are sorted and unique. With exactly two bindings, one for each
column, filtering the origin's list therefore returns zero or one
row. Use the same membership test for =contains?= and =visit-rows=
on the same captured view. Accept both column orders. Continue the
ordinary visitor for partial or repeated bindings.

The callback can mutate the caller's binding lists. If it does, the
ordinary scan would apply the revised filters to the remaining
targets of the original origin. After direct delivery, detect any
such change and resume the original visitor strictly after the
delivered target. Existing row and field callback modes expose the
same result. The direct branch neither creates a witness nor changes
the published cut, its version, its cancellation checkpoints or its
publication and witness budgets.

ordered result under the existing unique-target and exact-bit
premises. =bound_pair_callback_suffix= gives the suffix selected by
the native resume condition after a callback edit. These checks do
not prove the entire native mask construction or the effects of an
arbitrary Scheme callback.
