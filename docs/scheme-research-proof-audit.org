* Audit decision

At this audit's baseline, the [[file:research/scheme-dsl/index.org][DSL source ledger]] contained eight papers:
A22, F16, H13, F20, S20 and L25 concerned the language/kernel; H18 and
B22 added deletion and incremental-maintenance constraints. Later B23,
FL25 and S24 readings add Provider, physical-plan and nested-fact
questions without extending the audited proof coverage. These are
distinct from the separate
[[file:research/agent-inference/index.org][agent-inference collection]]. The next step is to connect paper assumptions
to admitted Scheme IR and observable transactions. Adding syntax, quoting a
paper or passing an abstract proof is insufficient for design closure.

The current checked subset has a coherent division: Scheme constructs program
values; admission exposes domains, lexical captures and dependencies; the native
core owns evaluation; retained Sessions own source/result publication; bounded
evidence binds a specific program and snapshot. No paper establishes the safety
of arbitrary host closures. Therefore unrestricted callback admission, silent
domain clamping and hidden dependencies are excluded from the checked subset.
Trusted host construction remains outside the proof boundary.

Generation has no maximum in either protocol's =Init/Next/Spec=. It ranges over
=Nat= and can keep increasing. =ExplorationDepth= and =ExplorationBound= exist
only for TLC state-space exploration; configuration values do not limit runtime
or constitute an all-generations theorem. Repeated source cuts are allowed,
so a stale job cannot become current merely because source bytes return to an
earlier value (ABA). Lean publication theorems quantify over all natural-number
generations, but still prove the abstract publication function, not Gerbil.

Safety is not liveness. Neither TLA model claims a solver eventually finishes,
or a transaction eventually wins against continuous competing publication.
A fairness/termination claim needs an explicit scheduling assumption and a
separate proof. Abort preservation is encoded as a required action contract;
model checking does not establish that native exceptions implement it.

Previously GitHub's =formal= job ran Lean only. It now executes the common
[[file:../justfile][Justfile proof gate]], including the TLA models and intentional faults. TLC is
pinned to the official 1.7.4 jar and verified by SHA256. The gate accepts
=ASCENT_TLC_GENERATION_CUTOFF= independently of protocol semantics; GitHub
uses 4, the default exploration configuration uses 2. Counterexample checks
require both TLC's violation exit code and the expected violated property;
parse/tool crashes cannot count as successful fault detection.

** Historical first slice: type representation to semantic height

The existing native formulas are:

- Relation with =d= distinct atoms and arity =a=: tuple universe size =d^a=,
  inhabitant cardinality =2^(d^a)= and rank bound =d^a=.
- Arrow =A -> B=: cardinality upper bound =card(B)^card(A)= and pointwise
  rank bound =card(A) * height(B)=.

Our design decision is to retain these as conservative bounds. For arrows,
=card= counts the full finite function space; it need not be the exact number
of monotone inhabitants. Finite exhaustive enumeration belongs in small native
truth models and semantic proofs; production normalization must continue using
saturating arithmetic rather than allocate the full function space.

The first slice has four connected deliverables, in dependency order:

1. Revalidate the actual exposed type/typed-term graph before height analysis.
   Own admitted domain/row spines and reject malformed arity/domain/children,
   cycles and escaped captures. The relation-operator preflight does not by
   itself validate =relational-type= or =relational-typed-term=.
2. Define the semantic relation/arrow inhabitants and their representation
   relation. Prove tuple-universe completeness and cardinality bounds,
   pointwise order/rank boundedness and strict progress. State scalar equality,
   duplicate elimination and zero-arity empty-tuple conventions explicitly.
3. Discharge =bounded_bottom_least_fixed= premises for this interpretation;
   relate exact semantic bounds to capped formula evaluation. A cap rejection
   is a resource outcome, never a proof of semantic nontermination. A bound on
   iterations does not by itself bound compiler-node expansion: retain the
   independent actual work counter and fail without publishing partial output.
4. Qualify the actual lowering against a Scheme-owned exhaustive truth model
   on tiny signatures, including nested functions and delayed changes at
   unsampled arguments. Publish source identity, proof hashes, complete rows,
   rejection outcomes and original budgets. Neither finite samples nor a
   historical receipt substitutes for the universal semantic theorem.

Exit condition: all four deliverables agree for the explicitly admitted
subset. Typed normalization, concrete rule execution, transaction refinement,
provenance algebras and general benefit keep separate open obligations until
represented and tested. No arbitrary host callback inherits these proofs.

** Concrete interpretation must precede compiler refinement

The next R1 proof should introduce explicit interpretation relations rather
than identify a Scheme list with a Lean finite table by notation:

1. =TypeRep(native-type, shape)=: admission owns the canonical acyclic type
   graph; distinct scalar-domain values and arity determine its tuple universe.
   Specify the admitted scalar equality and duplicate elimination, including
   empty domain / zero arity. The full arrow space supplies a conservative
   cardinality bound; admitted monotone functions are a subset of that space.
2. =ValueRep(shape, native-value, semantic-value)=: rows represent sets of
   tuples; a captured closure represents a function only relative to its typed
   lexical environment. Specify total application on the admitted domain,
   extensional observation and immutable capture obligations. Rejection of an
   escaped domain is distinct from an empty relation.
3. =StepRep(native-work, semantic-state)=: each successful normalization or
   engine step preserves typing and implements the stated semantic operator.
   Prove actual step monotonicity before applying =FiniteHeight= termination;
   its existing bounded-rank theorem assumes this premise. Capped arithmetic
   and actual work counters remain separate resource checks.
4. =ResultRep(native-result, least-model)=: finished public rows equal the
   least closure; unfinished/unsupported/bounded outcomes cannot be promoted
   to a completed result or a complete absence certificate.

Use the existing =DescriptorScope=, =LexicalLowering=, =RecursiveLowering= and
=FiniteHeight= files for these refinements. The immediate delivery is an
explicit scalar/row interpretation and native discrimination of duplicate
atoms, zero arity and captured environments; the compiler proof follows it.
Do not broaden the checked language while these premises remain unconnected.

** Publication has an explicit abstraction boundary

=program/session.ss= maintains pending source logs, committed source logs,
last/committed results and private engine state. Its explicit batch replacement
validates a prospective snapshot and completes the solve before adoption. Its
single-source API deliberately leaves replacement provisional until =run!=;
even a precomputed checked result must respect timed-run round boundaries.
These are different observable contracts and need separate trace refinements.

The [[file:../packages/proofs/lean/SessionPublication.lean][Lean publication contract]] assumes a qualified completed solve and rejects
stale work using a generation premise. The [[file:../packages/proofs/tla/SessionTransaction.tla][TLA transaction model]] has symbolic
source cuts and an external-commit action. The inspected native Session has no
corresponding public generation token or asynchronous commit protocol. A future
refinement must map synchronous clean batch boundaries to abstract snapshots
and pending work, or implement a token if asynchronous work is introduced.
Do not claim that the model already proves a native concurrent Session.
Generation is an unbounded logical natural; TLC exploration depth constrains
model exploration and must not become a runtime admission limit.

The native discriminator is a trace of public observations: fresh recomputation
after each completed batch, unchanged committed observations after rejected
batches, provisional single-source replacement followed by timed/resumed runs,
and frozen old results after subsequent insertions. Abstract failure controls
remain distinct from native failure qualification.

| Change family | Paper premise and present scope | Gate before optimization |
|---------------+---------------------------------+--------------------------|
| Increasing typed change | S20 §4.2 defines =df x dx= relating =f(x)= to =g(y)= when =dx= relates =x= to =y=. Current typed lowering has no such function-change translation | Define the change relation per admitted type and prove simultaneous function/argument application preservation. Tiny tests must include a changed argument and a change visible only at an unsampled input |
| Source withdrawal | H18 keeps recursive and nonrecursive support distinct; recursive counters become useful only after overdeletion. Native Session currently invalidates/rederives affected components; the positive grounded kernel is a separate product | Prove source-only logs, support completeness and founded recovery before replacing component rederivation with grounded maintenance. Keep unrooted-cycle and last-support controls |
| Signed stream change | B22 §4 represents changes with signed weights and derives set operators from Z-set operators. No corresponding circuit algebra is implemented here | Specify accumulation and set distinctness boundaries, then prove correspondence with snapshot solve. Duplicate source occurrences are not automatically signed multiplicities |

The ordered next work is therefore: concrete type/value interpretation;
descriptor and rule-step preservation; separate batch/provisional transaction
refinement; complete support correspondence; then typed changes and measured
benefit. Use native Scheme truth models and the existing proof suite for each
slice. A shared final row set alone does not qualify intermediate identities,
publication behavior, support completeness or cost. Model comprehension and
MRR Rust integration keep their existing later gates.
