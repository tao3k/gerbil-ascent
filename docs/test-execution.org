* Ownership
=gerbil build= owns the production build and =gerbil test= owns ordinary
Suite discovery, module loading and Case execution. =just build= and
=just check-policy= invoke the production build directly; the latter enables
=ASP_GERBIL_SCHEME_POLICY=1=. =just test= and =just test-file= invoke Gerbil's
standard test command, with verdict checks in the recipe. The full ordinary
suite invokes Gerbil once per module to release source expansion contexts; a
single all-source process exhausted the unchanged 1 GiB heap during validation. They do not prepare
an alternate library, fingerprint the toolchain or link a test executable.

=t/native/= contains the separate compiled qualification machinery:
=t/native/qualification.ss= prepares the library and immutable executable
for =just test-native= and =just test-native-suite=. =std/make= owns compilation
and currentness. Native actor scheduling applies only to this explicit gate.
The Python package owns process supervision and model-provider IO; Scheme
=std/test= owns assertions. =t/model/= contains the model study.
There is no project-owned general test runner or forwarding gxtest adapter.

* Compilation and isolation
Explicit native qualification invokes =t/native/qualification.ss= through =gerbil env gxi= so native Gerbil selects the
project dependency environment before resolving build imports. An explicit
=GERBIL_PATH= is retained. Bare =gxi= can miss dependencies installed by
=gerbil deps --install= into the project's =.gerbil/= directory; this was the
first failure in the remote Scheme jobs for commit =53e6691=.

Production and selected =*-test.ss= modules compile through the test entrypoint into
=.cache/ascent/native-library/lib=. Native =gxtest= directly loads the compiled
=.ssi= test module and executes the original exported Suites and Cases.
The compiled library comes before the checkout in =GERBIL_LOADPATH=; otherwise
source modules can be interpreted and invalidate performance comparisons.
The table-expression paired fixture's baseline is compiled alongside production.
=std/make= checks source dependencies on preparation misses. Content receipts
admit reuse of the native executable; they do not replace the production build graph.

A native =std/os/flock= lease protects a complete package invocation. The parallel
module pool finishes before exclusive modules start. Native qualification and
performance commands use the same lease; production builds use Gerbil locks. Children call the private Just recipes without
acquiring a nested lease. Independent invocations therefore cannot contaminate
timed Cases. No standalone scheduler tests are added: validation runs ASCENT's
actual modules and Cases.

Module deadlines and Case budgets are unchanged. Every native test must produce
CASE-OK, MODULE-OK, HARNESS-OK and final OK with a successful process exit.
Failure markers, missing markers, overflows and nonzero exits fail the command.
Pool logs and temporary output stay under ignored =.cache/ascent/=.

* DSL closure discriminator

=just build-dsl-closure= reuses std/make's current production Library and
compiles the seven known exported Suites into =t/model/study.ss='s
AOT entry. It uses std/test directly, including its standard Case verdicts,
MODULE-OK/HARNESS-OK markers and failure propagation. This is a fixed semantic
qualification entry, not a replacement for general gxtest discovery or the
full repository suite. the compiler output-dir option selects the current Library static output
before any older installed ASCENT artifact.

=just check-dsl-closure= checks source/artifact hashes, the seven-module inventory,
heap limit, five-second genuine-output watchdog and the existing 120-second module cap per Suite.
The seven known Suites run in separate serial processes; the five-second idle
limit is unchanged and the total limit matches _test-file. No timer
messages count as progress. Python hashes bytes and supervises the native
process; it owns no Case evaluation, expectation or DSL semantics. A failed
one-shot solve cannot be reclassified as complete by this entry.

The ordinary interpreter entry remains separately measurable. Passing the
AOT gate does not retroactively pass a silent interpreter startup, qualify
remote CI or establish application/model/performance benefit.

* AOT interrupted-build recovery

The AOT entry uses Gerbil's compile-module/compile-exe API with invoke-gsc,
static closure and parallel compilation explicitly enabled. Pending compiler
jobs must drain successfully before byte binding. Output-dir still selects
the current Library. Under the exclusive test lane, it clears only the
lane-owned static cache's .o.lock files left by a terminated process group.
It never clears dependency-prefix locks or the advisory lane lock. All writers
to this cache must use the test lane. The previous executable is removed
before compilation so a no-op or failed build cannot bind an older binary.
The 180-second build, five-second genuine-test-output watchdog and 120-second
module bounds remain unchanged. The recovery receipt records a real abandoned
candidate/reasoning object lock and the subsequent six-Suite qualification.

* Names and executable reuse

The project-owned =t/native/= directory contains compiled artifact qualification. =qualification.ss= prepares explicit compiled qualification,
=native-registry.ss= freezes Suite bindings, =compile-entry.ss= compiles the
entry, =artifact-admission.ss= binds source and executable identities, and
=module-process.ss= validates module process receipts. Model-specific study
and inert response projection belong in =t/model/=, separately from running
ordinary tests. Gerbil's actual =TestHarness= type and =HARNESS-OK= protocol
marker retain their upstream names. Historical JSON evidence retains the
paths and hashes at its recorded commit.

=entry-cache.ss= admits reuse of the last executable for each entry mode
(single module or module pool), under the repository lane lock. Generated entry
content, repository source digests, compiled library inputs, selected build
environment, compiler executable identities and executable bytes must match.
The generated entry's own compiled files are excluded from dependency inputs;
they are covered by its source digest and final executable digest. A missing,
malformed or mismatching receipt forces a rebuild. Failed compilation removes
prior admission before rebuilding; a fresh receipt is published atomically
only after successful compilation and unchanged source, interface and toolchain
checks. Native object and optimizer files are compiler outputs on a miss: the
completed object digests are bound after compilation, then checked on reuse.
The existing lane lock serializes preparation and execution.

This cache retains one executable per entry mode, rather than an unbounded
collection of per-module binaries. Switching the selected module remains a miss. An unchanged focused request
also bypasses the three fresh library-check compiler processes after the
compiled library and requested registry key have passed content admission. It caches
build artifacts only: every invocation still runs all Cases, setup and cleanup,
with the existing deadlines, output supervision and final verdict checks.

* Content admission IO and repeated scans

The coordinator loads its own Scheme source. Its previous Gambit port read loop
made content admission expensive even when no compiler ran: an initial probe using the default user package prefix inventoried
11,375 inputs and took 26.13 seconds on the development host. Upstream compiled
=call-with-file-reader= and =digest-from-reader!= reduced that inventory to
13.84 seconds while retaining SHA256 over every byte and bounded buffers.

A focused cache hit now carries the admitted input snapshot from library
preparation into entry preparation under the same lane lock. Entry generation
and module import do not compile library outputs. The entry source and binary
are still checked against their receipt; source and executable identities are
checked around actual execution. A library miss returns no reusable snapshot;
compilation binds a fresh inventory of completed outputs. This eliminates the
second full inventory on a hit without retaining input snapshots across commands
or using file timestamps as content identity.

=ASP_GERBIL_SCHEME_POLICY=1= enables policy checking. =GERBIL_BUILD_CORES=
controls compilation parallelism. The measured environment inherited 12 build
cores. Accepted project tests use the project dependency prefix; the initial
default-prefix probe failed to resolve its ASP build dependency and is not an
accepted test run. Policy checking is not the measured cache-scan bottleneck and its gate
remains enabled in =check-policy=. The justfile command definitions apply the
MRR environment boundary on macOS, clearing Nix compiler flags and SDK variables
for builds, standard tests and explicit compiled qualification. No manual shell
cleanup is required.

Direct execution of the unchanged six-Case finite-flow native entry took
0.20 seconds and ended in =OK=. This is execution time only, separate from
preparation, content admission and linking. These focused measurements do not
establish a stable whole-CI speedup or explain every earlier long invocation.

* Focused repeated-run observations

The unchanged six-Case finite-flow module took 103.81 seconds before reuse.
The final implementation took 169.47 seconds for its first build, followed by
29.36 and 40.76 seconds for two complete repeated invocations. Both repeats
started zero library-check compiler processes and zero entry compiler/link
processes; all six Cases still ran, including every million-row pair check.
The test module and production semantic sources are byte-identical to the
baseline. These are one baseline and two warm samples on a shared host, not
stable whole-suite or CI performance qualification. Earlier development
observations include a 315.36-second cold build and a 158.47-second repeat;
those negative timing observations are retained in the structured receipt.
Cold build, dependency fingerprint IO and full-pool preparation remain further
optimization targets. No deadline, heap bound or semantic assertion was relaxed.

* Standard command boundary qualification

The ordinary finite-flow module passed all six Cases through =just test-file=
in 24.80 seconds before the Just-owned environment cleanup and 10.56 seconds
with that cleanup. Both invocations executed the million-row verification;
neither launched library preparation or executable linking. These observations
were collected on a shared host and are not a stable matched speedup claim.
The artifact Suite passed seven Cases, including upstream Reader buffer
boundaries; response projection passed 27 Cases without model API calls.
The Python framework passed 21 tests. Ordinary setup, Case, cleanup and empty
Suite controls all failed the recipe as required, including upstream errors
that otherwise could leave a successful dispatcher exit status.

A single all-source =gerbil test t/qualification= process exhausted the unchanged
1 GiB heap after 25 successful Cases. The ordinary full-suite recipe therefore
calls =gerbil test= separately for each discovered module. This uses the same
upstream test API and per-module deadline without a project runtime dispatcher.
The full isolated source inventory is not qualified by the focused results;
CI retains the explicit compiled full-suite gate.

The explicit native actor pool passed ten Cases and its missing, unknown and
extra registry argument controls each returned exit 70. Setup, Case and cleanup
controls returned exit 42; the native empty-Suite control returned exit 70.
The first native rebuild failed with Nix SDK headers; removing only SDKROOT
exposed partial compilation artifacts left by that failed build. Cleaning only
the generated =t/native= and retired =t/runner= cache namespaces and using the
Just-owned environment boundary produced the accepted native pool result.
No production cache, source checkout, heap bound or test timeout was widened.

The explicit one-Case native cache-admission module was compiled successfully
and repeated in 12.82 seconds. The repeat emitted both library and entry cache
hits, started no compiler process, executed its Case and ended in =OK=. Its
admitted snapshot is reused only during the current lane-owned preparation.
