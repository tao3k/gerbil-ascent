* Delivery boundary

The public language is the =relational-program= and
=relational-fragment= API exported by =program/interface.ss=. Trusted
Scheme code constructs finite program values before admission. Its
checked rule subset has positive atoms, lower-stratum negation,
=where= (=even?=, =<=), =compute= (=identity=, =+=), checked reductions,
finite pointwise views, and min/max lattice declarations. Scalar
literals and explicit =(value expression)= captures are copied at
construction; no host procedure is called from a checked rule body.
Admission inspects dependencies, modes, types and budgets; a successful
solve yields a completed immutable result or an explicit failure.

=candidate/reasoning.ss= accepts inert Scheme data from an untrusted
caller. It shares the admitted fixed scalar and relational semantics
for its declared subset, but does not accept host =value= expressions,
finite views, lattice declarations or arbitrary callbacks. A complete
receipt says the admitted program reached a fixed point for the copied
source snapshot; it does not certify that the proposal expresses the
caller's intent. Its content digest is a local consistency marker,
not source authentication. Positive proof and nonmembership fields
have their own narrower verification contracts.

The Rust Ascent 0.8.0 oracle is a test-only historical comparison.
[[file:replication-checklist.org][Complete Rust replication]] is a separate research claim and not
the admission definition for this native language. The historical
=program/syntax.ss= is still built for that oracle, but it is not
re-exported by =program/interface.ss=. Retirement of that parser
requires moving its qualification to a test-only build path; its
presence does not enlarge the native public grammar. No internal JSON
protocol, model scheduler or Rust runtime bridge is part of this gate.

* Executable semantic admission

The shared contract test =t/qualification/scheme-library-contract-test.ss=
uses one independent Floyd-Warshall-style finite model for eight
diagnostic three-node graphs. The same source and rules are evaluated
through a direct native program, a first-class fragment and an inert
candidate. It compares complete *sets* after recursion, negation,
fixed filtering/computation and grouped sum. A multi-source update
withdraws an edge, changes a blocker and weights atomically; an
invalid transaction must leave the last completed result and an older
snapshot unchanged. This complements, rather than replaces, the
existing 64-graph native/operator/candidate corpora and their different
coverage. The candidate arm also requests and verifies a bounded stratified
receipt proof for each diagnostic graph. Order of rows, wall-clock timing and
candidate intent are outside the set-equivalence claim.

The repository gate is =just build=, =just test=, =just oracle=,
=just performance= and policy checks at one exact head, followed by
the same-head Ubuntu CI. The abstract Lean/TLA nonmembership gate is
=just check-nonmembership-formal= when that toolchain is available; it
does not prove the Gerbil implementation. A prior green head cannot
qualify a later edit.

The =just test= batch runner now records the discovered file list and
requires each file to produce one =MODULE-OK= in order. This closes a
shell-variable shadowing error that had silently repeated the previous
batch in place of three standalone modules. The corrected local run
reported 30 distinct =MODULE-OK= entries for 30 discovered files,
19 =HARNESS-OK= batches and 19 final =OK= markers, with no error or
overflow markers. The cold compilation of the new joint module has a
20-second startup allowance; its runtime still has the five-second
idle watchdog and the ordinary 45-second batch cap.

* Performance decision gate

Retained positive insertion may reuse the native Session's state.
Source replacement and withdrawal currently solve a prospective
snapshot and publish it only after completion. The paired
=just operator-retained-probe= checks identical complete outputs
against an independent model. Its single-update timing excludes the
retained initialization; its lifecycle timing includes it. Timing
and resident-memory receipts must be interpreted separately from
semantic equivalence. Change the insertion algorithm only for a
repeatable matched gain on the same program and budget. A deletion
algorithm needs alternative-support, last-support, cycle, lower-stratum
and failed-update cases before it can replace recomputation. See
[[file:research/scheme-dsl/deletion-h18.org][the deletion discriminator]].
The [[file:research/scheme-dsl/e4-retained-session.org][current local
rerun]] checks identical outputs but ran under high host load; it does
not admit an optimizer change. This gate therefore retains the existing
insertion Session and recomputation withdrawal algorithms.

On this development host the unchanged =just performance= suite stopped
at =ascent-table-expression= with p95 =2.628 ms= against its =2 ms=
limit; an isolated rerun measured =2.124 ms=. The host load average was
about 48. Neither run changes the budget or qualifies the local SS
gate. This performance result is distinct from the passing Scheme and
Rust semantic gates; an exact-head Ubuntu CI run is still required.

* Bounded model gate

The separate POO Flow Python Testing caller ran two pre-registered paired
pilots on five finite ASCENT/temporal tasks. It fixed prompts, source
fixtures, model settings, request budgets and independent choice/boundary
scores before each pilot. The first tool arm improved choice scores but
worsened boundary scores; the typed-observation pilot improved three
wrong-join boundary labels while all six closed-cut responses still
asserted release authority against the native denial. A deterministic
POO Flow Testing Runtime guard withholds that claim. See the protocols,
per-case results and limits on [[https://github.com/tao3k/poo-flow/pull/34][POO Flow PR #34]]. The scripted caller in
=ascent-reasoning-library-test.ss= remains a Library protocol test. Neither
it nor the small live pilots establish general model helpfulness, source
authority or deployed behavior. The Python adapter does not define the
Scheme grammar.

A later typed/founded observation study made 30 calls. Choice and
boundary scores were unchanged between its arms (15/15 and 12/15);
all six closed-cut outputs still claimed release authority, which the
native guard withheld. Its JSON observations measured that interface,
not Scheme reading. A separate nine-call pilot sent three actual Gerbil
calling programs, with no JSON observation. Native regrading accepted
8/9 answer shapes and found 0/9 exact row sets. The model did not see
the imported ASCENT implementation. A later five-call source-question
run did show the pinned ASCENT implementation and recorded three exact
answers, one correct diagnostic with a wrong answer shape, and one
=complete= versus =valid= verifier confusion. These small studies do
not isolate general Scheme literacy or model-to-Library tool use. The
next experiment and its three separate semantic, evidence and model
checks are specified in [[file:llm-reasoning-library-plan.org::*Integrated ASCENT, Rust and model gate][the integrated gate]].

* Mainline execution order

The next work is organized by capability and its admission gate.

The first joint acceptance case now follows one input through the
[[file:research/scheme-dsl/ascent-a22.org][Ascent paper's fixed-point boundary]],
pinned Rust 0.8.0, this Scheme Library, and the POO Flow Python model
caller. =model_study_negation_count_matches_finite_expectations= in
=rust/ascent-oracle/tests/integration/clause_composition.rs= pins the Rust
result for recursion, lower-stratum negation, even-weight computation and
count on the model-study source. The corresponding
=ascent-stratified-proof-test.ss= case checks complete =path=, =allowed=
and =weighted= sets plus =((1 1))=, correction to =((1 2))=,
duplicate support, current-source verification and stale
receipt rejection. The POO Flow consumer's frozen Python fixture checks
the public finite and founded proof verdicts before exposing any typed
observation to its model runner. This establishes a *same-input bounded
vertical case*, not complete Rust API parity or general model benefit.
The [[file:replication-checklist.org][historical Rust replication gate]]
remains open on its separately listed families and scale cases.

The support-withdrawal corpus adds four matching Scheme/Rust source
states with totals =20,20,8,12=. It covers alternate support, last
support, replacement and stale receipt rejection despite equal query
answers. Scheme direct/fragment/candidate and retained sessions share
an independent finite model; Rust runs fresh programs and checks all
intermediate relation sets. See [[file:llm-reasoning-library-plan.org::*Integrated ASCENT, Rust and model gate][the integrated gate]] for exact
inputs and the completed four-call model comparison. Both final model
candidates failed admission; this establishes a recorded model-input
boundary, while the native and Rust corpus remains qualified. This does not qualify
incremental deletion performance or exhaustive provenance.

1. *Bounded candidate evidence through the public receipt.* A caller may
   request finite stratified evidence with an explicit fourth
   =reasoning-attempt= work budget. Native completion is independent of
   evidence completion. Verifiers rebind the current source and candidate,
   then replay the finite closure and founded proof independently. The
   finite verifier can validate an empty answer without claiming a proof for
   absent rows. The native/candidate common-contract corpus and the proof
   corpus are required together. This
   closes the checked subset's receipt path, not exhaustive lineage or
   general Why-Not.
2. *Public lifecycle latency.* The matched three-node benchmark currently
   measures roughly 20 ms median for admit-and-solve after operator fusion,
   while its native core is about 0.3 ms; see
   [[file:small-graph-benchmark.org][the phase receipts]]. The next change
   must attribute snapshot construction and POO validation before editing
   their semantic owner, retain exact row sets and budget behavior, and show
   a reproducible matched reduction across all measured masks. The 1 ms
   public target remains open.
   A separate POO Flow model-study case measured an identical
   candidate and 188-byte receipt inside Scheme and around its
   persistent Python worker. Ten warm calls gave Scheme median
   2.915 s and worker median 2.917 s; their boundary delta median was
   2.03 ms. One cold call was 35.761 s versus 2.053 s of measured
   Scheme work. This includes three finite/founded source states and
   must not be compared to the three-node operator benchmark as if
   they were the same workload. The warm result does not justify a
   new ASCENT C ABI. Investigate compiled worker startup and process
   reuse for the cold path before any ABI extension.
3. *Language and explanation scope.* Expand typed higher-order change only
   after its finite operator laws and scale evidence; extend provenance and
   Why-Not only with explicit semantics for alternative supports and cycles.
   Keep the Rust 0.8.0 replication checklist as a separate historical claim.
4. *Model usefulness.* Exercise one candidate proposal, native Scheme
   evaluation with finite and founded verification, and one repair turn.
   Freeze exact row sets, receipt validity, source binding, syntax and
   authority scores before model calls. Include a self-contained Scheme
   control and an explicit public API contract control. The completed
   pilots establish no general model benefit; temporal release errors
   remain a live boundary.

An exact-head local and Ubuntu gate is required for a release candidate;
passing one focused module does not complete this sequence.
