#+TITLE: ASCENT Scheme Rule Syntax
#+STATUS: implemented syntax surface; semantic parity remains governed by rust-parity.org

* Design boundary

The =ascent= form is a hygienic Gerbil macro. It lowers declarations directly
to =gerbil-ascent-relation=, =gerbil-ascent-rule= and
=gerbil-ascent-program=. The existing POO contracts, planner and evaluator
validate and execute the result. No second evaluator or independent
fixed-point implementation is introduced.

The left arrow follows the rule direction in Rust Ascent and the A22 paper.
Scheme syntax adds lexical capture. Source rows and bounds are evaluated at
declaration time; predicates, generators and aggregators run when their rule
is evaluated. Bare rule identifiers denote logic variables. Use
=(lit expression)= for a declaration-time value and
=(expr (bound ...) expression)= for a value computed from the current row.

#+begin_src scheme
(ascent
 (relation edge (from to) edges)
 (relation path (from to))
 ((path source target) <-- (edge source target))
 ((path source target) <-- (path source middle) (edge middle target))
 (bounds 32 128 160))
#+end_src

The column identifiers declare arity and document each relation. They are
not runtime variable bindings or types. The explicit bounds use the
existing program contract.

* Forms

| Form | Meaning |
|------+---------|
| =(relation name (column ...) [source] [(index provider)] [(storage provider)])= | Set relation; omitted source is empty |
| =((head ...) <-- clause ...)= | One rule head |
| =(((head ...) ...) <-- clause ...)= | Multiple heads sharing one body |
| =(name term ...)= | Positive relation atom |
| =(not (name term ...))= | Stratified negation |
| =(guard (input ...) predicate)= | Scheme predicate over bound inputs |
| =(bind output (input ...) procedure)= | Compute one output |
| =(for output (input ...) expression)= | Generate one or several outputs from a Scheme iterable |
| =(aggregate output operation (input ...) (name term ...))= | Aggregate rows of one relation |
| =(aggregate (output ...) operation (input ...) (name term ...) pattern)= | Match each aggregate result and bind multiple outputs |
| =(bounds input derived output)= | Existing finite program limits |
| =(lattice name (column ...) source join [index])= | POO lattice declaration |
| =(fact head)= / =(facts head ...)= | Rust rules with an empty body |
| =(or (and clause ...) ...)= | Finite body disjunction, lowered to ordinary rules |
| =(if (input ...) expression)= | Scheme predicate over bound inputs |
| =(let output (input ...) expression)= | Compute a bound output |
| =(let (output ...) (input ...) expression pattern)= | Destructure a computed value with an irrefutable native Gerbil pattern |
| =(for (output ...) (input ...) expression pattern)= | Destructure each generated value with a native Gerbil pattern |
| =(if-let (output ...) (input ...) expression pattern)= | Native Gerbil match; failed pattern drops the candidate |
| =(match (output ...) (input) pattern)= | Destructure one bound value with native Gerbil match |
| =(expr (bound ...) expression)= | Head or body atom value computed from named bindings |
| =(pat (output ...) pattern)= | Match one positive atom column and bind native Gerbil pattern outputs |

The evaluator checks bound variables, negation safety and dependency
stratification. Syntax forms make those contracts readable; they do not
weaken them. A recursive path relation may feed a later aggregation, while
an aggregation dependency cycle remains outside the Rust 0.8.0 parity
surface.

* Extensions and evidence

A22 motivates embedded rules and fixed-point semantics. B23 motivates
relation-specific storage; the existing POO Provider boundary owns that
feature, and a declarative provider slot can be added after its syntax and
validation have an independent Rust comparison. F16 motivates
monotonicity-aware future forms; arbitrary Scheme procedures are not
silently admitted as monotone.

The mutual recursion, derived aggregation and comprehensive rule fixtures
exercise macro lowering against the existing qualification outputs. The
[[file:rust-parity.org][parity matrix]] records broader Rust 0.8.0 gaps; syntax
readability does not close those gaps.

* Rust 0.8.0 syntax inventory and next design

The pinned =ascent_macro-0.8.0/src/ascent_syntax.rs= parser and A22 Figure 1
include declarations, facts, multiple heads, positive and negated atoms,
conditions, =let=, =if let=, generators, aggregates, disjunction, relation
patterns and expressions, local macro definitions, source inclusion and
BYODS attributes. Current Scheme qualification covers the first group
through the forms above. A Rust 0.8.0 differential fixture compares facts,
disjunction, dynamic head expressions, =if let= and =?pattern= against the
Scheme forms. Body expressions with named dependencies pass both row-local
and indexed Provider qualification. Inline positive-atom patterns use native
Gerbil =match=. Broader atom expressions and pattern contexts,
embedded rule fragments, typed declarations and
the generated Rust API remain open. Parallel Ascent is an execution-policy
gap, not a token-level grammar feature.

Gerbil modules and hygienic macros should own reusable rule fragments and
namespaces. The =ascent= macro should expand those fragments into the same
POO declarations before evaluation. Bare atom identifiers denote logic
variables; Scheme values remain explicit through =(lit expression)= or
=(expr (bound ...) expression)=. This
avoids silently changing a join when an outer lexical variable has the same
name. Patterns use Gerbil =match=, with failed matches producing no row.
Negation and aggregation retain the existing stratification check. A future
monotonicity contract for user procedures and lattice joins needs executable
law evidence; the syntax alone cannot establish it.

* Scientific extension criteria

A stronger Scheme syntax should add capability through explicit semantic
contracts, not through more surface aliases. Rule fragments should be
hygienic module exports, so an imported fragment has one lexical origin and
does not capture a caller's logic variables accidentally. Relation names
should resolve through module and POO identities before planning, while
fact provenance and MRR admission remain outside the evaluator.

Pattern matching may use Gerbil's native =match=, but the DSL must state
which variables each pattern binds. A failed match removes the candidate;
an unbound dependency is rejected before evaluation. The explicit
dependency list in =(expr (bound ...) ...)= lets the planner safely choose a
Provider index for expressions known before the atom, while an expression
depending on an earlier column in the same atom is checked during row
matching. The 33-row custom Provider test exercises the indexed path.

For recursive user functions or lattice joins, monotonicity and join laws
need an admitted contract and falsifiable qualification cases. The Datafun
paper supplies a useful model for tracking monotonicity; it is a research
direction here, not a property inferred from arbitrary Scheme procedures.
Every extension needs the same Rust baseline fixture where applicable,
invalid-program behavior, and an SS cost receipt before parity is claimed.
