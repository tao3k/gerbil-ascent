#+title: Index lookup requirement ownership

* Production flow

=program/index.ss= owns the synchronous requirement collector. Adapters supply
admitted ordinary rules, positive actions, positive rule wrappers or atom lists.
Live-cache admission occurs before traversal. A fixed provider schema determines
whether sharing needs any metadata at all. Canonical hash owners do not traverse
unused metadata; curried owners keep only their own nonempty column requirements,
with one representative per relation and ordered column list. Terms and callbacks
are never evaluated during registration. Input lists and atom descriptors remain
borrowed and immutable; the owner constructs a fresh ordered spine.

A traversal failure preserves earlier requirements. Shared layout construction
remains deferred until an actual indexed lookup and publishes after complete
success. Relations without requirements never invoke the chain planner. Worker
registration consumes admitted bodies directly through
=row-indexes-plan-positive-rules!=, without flattening actions. Existing all/delta
cache versions, extension revocation, Provider dispatch and row witnesses keep
their respective owners.

Gerbil =1cfb032= =std/iter/macros.ss:88-127,282-298= specializes native list,
vector and range iteration and expresses folds through one owned accumulator.
=std/list/list-builder.ss:6-22= supplies a hygienic ordered spine builder;
=std/text/parser/ll1.ss:225-230= uses it for complete ordered traversal.
Here these native forms express provider discovery, dense layout publication,
and transactional collection. No public MOP dispatch is needed for private
metadata traversal; Provider behavior continues under its existing generics.

* Matched native lifecycle A/B

=reference.ss= is exactly
=cd164f1daf0c7ded7e72ceb9a625dd6334ef339d:program/index.ss=.
Both sides use identical current physical index and shared-chain modules. The
old worker registration adapter reproduces its previous flatten/map call.
Inputs model independently compiled atoms with detached equal column spines,
ordinary positive/negative/aggregate lookup requirements and nonlookup callbacks.
Input generation occurs before timing.

Each timed interval includes fresh index owner creation, requirement registration,
initial all/delta lookup, extension, committed row/size/version publication,
and repeated all/delta lookup while retaining the old bucket. Every result is
checked against an independent ordered row-list oracle. No expression compilation,
whole worker closure, actor scheduling or solver speedup is claimed.

=benchmark.ss= is generated by public =:asp-gerbil-scheme/benchmark-api=;
=runner.ss= validates that contract and calls =benchmark-run/result=. Each shape
has 50 alternating old/new pairs, GC before each interval, process user+system
CPU and root-processor cumulative allocated bytes. Both sides are compiled
symmetrically. No other build or qualification lane is launched during timing.
Values are medians, not wall-clock latency.

The four large shapes require >=20% CPU reduction and >=35 wins. Controls permit
10% CPU regression plus 20us resolution allowance. Every shape permits <=10%
allocation growth plus 4096 bytes. All final gates pass. Small curried input
pays 1232 extra bytes; its tiny CPU values establish no speedup.

The first traversal-only experiment retained repeated column requirements.
Its curried control was 3952 -> 3914us and 10615248 -> 10369552 bytes: little
CPU benefit. Structural deduplication belongs to the same requirement owner,
so the final experiment includes it and uses independent atom identities.
Initial receipts remain in ignored cache, separate from final receipts.

* Qualification and reproduction

The focused Suite checks all adapters at 0, 2, 31, 32 and 40 rows for canonical,
curried and mixed providers, expression non-evaluation, failed registration
retaining prior sharing, live-cache rejection and empty-owner rejection.
Existing index-entry and index-lifecycle Suites cover custom Providers,
revocation/rebuild, session source updates, logical aliases and held roots.
The positive-component Suite qualifies real worker closure, snapshots,
merge failures, cancellation and multiple worker counts.

Build project modules with the installed SDK and canonical artifact root:

#+begin_src sh
LIBRARY_PATH="$(brew --prefix openssl@3)/lib" GERBIL_PATH="$PWD/.gerbil" GERBIL_LOADPATH="$PWD/.gerbil/lib:$PWD" gxi -:max-heap=3G,debug=q t/performance/index-requirements/build.ss "$PWD/.gerbil/lib" "$PWD/.cache/ascent/index-requirements/runner" runner
GERBIL_HOME=/opt/homebrew/opt/gerbil-scheme@0.19/current GERBIL_PATH="$PWD/.gerbil" GERBIL_LOADPATH="$PWD/.gerbil/lib:$PWD" .cache/ascent/index-requirements/runner curried .cache/ascent/index-requirements/curried.sexp
#+end_src

Run all six shapes sequentially. Build the =qualify= lane with the same entry,
then require successful Cases, =test-result-ok?=, final =OK= and exit zero.
Binaries, logs and raw paired receipts belong to ignored
=.cache/ascent/index-requirements/=.

Final local qualification: four Suites, 64 successful Cases, final =OK= and
exit zero. The production policy roster reports 30 findings, zero errors and
=POLICY-NATIVE-OK=. A source-inventory check rejected one build while unrelated
checkout sources changed; a fresh stable build and qualification then passed.
No admission gate or timeout was relaxed.
