* Study: private ordered storage batch admission

Gerbil =2591dcd=, =std/list/list-builder.ss:8-22=, appends through an owned
head/tail queue. Its documentation at =25-32= warns that exposing a peek
before construction ends exposes subsequent mutations. Provider preflight
has a suitable lifetime: no partial accepted list escapes before the whole
batch has passed its ordered row checks and fact-budget check.

=program/admission.ss= now owns =gerbil-ascent-prepare-storage-batch=.
It validates every row, including duplicates and existing rows, in provider
order. It retains the first new row object and returns fresh forward list
headers plus the private deduplication table's cardinality. Gerbil's
=runtime/hash.ss:564-566= reads that stored count directly. Empty/singleton
expansions require no private deduplication table; their count is 0 or 1.
Existing membership, provider list headers and row objects remain unchanged.
=program/evaluate.ss= owns the later membership, source-count, all/delta,
index, size and version publication. The two all/delta header sequences remain
separate after appending; custom providers can observe their identity.
The private standard builder replaces cons/reverse copying, not persistent
source logs or published solver frontiers.

The frozen full engine is =program/evaluate.ss= at
=fcb9ed1117cf597b7acdcc2c9b5895cd1bffb1c3=, with only relative imports
made absolute. The isolated baseline exposes that revision's preflight slice
through explicit membership/count arguments. =just performance-storage-batch=
compiles both sides natively and checks exact module resolution. Each scenario

* Study: ordered finite replay with private row indexes

The installed Gerbil =2591dcd= compiler's =optimize-base.ss:24-29= owns
lookup tables in an =optimizer-info= record. Its =compile.ss:1446-1469=
collects generated items with cons and reverses its private accumulator.
These are separate choices for lookup and ordered publication.

The native =std/list/list-builder.ss:8-22= instead appends through a shared
tail; its documentation at =25-32= explicitly says that peek returns the
shared queue that later puts mutate. This is suitable for its builder
contract. Finite replay needs a different contract: a rule keeps the rows
visible at the start of each relation traversal while its bindings derive
later rows. A mutable-tail builder would change that frontier and its work
budget even when the final set happens to be equal.

=candidate/finite-evidence.ss= now keeps one private =replay-relation= record
per schema entry:

| State | Owner and purpose |
|-------+-------------------|
| Arity | The inspected schema, unchanged in the published closure |
| Present | Structural membership table keyed by replay-owned row copies |
| Reversed | Private cons accumulator in reverse insertion order |
| Frontier | Ordered list captured by callers; its spine is never mutated |
| Dirty | New rows require rebuilding the next requested frontier |

Insertion checks membership before copying or incrementing the derived-row
count. It copies a new row once, then indexes and accumulates that owned
copy. A rows request reverses the accumulator only when dirty; subsequent
reads reuse the published frontier until another insertion. Old frontiers
remain unchanged while recursive bindings run. Final closure publication
uses schema order and first-insertion row order, never hash iteration order.
Unlike the compiler's finished accumulator, this accumulator is still used
after a frontier is published, so publication uses nonmutating =reverse=,
not =reverse!=. Frontier cells are fresh; their row values remain replay-owned.
Generator detachment and the independently verified closure boundary retain
their existing roles. Relation lookup remains the small inspected schema
association list; this change targets repeated row scans and append copying.

=candidate/funs.ss= also replaces repeated bidirectional =member= scans in
=candidate-same-row-set?=. It first retains the old proper-list length check,
then returns directly for ordered equality. Otherwise two private structural
indexes compare distinct support counts and left membership in right. Equal
support sizes and inclusion establish both directions. This deliberately
retains the old length-and-support semantics: =((0) (0) (1))= and
=((0) (1) (1))= compare true. It does not introduce multiset comparison.

The new native Suite checks all 14,641 pairs of row lists of length zero
through four over three rows against a separate bit-support oracle. It also
covers scalar kinds, duplicate seeds and exact replay order, recursively
growing frontiers, derived-row exhaustion and detached verified closures.
The recursive fixture binds seed, one and the upper bound through source
relations, following the inspected grammar's source-only facts,
derived-only rule heads and bound-variable-only fixed operands. At size n
its retained p frontier lengths are 1 through n. Each round probes the seed;
each p row probes p/one/bound, computes and checks the limit. The independent
exact work count is =n+5*n*(n+1)/2=. One less must be bounded, which detects a live-tail traversal
that might still produce the same final row set with a different work count.

The =306aa91= reference keeps =candidate/funs.ss= byte-for-byte and changes

datum traversal, candidate inspection and other dependencies are shared.
Inputs, inspected programs, model answers and verifier certificates are
prepared outside timing. Each generator call must produce the independent
expected ordered closure; each verifier call must return valid. These model
answers are independent fixtures, not timed native-solver outputs.

* Study: bounded datum cursors and private return frames

The installed Gerbil =2591dcd= runtime's =table.ss:141-152= walks the owned
table with an index cursor instead of allocating a task for each key/value.
The compiler's =compile.ss:1446-1469= builds and reverses its own accumulator
without mutating incoming syntax. These examples distinguish traversal state
from input state; they do not prescribe a particular tree-walk algorithm.
The compiler's =optimize-base.ss:24-29= names owned state with an
=optimizer-info= record. The guard likewise uses a private =datum-frame=
record instead of exposing numbered event-vector slots. As in
=optimize-base.ss:572-573=, =using (frame :- datum-frame)= projects slots
directly after the constructor and private ownership establish the record
type. The specialization covers only return records; caller-owned data keeps
its explicit type, cycle, depth and budget checks.

=candidate/datum.ss= owns the inert pair-tree guard used by snapshot admission,
candidate parsing and proof checking. It accepts integers, booleans, symbols,
characters and null, rejects executable/mutable opaque leaves, and checks
cycles using the current path rather than a global visited set. Shared acyclic
subtrees consume their occurrence budgets again when revisited.

The guard previously allocated three event vectors and three list cells per
pair. Single-branch chains now use budgeted cursors and double-speed cursors
for cycle rejection, without per-pair frames or active-table entries. These
are scalar-car/cdr spines and car chains with null cdrs. On reaching a branch,
the guard activates the already charged prefix once, then continues
depth-first traversal with private return records. Each record
holds the input pair, its original depth and whether the cdr is being visited.
The input remains read only. Scalar children are charged directly.

A completed single-branch scan cannot contain an active ancestor: that
ancestor's pending branch either makes the chain cyclic or forces a branch
fallback before completion. Fallback checks each prefix pair's active identity
before entering the branch. Prefix activation is bounded by the number of
pairs just scanned; it does not traverse their subtrees again. This applies
to both cdr spines and unary car chains. A unary step charges its pair and null
cdr before the car, retaining the same occurrence total and Boolean verdict;
pair depth is checked at every step. No unbounded =list?= preflight or repeated
suffix replay is involved.

The work budget still counts every entered pair and leaf, including null.
Unwinding a completed pair does not consume a node. Pair depth increases only
through car edges; cdr edges retain their original depth, and leaves have no
pair-depth constraint. The active identity entry stays true until both
branches finish, then becomes false. No frame, table or input pointer escapes
the Boolean result, and early rejection discards only private state.

The independent structural oracle in =scheme-bounded-datum-test.ss= enumerates
147 scalar/pair terms against 18 node budgets and five pair-depth limits:
13,230 combinations, each checked against the original and current guard.
Additional Cases cover admitted scalar leaves, exact shared-subtree budgets,
car/cdr cycles, mixed-prefix ancestor cycles, exact late-fallback budgets,
arbitrary-precision budgets, input identity preservation, 4096-element/deep
structures and procedure rejection without invocation. Parser-owned candidate descriptions
and the complete provenance/deletion Suite provide consumer checks.

=just performance-bounded-datum= compiles both guards and both verifier
variants into one native prefix. Arguments select the scenario and library;
no new environment switch controls traversal. The original =b622b50= guard
is frozen byte-for-byte under =t/performance/bounded-datum/reference.ss=.
The verifier reference copies that revision's =provenance-graph.ss= with only
its datum import redirected. Both variants share the same current witness
replay and other dependencies. Its A/B measures the complete verifier call
while isolating its direct guard calls; it is not a before/after measurement
of the entire historical dependency graph or complete solving.

Every scenario has 50 alternating pairs and ten calls per sample. Kernel
fixtures cover flat, shared, deep and rejected data, plus four-element and
late-mixed-prefix controls. The latter must remain linear when specialization
falls back near the tail. Guards must match independent expected verdicts. The verifier uses
equivalent 192-edge certificates, checks exact witness/alternative parity
before timing, and must accept both variants on every pair. Initial GC precedes
warm-up; natural collection remains in the measured batches. Compilation,
startup and fixture/certificate construction are outside timing. Native
resolution and =.o1= files are asserted before measuring.

The selected ASP policy additionally flags generic arithmetic in the bounded
cursor loop. The node/depth budgets retain the existing integer domain,
including rejection at nonpositive node budgets and negative pair-depth
limits. No unchecked fixnum arithmetic is substituted: an arbitrary-precision
budget must not overflow or silently change the old verdict. This is an
advisory performance finding, not an absent input validation gate.

* Study: private indexes for ordered complete provenance

The installed Gerbil =2591dcd= compiler's =optimize-base.ss:334-343=
keeps a class's method table with the class that owns it. At
=435-453=, type/class declarations populate private lookup tables rather
than rediscovering metadata from output lists. The useful pattern is an
explicit owner and a lookup representation chosen for its queries.

In =candidate/provenance-graph.ss=, the completed witness is immutable input
to a single enumeration call. That call now owns three temporary indexes:

| Index | Equality and purpose | Ordered evidence |
|-------+----------------------+------------------|
| Relation/row to first node | Structural equality, matching the former row lookup | Witness node identities remain unchanged |
| Relation to nodes | Symbol identity; bucket spine is private | Buckets are reversed once into witness order |
| Seen alternatives | Structural equality of the entire edge | Accepted edges still accumulate in a list |

The third index replaces repeated =member= scans. A private counter replaces
repeated =length= scans without changing the cap: a duplicate edge consumes
no capacity; the first distinct edge beyond the limit returns =bounded= with
no alternatives. Source labels retain their occurrence positions, including
duplicate source rows. Rule occurrence positions and input-node order also
retain their original meaning. Hash iteration never determines wire output.

Relation buckets replace repeated full-witness filtering during grounding.
They retain node order, so body-row probes and fixed-clause evaluations hit
the same work budget at the same position. No index escapes into a certificate
or retained maintenance object. Verification and opening maintenance benefit
through their existing reconstruction call; withdrawal publication and its
work accounting remain separate responsibilities.

The original =8b926e2= implementation is frozen byte-for-byte at
=t/performance/provenance-index/reference.ss=. Native A/B runs through
=just performance-provenance-index=, with explicit scenario and library
arguments. Both modules must resolve to the same native prefix and have
compiled =.o1= files. Each scenario performs 50 alternating pairs with exact
status, witness and ordered-alternative comparisons outside the timers,
plus an independent alternative-count assertion.

The timed boundary is the complete =candidate-positive-provenance= call,
including closed-absence witness replay and index construction. Snapshot and
candidate construction, process startup, verification, opening maintenance,
and subsequent withdrawals are excluded. Private indexes have a fixed
memory cost; the small graph is a diagnostic control, not a speedup claim.
Before sampling, larger scenarios require at least 10% median CPU improvement,
35/50 CPU wins and no more than 50% additional allocation. CPU and allocation
are measured with =##process-statistics=; wall-clock is not a qualification.

budget/cap Case includes duplicate =#f= rows, characters and unrelated relations;

Generated transcripts stay under ignored =.cache/ascent/provenance-index/=.

* Feature: finite selection and admission

=program/operator.ss= lowers =select-eq= into a singleton source relation
plus an equality join. A direct literal term in the body and head was
tried locally. It removed one relation and allowed a smaller source
budget, and it passed the finite selection and operator qualifications.

source handles with the literal version, under equal budgets and with

alternating admission-plus-solve samples for the literal version were
much slower, despite noisy host timing. The experiment was reverted;
the singleton join remains the implementation. Do not infer a runtime

snapshot now delegates that single copy to =relational-source=. A

and append paths had the same duplicate =relational-source= validation

and copied the row lists. They now send that checked copy directly to
the native session. Append uses the existing single-row validator and
copier directly, without building a temporary one-element list.
Existing replacement rollback and isolation cases,
plus a new append isolation and non-scalar case, protect the contract.
These are fewer copies at the boundaries; their runtime benefit still
needs a matched measurement rather than an inference from shorter
source.

* Study: owned finite mapping construction and canonical receivers

The installed Gerbil =2591dcd= compiler's
=compile.ss:1446-1469= constructs a private accumulator in
=generate-meta-define-values%= and uses =reverse!= on that accumulator,
while the incoming syntax stays untouched. =base.ss:147-174= returns
already interned runtime identifiers directly and only constructs/caches
identifiers when the admitted binding shape requires it. These are ownership
and representation decisions, rather than a blanket preference for mutation
or another wrapper around every value.

Applying that distinction to =program/scheme-checked.ss= removes two
redundant ownership copies along the finite mapping path. The input row is
checked without making an intermediate copy: =append= itself copies its
spine. The output row is checked while making a fresh copy, and becomes the
private tail of the combined row. =relational-finite-view= then gives these
fresh rows to a private source constructor without copying them again.
The ordinary public =relational-source= still copies caller-owned rows.
Shape admission remains before scalar checks, and the closed scalar
predicate has no user callbacks. A failed copy can allocate private temporary
pairs but never returns them or mutates the original row.

The same admitted-identity idea applies to =program/types.ss=. The exact
hash Index Provider and set Storage Provider are already validated by their
own module initializers (=table/provider.ss:53= and =table/storage.ss:112=).
Their relation-slot predicates now accept those exact objects directly.
Derived and custom objects still run the original full receiver contract.
There is no mutable admission cache, callback suppression for custom receivers,
or new exported constructor that lets callers claim ownership.

A live =gxi= probe confirms that imported exported bindings can be reassigned.
Comparing against the mutable exported default is therefore not a stable
admission fact. Provider modules now retain the originally validated object
privately and export a pure canonical-identity predicate. Relation contracts,
physical indexing, evaluator Set shortcuts, session append admission and
reuse selection use that predicate. Existing exported defaults retain their
constructor role. A dedicated native Case rebinds both defaults to false,
checks rejection of false receivers, and extends/queries an existing physical
index through its retained original receiver; it restores both bindings in
the finally clause. Derived and custom objects still have distinct identities.

* Study: one owner for inert data operations

Gerbil =2591dcd= separates the lower-level syntax representation from compiler

=syntax->datum= implementation at lines 76-88 reconstructs pairs, vectors and

=match= rather than repeating field projections. The shared ASCENT copier
uses that pair-pattern form while retaining its recursive algorithm.
=compiler/base.ss:8-10= imports the expander rather than defining another copy
of those representation operations.

The transferable lesson is ownership of data transformations at the lowest
appropriate domain layer. ASCENT's inspected candidate grammar is narrower:
scalar leaves and pairs. Gerbil's syntax conversion is not a candidate copier;
its handling of syntax objects, vectors and boxes would change our contract.

Previously, =types= owned the bounded pair walker, =funs= owned a recursive
pair copier, and =program= and =reasoning= each defined another pair copier.
The =funs= module also depends on the candidate parser for variable recognition.
Using it as the parser's shared data layer would introduce a dependency cycle.

=candidate/datum.ss= now owns the unchanged bounded pair walk and the single
=candidate-copy-pairs= implementation. It imports no candidate, compiler,
crypto, evaluator or proof module. Consumers import these operations directly:

| Module group | Responsibility |
|--------------+----------------|
| =datum= | Bound inert pair trees; detach pairs at publication boundaries |
| =types= | Snapshot and diagnostic records, snapshot consistency and digest |
| =program= | Inspect grammar; lower admitted forms; describe parser vocabulary |
| =funs= | Bind inspected rules, schemas and strata |
| Proof and provenance modules | Produce/check their distinct evidence semantics |
| =reasoning= | Coordinate attempts and publish detached receipts |

=types= continues to export the existing public bounded-data predicate through
its imported binding. Internal consumers use =datum= directly. The old copier
export in internal =funs= is removed and every repository consumer is migrated.
The build declaration adds one library module; no build procedure is added.

Pair copying still reconstructs both cars and cdrs, preserves leaf identity,

refactor, with no stack-depth or runtime speedup claim.
