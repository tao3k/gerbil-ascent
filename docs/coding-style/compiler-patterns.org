* Choose an expression layer from the transformation it owns

The installed Gerbil =1cfb032= compiler shows several complementary forms.
=compiler/compile.ss= defines =with-primitive-bind+args= with =defrules=:
the syntax wrapper owns ordered argument traversal and temporary bindings.
=compiler/method.ss= defines =with-context= with =defrule=, while
=defcompile-method= uses =syntax-case= and =with-syntax= to generate class
inheritance, delayed method registration and a parameterized traversal entry.
=compile-e= dispatches by the normalized AST terminal. These are different
expression tools with different responsibilities, rather than one object
pattern to apply throughout a program.

In =program/syntax.ss=, pure declaration and rule forms now use
=defrule=/=defrules=. Omitted relation, lattice and program arguments normalize
to a complete form before reaching one constructor expression. Single rule
heads normalize to the same multiple-head form; facts use the same empty-body
form. The collector forwards declaration options to their declaration macro
instead of duplicating its option grammar. This retains source order and
keeps construction at the declaration boundary.

Identifier-sensitive term classification, macro argument diagnostics and the
guarded collector still use =syntax-case=. Index and storage providers retain
their existing generic dispatch, where alternative implementations actually
share a behavioral contract. Pure graph traversal remains a named algorithm.
Syntax normalization removes duplicated expansion definitions; it does not
establish a runtime or end-to-end performance improvement.

The native =std/test= qualification runs the syntax, lattice, aggregate,
BYODS index, positive rule, binding and equivalence-storage Suites:
93 Cases pass with final =OK= and exit zero. The syntax Suite also evaluates
malformed source to check its original expansion diagnostics. Its static
entry therefore links the expander, calls =gerbil-load-expander!= and resolves
the installed Gerbil core through =GERBIL_HOME=. Earlier entries without
these requirements failed; their logs and the successful receipt remain in
ignored =.cache/ascent/syntax-normalization/=. This is local qualification,
not a completed remote CI claim.

* Invocation-owned analysis and ordered search

Gerbil =1cfb032= =compiler/optimize-base.ss:24-33= defines =optimizer-info=
with a constructor that owns its analysis tables. The useful lesson for
=table/index-sharing.ss= is to make column analysis a complete invocation-owned
descriptor. Admission now detaches and sorts the requirements; adjacent
comparison rejects duplicate columns. A private =column-order= carries the
admitted sets and ordered strict-subset successors. Matching uses =ormap= for
first-success augmentation, retaining successor order and matching updates.
Sorted-set inclusion is a flat monotone recurrence. Compiler and search
metadata do not retain runtime rows or cross an engine's ownership boundary.

The certificate checker independently rebuilds widths and lazy membership
tables from the original supplied sets. It accepts unsorted admitted sets;
it cannot depend on the planner's sorted-merge precondition or successor graph.
One selected membership table is captured before each =andmap= traversal.
Existing exhaustive partition enumeration checks all 128 subsets of the
three-column requirement universe, alongside rejected nonmaximum and
inconsistent certificates.

The complete native layout call improves target chain/split CPU about 95%/88%
with lower allocation. A branching fixture fails exact layout stability even
for repeated baseline calls and remains a negative result. Empty input adds
128 allocated bytes. See [[file:../../t/performance/column-order/README.org][column-order qualification]]
for the frozen source, fixed gates, controls and scope. These measurements do
not establish runtime query or solve improvements.

* Buffered protocols and empty-delta proofs

Gerbil =1cfb032= =std/io/bio/types.ss= separates owned byte buffers and
cursor state. =std/io/bio/input.ss= expresses complete read/fill/retry protocols
with =defrules __bio-read=, selecting operations at the buffer boundary.
=core/finite-flow.ss= applies this pattern to bitmap deltas: a hygienic
=fill-bitmap-delta!= rule owns write/count order, while =fresh-bits!= selects
the stored/blocked state before the byte loop. The loop contains no per-byte
presence tests or callbacks.

One invocation lazily owns a scratch bitmap. Equal incoming/total bitmaps
prove no new facts; the caller consumes only the zero count and never merges
stale scratch. Every remaining path overwrites all bytes. Budget checks still
precede root mutation; first insertion copies scratch separately into total
and pending. Returned frozen views retain roots and domains, never scratch.
Reentrant cancellation observations and budget-failure retries exercise these
ownership boundaries alongside the original exhaustive and million-fact tests.

The complete cyclic flow call improves CPU about 44% and allocation about
34% in 50 matched native pairs. Ordinary dense and blocker-heavy inputs fail
their fixed 10% CPU improvement gates; small/empty controls pass, with 32 extra
allocated bytes for empty input. Three consumer Suites pass 31 Cases. See
[[file:../../t/performance/flow-delta/README.org][flow delta qualification]] for the frozen reference, independent truth,
rejected and overlapping series, and the limits of these local results.

* Study: expression optimization conditions and compiler output

Study the installed Gerbil compiler directly, including the conditions that
admit a rewrite and the bindings retained in its output. Surface similarity
to another Scheme dialect is insufficient evidence for an optimization.

At Gerbil revision =2591dcd=, =compiler/optimize.ss:163-179= collects
mutators before generating specializers and lifting dispatch lambdas, then
collects and refines type information to a fixed point. These are distinct
passes with explicit analysis dependencies. =optimize-call.ss:89-131=
requires equal arity and immutable arguments/references before substituting
an immediately applied lambda. Quotes and stable references are substituted;
other operands retain temporary bindings. =optimize-xform.ss:178-185=
rejects mutation of an inline substitution.

A project-local compiler probe used =compile-module= with optimization and
generated Scheme only, without rebuilding the SDK. Its emitted static SCM
shows the immediate immutable lambda reduced to one =##fx+= expression;
the lambda with a mutated argument survives the Gerbil pass, and effectful
operands retain bindings. Source execution separately checks both arithmetic
results and that each effectful operand runs exactly once. This establishes
the Gerbil source transform, not the final C compiler's closure allocation
or a speedup. Probe sources and generated artifacts stay in ignored
=.cache/ascent/expression-study/=.

For our code, =core/rule-bindings.ss= already has direct calls for admitted
small arities; =program/operator.ss= uses fixed local helper signatures.
These require inspection of emitted code before further manual inlining.
=table/funs.ss= now selects its complete ordered/arbitrary loop once per
batch. Ordered column positions become immutable forward distances before
row traversal; =list-tail= advances each cursor. One synchronous
=hash-update!= operation replaces the separate lookup and set. Its callback
is shared within one batch and reads a private row slot; stable lexical
bindings coexist with explicitly owned mutable state. No callback is
allocated per row, and each insertion creates a fresh bucket spine.
The native =runtime/table.ss:440-464= expansion hashes and probes the key
once and calls the updater directly in its hit/insert branches.
Arbitrary and repeated columns retain their
original projection. No caller column list is changed or cached across
batches. This applies the compiler's fixed-shape specialization approach at
a production boundary where shape metadata is already available; it does
not assume that the compiler will hoist an arbitrary captured branch.
Qualification measures the complete physical build/extend/lookup lifecycle;
it does not establish an end-to-end solve speedup.

Projection-only hoisting improved this lifecycle's CPU by approximately 2%
and failed the preset 20% gate. Combining it with one native hash update passed

* Study: admitted callback arguments and ordered pattern extension

The installed compiler's =optimize-call.ss:90-131= only substitutes lambda
arguments after proving equal arity and stable bindings; other operands retain
explicit lexical bindings. =compile.ss:557-628= separately lowers fixed/rest
case-lambda dispatch. The transferable rule is to specialize a proved calling
shape while preserving operand evaluation, rather than assuming that =apply=
or a shorter source expression will disappear in native code.

=core/rule-bindings.ss= applies this at the admitted rule boundary. Zero,
one and two input names use direct calls; larger callbacks retain =apply= and
an ordered argument list. All names are resolved before invoking user code,
missing-name diagnostics retain their first failing input, and a bound =#f=
is a value. No user callback becomes an unchecked call or a cached value.
The evaluator shares this operation for guard, binding and generator clauses;
expressions use the same core owner. Aggregate input tuples still require
lists and use its ordered projection helper.

The compiler's =generate-meta-define-values%= (=compile.ss:1446-1469=)
constructs only its owned output and preserves publication order. Our pattern
operation combines finite output-name traversal, result arity validation and
fresh binding construction. It produces two fresh pairs per output rather
than the old map-plus-append's three, retains output order and the caller's
original environment tail, and never mutates callback-owned tuples. A cyclic
or improper callback result is bounded by the admitted output count and still
raises the original pattern diagnostic. Row and aggregate patterns share it.

the desired calling convention.

* Feature: syntax boundaries

=program/syntax.ss= and =program/scheme-language.ss= both lower atoms,
negation, and reducers. Their generated objects and error paths must
be compared production by production before sharing code. Keep
lexical fragment handles hygienic, preserve source locations and
diagnostics, and never broaden the public checked scalar grammar
to accept arbitrary callbacks. An extra macro that hides one runtime
call would make the layer harder to read.

The current =relational-atom= and =relational-atom/lexical= expansions
look alike but quote a relation spelling versus evaluate a lexical
handle. That difference is the ownership boundary, so a common
expander would need to keep it visible. =relational-copy-row= and the
operator project constructor use =map identity= to copy list spines
before retention; these are intentional copies, not redundant maps.
The contract in =docs/native-library-acceptance.org= also keeps the
historical =ascent= syntax on the test path, so deleting or folding it
into the native language would be a separate interface change.
The same snapshot-copy pattern appears in =candidate/reasoning.ss= and
=program/scheme-admission.ss=. Its presence across those boundaries
is evidence of an isolation rule, not a reason for a blanket rewrite.

* Study: compiler phase contracts and higher-order normalization

This study reads the installed Gerbil compiler Scheme directly, rather than
inferring quality from an optimization result. Three concrete structures matter:

- =compiler/optimize-top.ss:21-86= declares separate visitors for top-level
  types, declarations, expression types, complete type collection and mutators.
  The operation determines the visitor, while the AST representation stays
  shared. ASCENT already separates descriptor validation from lowering inside
  =relational-typed-compile=; the appropriate improvement is to state their
  different obligations, rather than introduce another visitor framework.
- =compiler/optimize-base.ss:15-29,492-503= names optimizer, local and path
  contexts separately. Type lookup searches path facts, then local facts, then
  the optimizer table; alias resolution delegates to this lookup. The mutable
  optimizer tables are fresh in the optimizer-info constructor. ASCENT's
  compile counters, source tables and domain accumulator likewise belong to
  one invocation. Reified closure environments use descriptor identity and
  lexical bindings; source-name equality cannot replace that relation.
- =compiler/optimize-top.ss:182-194,213-268= still visits an expression when its
  binding type is already known. Lambda and let handling establish the local
  environment around the body traversal. Known metadata therefore does not
  authorize skipping traversal or changing scope. In ASCENT, validation,
  lowering visits and conservative finite-height expansion keep their original
  budget charges even when source lowering reuses an existing source node.

The complete =program/higher-order.ss= owner now carries adjacent polymorphic
and domain signatures for all 21 definitions, including its three representation
constructors. Comments state the distinct relation/arrow field meanings, source

Removing comment lines from the module yields exactly the previous source bytes.

* Study: operator traversal and local rule emission

The installed Gerbil compiler's =optimize-top.ss:244-291= uses named local
=collect-e= procedures inside =collect-type-let-values%= and
=collect-type-letrec-values%=. The local procedure handles one binding's type;
the enclosing procedure owns traversal order and the dynamic local environment.
Ordinary let expressions are compiled before the body environment is installed.
Recursive bindings are compiled inside their environment, in two explicit
passes. The useful lesson is to keep scope and ordering visible in the driver
while moving a separate responsibility into a small local procedure.

=program/operator.ss= now applies this structure to =lower-operator-graph=.
Named local definitions replace the manual letrec/lambda binding list.
=emit= owns graph traversal, active lexical bindings, closed-node memoization,
fixed-point placeholders and projected-join fusion. =emit-operation-rules!=
receives already lowered inputs and owns ordinary union, join, selection,
projection and finite mapping rule emission. Both close over one compilation's
relation/rule/source accumulators; no public interface or shared context is
added. The public compilation contract is adjacent to its actual definition.

Free-parameter validation still precedes memo lookup. Fixed-point relations
are allocated before their bodies, transformer input graphs are emitted before
their bound bodies, and ordinary inputs are lowered before their output and
private sources are allocated. The operation clauses and scope traversal match
the preceding revision after whitespace normalization. Rule construction,
gensym order, final publication reversal and budget enforcement are preserved.
