#+TITLE: Complete finite evidence replay plans

* Production flow and source learning

The unit covers finite certificate generation, ordered closure publication and
independent certificate verification. Gerbil =1cfb032=
=compiler/optimize-base.ss:24-29= owns identity tables per optimizer invocation;
=core/contract.ss:401-432= binds typed expressions with =using=. Existing native
=with=, =match= and =foldr= support admitted rule layouts and ordered expression
composition. Private final =finite-rule= / =finite-clause= records carry resolved
relations and prepared expressions through one replay. They retain no rows,
frontiers, evaluated bindings or result across calls.

Relation names, head getters, atom terms and fixed scalar operators are resolved
before repeated execution. The shared scalar preparation checks current binding
presence, first binding, exact numeric domains and already-bound outputs on each
call. Positive proof generation uses the same expression layer; its independent
proof verifier retains direct interpretation.

Each finite verifier still admits the external certificate and independently
replays the whole candidate. Row probes, unsuccessful matches, final absence
steps, reduction scans after invalid numeric values, round visibility, strata,
material limits and exact work outcomes are preserved. No producer closure is
used as verification truth. Rows are copied at replay admission; the final
private closure is transferred to its certificate after replay owners end,
avoiding a second deep copy. Separate generation calls and independently returned
verified closures remain isolated. External row grammar and size are admitted
before structural uniqueness hashing.

* Frozen complete consumers and fixed gates

Baseline =71ac687dfd552818134ba0dc0e337cac08a188a0= freezes
=candidate/finite-evidence.ss= byte for byte in =reference.ss=, original blob
=f7934aa062cba7b143fafea078b57a1ade03660e=. Other candidate inspection, snapshot,
strata and material-budget dependencies are shared. Neither arm invokes the
native solver. Prepared snapshot/candidate/independent expected rows are outside
timing. Both arms generate a full certificate, independently verify/replay it
and project status, every ordered closure entry, verdict and verified closure
inside timing. Complete projections must match; query rows also match independent
mathematical expectations.

Wide uses 16 source/derived relation pairs, 64 source rows each, an even filter
and doubled output. Negation excludes two independently specified source values.
Reduction sums 128 weight rows grouped by eight keys, including empty sum groups.
Small uses one two-row source/derived pair. All inputs remain within unchanged
finite material limits.

Before first timing, gates fixed 20 alternating CPU pairs, 20 ASP Scheme API
admissions and five dedicated cumulative allocation pairs. Wide/reduction need
<=90% CPU and >=16 wins; negation/small permit <=110% CPU +20 us. Allocation
permits <=110% baseline +8192 bytes. Native CPU includes natural GC; allocation
samples reject negative differences. Arms run sequentially without compilation
or tests alongside timing. No sample, gate, budget or timeout was relaxed.
