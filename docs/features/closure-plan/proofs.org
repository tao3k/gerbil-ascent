** Audit findings and architecture decisions

1. Compilation and worker eligibility are different contracts. A compiled
   positive plan can contain expressions or callbacks. Both Session admission
   and component dispatch must use explicit purity and Provider capabilities;
   plan existence cannot authorize concurrent execution. Check every consumer
   whenever the admitted plan representation changes.
2. =credited_compiled_closed= and =completed_compiled_least= connect useful
   semantic laws, but faithful native row enumeration, valid rules, external
   read framing, actual credit/tail completeness and local stability remain
   premises. Discharge these through representation and execution refinement
   for the admitted grammar. Additional abstract lemmas alone do not close R1.
3. Ordinary Set iteration is proved for every Nat round in =SemiNaive=.
   Arbitrary Provider gamma/injection and total/delta contracts, user lattices
   and S20 higher-order function changes remain separate obligations.
4. Ready-component scheduling and credit/drain publication are implemented for
   pure canonical Set components. Preserve dependency cuts and terminal
   completeness while removing global waiting. General Provider concurrency
   and partitioning one large SCC require explicit new protocols and evidence.
5. Existing TLC models have unbounded Nat semantics but finite exploration;
   =Spec= alone establishes neither invariance nor liveness. Unbounded temporal
   proof and native event correspondence remain TLA+ responsibilities.
6. A physical index cache is not B23 index sharing. Sharing requires a layout
   and selection algorithm that covers logical lookup requirements, then
   application measurements. Provider fixture gains cannot establish whole
   application or real-model benefits.
7. Historical append-only sections retain their original source boundaries.
   The current plan below supersedes historical next-step wording. The removed
   Lean SessionPublication replica must not reappear as a planned dependency.

** Native compiler correspondence: next connected design obligation
:PROPERTIES:
:CUSTOM_ID: native-compiler-correspondence
:END:

The 2026-10-06 rereading of A22 section 4, B23 section 3.3 and section
5.5, and S20 sections 4.2-4.3 selects the admitted callback-free compiler
path as the next connected obligation. This is a library obligation. MR/MRR
bindings and model comprehension cannot establish it.

A22 generates nested rule loops and an SCC evaluation path. Its clause-order
restriction is a binding prerequisite, not a proof that arbitrary Scheme
callbacks commute. B23 equations (1)-(2) require total/delta concretizations
to cover represented facts and include all newly implied facts in delta;
raw inserted rows are insufficient for closure Providers. S20 defines an
arrow change using both the old argument and its change; existing rule pivots
are not a derivative of a higher-order closure. These premises constrain
separate native owners, even when all three eventually produce relation rows.

*** One semantic path, three implementation correspondences

1. Relate the actual admitted descriptors and compiler metadata to the existing
   semantic terms/rules. Variable symbols need an injective identity map into
   Lean names, separate from symbol-valued scalar encoding. Fresh allocation
   order, repeated occurrences and lexical capture must commute with lowering.
2. Lift the finite-vector matcher to the complete candidate scan and recursive
   multi-atom traversal, including ordered emissions and the returned dirty
   vector. Relate the actual stored actions, selected keys and head readers to
   that traversal. A matcher theorem alone does not cover a continuation's
   reads, head slots, or recursion through the same mutable vector.
3. Connect full/pivot traversals to actual Provider enumeration and the existing
   constructed ground-rule model. Then discharge finite domain/rank and
   completed execution premises to obtain the least model. Semantic stability,
   budget refusal, pending execution and committed publication remain distinct.

Reuse =PositiveSlots=, =PositiveTraversal=, =IndexedPositiveTraversal=,
=IndexedIteration= and =GroundedBinding=; do not introduce another runtime,
serialized proof format or parallel semantic interpreter. Native Scheme owns
admission and execution. Inspection for independent qualification belongs to
existing native Suites; it must not become a per-row production revalidator.

=PositiveSlots.compiled_vector_refines= proves bounds for the Lean compiler's
callback-free grammar and all sufficiently large vectors. It does not itself
prove that the native Scheme plan decoder produces those actions or that every
native head/key access is covered. Each row of this map must discharge a
premise consumed by the next row; extra abstract lemmas without that connection
are not closure evidence.

*** Effects, finite height and optimization permission

Plan existence is an execution representation decision. Purity is a separate
permission: the compiler sets =pure?= false for host calls, and actor admission
also checks storage/index capabilities. =relational-stable= records a caller
contract; it is not a theorem of callback monotonicity, totality, termination or
commutation. Keep sequential callback observations and mutable-payload fallback
controls in their existing owner. Extending the pure proof to callbacks requires
an explicit mathematical function interpretation and an independently stated
effect contract; the pure least-model theorem must not quantify over arbitrary
host procedures.

Finite signature admission derives a bound from the actual declared domain and
type. A resource budget can interrupt a computation; it cannot prove semantic
termination. TLC exploration cutoffs bound checker work, not native generation
semantics. No fixed generation constant is introduced by this correspondence.

B23's minimum physical-index count permits several layouts with different
lookup costs. Representation minimality, allocation reduction and whole solve
CPU/peak-memory benefit therefore remain separate gates. S20 optimization
must wait for an actual typed compiler transformation preserving changed
captures and fixed-point meaning; insertion validity algebra alone is not
that transformation. Deletion/support maintenance continues under its own
H18/B22 contracts rather than being renamed an arrow delta.

** Historical first slice: type representation to semantic height

The existing native formulas are:

- Relation with =d= distinct atoms and arity =a=: tuple universe size =d^a=,
  inhabitant cardinality =2^(d^a)= and rank bound =d^a=.
- Arrow =A -> B=: cardinality upper bound =card(B)^card(A)= and pointwise
  rank bound =card(A) * height(B)=.

Our design decision is to retain these as conservative bounds. For arrows,
=card= counts the full finite function space; it need not be the exact number
of monotone inhabitants. Finite exhaustive enumeration belongs in small native
truth models and semantic proofs; production normalization must continue using
saturating arithmetic rather than allocate the full function space.

The first slice has four connected deliverables, in dependency order:

1. Revalidate the actual exposed type/typed-term graph before height analysis.
   Own admitted domain/row spines and reject malformed arity/domain/children,
   cycles and escaped captures. The relation-operator preflight does not by
   itself validate =relational-type= or =relational-typed-term=.
2. Define the semantic relation/arrow inhabitants and their representation
   relation. Prove tuple-universe completeness and cardinality bounds,
   pointwise order/rank boundedness and strict progress. State scalar equality,
   duplicate elimination and zero-arity empty-tuple conventions explicitly.
3. Discharge =bounded_bottom_least_fixed= premises for this interpretation;
   relate exact semantic bounds to capped formula evaluation. A cap rejection
   is a resource outcome, never a proof of semantic nontermination. A bound on
   iterations does not by itself bound compiler-node expansion: retain the
   independent actual work counter and fail without publishing partial output.
4. Qualify the actual lowering against a Scheme-owned exhaustive truth model
   on tiny signatures, including nested functions and delayed changes at
   unsampled arguments. Publish source identity, proof hashes, complete rows,
   rejection outcomes and original budgets. Neither finite samples nor a
   historical receipt substitutes for the universal semantic theorem.

Exit condition: all four deliverables agree for the explicitly admitted
subset. Typed normalization, concrete rule execution, transaction refinement,
provenance algebras and general benefit keep separate open obligations until
represented and tested. No arbitrary host callback inherits these proofs.
