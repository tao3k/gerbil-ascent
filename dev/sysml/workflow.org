#+TITLE: ASCENT design, proof and implementation workflow
#+DATE: 2026-11-02
#+STATUS: first DSL tranche implemented; source refinement and remaining inventory open

* Authority and scope

Org records decisions, alternatives, premises, evidence and remaining work.
SysML records boundaries, allocation and executable architectural constraints.
Lean owns universal semantic/representation laws. Quint owns interleavings,
invalidation, cancellation and publication transitions. Existing Scheme owners
implement the behavior; independent native checks establish correspondence.
Matched performance experiments remain a separate admission requirement.

Neither SysML validation nor Lean source rendering establishes whole Scheme
source refinement. Fixtures declare assumptions; they do not observe callbacks,
VM execution, allocation or the truth of their own evidence flags. A path to a
theorem is a navigation link, not a certificate that its premises apply here.
Do not automatically translate unrestricted SysML into Lean or generate a new
Scheme evaluator. Restrict any generated region and prove/check its decoding
and execution correspondence separately.

Production =gerbil build= and DSL loading do not invoke these development tools.
The workflow does not change the SDK, evaluator, cancellation points, fact
budgets, provenance rules, concurrency configuration or performance gates.
The declaration/API candidate is described separately below; it has its own
unclosed native and source-refinement obligations.
The existing [[file:matching-state.sysml][matching study]] and all its negative controls are retained.

* Lifecycle and evidence

| Stage | Required deliverable | Exit condition | Does not establish |
|-------+----------------------+----------------+--------------------|
| Inspect | Current owner, existing semantics, callers and tests | Baseline identities and counterexamples recorded | Proposed behavior is implemented |
| Decide | Org decision and SysML allocation | Alternatives and observable compatibility effects reviewed | General semantic soundness |
| Specify | Formal definitions and explicit assumptions | Independent reference meaning and representation relation stated | Actual decoder/VM satisfies assumptions |
| Prove | Existing Lean/Quint owners extended as needed | Kernel-checked laws; bounded temporal checks with fault controls | Whole-source or timing correctness |
| Implement | Changes to existing Scheme owner | Public semantics, ownership and failure behavior preserved or explicitly revised | New revision is qualified |
| Refine | Source-to-model map and independent native oracle | Actual decoding, state transitions and publication obligations checked | Universal source closure from finite tests |
| Measure | Same workload, limits and semantic coverage | Original time/allocation/resource gates pass | Unmeasured workloads improve |
| Deliver | Reviewed exact revision and acceptance receipts | Required exact-head CI completed; gaps explicitly retained | Unrelated claims close |

Each change must name the primary owner of every claim. Reuse an existing
theorem/model where its premises match; do not create a second model merely
to give both tools the same badge. A temporal model is optional when no new
temporal question exists. Proof and implementation development can iterate;
the acceptance boundary must still separate their claims.

A receipt records the exact commit plus dirty inputs, dependency/tool identity,
native artifact identity, command, limits, complete workload, natural exit,
negative controls and unresolved obligations. A new source revision invalidates
old source acceptance until applicability is checked. Do not overwrite failures,
reinterpret timeout as a counterexample, widen gates or select favorable reruns.
Missing cumulative allocation is unknown, never zero or inferred from live heap.

** DSL-ROLE: explicit relation and update ownership
:PROPERTIES:
:CUSTOM_ID: dsl-role
:END:

Inspected baseline: [[file:../../program/scheme-language.ss][relational-collect]] supplied every declared relation as a source handle;
=relational-fragment= instead separates source/private handles. The existing
[[file:../../program/scheme-session.ss][Session facade]] enforces those handles. This is an observable design difference,
not evidence of a broken Session permission check.

Proposed decision: explicit input, derived-only and mixed roles. Input permits
external facts; derived-only permits rule heads; mixed permits both. An update
additionally requires the admitted writable handle. Empty rows do not determine
the role. Decide how existing declarations map before changing defaults; mixed
relations must not silently lose their externally supplied supports.

| Obligation | Existing owner/reference | Remaining work |
|------------+--------------------------+----------------|
| Preserve roles through lowering/composition | [[file:../../program/scheme-language.ss][DSL]], [[file:../../program/scheme-admit.ss][composition]] | Define role representation and preservation theorem; currently absent |
| No foreign/private update authority | [[file:../../program/scheme-session.ss][source handles]], [[file:../../packages/proofs/lean/DescriptorScope.lean][descriptor scope]] | Scope theorem does not prove role permissions; establish concrete relation |
| Failure preserves prior publication | [[file:../../packages/proofs/quint/SessionTransaction.qnt][transaction model]], [[file:../../program/session.ss][Session]] | Extend only if role changes add transitions; validate actual rejection/rollback |
| Direct/fragment parity | [[file:../../t/qualification/scheme-library-contract-test.ss][library tests]], [[file:../../t/qualification/scheme-session-deletion-test.ss][update tests]] | Add explicit role parity, mixed support and illegal-update cases |

Required negative controls: remove handle checking; accept a derived-only
external update; allow a head on input-only relation; leak one fragment's
private handle. Rejection must precede mutation. An accepted mixed relation
must preserve native fresh-solve equality and complete provenance support.

** DSL-DOMAIN: expose existing finite-domain capabilities
:PROPERTIES:
:CUSTOM_ID: dsl-domain
:END:

Inspected baseline: [[file:../../program/scheme-checked.ss][finite-source/finite-lattice constructors]] copy domains and rebuild membership
checks. [[file:../../program/higher-order.ss][Typed descriptors]] have relation/arrow types, finite-height reasoning and
an expansion budget. The ordinary relation/lattice macro lacks a direct domain
form. Existing arithmetic can generate unbounded exact integers.

Proposed decision: optional domain declarations lower to these existing
constructors. Do not create another type system. Align the per-column domain
representation with the typed API's current finite-universe representation
explicitly; they are not automatically interchangeable. Validate initial,
appended, replacement and derived rows. Reject rather than clamp violations.

| Obligation | Existing owner/reference | Remaining work |
|------------+--------------------------+----------------|
| Finite-height stabilization | [[file:../../packages/proofs/lean/FiniteHeight.lean][bounded_rank_stabilizes]], [[file:../../packages/proofs/lean/FiniteOperators.lean][operator laws]] | Discharge bounded-rank/progress premises for the actual admitted representation |
| Domain survives admission and updates | [[file:../../program/scheme-snapshot.ss][snapshot rebuild]], [[file:../../t/qualification/scheme-higher-order-test.ss][domain/rollback cases]] | Add macro-to-constructor equivalence and cross-entrypoint cases |
| Budget exhaustion never publishes closure | [[file:../../t/qualification/scheme-closure-contract-test.ss][successor and lattice cases]], [[file:../../packages/proofs/quint/SessionPublication.qnt][publication model]] | Preserve exact statuses under the new macro form |

Required controls: out-of-domain initial/derived/replacement rows, one-key
unbounded max, unbounded successor, and a finite but underbudget computation.
Finite height does not promise completion within a particular resource budget.

** DSL-DIAGNOSTIC: source origin without semantic interference
:PROPERTIES:
:CUSTOM_ID: dsl-diagnostic
:END:

Inspected baseline: [[file:../../program/planning.ss][planner]] reports zero-based rule/body/head paths. [[file:../../program/scheme-admit.ss][admit/report]] mapped
them to broad error codes plus explanatory exceptions. It returns no runnable
admission on rejection. Macro expansion already rejects malformed syntax.

Proposed decision: preserve source file/span and nested fragment origin through
lowering. Keep machine-readable codes separate from prose. Metadata must not
evaluate user expressions, force extra getters, change exception order or
participate in relation identity, deduplication or provenance support keys.

No existing theorem is claimed to prove diagnostic transport. Specify a
source-origin erasure relation and prove unchanged accepted meaning/rejection
for the covered descriptor fragment before claiming formal closure. Do not
duplicate the scheduler in a new Quint model for this metadata-only question.
Native tests must exercise macro-generated rules, repeated fragment instances,
composed dependency cycles, malformed syntax and getter/exception ordering.

* Review checklist for a Scheme change

1. Select a requirement above and record current source/dependency identities.
2. State observable behavior, changed semantics and rejected alternatives in Org.
3. Update the allocated SysML contract and named positive/negative fixtures.
4. State Lean/Quint premises and distinguish reused laws from new obligations.
5. Modify existing Scheme owners and provide the concrete representation map.
6. Run independent native oracle/fault controls, then the unchanged full gates.
7. Measure complete workflow cost where a performance claim is made.
8. Report each obligation separately as open, model-proved, bounded-tested or
   source-refined with its actual evidence; never promote all from one badge.

* Checked DSL implementation candidate

The 2026-11-02 candidate adds annotations to existing declarations:

#+begin_src scheme
(relational-program
 (relation edge (from to) '((1 2))
           (role input) (domain '((1 2 3) (1 2 3))))
 (relation reach (from to) '()
           (role derived) (domain '((1 2 3) (1 2 3))))
 (rule (reach ?x ?y) (edge ?x ?y))
 (limits 16 32 64))
#+end_src

Both annotation orders lower to existing finite-source/finite-lattice builders.
An explicitly false domain rejects rather than disabling checking. Ordinary
unannotated direct relations retain mixed semantics, including empty relations.
Fragment source declarations retain mixed semantics by default; private
declarations default to derived. Sources remain the only exported mutation
capabilities. A derived role in a fragment's source group conflicts with that
group's source-handle grant and is rejected at admission. No role is inferred
from row emptiness. Checked admission and checked Session opening recheck roles.
Trusted lower-level host evaluation is not given new checked-language guarantees.

Rules retain detached reader locations for their head/body syntax. Admission
reports expose =relational-diagnostic-origin= in addition to the existing path.
The origin uses the native reader location representation; full source spans,
macro expansion ancestry, detailed planner error taxonomy and actual dependency
cycle paths remain open. New role violations have typed machine-readable codes.
Existing planner error codes are preserved. No diagnostic callback executes
inside the rule evaluator.

[[file:../../packages/proofs/lean/DslDeclarations.lean][DslDeclarations]] proves permission, exact source-handle filtering/composition,
domain membership and origin-erasure laws. Its stated representation premises
remain obligations for Scheme; source rendering equality is not their proof.
LeanPoo is selected by the authorized release tag =v0.1.2=, resolved to
=b29ea0d9d2ffeed0c13b66794fc6d418fd5b0393=. The new laws and complete 180-job
Lean library passed under the unchanged Guard budgets on that release.

The new [[file:../../t/qualification/scheme-declaration-contract-test.ss][native discriminator]] is separate from the existing semantic suites;
it does not replace or reduce them. The initial 14 new Cases passed through the standard
