* Component ownership and shared-reader refinement (2026-10-07)

The [[file:../../scheme-trrel-uf-design.org][UF design]] now connects captured member ownership and unique
root pairs to disjoint rectangle enumeration, and derives disjoint additive
union for consecutive exact frontiers. Repeated members and root pairs remain
checked Lean counterexamples. SCC equivalence, candidate completeness and native
extraction are explicit remaining premises rather than assumed whole-frontier
correctness. The complete Lean build passes 90 jobs, with 24 rectangle laws and
14 examples.

The shared-reader Quint model checks last-owner retirement, ownership conservation,
revision compatibility and per-reader completion. Aggregate fairness passes a
single-reader control but permits starvation with two readers. Premature
retirement, leaked ownership and equal-content revision reuse fail their named
invariants. The accepted shared model covers 14,175 states, has no generation
ceiling or state constraint, and retains a 315-state one-reader control. Eleven
seeded defects are caught across the view and reader models. This formal unit
uses the engine migration at =9fd161f=; it adds no new Scheme behavior or cost
claim and does not replace the migration's native/cost evidence.


* Grouped encoding and presentation journal progress (2026-10-07)

The BYODS refinement now includes eleven Lean encoding/orientation laws and
a separate Quint ProviderReplay publication model. Encoding a two-column row
and encoding a three-column false-group row are provably distinct. Exact
encoded frontiers derive from the constructed root/member plan; derived batch
orientation preserves facts, uniqueness and counts. The Quint model uses a
constructed predecessor/successor step and an independent input-closure oracle;
six faults discriminate scope aliasing, early/omitted journal events, erased
derived kind, mutable old cuts and refusal writes. Native Scheme tests cover
false/true/ungrouped isolation, actual public export order, old cuts, detached
row spines and whole-batch orientation.

These are representation and publication obligations around Sections 3.3 and
5.4. Export order is an additional Scheme Library contract, not a BYODS semantic
requirement. Full custom-provider/lattice admission, application and benefit
coverage remains open. Continue with universal storage/replay refinement and
application controls under the existing closure matrix; MR/MRR remains deferred.
See [[file:../../scheme-trrel-uf-design.org][the UF design]] for the complete ownership/scope mapping.


* Canonical parts capability extraction and application correspondence (2026-10-07)

Native dispatch must distinguish a checked custom visitor from an admitted
exact-selector visitor, including nested unions. A source-bound native red
control exposes the previous type failure; the repaired predicate extracts
actual admission, unions compose both child capabilities, and bind/export
retain the captured capability. The canonical index owner declines before key
evaluation or consumer invocation. This supplies executable representation
controls for the selected-matcher equality-elision premise. It does not prove
universal native key equality or foreign callback laws.

The complete Steensgaard program instantiates allocation/assignment injection
and field-matched store/load consequences. Independent partition and graph
saturation, Rust explicit/eqrel comparison, retained withdrawal and actor
cancellation controls qualify this finite application correspondence. The
then-eager eqrel buffers retained a concrete Provider concretization storage gap. The later
compressed equivalence publication section supersedes that representation
limitation. Full application and resource acceptance require their own
source-bound evidence; universal native refinement remains separate.
Cross-thread VM allocation subtraction is invalid and is excluded from
worker comparisons. See the [[file:../../scheme-trrel-uf-design.org][implementation design]] and its integrated receipt.


* Canonical equivalence representation bridge (2026-10-07)

The Provider concretization equivalence representation audit identified an implementation gap:
weighted components existed, but the canonical engine retained every implied
pair. Native =eqrel= now constructs frozen component-square totals and exact
cross-component frontiers, with logical budget preflight and ordered explicit
journal export. Canonical receiver identity admits frozen actor reads; the
coordinator retains exclusive component mutation and failure recovery.

Lean adds =equivalence_blocks_exact=, =equivalence_blocks_count=,
=equivalence_blocks_budget= and =equivalence_blocks_units= to =ProviderRectangles=. They derive the constructed
frontier from explicit member extraction premises and the equivalence insertion
law; the native hash/member extraction bridge remains qualified by executable
truth tests. Lean tests remain under =Tests=. Quint reuses =ProviderViews= for
publication, logical budgets, held readers, cancel/drain and stale replies.
A finite TLC run is not a proof of arbitrary native histories or liveness.
Full OpenJDK correctness/performance and the ten connected package gates remain
separate from this representation implementation.
