* Ordinary source tests

=just test= discovers every flat =t/qualification/*-test.ss= and retains the
whole-inventory 180-second deadline. =tools/test-modules.ss= supplies independent
process work to =std/sync/wg=. ASP's =testing-interface= supplies the native
GxTest command, runtime profiles and balanced batches. GxTest owns module,
Suite, Case and assertion execution. =just test-file= retains the direct
native command for one file.

* Capacity and distribution

=GERBIL_BUILD_CORES= selects native capacity when configured; otherwise ASP
uses the native CPU count. There is no fixed four-worker cap or separate
project concurrency setting. The CI runner currently supplies four cores;
the development host supplies twelve. Build recipes use the detected machine
capacity through the same native variable.

Native compatible batches have balanced file counts. Before source batching,
ASCENT transposes the ordered inventory into capacity-sized lanes so adjacent
expensive UF/reference modules run on different workers. This changes only
assignment: every discovered file occurs once, profiles remain native, and
Suite/Case order inside each module stays native. Isolated compiled performance
Suites retain their process-isolation profile.

* Module identity

Reference algorithms import shared production dependencies by their canonical
=:gerbil-ascent/...= names. A relative =../../../program/types.ss= source path
can create a second expander context beside the compiled Library context and
reinitialize its runtime namespace. Previously loaded reference Sessions then
retain a different prototype. The source-import regression loads late source
fixtures and checks both held and newly constructed Sessions.

* Completion and logs

Each worker owns a log under ignored =.cache/ascent/test-modules/= storage.
Real module/Case progress and typed exception details are forwarded immediately.
After all workers quiesce, the original logs are replayed contiguously for the
Case audit. Acceptance requires exit 0, all module completion markers, native
=HARNESS-OK= and final =OK=, with zero =ERROR CASE/CHECK/MODULE/HARNESS=.
A timeout or missing marker remains a failure. No timeout or test is removed
to accommodate slow imports or uneven batches.
