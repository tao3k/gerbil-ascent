#+TITLE: Checked request costs and live provenance admission
#+DATE: 2026-10-23

* Measurement boundary
The published three-CPU matrix at 5de560ad recorded 457.047250 ms for the
longest large Rayon request with twelve clients and twelve Rust workers.
This interval includes source replacement, run/export, integer extraction,
independent expected-answer construction, sorting, equality checking, and SHA
updates. It is not an isolated inference-kernel measurement. That historical
receipt did not retain the phase partition of its longest request. Its
independent phase medians cannot reconstruct that partition.

The common benchmark now carries the total, replacement, run/export, and task
identifier together whenever it selects a maximum. It emits the partition
after measurement. The driver checks the identity, unique schema, maximum,
nonnegative components, and exact sum. The original full answer oracle, input
sizes, five fixed samples, thirty-second soak, compiler-isolation audit,
twelve clients, and 240-second row limit remain required. Historical receipts
without this partition remain explicitly unknown.

* Remove avoidable fixture conversion
Rust integer result cells now use checked integer conversion directly instead
of formatting a decimal string and parsing it back. The large request has
30,720 two-column output rows, so this removes 61,440 temporary string
round trips from extraction. This is benchmark conversion work, not evidence
of an inference-kernel speedup. Both arms of a kernel comparison use the same
conversion and observation code.

* Refuse unsupported proofs without unused projection
Current live generation remains mandatory under the same cancellation and
deadline control. Unsupported evidence has no fingerprint and cannot verify.
This path uses the existing Scheme source-status RPC rather than materializing
an unused program projection. Supported proofs still re-read the full projection
and compare its fingerprint BEFORE rejecting foreign candidates. Same-generation
mutable object changes cannot be detected from a generation counter alone.
Eligible candidates then replay with the remaining deadline and recheck live
fingerprint authority afterward. No fingerprint or replay result is cached.

The two Scheme RPCs read source-state-generation through the same source lookup.
A compiled native regression compares their actual generations across source
replacement. Separate regressions preserve cancellation, an exhausted proof
budget, closed owners, unsupported invalidation, and full fingerprint admission
before foreign-candidate refusal after a same-generation payload mutation.
These tests do not establish formal equivalence of all C ABI or Scheme behavior.

The Lean-rendered Rust branch binds projection choice to fingerprint presence.
The Quint model retains owner, generation, cancellation, deadline, fingerprint,
unsupported refusal, and unused projection controls. Additional counterexamples
reject skipping fingerprints for foreign candidates or verifying foreign proofs.
It models admission; it is not a proof of the Scheme RPC implementation.

* Aggregate projection and checkpoint handoff investigation
The retained e43b30bb three-CPU matrix attempted all 24 original rows. Small
and closure workloads had complete matched answers. The large single-VM row
exhausted its original 240-second row limit, so the complete matrix remained
inadmissible. Its separate diagnostic also timed out. Source replacement
accounted for 219.659 seconds wall, 126.553 seconds CPU, 1.092 seconds GC wall,

of expensive controller handoff; it is not evidence of a GC-dominated replace.

The twelve-VM mean/provenance diagnostic on that same runner failed for all
twelve clients under the unchanged one-second proof controls. For example,
source projection took 3,790.683 milliseconds with 3,751.374 milliseconds GC
wall, 291.635 milliseconds GC CPU and 0.303 milliseconds owner queue time.
This identifies projection allocation and descheduled GC as a separate path.
It does not establish the exact cause of every historical construction timeout.
The archive publishers share a start barrier; this does not prove that every
projection overlaps archive I/O.

** Current guarded changes
Factory-owned scalar Aggregate values use a nine-field ObjectContract view
only while their owned shape, owned Term children and original public protocol
identities remain current. Every invocation reads the current fields; no
successful validation or fingerprint is cached. Unknown getters, changed
protocols, tuple output, failed views and foreign children use the original
ordered public classification. Source projection still constructs and checks
the complete Program before encoding it. Eight new native DSL cases compare
mutations, callbacks and exceptions with ordinary public admission.

The parent controller can spin for at most 1,024 polls when its local pool has
one active owner and the host reports at least three processors. Otherwise it
keeps the original 32 polls. The child keeps 32. This local advisory count is
not a global CPU reservation. Every signed work checkpoint, generation check,
controller decision, peer-death check and sleep registration remains required.
This is a candidate handoff optimization until the original isolated matrix
completes; the bounded policy theorem is not a measured speedup.

An additional Rule-view extension increased scoped allocation by approximately
3.7 percent relative to the Aggregate-only candidate and was withdrawn before
acceptance. The original Rule behavior is retained.

** Allocation evidence and source correspondence
The diagnostic tools/ci/projection-allocation.ss executes 256 real production
source-projection calls against the same mean constructor and checks the
supported status and rows. The frozen SDK reports scoped cumulative Scheme
allocation through exec-stats, with raw bytes-allocated snapshots on both sides.
Negative reports, negative or decreasing raw counters, reports above the raw
delta and raw values outside exact binary64 integer representation are rejected.
The precision bound is a counter representation bound, not a heap limit.

On the local twelve-logical-CPU host, the structured probe reported
5,028,463,576 bytes and eight collections for the preserved baseline versus
1,729,018,360 bytes and three collections for the Aggregate-only candidate.
This normal-return, nonnested, balanced-stack scope is diagnostic allocation
evidence. It is not wall-time admission, whole-process physical allocation,
or an independent proof of the frozen SDK allocator. Earlier time-macro probes
had different probe accounting and are retained as separate measurements.

CompilerCost.lean binds the exact Aggregate classifier, public constructor,
parent policy, actual receive-native-reply call site and allocation probe to
Lean-rendered source checks. Its theorems establish the scalar view's field
predicate implication, guarded fallback policy, bounded waiting policy and
signed counter admission. AggregateAdmission and CheckpointSpin add reachable
mutation counterexamples while retaining all preexisting obligations.
These results rely on the existing POO metadata reader and SDK counter premises;
they do not prove the complete MOP, C ABI, allocator, compiler, mutable cache,
SCC implementation or Actor/Rayon message conversion equivalent to Lean.
