* Study: private indexes for ordered complete provenance

The installed Gerbil =2591dcd= compiler's =optimize-base.ss:334-343=
keeps a class's method table with the class that owns it. At
=435-453=, type/class declarations populate private lookup tables rather
than rediscovering metadata from output lists. The useful pattern is an
explicit owner and a lookup representation chosen for its queries.

In =candidate/provenance-graph.ss=, the completed witness is immutable input
to a single enumeration call. That call now owns three temporary indexes:

| Index | Equality and purpose | Ordered evidence |
|-------+----------------------+------------------|
| Relation/row to first node | Structural equality, matching the former row lookup | Witness node identities remain unchanged |
| Relation to nodes | Symbol identity; bucket spine is private | Buckets are reversed once into witness order |
| Seen alternatives | Structural equality of the entire edge | Accepted edges still accumulate in a list |

The third index replaces repeated =member= scans. A private counter replaces
repeated =length= scans without changing the cap: a duplicate edge consumes
no capacity; the first distinct edge beyond the limit returns =bounded= with
no alternatives. Source labels retain their occurrence positions, including
duplicate source rows. Rule occurrence positions and input-node order also
retain their original meaning. Hash iteration never determines wire output.

Relation buckets replace repeated full-witness filtering during grounding.
They retain node order, so body-row probes and fixed-clause evaluations hit
the same work budget at the same position. No index escapes into a certificate
or retained maintenance object. Verification and opening maintenance benefit
through their existing reconstruction call; withdrawal publication and its
work accounting remain separate responsibilities.

The original =8b926e2= implementation is frozen byte-for-byte at
=t/performance/provenance-index/reference.ss=. Native A/B runs through
=just performance-provenance-index=, with explicit scenario and library
arguments. Both modules must resolve to the same native prefix and have
compiled =.o1= files. Each scenario performs 50 alternating pairs with exact
status, witness and ordered-alternative comparisons outside the timers,
plus an independent alternative-count assertion.

The timed boundary is the complete =candidate-positive-provenance= call,
including closed-absence witness replay and index construction. Snapshot and
candidate construction, process startup, verification, opening maintenance,
and subsequent withdrawals are excluded. Private indexes have a fixed
memory cost; the small graph is a diagnostic control, not a speedup claim.
Before sampling, larger scenarios require at least 10% median CPU improvement,
35/50 CPU wins and no more than 50% additional allocation. CPU and allocation
are measured with =##process-statistics=; wall-clock is not a qualification.

The original Scheme Suite adds exact reference comparisons to all 64 graphs
and checks every successive source withdrawal against a separate matrix
closure and a fresh native relational solve. A separate 72-combination
budget/cap Case includes duplicate =#f= rows, characters and unrelated relations;
it also asserts the independent source-label sequence and exact 13-edge cap.
Generated transcripts stay under ignored =.cache/ascent/provenance-index/=.

* Feature: finite selection and admission

=program/operator.ss= lowers =select-eq= into a singleton source relation
plus an equality join. A direct literal term in the body and head was
tried locally. It removed one relation and allowed a smaller source
budget, and it passed the finite selection and operator qualifications.
A paired native probe then compared the original declaration order and
source handles with the literal version, under equal budgets and with
independent expected-row checks. At 64 and 256 source rows, most
alternating admission-plus-solve samples for the literal version were
much slower, despite noisy host timing. The experiment was reverted;
the singleton join remains the implementation. Do not infer a runtime
gain from the smaller rule shape.

=program/scheme-admission.ss= used to copy Core relation rows before
calling =relational-source=, which checks and copies them again. The
snapshot now delegates that single copy to =relational-source=. A
mutable Core input-row test changes the caller's list after admission
and confirms the admitted result stays unchanged. Retained replacement
and append paths had the same duplicate =relational-source= validation
after =relational-copy-rows= had already checked scalar values, arity,
and copied the row lists. They now send that checked copy directly to
the native session. Append uses the existing single-row validator and
copier directly, without building a temporary one-element list.
Existing replacement rollback and isolation cases,
plus a new append isolation and non-scalar case, protect the contract.
These are fewer copies at the boundaries; their runtime benefit still
needs a matched measurement rather than an inference from shorter
source.

The reproducible boundary probe is =just admission-copy-benchmark=. It
runs the old and new operations in one Gerbil process, checks equal
rows and independent list spines after every sample, warms both paths,
and alternates their order for eight pairs per case. Bulk admission
and replacement use 512 two-column rows, 20 repetitions per timed
sample; single-row append uses 1000 repetitions. Timing starts inside
the loaded process, so Gerbil startup is excluded. This measures row
copy and validation work only; it does not measure a complete retained
solve, rollback, or application latency.

Two consecutive local runs of =GERBIL_PATH=/private/tmp/ascent-v0121-gerbil
just admission-copy-benchmark= each completed all three cases, six
warm-ups, 48 alternating timed samples, final =OK=, and exit 0. Times
below are median microseconds for one timed sample. Each case has eight
old/new pairs; "new wins" counts pairs where the new sample was faster.

| run | boundary    | rows x repeats | old median us | new median us | new wins |
|-----+-------------+----------------+---------------+---------------+----------|
|   1 | admission   | 512 x 20       |        280082 |        236348 | 4/8      |
|   1 | replacement | 512 x 20       |        218451 |         61335 | 7/8      |
|   1 | append      | 1 x 1000       |       6309096 |           760 | 8/8      |
|   2 | admission   | 512 x 20       |        261153 |        133609 | 6/8      |
|   2 | replacement | 512 x 20       |        191588 |          4591 | 7/8      |

The admission pair counts are inconclusive under host timing noise.
Replacement and append consistently favor the single-copy boundary.
These results establish local copy/validation cost, not an end-to-end
speedup for a retained solve. A broader runtime performance claim
requires a matched complete workload on an uncontended machine.

* Study: owned finite mapping construction and canonical receivers

The installed Gerbil =2591dcd= compiler's
=compile.ss:1446-1469= constructs a private accumulator in
=generate-meta-define-values%= and uses =reverse!= on that accumulator,
while the incoming syntax stays untouched. =base.ss:147-174= returns
already interned runtime identifiers directly and only constructs/caches
identifiers when the admitted binding shape requires it. These are ownership
and representation decisions, rather than a blanket preference for mutation
or another wrapper around every value.

Applying that distinction to =program/scheme-checked.ss= removes two
redundant ownership copies along the finite mapping path. The input row is
checked without making an intermediate copy: =append= itself copies its
spine. The output row is checked while making a fresh copy, and becomes the
private tail of the combined row. =relational-finite-view= then gives these
fresh rows to a private source constructor without copying them again.
The ordinary public =relational-source= still copies caller-owned rows.
Shape admission remains before scalar checks, and the closed scalar
predicate has no user callbacks. A failed copy can allocate private temporary
pairs but never returns them or mutates the original row.

The same admitted-identity idea applies to =program/types.ss=. The exact
hash Index Provider and set Storage Provider are already validated by their
own module initializers (=table/provider.ss:53= and =table/storage.ss:112=).
Their relation-slot predicates now accept those exact objects directly.
Derived and custom objects still run the original full receiver contract.
There is no mutable admission cache, callback suppression for custom receivers,
or new exported constructor that lets callers claim ownership.

A live =gxi= probe confirms that imported exported bindings can be reassigned.
Comparing against the mutable exported default is therefore not a stable
admission fact. Provider modules now retain the originally validated object
privately and export a pure canonical-identity predicate. Relation contracts,
physical indexing, evaluator Set shortcuts, session append admission and
reuse selection use that predicate. Existing exported defaults retain their
constructor role. A dedicated native Case rebinds both defaults to false,
checks rejection of false receivers, and extends/queries an existing physical
index through its retained original receiver; it restores both bindings in
the finally clause. Derived and custom objects still have distinct identities.

=t/qualification/scheme-finite-mapping-test.ss= compares all input/output
width pairs from zero through four, duplicate order, shared input/output
aliases, caller mutations, invalid signatures, malformed/cyclic lists,
scalar rejection and receiver admission against the old boundaries.
=just performance-finite-mapping= builds both frozen and current implementations
as native modules and checks their resolution paths. The frozen copy, finite
row, source and view definitions come from =541d5b5=; a Scheme-reader audit
checks all five forms against that source revision. Scenario and library
paths are explicit =main= arguments, and logs remain in ignored =.cache=.

Each construction scenario uses 128 entries, widths one or eight, ten calls
per sample and 100 alternating old/new pairs. Ordered row parity is checked
outside every timed interval. Gates are at least 20% lower allocation,
10% lower median CPU cost and 75/100 CPU wins for the optimized cases;
the ordinary source control requires equal allocation and at most 5% CPU
regression. Wall time is diagnostic from the start. The canonical receiver
scenario compares the two original slot predicates with the current ones
through the same public =element?= protocol.

The complete-view reference freezes the original Core contracts and four
constructor/helper definitions as well as the checked functions. Otherwise
sharing modified Core constructors would hide the admission change in both
variants. The ordinary-source control deliberately shares current Core to
check the unchanged public ownership boundary; receiver cost is also measured
separately through frozen slot predicates. Native compilation includes these
reference modules explicitly, rather than leaving one side interpreted.
No complete solve, rollback, tail-latency or application speedup follows
from these construction measurements.

The first non-fused copy attempt fails its narrow-row CPU gate (74/100 wins,

55/100 CPU pairs improve. These failures remain recorded; gates are unchanged.
The subsequent shared-Core probe still fails the view gate after canonical
admission changes (12.5% less allocation, 7.8% lower CPU, 60/100 wins).
It isolates the copy change under faster common admission; it does not
measure the complete before/after batch. Its negative result remains separate
from the corrected frozen-Core comparison.

* Feature: execution and evidence

The stateful engine is in =program/evaluate.ss=; =program/analysis.ss=
owns immutable declaration caches. A change that crosses this boundary
needs retained-session source replacement, cache invalidation,
provider dispatch, and stale-receipt tests together.

For each code change, record the old and new invariant, the exact
v0.19 source operation used, a qualifying example including edge
cases, and the smallest relevant =just test-file= result. A complete
slice also needs =just test=, =just check-policy=, and =just build=.
The =justfile= harness requires =MODULE-OK=, =HARNESS-OK=, final =OK=,
and no error or overflow markers. For a performance claim, compare
matched runs from =just small-graph-benchmark= and the existing
scenario recipes, including timing spread and semantic equivalence.

small-graph receipts in =docs/small-graph-benchmark.org= include earlier

* Study: certificate boundaries with explicit shared owners

The installed Gerbil =2591dcd= sources provide several concrete style lessons:

| Upstream source | Technique | ASCENT application |
|-----------------+-----------+--------------------|
| =compiler/optimize-xform.ss:18-39= | Shared traversal dispatch with a dedicated mutation handler | Separate certificate material helpers from each verifier's proof semantics |
| =compiler/optimize-xform.ss:117-164= | Small reference/set handlers preserve their own matching and publication rules | Retain exact-replay and inductive-nonmembership checks as distinct algorithms |
| =compiler/base.ss:80-93= | Equality is selected from identifier semantics: bound-identifier comparison or symbol identity | Certificate row uniqueness retains structural equality, not symbol/object identity |
| =std/struct/dag.ss:35-54= | Tables and visiting state belong to one traversal; cleanup is explicit | Allocate a fresh membership table for each uniqueness check |

The two certificate modules repeated material caps, bounded list traversal,
row uniqueness and program serialization. Their shared details had multiple
owners, while their meaningful differences were implicit in long helper bodies.
This is a responsibility and protocol-maintenance issue even without a timing
regression.

=candidate/certificate-limits.ss= now owns the original relation/row/cell/arity
caps and bounded spine/structural uniqueness helpers. Bounded traversal remains
an explicit =do= loop: an eager fold or a complete =length= followed by a cap
check cannot terminate an adversarial cyclic spine at the required boundary.
Each verifier retains its schema/groundness checks and their original ordering;
there is no extra whole-certificate validation pass.

=candidate/program-identity.ss= owns the ordered projection of relation, fact,
rule, query and limit fields, followed by byte serialization and hashing.
A named three-field entry projection removes repeated anonymous field reads.
It does not serialize an entire vector, sort declarations or normalize rows.
Two explicit fingerprint functions preserve the historical untagged finite
format and =positive-program-v1= positive format. Query source labels remain
excluded, while fact/rule labels remain included.

The public certificate records and verifier entry points retain their fields
and contracts. Exact finite replay, inductive nonmembership, stratified proof
checking and production evaluation keep their distinct semantic roles. The
build entry only declares the two new library modules; regression Cases stay
in native Unit Tests.

The boundary Unit Test has independent fixed SHA-256 goldens for both wire
formats, checks projected-field changes and intentionally unprojected query
labels, covers finite length/cap combinations, and rejects improper/cyclic
spines and structurally repeated rows. Consumer qualification covers finite
evidence, positive nonmembership and stratified proof checks. No runtime
speedup is claimed.

* Study: one owner for inert data operations

Gerbil =2591dcd= separates the lower-level syntax representation from compiler
coordination. =expander/stx.ss:8-9= depends on =common=; its
=syntax->datum= implementation at lines 76-88 reconstructs pairs, vectors and
boxes according to their representations. =datum->syntax='s local
=wrap-inner= traversal at lines 97-108 follows the same explicit shape cases.
=apply-mark= at =expander/stx.ss:176-183= names a pair's head and tail with
=match= rather than repeating field projections. The shared ASCENT copier
uses that pair-pattern form while retaining its recursive algorithm.
=compiler/base.ss:8-10= imports the expander rather than defining another copy
of those representation operations.

The transferable lesson is ownership of data transformations at the lowest
appropriate domain layer. ASCENT's inspected candidate grammar is narrower:
scalar leaves and pairs. Gerbil's syntax conversion is not a candidate copier;
its handling of syntax objects, vectors and boxes would change our contract.

Previously, =types= owned the bounded pair walker, =funs= owned a recursive
pair copier, and =program= and =reasoning= each defined another pair copier.
The =funs= module also depends on the candidate parser for variable recognition.
Using it as the parser's shared data layer would introduce a dependency cycle.

=candidate/datum.ss= now owns the unchanged bounded pair walk and the single
=candidate-copy-pairs= implementation. It imports no candidate, compiler,
crypto, evaluator or proof module. Consumers import these operations directly:

| Module group | Responsibility |
|--------------+----------------|
| =datum= | Bound inert pair trees; detach pairs at publication boundaries |
| =types= | Snapshot and diagnostic records, snapshot consistency and digest |
| =program= | Inspect grammar; lower admitted forms; describe parser vocabulary |
| =funs= | Bind inspected rules, schemas and strata |
| Proof and provenance modules | Produce/check their distinct evidence semantics |
| =reasoning= | Coordinate attempts and publish detached receipts |

=types= continues to export the existing public bounded-data predicate through
its imported binding. Internal consumers use =datum= directly. The old copier
export in internal =funs= is removed and every repository consumer is migrated.
The build declaration adds one library module; no build procedure is added.

Pair copying still reconstructs both cars and cdrs, preserves leaf identity,
and intentionally duplicates shared acyclic pairs. It is not input admission;
its callers retain their existing finite-data checks and trusted-description
boundary. Node/depth budgets, cycle rejection, digest bytes and diagnostic
publication order remain unchanged. The bounded walker remains iterative;
the copier retains its prior recursive algorithm. This is a responsibility
refactor, with no stack-depth or runtime speedup claim.

The native boundary Case copies nested and shared pairs with an improper tail,
then mutates the caller's pair and one published branch independently. It
checks unchanged values in the detached copy and its other branch. Existing
Cases retain cycle/depth/work exhaustion, source/receipt mutation isolation,
fixed digest bindings and independent graph/reference checks.

The selected-library policy completes with =errors=0= and three findings:
two pre-existing =program/finite-arithmetic.ss= warnings and one R013 warning
for =candidate/datum.ss=. The latter's reported facets include manual-loop
and numeric-domain signals. Its bounded active-path traversal needs explicit
pending work and remaining node/depth budgets; eagerly applying a list
combinator would traverse input before enforcing those limits. The warning is
retained as an advisory, with the specialized boundary documented rather than
adding an unrelated combinator to satisfy file-level coverage.
