#+TITLE: Query-owned ordinal index acceptance
#+DATE: 2026-10-23

* Actual execution change
Single-column joins use the query-owned injective Cell ordinal for direct
lookup instead of hashing that code for every candidate lookup. Composite
indexes, scalar interning, fact digests, deduplication, publication order,
lattice handling, and all cancellation/resource accounting remain unchanged.
No Scheme handle is dereferenced by a Rayon worker.

A density-bounded spine retains hashed sparse bins. Growth moves each whole bin,
without sorting or rebuilding its row sequence, and removes the migrated sparse
entry. The spine has at most twice the distinct-key count plus six logical
slots. Checked arithmetic and the Vec native byte limit retain sparse fallback.
This bounds logical extent, not physical cumulative allocator traffic or RSS.

* Independent compiled checks
The real generic implementation is tested against an independent HashMap over
five insertion strides, 257 keys, 1,028 appends per history, every key after
every append. Another history inserts high keys before low keys and checks
whole-bin migration, duplicates, and distinct typed identity. Overflow and very
large ordinals retain sparse admission. A counting wrapper around the actual
randomized hasher records 10,000 hashes for 10,000 old indexed reads and zero
for the same dense reads in the candidate, with identical row sequences.

This is work-count evidence. It does not establish an end-to-end latency ratio.
The original independent naive oracle, delta witness counts, complex-value,
lattice, source replacement, provenance, cancellation and limit suites remain
required in both supported Rust feature configurations and the Scheme bridge.
Rust Ascent remains a dev-dependency used for alignment.

* Formal boundary
Lean proves lookup denotation across monotone migration and the admitted logical
extent bound. Its rendered extent guard is byte-compared with the marked Rust
guard. Quint checks ordered rows, exclusive dense/sparse ownership, spine and
native bounds, and same-request phase partitions. Required fault cases retain
unbounded growth, native-limit omission, lost or reversed migration, duplicate
ownership, skipped sparse insertion, mixed phase maxima, and omitted validation.

These results do not establish Rust Vec/HashMap/allocator source refinement.
The generated guard alone is not a proof of the complete mutable index, SCC
implementation, decoder or Actor/Rayon message transformation. Those source
obligations remain explicitly open.
