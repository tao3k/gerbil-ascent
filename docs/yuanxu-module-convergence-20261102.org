* Terminology and current acceptance boundary

Gerbil is the Scheme language and its compiler/runtime/package toolchain.
Gambit is the underlying Scheme compiler/runtime. Neither is called an SDK in
this acceptance record. =gerbil-scheme-rust= is the Rust integration library;
its C ABI invokes the native Gerbil builder and test runner. ASCENT is the rule
engine Library consuming those interfaces. Apple's SDK and =SDKROOT= retain
their platform-specific meaning.

The native ownership chain is:

#+begin_example
ASCENT init.ss                 module declarations and dependencies
ASCENT build.ss                native build declarations and products
Gerbil build/test              package dispatch, builder and GxTest
Rust integration library C ABI in-process access to those native operations
ASCENT Rust consumer           Library behavior and ownership qualification
#+end_example

This list describes existing owners. It introduces no dispatcher, environment
protocol, generated inventory, compatibility layer or acceptance framework.
Language, package-build, ABI-transport and Library-semantic checks have distinct
claims. A passed integration-library test does not qualify ASCENT.

* Real role adaptation and direct consumer migration

Yuanxu's interface reader admits one Module =.def= plus optional explicit
external imports. Mixing the former native import/export API with that
publication was refused. The corrected boundaries are:

| Entry | Responsibility |
|-------+----------------|
| program/interface.ss | Program Module declaration |
| program/types.ss | Existing value Contracts plus Program scope Contract |
| program/func.ss | Actual native constructors and clause lowering, formerly in objects.ss |
| program/objects.ss | Actual Program scope value, without procedure wrappers |
| program/api.ss | Complete native Scheme language/API export surface |
| rules/interface.ss | Rules Module declaration |
| rules/func.ss | Actual rule API and hygienic define-program syntax |
| table/interface.ss | Table Module declaration |
| table/func.ss | Native table API export surface |

Existing Scheme, Rust fixture, CI and binding consumer imports were updated
directly. The former =program/interface=, =rules/interface= and =table/interface=
runtime APIs are not compatibility re-exports: those paths now denote Module
declarations. The old =program/objects= constructor entry now denotes its actual
object role; constructor consumers import =program/func= instead.

Two implementation ownership cycles were removed rather than hidden:

- =program/execution-control.ss= moved to =core/execution-control.ss=. The
  matcher no longer depends upward on Program for its execution checkpoints.
- =interface/rule-module.ss= moved to =rules/source.ss=, together with closed
  source/evidence lowering. Rules no longer import their loader from the ABI
  owner while that loader imports rule declarations back from Rules.

There are no forwarding files at the removed paths. Original implementation
bodies and consumers move together; the native package/integration library traversal discovers
their current imports through the existing build interfaces.

* Scope and nominal type identity

The namespace exported by init exposes each selected Module value directly.
A consumer demands its published operations and Types, for example:

#+begin_src scheme
(import "init.ss" (only-in :clan/poo/object .get))
(def program-scope (.get gerbil-ascent.init.exports Library program))
(def table-scope (.get gerbil-ascent.init.exports Library table))
(def program-type (.get program-scope types program))

A source publication and a separately imported native module can own different
nominal prototypes. Equal names and equal source text are not identity evidence.
An initial test incorrectly treated an inert view as its scope. A subsequent
cross-context validation correctly rejected a provider against a different
native import's nominal Contract. Both failures are retained.

Program and Table publish their actual Types alongside their actual values,
following Yuanxu's existing typed-scope pattern. The integration test validates
those public Contracts again and passes Table providers into Program constructors
within the same selected source context. It then exercises sibling Sessions,
source replacement, withdrawal and restoration with independent exact rows.
Candidate follows the same boundary for receipt values. It publishes
=receipt-digest=, =receipt-status= and =receipt-rows= alongside =attempt=,
=capture= and =verify=. Obtain these operations from the same Candidate Module;
a getter from a separately imported module instance cannot read its nominal
receipt type. The independent Library consumer checks current-source rejection
and historical-snapshot acceptance through that public owner.

No structural cast, prototype alias, permissive replacement Contract or previous
validation result bridges different source epochs.
