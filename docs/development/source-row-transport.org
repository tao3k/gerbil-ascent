#+title: Source result transport independently of evaluator selection

* Observed production boundary

The typed =define-program= closure fixture in
=rust/ascent-scheme/benches/process_throughput.rs= selects the ordinary
Session. A native production-interface probe observed only =primordial=
execution checkpoints and an ordinary list reply despite requesting packed
rows. It must not be reported as a resident Actor qualification.

The baseline =source-run= implementation in =interface/engine-api.ss= permits
integer packets only for a finished Actor result. The Rust decoder in
=rust/ascent-scheme/src/values.rs= already accepts the same integer packet
independently of the evaluator. Ordinary list decoding promotes and snapshots
each row. The existing numeric buffer path copies one signed integer buffer.
The 1,000-request closure baseline retained all tuple comparisons and recorded
substantial time inside decoding and release. Raw traces remain in =.cache/=.

* Selection rule and unchanged authority

Keep the existing Actor-ready expression and its getter evaluation order.
Select the existing integer encoder when that expression is true, or when
the caller explicitly requests packets for an ordinary Session. Keep the
existing encoder's signed-64, rectangular, nonempty shape checks and ordinary
fallback. Do not replace the evaluator or classify host callbacks as pure.

Representation selection does not grant completion. In particular, an ordinary
partial result may use a lossless integer representation while its complete
flag, generation, retained result, cancellation outcome and proof scope remain
unchanged. The current Actor partial-result behavior remains unchanged.
The existing final publication checkpoint still runs after serialization.

* Mathematical and source obligations

=IntegerRowTransfer= in =WeightedExportCapacity.lean= already proves that
unpacking flattened rectangular rows preserves all rows and their order.
Extend that model with the three-Boolean selection decision. Relate the old
ready flag to its original requested/Actor/finished expression. Prove that
the Actor decision is unchanged, no non-requested packet is introduced, and
selection preserves arbitrary receipt metadata as well as decoded rows.

The existing native-call model charges =rows * (6 + 2 * columns)= for the
known-kind ordinary row path and three calls for the packed numeric vector.
This excludes Scheme packing, Rust allocations, IPC, GC and scheduler time.
It is not a wall-time or cumulative-byte theorem. Gambit's backward allocation
readings remain unavailable evidence, not zero allocation.

Bind the selection source and its Quint counterpart to the Lean renderer.
Quint must reject changes that force completion, erase cancellation or resource
failure, lose provenance metadata, reorder rows, or bypass transport opt-in.
These checks do not prove the compiler, numeric ABI or mutable runtime.

* Native acceptance

Compare ordinary and packed replies through =gerbil test= for the real typed
DSL, signed endpoints, bignum fallback, empty results, partial completion,
callback observations, stale proof scope and source replacement. Preserve the
existing Actor, cancellation, resource and provenance suites. Run the Rust

Rebuild the production worker through the existing package/archive interface.
Repeat the same 1,000 verified closure requests and report client queueing,
encoding, call, decoding/release, CPU, natural GC and resource costs separately.
Retain the fixed-work workload and its original limits. A faster ordinary
Session transport does not establish resident Actor integration or scheduler
fairness. The latter remains a separate production-path obligation.

Record preparation, client queueing, encoding, native execution, decoding,

* Ordered binary views at the reply boundary

The affine and packed integer source views own two field readers and the
published row count. Their full visitor advances by increasing ordinal.
Their list exporter advances backwards and prepends, yielding the same
order. Bind the optimization to that exact exporter and its field visitor.
Replacing an exporter removes this permission unless the exporter is the
same procedure. General view selection and list consumers keep their
existing paths.

An eligible complete Result hands the existing integer packet writer the
captured count and two positional fields per row. Validate a positive
count and the fixnum allocation extent before constructing the signed
64-bit vector. Bound every write by the declared count and require exact
delivery. Check the existing cancellation and deadline authority in the
writer. Each packet belongs to its invocation. Publication still happens
at the existing reply acceptance point, after every requested relation
has produced its complete payload.

The Lean correspondence is in =MillionQueryWorkload.lean=.
=binary_reply_matches_complete_export= states the order and decoding
equivalence. =binary_reply_writes_fit= and =binary_reply_refuses_partial=
cover the bounded writer and canceled or short reply.
=binary_reply_keeps_capture= states the result-version frame. The proof
models the ordered field sequence and its allocation bounds. Native tests
check selection of the exact exporter, interruption, and old reply
isolation at the Scheme boundary.

The private writer polls the current execution authority before allocating,
at 1,024-row intervals when an authority is present, and after traversal.
These are zero-work checks on already admitted rows. The Session's
work and fact budgets retain their original meaning. The engine compares
the generation captured at request entry with the generation at reply
acceptance. A reentrant replacement during a checkpoint can therefore
advance the Session without relabeling the in-progress packet.

The qualification Case drives =source-run= through a committed identity
projection with descending origins. It compares complete list order,
rejects a replacement beyond the existing fact budget, interrupts the
writer after its first block, and changes the source during another
packet. An already returned packet keeps its original fields. Separate
controls replace the view's list exporter and inject count underflow and
overflow. The reordered view uses the existing list writer.

The million-row delivery Cases reuse the two alternating inputs and the
existing Actor publication. They live in a separate test module so the
original list gate keeps its imports and suite unchanged. Both use the
same production packet encoder.
The list arm declines the capability, and the ordered arm gives the list
exporter a refusal stub. Both check the packet's count and width and
decode every signed cell into the same ordered Scheme consumer. The
request timer includes replacement, publication, packing, decoding and
delivery. Rust's VM transfer and PyO3 are outside this native timing.
The ordered path applies to completed views carrying the certificate.
Results produced by other evaluators, including timed results without
the certificate, retain the existing packet writer.

* Actor Session delivery into a caller buffer

=ascent-engine-session-copy-integer-relation!= captures one completed
publication through the Actor Session's existing =.last-completed=
request. Pending source changes become visible only after a new
publication. Delivery uses the captured Result for its entire lifetime,
even when a newer Result is published before the copy.

The caller supplies an exclusively owned mutable =s64vector= and an
optional starting cell. The function returns a row count and copies the
ordered binary payload into the indicated slice. The count and width
header stays in the private integer packet. A missing publication or a
relation without the existing ordered binary capability returns =#f=.
Invalid offsets and insufficient buffer capacity raise before staging the
packet. Cells outside the requested slice retain their original values.

The integer writer keeps the existing extent, type and cancellation
checks, including its final check after staging. A last authority check
precedes =s64vector-copy!=. Before that point, refusal leaves the entire
destination unchanged. The single copy has no callback or checkpoint,
and the Session retains no reference to its destination. Source budgets
and detached mutable lists still use their existing paths.

A packed source view can also copy its existing private lane directly.
The ordered-view certificate binds the copier to the same exporter and
row count as the field visitor. The copier closes over the admitted
immutable cells and never exposes their vector. Controlled calls keep
the staged protocol and its checkpoints. Without an execution authority
the certified lane needs only the capacity check and one native copy.
Affine views continue to produce their fields through the packet writer.

=MillionQueryWorkload.copyBinaryReply= specifies the snapshot, packet and
destination boundaries. The success theorem relates the slice to the

exercise the live owner request, publication changes and cancellation

=copy_packed_lane_matches_staged= establishes that the frozen lane has the

* POO reuse boundaries

Yuanxu's pinned POO already provides persistent correlated table indexes
and an SCC partition over admitted symbolic owners and packed adjacency.
An occurrence ordinal is a suitable primary key for a grouped index
comparison. A tuple used as the primary key would collapse repeated
source occurrences. Compare build cost and complete ordered bucket
delivery, using the same key equivalence, before changing the engine's
native hash backend. Each all or delta lane must keep its own version
and preserve refusal of custom provider packets.

For a Boolean cycle check, translate all endpoints, including missing
parents, and compare against the dense traversal. The recursive engine
also consumes a source-before-target component order and cancellable
checkpoints in the traversal. An ordinal SCC interface can share the
upstream core once it can expose those properties without symbol
conversion or a second graph capture. POO's public symbolic partition
and persistent bucket APIs keep their existing contracts.
