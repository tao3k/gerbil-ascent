* Study: decide strict dependencies before constructing edge records

Installed Gerbil =2591dcd=, =compiler/optimize-call.ss:822-831=, delays
compilation of conditional branches until the transformed test is available.
For a folded constant it forces only the selected branch; an unknown test
retains both branches. The transferable pattern is to make the admission
decision before allocating the specialized branch's intermediate data.

=core/rule-semantics.ss= previously built a dependency vector and list header
for every reading clause/head pair, even when a pure positive declaration
necessarily had stratum zero. It then discarded those records. Stratification
now first checks for negation/aggregate reads or lattice-to-relation
projection. The latter reuses the existing semantic predicate. Without
strict dependencies it returns fresh zero strata immediately. Otherwise it
constructs exactly the previous ordered edges and runs the existing SCC,
cycle-diagnostic and minimum-stratum propagation path. Multihead declarations,
duplicate heads, nonreading clauses and mixed relation/lattice kinds retain
their semantics. This decision reads admitted immutable plans, not source
rows, runtime frames or callbacks. Invalidation successors still retain all
reading edges; only unused stratification records are omitted.

=just performance-strata-preflight= freezes semantics, planning and evaluator
at =1de7af462fafc1b90fe475fbfd9b4ed821f79eb1=, changing only module paths and
redirects among those owners. Both sides share the same current component
scheduler and other runtime modules. All owners compile to native code with
exact resolution checks. Seven scenarios use 50 alternating pairs each.
Initial collection and four warmup checks are outside timing; natural

requires 90% less allocation, 30% less CPU and 35 wins; cold solves require

* Feature: declaration compilation and ordered stratum grouping

The installed compiler makes pass ownership visible in its entrypoints.
=gerbil/compiler/optimize.ss:27= scopes mutation and local-type tables to one
=optimize!= invocation; =compile.ss:57= declares the syntax handlers for binding
collection explicitly. =optimize-base.ss:24= names optimizer metadata with a
structure instead of spreading its field interpretation across callers.
These are concrete ways to expose invariants to a reader and to the compiler.
They do not establish that every upstream implementation is faster.
For diagnostics, =base.ss:97= passes the current compile context and source
syntax to =raise-syntax-error=. ASCENT's corresponding boundary keeps the
rule/body/head or program-dependency path and re-raises the original exception
after the optional diagnostic callback observes it.

ASCENT now has one declaration compilation entrypoint,
=gerbil-ascent-prepare-program= in =program/planning.ss=. It accepts relations,
rules, a validated schema and the diagnostic callback. It resolves atoms,
checks body/head variable bindings, computes strata and groups active rules.
It neither reads source rows nor invokes storage or rule callbacks.
=program/evaluate.ss= requests this result through the existing declaration
cache, then constructs its own execution metadata, variable frames and timers.

#+begin_example
relations + rules + validated schema
                  |
                  v
planning: resolve -> bind/check -> strata -> ordered active rules
                  |
                  v
analysis cache: immutable declaration plan
                  |
                  v
engine: owned rows, indexes, variable frames, budgets and timers
#+end_example

The earlier active-rule construction scanned every rule's heads once per
stratum. The replacement groups each rule's heads in one traversal, prepends
the resulting active rule to its stratum, then reverses the accumulators.
Hash iteration order cannot change rule order: a rule contributes at most one
group to each stratum, and each stratum reverses the same source-rule traversal.
Head order and duplicate heads are retained. Delta positions and diagnostic
paths still use the original lowering functions.

The private plan vector layout and public POO declarations remain identical.
Source admission still precedes declaration compilation inside engine creation,
preserving the existing error and provider-callback order. This change removes
declaration compilation from the large engine closure without moving callbacks
into a different phase. It does not claim a measured solve-time speedup.

Qualification adds two Cases to the existing =ascent-rule-program-test.ss=:
storage and guard callbacks remain idle during compilation and execute during
evaluation; a multi-head rule spanning two strata retains repeated heads,
source-rule order and the correct delta positions. Existing language diagnostic,
negation, aggregate, lattice and retained-session tests cover the other seams.

Local validation of this change uses the pinned cache SDK with
=GERBIL_BUILD_CORES=12=: standard =just build= succeeds; =just check-policy=
checks 42 modules with findings=0 and errors=0; =just test= passes 50 modules
and 398 Cases; exclusive =just performance= passes all 17 distinct SS scenarios.
The commands return exit 0 with the original module deadlines, Case budgets,
fixture thresholds and 1000-sample performance contracts. Logs remain under
ignored =.cache/ascent/planning-*.log=. These are local receipts, not remote CI
or a paired declaration-compilation benchmark.

* Feature: local name indexes throughout declaration lowering

The installed Gerbil compiler's =compile.ss:1115= creates a local
=make-hash-table-eq= while walking imports. Its continuation records an
expander context only once and keeps the original traversal order. ASCENT
can apply that representation to admitted names; compiler context identity
and ASCENT variable scope remain different semantic contracts.

=program/objects.ss= and =program/planning.ss= now share an admission-local
membership predicate. Small scopes use =memq=. For scopes with at least 32
names, the 32nd query builds one identity index. Multiple heads share that
snapshot after body lowering. A bounded 32-cell probe avoids a full length
scan. The threshold limits allocation for short query sequences; it is an
implementation choice, not an optimal threshold proven for every workload.

Wide atoms separately index the growing same-atom scope. Freshness is read
before inserting the current name; repeated variables and names introduced
by patterns still compare row values. Physical key eligibility consults
only the prior clause scope. Pattern-output collision checks retain their
list representation and remain a second phase after expression-input validation.
Wide generator and aggregate outputs use indexed collision checks; wide
aggregate input queries use a variable-only atom index. Checked fixnum
operations apply only to the probe and query counter bounded by 32.

Custom clause planners still receive the original bound-name list. Result
vectors, declaration order and diagnostic priority are unchanged. Scratch
tables and lookup closures disappear after admission; immutable plans retain
no variable frames, engine rows, global name cache or new metadata fields.

Three binding Cases check 31/32/33/128-name boundaries with uninterned
symbols, fresh and repeated variables, prior-scope index eligibility,
callback timing, ordered pattern outputs and expression-error priority over
pattern collisions. Four whole-program Cases exercise multi-head atoms,
tuple generators, aggregates, patterns and head expressions, preserving
=#f= values and ordered output columns across the same boundaries.

* Feature: explicit SCC traversal state shared by both graph consumers

The installed compiler's =optimize-top.ss:703= (=extract-keyword-args=)
uses a named tail loop with an explicit accumulator and one final reversal.
The transferable lesson is to state the traversal invariant and retain only
the state needed by the next step. That source does not implement SCCs;
Tarjan's lowlink and component ordering remain ASCENT's responsibility.

=program/graph.ss= now represents DFS continuations as invocation-local
frames: the vertex and the remaining suffix of its adjacency list. Entering
a child pushes a frame; finishing it propagates its lowlink to its parent.
Cross edges still use the neighbor's discovery index, and the original SCC
member stack remains separate from DFS frames. Every traversal transition
is a tail call. The numeric root loop also removes the =iota= vertex list.
Caller-owned edge lists are never mutated. Time remains =O(V+E)= and auxiliary
space =O(V)=; this changes representation and constants, not the algorithm's
asymptotic complexity. Both relation stratification and rule summaries use
the same implementation without changing their APIs or diagnostic ordering.
The frame pair is destructured with native =with= rather than repeated field
selectors. Checked =fx+=, =fx<=, =fx== and =fxmin= apply only to dense IDs and
discovery counters bounded by =vector-length=, including the final count
sentinel. No caller-owned data values are numerically specialized.

Two Cases in the existing SCC summary module compare exact ordered outputs
for all 512 three-node directed graphs, each with original, reversed and
duplicated adjacency lists, and qualify 20,000-vertex chains and cycles.
The recursive reference is frozen from =761dcea= in
=t/qualification/ascent-graph-fixture.ss=. The existing stratification oracle
also continues to check minimum strata and concrete strict-cycle diagnostics.

* Feature: stratification and dependency cycles

The initial implementation used stratum relaxation and repeated
reachability searches for strict-cycle diagnostics. The second round
below replaces it with SCC condensation while preserving minimum
strata, diagnostic kind, and encountered-edge ordering. The rule
summary and relation stratifier share Tarjan traversal but retain
their different vertices and output contracts.

* Second round: SCC stratification and reusable graph analysis

The installed Gerbil Compiler gives three concrete lessons for this
implementation. =compiler/optimize-xform.ss:16= registers handlers by AST
form with =defcompile-method=; =compiler/optimize.ss:27= creates pass-local
mutator and type tables before traversal; =compiler/optimize-call.ss:43=
specializes calls after resolving their operators and checking safety.
The applicable pattern is to move declaration work into checked planning
and keep mutable execution state local. The compiler's method hierarchy
and unchecked-call machinery are not needed for this graph algorithm.

Previously =program/funs.ss= relaxed every dependency edge until the
strata stopped changing. A reverse-ordered strict chain required one
pass per relation, giving worst-case =O(V*E)= work. Cycle diagnostics
then searched reachability separately for strict edges.

=program/graph.ss= now owns the Tarjan implementation formerly embedded
in =program/summary.ss=. Both the rule summary and relation stratifier
use it with their own vertices and edge metadata. A strict edge within
one SCC is rejected, selecting the first invalid dependency in the old
ordering to preserve aggregate, negation, and lattice-projection error
messages. Every positive SCC receives the maximum incoming level; a
single source-before-consumer pass propagates the minimum strata.
Graph analysis and propagation take =O(V+E)= work. Programs containing
only positive dependencies use stratum zero without building SCCs.

The frozen relaxation oracle in
=t/qualification/ascent-strata-fixture.ss= comes from commit =74f0046=.
The qualification test compares 6,656 three-node graph configurations,
including single strict edges, mixed strict kinds, and lattice
projections. Additional checks cover a positive SCC with a strict
incoming edge, empty declarations, and duplicate dependencies. All
strata and concrete cycle diagnostics matched the oracle.

* Feature: compile dependency adjacency with immutable rule analysis

Source baseline: =536c87a=. Gerbil v0.19's =std/make.ss:224-246,338-343=
creates the completion table once for a build invocation and lets its workers
consult the shared module dependency metadata; worker readiness and channels
remain separate state. =gerbil/compiler/optimize-base.ss:24-29= similarly
places optimizer metadata in a named owner rather than reconstructing it at
every use. The useful principle here is lifetime: compile declaration facts
at their owner boundary and keep invocation state out of the cached value.
This is an architectural inference, not a claim of algorithm parity with make.

ASCENT previously rebuilt every source-to-head edge at each source replacement
in =program/update-selection.ss=. =program/planning.ss= already constructs and
caches immutable admitted rule plans. It now also compiles adjacency through
=core/rule-semantics.ss= and retains it at analysis slot 6. All earlier slots
keep their meaning. Changing rules creates new analysis; source-only updates
reuse the original declaration analysis and its graph.

| Owner | Responsibility |
|-------+----------------|
| =core/rule-semantics.ss= | Compile atom, negation and aggregate reads to all rule heads |
| =core/dependency-graph.ss= | Read adjacency and close a caller-owned selection bitmap |
| =program/planning.ss= | Build graph once with admitted immutable plans |
| =program/update-selection.ss= | Admit reuse, compare source snapshots and allocate each update's bitmap |

The graph is private planning metadata, read-only after construction. It owns
only dense relation IDs, never source rows, callbacks, mutable engine frames or
reuse results. Each traversal owns its queue and marks before enqueue, so
cycles and duplicate edges cannot revisit a vertex. Traversal order is not an
observable rule execution order: the result is a Boolean relation selection.
Positive, negative and aggregate dependencies all invalidate every head;
guards and bindings do not add an edge.

The existing session-deletion Suite checks every three-node graph and root
against independent matrix reachability, and now reuses the same adjacency
across roots while checking it is unchanged. Additional tests cover self-loops,
duplicate edges, independent invocations, zero vertices and a 4096-node chain.
Existing retained Session cases cover deletion, negation, aggregates, lattice
replacement, append logs, failed transactions and subsequent append behavior.

=just performance-update-dependencies= freezes the old selection implementation
from =536c87a=, with only its relative checked-language import normalized. Both
implementations run as compiled native modules, with path and object checks,
on the same admitted program and prepared analysis. Declaration construction
and graph compilation occur before the timer; the measured boundary is repeated
source-selection, including eligibility, source comparison and closure. It is
not a full replacement/solve or cold program-construction measurement. A graph
adds retained metadata and one upfront edge-building pass; that cost is not
represented as free. Four cases cover chain/wide dependencies, changed/unchanged
sources. One initial collection precedes warmup; natural GC remains included.
100 alternating pairs check exact bitmap parity outside each timed batch.
Wide graphs must reduce allocation by 20%, CPU median by 10%, and win at least
75 pairs; chains must not increase allocation or regress CPU by more than 5%.
These limits are fixed before sampling. Logs remain under ignored
=.cache/ascent/update-dependencies/=.
