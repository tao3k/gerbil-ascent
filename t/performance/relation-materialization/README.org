#+TITLE: Complete bounded relation materialization and traversal qualification

* One execution representation for the relation family

This change replaces repeated source traversal and per-pair neighbor closures
across composition, delta steps, transitive closure and shortest-distance
projection with a prepared relation view. Public source values remain official
persistent UIntTrieSet snapshots. The view reads that snapshot into the existing
private adjacency exactly once, and provides typed source and neighbor visitors.

Dense domains reuse the adjacency to seed every projection, without copying an
extra encoded-row list. Direct tail-recursive neighbor kernels perform emission,
frontier expansion and distance refinement through the original deduplication,
budget and minimum-distance admission boundaries. No global cache is added.
Each POO snapshot owns its view and retains its original lazy slot demand.

The existing 512-radix dense boundary proves the source index, target and encoded
base fit fixnums; only that source traversal uses fx primitives. Its reverse-row
recursion is bounded by at most 512 distinct targets. Larger sparse domains
retain the official native source fold, preventing a radix-sized seed scan and
unbounded reverse-row recursion. General pair arithmetic still admits sparse
integer keys. No radix limit or fact budget is tightened or widened.

* Public behavior and callbacks

The public two-argument right-index visitor, external compose-left, delta-step,
closure-bounded, membership and distance slots retain their protocols. Direct
neighbor access is selected only when the published right-index visitor is the
exact one created by the view. Overridden neighbor visitors retain callback
execution and ordering on admitted inputs. The adjacency vector remains
closure-local; native accessors are private execution metadata.

Official fold order is preserved during dense source visitation; existing
reverse neighbor order and canonical sorted output remain unchanged. Source
withdrawal produces a new view while previously demanded snapshots remain
unchanged. The bounded closure entrypoint shares the same representation.

* Two matched complete-workload runs

Each workload uses 20 warmups and 1000 alternating old/new pairs, identical
input, expected semantic results, runtime and 1 GiB heap fence. There is no
forced per-sample GC. Allocated bytes come from Gambit process-statistics slot 7,
not the latest-GC gauge. [[file:final-first.sexp][First final raw samples]] and [[file:final-repeat.sexp][repeat final samples]]
retain every time and allocation measurement.

least 900 strict paired byte wins. Timing claims require a lower median and

* Measured control costs and acceptance boundary

The sparse two-edge graph, external tiny-left composition and index-only demand
are controls, with no speedup or non-increasing-allocation claim. The prepared
view has fixed metadata cost: sparse control allocates 1024 extra bytes (about
1.79%), external composition 256 extra bytes, and index-only demand 608 extra
bytes. Sparse medians are 15 -> 16 us in both final runs; external and index-only
medians are approximately unchanged. This change does not claim every graph
size or every demand improves.

The first probe classified the tiny sparse graph as a primary allocation gate.
The fused candidate failed that gate; =allocation-gate-benchmark.ss= and
=fused.sexp= preserve it. We then classified this tiny sparse case as a disclosed
control because the measured cost is fixed view metadata, with no timing gain
claimed there. This changes the new probe's classification, and does not change
any original SS fixture, time budget, sample count, heap fence or GC profile.
