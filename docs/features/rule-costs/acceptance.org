* Scope

The existing =core/positive-plan.ss= runner owns optional counters for native
Scheme matching. No reference Dusa/miniDusa code, new evaluator, Python consumer,
choice syntax or external study framework is introduced. The existing DSL and
test harness own the workload. The paper sources are listed in the README's
References: =10.1145/3704849= and its prefix-cost reference
=10.1145/581771.581774=; Ascent rule planning is =10.1145/3497776.3517779=.

This measures one fresh serial solve of canonical pure Set plans. Unsupported
callbacks, storage/index providers, lattice rules, retained sessions and parallel
or cancellable engine routes refuse measurement instead of returning zero work.
A collector cannot be reused for a second solve. Native engine cancellation is
not qualified by this diagnostic; interruption is checked at the plan's existing
checkpoint. Normal unmeasured paths keep their original admission/dispatch.

* Counter definitions

| Counter | Charge point and meaning |
|---------+--------------------------|
| candidate-rows | A candidate actually passed to the native atom matcher, including mismatches |
| partial-matches | One successful body-prefix extension |
| complete-witnesses | All premises matched, before emitting heads |
| head-proposals | One head emission attempted, before Set deduplication |
| admitted-rows | A novel derived row admitted to the current pending round, not necessarily published |
| repeated-prefixes | A successful prefix/support-row visit previously observed in this collector |
| repeated-candidate-visits | A candidate attempt previously observed with the same relevant prefix/support rows, including failed matches |

Repeated observations use relation/slot descriptors and full supporting rows,
not stale unused frame slots or the final projected head. Slot identity follows
first variable occurrence. Heads are omitted so identical relational prefixes
in different rules can be compared. This is a structural diagnostic, not a
general equivalence checker for reordered rules or arbitrary expressions.

Revisiting a prefix with a new suffix may be legitimate work. Different complete
witnesses producing one head are not collapsed into one derivation. No-op head
proposals remain visible. Disabling prefix recording returns =#f= for both repeat
counters, rather than claiming zero. The observer retains support keys and has
memory/time overhead; these counts do not establish wall-time speedup or the
paper's asymptotic theorem. Index construction, field validation and old-lane
membership scans are outside the matcher counter's scope.

The observer reports work, not completion authority. Refusal or interruption
keeps partial counters; it does not turn admitted pending rows into a completed
published result. Failed emission cannot count unattempted later heads.

* Independent finite-domain check

=finite-domain-closure= in the existing semi-naive oracle fixture enumerates
all assignments of every rule variable over a declared finite domain, tests
ground body membership, and applies synchronous immediate consequences until
settled. It imports no native planner, matcher, index or delta code. It is
restricted to function-free positive variable-only rules over declared relations.
Source values outside the domain are rejected. This is not finite-choice or
general Scheme callback semantics.

The native DSL corpus checks every directed two-node graph (16 inputs) in both
representations. Every source, intermediate and exported relation is compared
with that representation's independent least closure. Measured and unmeasured
native executions must produce identical ordered rows. A sparse four-node chain
and the complete two-node graph provide explicit paired work receipts.

* Remaining repeats: plan ownership and explicit projection

The collector now partitions each repeat by compiled plan identity. A
=same-plan-*-revisit= has already been seen by that plan. A
=cross-plan-*-revisit= is a plan's first encounter with a structural prefix
already seen by another plan. Subsequent visits by that plan enter the same-plan
bucket, so the two buckets sum exactly to the existing total. Both partial
successes and all candidate attempts are partitioned. Disabled recording keeps
every repeat counter unknown (=#f=). This is ownership attribution, not an
automatic determination that matching is avoidable. It adds diagnostic memory
only while recording; no matching result is cached or reused by the observer.

On the unchanged chain, baseline repeats are seven successful prefixes and
22 candidates, all cross-plan. On the dense input they are 44 and 84, also all
cross-plan. Full-prefix factoring leaves respectively 2/5 and 32/48 cross-plan
repeats. These samples show no same-plan revisits after empty-pivot pruning;
they do not establish this property for recursive programs or other workloads.

The semantic distinction is:

| Observation | Required work or possible reuse | Obligation |
|-------------+--------------------------------+------------|
| Different full support tuples for one projected answer | Distinct witnesses in a derivation-sensitive contract | Equal Set answers do not justify deleting provenance |
| Same prefix in different rules | Prefix bindings may be shared | Every different suffix and head still needs evaluation/admission |
| Same prefix in a later delta traversal | May carry new suffix facts or updates | Bind reuse to its source cut and invalidate dependencies |
| Matching before an empty selected delta | Avoidable on the qualified pure route | Existing native empty-pivot optimization handles this |
| Variables retained only for a discarded witness | Explicit existential projection can reduce materialization | No downstream use, callbacks, counts or witness-sensitive consumers |

The new third lane is ordinary existing Scheme DSL. It changes the intermediate
from =prefix(x,y,z,t)= to =prefix(x,t)=. Both downstream rules read only =x,t=;
=y,z= have no consumer outside the defining body. The original two lanes,
graphs, limits and independent oracle are retained unchanged.

#+begin_src scheme
(rule (prefix ?x ?t)
      (edge ?x ?y) (edge ?y ?z) (edge ?z ?t))
(rule (left ?x ?w) (prefix ?x ?t) (tail ?t ?w))
(rule (right ?x ?w) (prefix ?x ?t) (tail ?t ?w))
#+end_src

For this nonrecursive positive Set program the answer argument is elementary:
the direct rule succeeds for =(x,w)= iff there exist =y,z,t= satisfying its
four premises. The projected relation contains =(x,t)= iff there exist =y,z=
satisfying its three defining premises. Substitution yields the same existential
formula. This is a query-answer equivalence argument for the declared outputs,
not a transformation theorem for arbitrary recursive, aggregate, negative,
lattice, callback or provenance programs. A consumer needing =y= or =z= is
outside its precondition. No compiler rewrite or new syntax is installed.

* Scheme DSL design assessment

This assessment distinguishes semantic specification, native test evidence and
unproved implementation properties. A paper reference or macro implementation
alone is not a correctness proof of this Library.

| Design question | Current source boundary | Assessment and limit |
|-----------------+-------------------------+----------------------|
| What does a pure rule mean? | =scheme-language.ss= restricts terms and exposes relation dependencies | Positive finite, function-free Set rules have a clear closure specification; the finite oracle covers the present variable-only subset, not all DSL terms |
| Can host mutation silently change a rule? | =relational-term= captures explicit values; =scheme-checked.ss= admits immutable scalars | Construction-time values and rule-time variables are distinct; arbitrary host callbacks must retain separate operational semantics |
| Does composition preserve private identities? | =relational-atom/lexical= and fragment construction allocate fresh handles | Composition is structurally meaningful; immutable plan sharing must not alias engine frames |
| Are nonmonotone reads explicit? | =core/rule-semantics.ss= stratifies negative/aggregate and lattice-to-Set reads | These boundaries must survive rewrites; the positive oracle does not validate them |
| Is completion explicit? | Mandatory limits, solve completion, Session admission and source revisions | A budget or interruption bounds execution, not mathematical closure; partial output must never certify a completed least model |
| Is declarative meaning separated from cost? | Body order, indexes and semi-naive lanes determine observed work | Ordered cost semantics is useful; equal answer sets do not imply equal work, row order, bounded-run behavior or provenance |
| Can users express economical sharing? | Existing ordinary intermediate relations | Yes, including live-variable projection, but users currently choose the representation manually; there is no qualified automatic prefix optimizer |
| Is derivation identity preserved by factoring? | Set admission deduplicates values; provenance has its own path | Query-equivalent source rewrites need a separate support mapping before use in provenance-sensitive contexts |

The design is well founded for the specified positive Set subset, with explicit
boundaries for extensions. The remaining gap is a mechanically checked
end-to-end refinement from all admitted DSL programs to native execution,
including revision and incomplete-run behavior. Current finite tests provide
bounded counterexample checking, not that general theorem. The single-head
surface also makes identical-body sharing manual despite multi-head support in
the native plan; this is a design tradeoff, not grounds to silently fuse rules
and change rule/provenance identities.

The paper basis is: Martens/Simmons/Arntzenius, Section 7.1, for prefix-firing
accounting; Chandra/Merlin (STOC 1977) for distinguishing conjunctive query
equivalence from implementation; and Green/Karvounarakis/Tannen (PODS 2007)
for distinguishing query answers from richer provenance information. Full
citations and primary-source links are in README References. No complexity
bound or provenance algebra from those papers is claimed as implemented here.

* Recursive diagnosis and minimal native reuse

The added task uses existing Scheme DSL only:

#+begin_src scheme
(rule (path ?x ?y) (edge ?x ?y))
(rule (path ?x ?z) (path ?x ?y) (path ?y ?z))
(rule (answer ?x ?w)
      (edge ?x ?y) (path ?y ?z) (path ?z ?w))
#+end_src

All 16 two-node graphs and a four-node revision sequence are checked against
the independent finite-domain oracle. Fresh metered and unmetered rows agree.
Retained Session answers are separately checked after each source replacement;
the old snapshot remains unchanged. The collector still refuses retained
execution: fresh recomputation costs are not represented as Session costs.

The diagnosis found that trusted scalar field checks conservatively selected
the ordered path, which disabled the existing disjoint delta lanes even for
pure immutable Set rules. As a result, one complete supporting combination
could fire at more than one pivot. The evaluator now enables the existing
first-fresh partition on the already qualified fresh serial scalar Set route.
It also computes the first empty old lane once per rule/round and reuses this
fact to reject later pivots before matching. The check uses the same
=all-size == delta-size= condition already used by the native old-row accessor.
It is recomputed for the current cut, not cached by cardinality across cuts.

The two changes preserve each distinct full supporting combination while
removing repeated scheduling of that combination. They do not project away
support columns, fuse rule identities or discard different witnesses for an
equal head. Opaque callbacks, custom providers, lattices, retained sessions,
parallel and canceled engine routes keep their prior eligibility boundaries.
The existing row-order reference regression remains applicable.

Here a supporting combination means full ground premise values under Set
semantics at one source cut. It does not distinguish duplicate source-log
occurrence IDs, raw provenance graph nodes or all recursive proof trees.
Preserving those richer representations needs their own correspondence; this
patch does not certify graph isomorphism or occurrence-sensitive provenance.
