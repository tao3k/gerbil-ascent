* Still requests and index compatibility dispatch

The frozen Gambit source =lib/mem.c= uses =requested_words_still= in
=resize_heap= for an imminent still allocation. It first adds the
request to =occupied_words_still=, includes that charge in =adjust_heap=,
and subtracts the still occupancy when computing the maximum movable
section count. =___alloc_scmobj= then creates and registers the object
or rolls back the charge on allocator failure. An ordinary =##gc= passes
zero. A nonzero request is an allocation accounting protocol, not a
movable export reservation API. No ASCENT library call uses it as one.

A native Test under the 2 GiB maximum allocated a real 128 MiB byte
vector. One GC occurred during allocation. Its reported still charge
rose by 134,217,984 bytes, including runtime accounting beyond the
134,217,728 payload bytes. After dropping the only explicit root, the
following collections showed a still decrement of 134,217,568 and
134,217,360 bytes relative to that allocation collection. The last-GC
heap-size observations were 201,792,456 before allocation, 490,151,112
during it, and 509,025,848 after the second release collection. This
control does not equate any of those figures with RSS. Its first
version required an exact payload-sized decrement in the combined still
counter, which also accounts for other live objects, and failed that
assertion. The native logs are retained. The new guarded Lean
=still_request_charges_live_and_cap= states the source accounting before
reserve, history and section rounding. Evidence:
=/private/tmp/ascent-index-advance-suffix.O79Jva/still-charge.log=.

For index-entry reads, the generated compatibility procedure previously
collected every required argument in a variadic list, checked its length
and forwarded it through =apply=. The staged procedure leaves the four
required values in native argument slots and dispatches only the optional
order flag. The same transformation applies to the two required
