* Semantics and owner

=table/trrel-uf.ss= owns per-run, per-group SCC state. =table/storage.ss= now
constructs that state for =trrel_uf=; ordinary =trrel= retains its own owner.
The existing =table/trrel.ss= export forwards the UF extension to the new owner.
Direct internal callers must pair the UF extension with its UF constructor,
not the ordinary transitive-state constructor. Binary and grouped ternary rows
retain the admitted Provider's reflexive directed-closure behavior and exact
new concrete frontier, including false-valued/grouped keys and duplicates.

The design follows B23 §5.4's SCC/union-find representation seam, adapted to
Scheme's storage extension interface. It does not claim the original Rust
algorithm has been copied instruction-for-instruction or its complexity and
application measurements reproduced. See [[https://kmicinski.com/assets/byods.pdf][the paper]] and [[file:scheme-paper-closure.org][whole-paper closure matrix]].

* Insertion, refusal and compression

A group owns a value-to-node map and current component roots. Nodes carry
parent links, root-only immutable member lists, cached root size and a private
identity-keyed reachability table. There is no retained concrete-row membership
map or per-node predecessor/successor tuple index in the UF Provider.

For a new a->b edge, the missing frontier is computed from component rectangles
Pred(a) × Succ(b). Each missing rectangle expands to the member Cartesian
product; new admitted nodes supply their reflexive facts. Exact counting occurs
before frontier materialization or mutation. A budget rejection therefore
cannot install new nodes, change parents or mutate component reachability.
Parent lookups are read-only, so even unsuccessful preflight does not perform
path compression. No caller callback runs between counting and commit.

If b reaches a, exactly Pred(a) intersect Succ(b) forms the new SCC. Union
chooses the largest existing component, joins losing members and releases their
root tables. Surviving component edges are normalized to current roots;
internal edges disappear. Cached size avoids repeated member-list length scans,
and member concatenation copies losing spines while retaining the winner's
spine. Weighted union is an engineering design choice; a native logarithmic
parent-depth bound is not a proved claim in this patch.

A completed 64-node cycle concretizes to 4,096 rows while this Provider retains
64 node entries, one component and zero inter-component arcs. The public engine
still materializes rows for rule evaluation and results. This structural
compression observation is not a measured whole-engine memory saving. For a
DAG with many singleton SCCs, stored component reachability may remain quadratic;
rectangle traversal and merge normalization have costs that require controls.

* Qualified result at the rebased source snapshot

76 native modules and 648 Cases pass with parent exit 0 under the unchanged
1 GiB limit. Lean completes 64 jobs; the SCC TLC model explores 17,929 distinct
states (77,398 generated) and detects all three mutations. The first full run
had 76 passing children but failed parent final hashing with heap overflow and
is explicitly rejected. Hashing now streams through an 8,192-byte buffer;
an independent SHA-256 comparison covers empty/boundary files and the roughly
42 MiB native carrier using only a 128 MiB probe heap. Byte-boundary and tamper
checks remain permanent native suite cases.

In the 32-node matched Provider lane, DAG CPU median decreases 262.5 to 171 us
(43/50 paired wins); cycle CPU decreases 592.5 to 352.5 us (47/50 wins).
Wall wins are 42/50 and 48/50 respectively. Allocation moves in the opposite
direction: DAG 210,080 to 328,848 bytes; cycle 429,584 to 765,360 bytes, with no
allocation pair won. Thus structural SCC compression and fixture CPU reduction
are established, but allocation regresses about 57%/78%; overall Runtime net
benefit remains unestablished. Allocation/merge temporary reduction is the next
cost gate, alongside larger application and retained-state memory measurements.

** Finding and source boundary

This review reads implementation =93e81c1c3645197578073fd5481bf7195f16fd0b=.
It reopens B23 sections 3.3, 4 and 5.1 and S20 sections 6.3 and 7. The
following design is a proposal; no relation-view implementation, new theorem,
TLA trace refinement or measured benefit is delivered by this review.

B23 section 4 queries relation representations through logical indexes and
iterators. Section 3.3 requires total/delta coverage of the joined concrete
relation and inclusion of every newly implied fact in delta. Section 5.1's
space argument relies on retaining equivalence classes without retaining every
pair. These premises explain why a compressed private kernel alone cannot
supply the paper's whole-engine space result.

The native implementation has four concrete materialization seams:

| Owner | Current action | Consequence for compressed storage |
|-------+----------------+------------------------------------|
| [[file:../table/storage.ss][storage dispatch]] | =.extend-rows= returns a proper list; custom output is checked and copied | An implicit frontier is expanded before the evaluator consumes it |
| [[file:../program/initialization.ss][source initialization]] / [[file:../program/admission.ss][row admission]] | Every admitted expansion enters =all= and =present=; =delta= initially shares =all= | Provider compression does not remove engine row or membership retention |
| [[file:../program/evaluate.ss][evaluation]] | Derived and appended expansions update row buffers, sizes, membership and index versions | Changing only initialization cannot remove later materialization |
| [[file:../program/result.ss][result publication]] | Promises capture persistent row roots and defer their reversal; size observation forces those rows | Lazy ordering is not a lazy concretization of Provider state |

For a completed strongly connected active domain of n nodes, the UF view has
n squared concrete pairs. The engine retains those pairs even when the private
Provider has one SCC. This is a code-derived representation bound, not a heap
measurement. Outputting all pairs also takes at least n squared enumeration
steps; changing internal storage cannot remove that output cost. A sparse query
and a full result export must therefore be separate measurement conditions.

** Proposed ownership and semantic contract

A relation owner should retain a committed representation and issue immutable
views for the compiler's actual lookup requirements. Each view binds the
relation identity, source generation, representation revision and total/delta
lane. All keyed and full enumerators for that view must denote the same concrete
relation. Iterator progress belongs to an invocation, never to a shared mutable
cursor. The existing physical index receiver remains appropriate for explicit
Set rows; it cannot gain compressed semantics by omitting rows from its supplied
snapshot. That would violate its current complete-lookup admission contract.

For one completed positive cut, let O be the old concrete relation and N the
next concrete relation, with O contained in N. Require total union delta to
represent N, and require delta to include N minus O. Exact delta is the preferred
built-in contract because current graph kernels already satisfy it. B23 permits
some overlap; any future overlapping view must preserve authoritative head
deduplication and must not count overlapping enumeration as distinct facts.
Initial evaluation still needs full seed visibility, including empty-body
rules. Returning only injected edges does not satisfy this contract.

A UF frontier may be represented by component-member rectangles rather than a
list of pairs. A rectangle must retain the member snapshots from its own cut.
Closing a cursor over mutable parent links or current root membership is unsafe:
a later merge can change the meaning of an outstanding delta or old result.
Overlapping rectangles need either a proved disjoint partition or deduplication
with an explicitly accounted space cost. Compression of delta is therefore a
separate obligation from compression of total storage.

Keep logical fact limits distinct from physical allocation. A single compressed
rectangle may imply many facts; its small descriptor cannot bypass the existing
logical limit. Preflight must compute its exact new cardinality before mutation.
Source duplicates retain their existing input-count semantics. Derived facts
retain unique admission semantics. Changing those observable budget rules would
require a separate contract decision, not an incidental iterator optimization.

** Actors, failure and observation

Use one mutation owner per relation representation initially. Pure consumers
may receive frozen views through the existing actor scheduling path; each
consumer gets its own iterator. Readiness and reply credits must bind the view
revision as well as the existing work identity. Concurrent graph mutation is a
later capability requiring its own publication protocol and lawful Provider
implementation; Scheme green threads alone do not make mutable graph state safe.

Cancellation must drain users of a staged view before its backing state can be
retired. Failure cannot publish some new rows with old membership or sizes.
Source replay remains the recovery authority for a poisoned owner. Rebuilding
from a materialized closure would turn derived facts into sources. A published
result must retain a frozen representation or an owned snapshot independently
of later merges, replacement and actor cancellation. Full row export remains
explicitly materializing; keyed observations should not force that export.

S20's function-change translation has a different obligation: changes depend on
both a discrete base argument and its change. A compressed relation delta is
not a function derivative. Keep the higher-order descriptor/compiler bridge
separate while reusing only the established typed algebra where its premises
are met.

component counts alone closes this architecture gate.

* Frozen rectangle validation and design counterexamples (2026-10-07)

The first implementation unit now supplies native UF frontier and total views.
The private =uf-view= carrier retains immutable member-list roots in rectangles,
with an exact count computed before graph mutation. It retains no mutable node,
parent pointer, shared cursor or concrete tuple cache. Merge replaces member
roots; a held view keeps its old lists. Each enumeration creates fresh row
spines. Field objects remain borrowed, so this is a structural freeze, not a
promise that arbitrary mutable host values are immutable.

The existing =.extend-rows= implementation delegates to that same frontier plan
and materializes its list at the current engine boundary. Source initialization,
engine membership/index buffers and result publication still use explicit rows.
This unit therefore closes the frozen UF representation contract below; it does
not complete the whole-engine relation-view migration described above.

** Lean algebra and implementation premises

[[file:../packages/proofs/lean/ProviderRectangles.lean][ProviderRectangles]] proves twelve laws for actual finite member-list Cartesian
enumeration: rectangle membership/length, union membership/length, member and
rectangle-family uniqueness, exact frontier transport, total/frontier coverage,
first-column lookup, budget equivalence and duplicate-descriptor overcounting.
The cardinality formula is the sum of products of the member-list lengths.
Unique-fact counting additionally needs unique members and pairwise disjoint
rectangles. A correct Set observation alone cannot establish that condition.

The exact-frontier transport theorem assumes each rectangle family denotes
=N minus O=. It does not prove this premise from native SCC hashing. Native
construction freezes new singleton diagonals and every missing ordered
component rectangle before merging; independent graph checks below test this
correspondence. The snapshot freezes every reachable ordered root pair exactly
once. Group isolation is a native check; the Lean rectangle model is binary.
Native =equal?=, arbitrary field objects, allocation failures, compiler decoding
and UF state extraction retain their separate representation obligations.

Tests, defect examples and all twelve axiom reports are in
[[file:../packages/proofs/lean/Tests/ProviderRectanglesTests.lean][Tests/ProviderRectanglesTests]]. They include a bridge with four implied facts
but one descriptor, repeated rectangles with the same membership but twice the
count, a raw-edge delta missing an implied pair, empty rectangles and diagonals.
No custom axiom, =sorry= or =native_decide= is introduced.

** TLA protocol and fault discrimination

[[file:../packages/proofs/tla/ProviderViews.tla][ProviderViews]] models one outstanding reader, staged source cuts, atomic
publication, cancel/drain, view retirement, reply revision and logical budgets.
Cuts can repeat (including ABA). Generation ranges over natural numbers;
=Explore= constrains TLC enumeration only and is absent from =Spec=.
Rows are symbolic observations. The model does not recompute graph closure,
prove enumeration/cardinality algebra, or extract Gerbil mailbox actions.

| Deliberate design fault | Required violated invariant | Design correction |
|-------------------------+-----------------------------+-------------------|
| Read current mutable roots from a previously issued view | FrozenRead | Capture member roots at the original cut |
| Free backing storage when cancel is requested | ReaderAlive | Retire after the outstanding reader drains |
| Publish a candidate while it is still staged | AtomicPublication | One complete source/revision/result publication |
| Accept a reply from an earlier revision | CurrentReply | Admit the revision together with the reply |
| Accept a large implied relation by counting its small descriptor | LogicalBudget | Preflight logical fact cardinality |

These are seeded fault variants, not reports that the current actor engine
contains all five bugs. A successful fault gate requires TLC exit 12 and the
named invariant violation; parse failures and crashes are rejected. The native
view implementation addresses the mutable-root design fault structurally.
Reader retirement and reply admission remain temporal requirements for the
future engine integration, not implemented actor capabilities in this patch.

** Independent native correspondence and acceptance

[[file:../t/qualification/ascent-provider-views-test.ss][The native suite]] checks all 512 three-node graph subsets in forward and
reverse insertion order: 1,024 histories and 4,608 insertion prefixes. A separate
Boolean adjacency/Floyd implementation supplies total and exact-difference
truth. Each prefix checks count, frontier uniqueness/completeness, keyed reads,
held old total views, refusal at one below the required budget, exact retry and
zero-budget duplicate insertion. Additional controls retain a frontier through
later SCC merges, mutate an exported row spine, isolate false-valued group keys,
check reordered keyed columns and preserve the original list adapter's order.
The 64-node cycle has 4,096 logical rows and supports a 64-row keyed observation;
these structural counts do not establish allocator or whole-engine gains.

The new native module and both proof artifacts are registered in the existing
acceptance paths and GitHub formal job. The dated
[[file:evidence/scheme-provider-views-20261007/receipt.json][receipt]] records successful exits, source hashes and rejected preparation
attempts. Completing the remaining engine migration requires the existing
initialization/admission, evaluator, index and publication owners to consume
these views consistently, followed by the temporal and cost gates above.

One migration constraint remains visible in this unit: total-view enumeration
follows component traversal, while the current published engine result follows
fact arrival order. The list adapter preserves existing frontier arrival order;
the total snapshot promises complete unique membership, not that historical
order. The engine migration must resolve the public ordering contract explicitly.
Keeping a history of rectangle events may itself retain significant storage;
its cost must be measured rather than hidden behind a lazy result interface.

A further Lean counterexample blocks an invalid generalization to arbitrary
lattices. For a =min= key/value lattice, replacing winner 5 with winner 2 is
ascending in the abstract lattice order, but the exact tuple =(key,5)= disappears.
Thus a lawful join does not imply monotone Set concretization. Existing
=SemiNaive.iterations_equal= requires its =ViewMonotone= premise; the UF rectangle
unit cannot discharge it for general winner-row lattices. The new test makes
this false premise explicit. This is a proof-scope discriminator, not evidence
that every native lattice program fails. General lattice transfer needs its own
concretization and consumer contracts before the actor eligibility is broadened.

One candidate for preserving ordered full export is a persistent injection
journal with source/append events and derived-round boundaries. A frozen result
could replay only the deterministic native UF kernel when full ordered rows are
requested, while ordinary keyed reads use its compressed snapshot. The journal
must retain derived injections separately from source recovery logs; they must
never be replayed as authoritative sources during Session reconstruction. It
must also encode each round's historical emission orientation. Acceptance needs
exact legacy order, bounded full-export cost and measured retained journal size.
This candidate is not implemented here and does not promise linear storage for
arbitrary dense injections or DAG component reachability.
