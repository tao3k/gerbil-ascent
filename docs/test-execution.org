* Ownership
=build.ss= declares the production modules and the reviewed parallel test modules.
It uses native =std/make= for compilation and incremental dependency checks.
=just= exposes the existing commands and starts separate module processes with
=xargs -P=. There is no separate test framework in =tools/= and no Python runner
on the active build/test/performance entrypoints.

The real tests remain in =t/qualification/*-test.ss= and =t/performance/*-test.ss=.
Native =gxtest= discovers exported Suites; =std/test= owns Case execution, setup,
cleanup and assertions. The small =t/harness/gxtest.ss= adapter checks the
compiled library and propagates the native gxtest return value to the process.
The temporal harness retains its visible import boundaries.

* Compilation and isolation
Production and selected =*-test.ss= modules compile through =build.ss= into
=.cache/ascent/native-library/lib=. Native =gxtest= directly loads the compiled
=.ssi= test module and executes the original exported Suites and Cases.
The compiled library comes before the checkout in =GERBIL_LOADPATH=; otherwise
source modules can be interpreted and invalidate performance comparisons.
The table-expression paired fixture's baseline is compiled alongside production.
=std/make= checks source dependencies before each invocation; no custom fingerprint
cache duplicates its currentness logic.

A native =std/os/flock= lease protects a complete package invocation. The parallel
module pool finishes before exclusive modules start. Builds and performance
commands use the same lease. Children call the private Just recipes without
acquiring a nested lease. Independent invocations therefore cannot contaminate
timed Cases. No standalone scheduler tests are added: validation runs ASCENT's
actual modules and Cases.

* Commands
#+begin_src sh
just build
just check-policy
just test                    # capacity from GERBIL_BUILD_CORES / native CPU count
just test 12
just test-serial
just test-file t/qualification/ascent-rule-program-test.ss
just test-parallel
just performance-scenario ascent-table-expression
just performance
#+end_src

Module deadlines and Case budgets are unchanged. Every native test must produce
CASE-OK, MODULE-OK, HARNESS-OK and final OK with a successful process exit.
Failure markers, missing markers, overflows and nonzero exits fail the command.
Pool logs and temporary output stay under ignored =.cache/ascent/=.

* Evidence boundary
The first replacement-entrypoint run passed 46 parallel modules; the interpreted
retained-operator test module exceeded its original 120-second deadline. That
failed log is preserved in the cache. Native =gxtest= subsequently executed the
compiled version of that unchanged test module successfully with the same
deadline. This is an isolated result; the full compiled suite requires its own
completed run.

The final package-entrypoint run passed all 50 modules and 396 Cases, with
zero error markers and process exit 0. It used =GERBIL_BUILD_CORES=12=, compiled
test modules, and the unchanged module deadlines and Case budgets. Its logs are
local cache artifacts; this is local validation, not remote CI evidence.
A speculative contract-union optimization failed its paired Program admission
criterion and was withdrawn. No production speedup is claimed from that study.

Historical Python study collectors referring to the removed runners are archived
experiments. Use the native Just commands above for current qualification.

Additional local checks: the binary-program performance module passed, and the
ordered-relations native comparison completed twice (10 scenarios, 1000 pairs
per scenario per run). The table-expression SS scenario still exceeded its
original 120-second module deadline. No deadline or SS threshold was increased;
the full performance suite is not qualified by these results.
