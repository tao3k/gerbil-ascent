#+TITLE: Ordered lexical dependency admission

* Production flow and Gerbil source
=program/operator-analysis.ss= previously concatenated every child dependency
list before deduplicating it, including repeated paths through a shared DAG.
The new private merge consumes ordered identity sets. Empty and identical
spines are reused. For different sets, a native eq table admits only new right
members; if the right set adds nothing, the left spine is retained. Only a
changed result receives a fresh ordered header.

A binding filter copies a dependency spine only if its parameter occurs.
Fix binds exactly its own parameter; apply binds only its transform parameter,
then merges actual-input captures with external transform captures. First
traversal order is now implemented as promised by the original comment; descriptor
identity and invocation-local cache lifetime remain part of the lexical memo contract. Child cached lists are never mutated.

Gerbil SDK 1cfb032 =src/std/list/list-builder.ss:5-22= provides a hygienic list
builder with one private tail and owned result cells. The implementation uses
that native macro for publication of changed ordered sets, native identity hash
tables for admission, and =foldl= for input composition. No public constructor,
MOP receiver, build entry, runtime knob or SDK build was added.

* Native evidence contract
=reference.ss= freezes =cc7f360bcf6285863419522de10e7d00d07ec215:program/operator-analysis.ss=;
only its two relative production imports become absolute module imports.
Both A/B lanes are compiled symmetrically. Fifty alternating pairs time complete
graph validation, detached finite-source admission and scoped dependency
analysis, then collect dependencies for every node. An independent ordered-list
oracle checks identity sets in the baseline and exact identity/first-occurrence
order in the new implementation outside timing.

The public ASP benchmark API constructs and runs the fixture contract. Shared
DAG and unary-chain targets require >=20% CPU reduction and 35/50 wins. Closed,
tiny and source-only controls allow 110% plus 20us. Allocation gates are 110%
plus 4096 bytes. No build or qualification lane is launched by this run during
timing. These receipts do not claim whole compilation or solve speedups.

* Ordering correction and rejected evidence
SDK =src/std/list/list.ss:9-16= implements its exported =append-map= by folding
=cons= across every child list. This reverses each child's entries. The old
analysis therefore promised first traversal order in its comment but did not
implement it for multiple lexical parameters. A three-parameter example
produced baseline identity ordinals =(1 0 2)= versus independent truth =(0 1 2)=.
The new implementation fixes this private dependency order; every node still
has exactly the same lexical identity set as the frozen baseline.

Gerbil descriptors with identical fields can be =equal?= despite distinct
lexical identities. The initial structural comparisons and timings are not
admitted as final evidence. A subsequent strict identity comparison rejected
the baseline order. Final A/B gates require baseline identity-set equality and
new exact first-occurrence identity order; they do not claim unchanged baseline
list order. Qualifier assertions use the same explicit =eq?= comparison.
