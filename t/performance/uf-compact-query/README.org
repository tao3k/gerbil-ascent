* Gerbil source correspondence

Gerbil =1cfb032= =core/sugar.ss:933-973= binds admitted values before
entering their consumer extent. =std/list/list-builder.ss:5-24= owns fresh
result spines inside the consumer extent. The private
=with-compact-bindings= rule applies these two boundaries together: validate
all coordinate ranges, retain first key tails in three lexical slots, reject
conflicting repeats, then construct the selected consumer. A fixed false key
is an ordinary key tail; absence uses a separate false slot.

Binary and single-prefix indexed layouts are selected from captured schema,
not from selector order. Group constraints select the lowest descriptor cost among covered group and
endpoint routes, borrowing a frozen bucket or ordered axis plan. A group with
one descriptor publishes directly before costing other axes or constructing a
traversal closure. Multiple equal-prefix owners retain captured descriptor order. Two unscoped endpoint
bindings intersect frozen ordinal plans without a vector or prefix checks.
Sparse multi-owner plans intentionally omit single-owner keys. Missing plans
therefore use exact frozen owner buckets instead of admitting an empty answer.
The materializer chooses binary/group scalar publication once; complete
points and tiny/scan/mixed layouts retain their established flows. Partial
group queries use the same slots and exact owner membership, with no second
binding-vector initialization. Absent groups and conflicting conditions return
before allocating result builders. Every public checked consumer validates
ranges even after an earlier conflict.

* Fixed native A/B contract

=benchmark.ss= contains CPU, allocation and semantic admission policy.
=runner.ss= uses the existing ASP benchmark API through =paired-study.ss=;
=run.ss= and upstream native build scheduling own compilation. The Just recipe
is one standard native invocation with the unchanged 90-second parent budget.
No second test/build harness is introduced.

Each scenario has 20 alternating CPU pairs, 20 ASP admissions and five
allocation pairs, with eight identical consumers per sample. Every natural GC
remains charged to CPU. Reordered, conflicting and wide planning targets
require CPU ratio <= 0.90, at least 16 wins, and allocation ratio <= 0.80.
Controls retain <= 1.10 CPU plus 20 microseconds and <= 1.10 allocation,
including complete points, partial queries, detached wide rows, single-axis,
scan, capture, tiny capture and repeated tiny reads. Exact ordered row truth is
checked independently outside measured intervals.

=wide= consumes all selected pairs through the native checked parts API;
=wide-rows= materializes the same detached rows. This distinction is necessary
to report plan initialization separately from obligatory result allocation.
The initial draft demanding 20% less allocation for wide full-row output
failed four attempts; its receipts and original contract are retained in
=.cache/ascent/uf-compact-query=. That draft is not qualified. Earlier UF
study contracts and their full-row scenarios remain unchanged.

* Retained rejected experiments

The first grouped compact flow scanned every descriptor under a prefix. A
new fixed control with 64 groups, 32 independent SCCs per group and four
endpoints per SCC exposed CPU 1,168 -> 6,424 microseconds (5.5x), zero wins.

regression. The initial narrowed flow still allocated 160 extra bytes per

for a single captured descriptor removes that traversal allocation. All
failed receipts remain retained; neither gate was weakened.

* Model and implementation correspondence

Lean =compact_slots_acceptance= and =compact_query_refinement= establish that
three scalar optional bindings admit exactly the complete conditions when
compilation covers every repeat and retains only grounded values. Existing
conflict, ordered-filter and ordinal-intersection laws remain applicable.
=partial_plan_refinement= preserves the independent fallback when a cached
plan is absent. =narrow_routing_cost=, =narrow_routing_coverage= and
=narrow_routing_query_refinement= establish that cost selection cannot increase
the chosen cost or lose accepted rows when every candidate covers the query. This is conditional algorithm refinement, not a proof of the native compiler
or hash-table implementation.

Quint =Compact= retains first slot values and an explicit conflict bit;
=CompactQueryExact= checks repeated/reordered/partial queries against full
row filtering. =CompactRangeExact= rejects a late invalid coordinate after
an early conflict. =CompactFallbackExact= distinguishes missing cached plans from missing
endpoints. =CompactNarrowExact= checks route selection with different costs
and the same complete filter and order. All four new fault variants must be
rejected, alongside all 18 prior variants. The finite two-descriptor model is separate from larger
native owner/order regressions.

Native =t/qualification/ascent-uf-query-test.ss= compares materialization,
row streaming, checked parts and admitted parts against independent ordered
full-row filtering. New cases include interleaved equal-prefix owners, legal grouped single-owner holes,
lowest-cost single buckets, ordered multi-owner plans and uncached non-self axes,
borrowed canonical values, false keys, binary layouts, partial and conflicting
conditions, and late range errors. Python checks actual compiled API/ABI
against an independent UF closure, with wide/late-conflict/partial queries and
held cuts across owner retirement. Python does not schedule Scheme tests.
