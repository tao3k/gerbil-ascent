#+TITLE: Bound reachability across graph versions

* Research and scope

[[https://doi.org/10.1145/6012.15399][Magic Sets (Bancilhon et al., 1986)]] propagates bindings from a declared query into bottom-up deduction. With a fixed origin =s=, the two positive transitive rules specialize to =reachable(y) :- edge(s, y)= and =reachable(z) :- reachable(y), edge(y, z)=. A fixed target lets evaluation return on discovery. This design covers that rule pair over directed integer edges.

[[https://kmicinski.com/assets/byods.pdf][BYODS (Sahebolamri et al., 2023)]], Sections 5.3 and 5.4, motivates choosing a representation for the operations the relation needs. The existing condensed implementation is a good fit when it can amortize closure across probes. This workload favors a shared adjacency index and work proportional to demand after a single-edge edit. The physical index contains successor lists, rather than closure rows or a mask per SCC.

* Contracts and proof obligations

The query asks whether at least one edge connects the bound origin to the bound target through a directed walk. For a self-query, a self-loop or a cycle suffices. An empty pending list gives a completed miss. Discovering the target gives a hit whose reverse predecessor chain records edges from the same graph. A resource failure or cancellation aborts without returning a miss or publishing a graph.

An index snapshot owns two cold integer-key hash tables and two persistent trees of changed buckets. A changed edge replaces one successor bucket and one predecessor bucket. A deletion that empties a bucket masks the cold entry. A successful edit issues a fresh identity even if its edge set is unchanged. An older graph remains usable and can verify its own witnesses. Other versions and branches reject the witness even if the path still exists. Witness vertices are returned as a caller-owned list. This interface supplies one positive path witness. General ASCENT provenance and existing result traversal continue through their existing interfaces.

The one-way reference rejects an empty successor or predecessor bucket before creating a worklist. For a distinct target with one predecessor, it starts from that predecessor and walks the transpose. Other queries start from the origin's successors. Both directions use the Gerbil standard FIFO queue and mark before enqueue. A self-query can only return after discovering an edge into the origin. The reverse search normalizes its chain before issuing a witness.

| Native operation | Lean correspondence |
|------------------+---------------------|
| Scan the origin's successors before entering the worklist | =seed_iff=, positive rather than reflexive reachability |
| Mark on discovery and enqueue a pending vertex at most once | =GraphWorklist.enqueue_wellformed= and the order-independent =RuleGraphClosure.visit_invariant= |
| Stop at target discovery or empty pending queue | =chain_positive= for a hit and =exhausted_fifo_iff= for a miss |
| Reject an empty target bucket, or traverse the transpose | =no_incoming_is_miss= and =reversed_index_exact= |
| Shadow the affected buckets and insert or delete just one edge | =index_write_exact=, =set_edge_exact= and =edit_preserves_mirror= |
| Normalize a reverse witness and replay it against the same version | =reverse_chain_checks=, =check_positive=, =witness_sound= and =other_version_rejected= |
| Abort after a checkpoint or budget failure | =failed_not_miss=, with native exception paths tested independently |

The kernel checks the abstract worklist and pointwise bucket update. =GraphWorklist= uses a list order. The =RuleGraphClosure= invariant used by the native FIFO is independent of the choice of pending vertex. Gerbil hash equality, tree ownership, queue operations and dynamic cancellation are checked through source review and native tests. No extraction of Scheme code is part of the proof.

* Scheme interface and cost

The =gerbil-ascent/program/api= module exports the opt-in graph interface. Open accepts a proper list of two-fixnum rows, removes duplicates and admits each row against the work budget and each distinct edge against the edge budget. Edit returns the new immutable graph, changed bucket count and actual old-edge reads. Query returns a witness or false, and actual searched edges. Path export returns independently owned pairs, and replay checks the version before reading its edges. The work budget charges every build row, bucket edge visit or copied prefix cell, pending dequeue and witness copy or edge comparison. The existing execution control also receives these work checkpoints.

Cold construction makes one pass over the input with expected linear hash work. Each changed edit examines at most the two endpoint degrees, copies at most those two prefixes and path-copies the affected red-black tree branches. Each query examines only the chosen reachable region and stops on discovery. Its worst case still reaches the whole region, with one queue admission per discovered vertex. It retains no per-query cache on the graph. A retained witness owns its chain and a version token, rather than a reference to the source index.

* Experiment and cost accounting

Use the complete [[https://snap.stanford.edu/data/p2p-Gnutella25.html][SNAP Gnutella25 snapshot]] with 22,687 endpoints and 54,705 directed edges. Record the compressed SHA-256. Select origins of different out-degrees, unreachable pairs, self-cycles and single-edge deletions/restorations. Generate edits from the snapshot and describe their selection. This is a real topology with controlled edits. The snapshot alone does not establish historical edge churn.

Compare the existing direct Scheme and Actor Sessions using both forward-bound and reverse-bound unary rules and a singleton answer relation. Delete by replacing the source and restore by the existing single-row append. Use a standalone full FIFO traversal over a dense vector as the dataset oracle, and Boolean matrix closure for exhaustive small graphs. Record cold preparation, update, first query and witness separately. Report per-sample combined latency before taking quantiles. Record positive-plan work in a separate fresh serial solve, where the existing collector is supported. The retained Session timing lane supplies Boolean answers and does not expose path witnesses or physical index counters for this rule.

A hundred-fold performance claim requires comparable measured wall time on the same work and a successful baseline. An edge-count ratio alone is a work reduction. Exporting every row retains its output-size lower bound.

* Two-frontier candidate

For distinct endpoints, start one rooted FIFO at each endpoint. The second FIFO traverses the transpose. Advance the FIFO with fewer pending vertices, preferring the forward queue on a tie. The first scan uses the reverse root when its bucket has one edge and the forward root has more than one. Each scan looks for the other side's seen set before admitting a new vertex. A meeting across a scanned edge supplies a nonempty directed path. The witness combines the forward chain with the backward chain after removing the duplicate meeting vertex. An emptied FIFO proves absence only after a complete scan and while the two seen sets are disjoint. Equal endpoint queries keep the existing positive one-way search, which detects a real self-loop or cycle.

The algorithm reuses both existing versioned adjacency indexes. It adds query-local state only. Empty source and target buckets still return immediately after the cancellation check. A singleton outgoing bucket is charged and scanned before allocating either frontier. When its edge leads elsewhere, the forward queue starts at the resulting successor. Each examined edge, non-root dequeue and witness-copy step still charges the existing work budget. The first bucket scan at either root is initialization. An exhausted or canceled operation yields no answer.

Both frontiers use one integer-key seen table. Forward chains are nonempty pairs and backward chains use a private tagged record. A lookup therefore gives the absent, same-side, or opposite-side case without a second hash probe. A self-query uses the reverse root tag as a target marker and has no reverse FIFO.

In Lean, =meeting_positive= proves the edge join, =exhausted_disjoint_miss= proves queue exhaustion independent of scheduling order, and =stitch_checked= aligns the witness list with the existing verifier. =edit_preserves_mirror= is the index premise and =shared_seen_disjoint= ties the tagged lookup to the two disjoint seen sets. =failed_not_miss= and =other_version_rejected= continue to apply. These are proofs over the corresponding transitions and lists. The native tests check queue operations, mutable hash tables, checkpoint sequencing and witness ownership.

An independent edge-count screen held the 32 file positions fixed. Nearest-rank P95 was 32,836 edge visits for the one-way reference, 1,920 when selecting by the next bucket degree, 633 when weighting pending vertices by that degree, and 551 when selecting by pending vertices alone. Selection uses queue length because it had the smallest measured P95 and reads the queue's stored length to decide which queue to advance.

* Split and merge over existing integer adjacency

The [[https://github.com/tao3k/gerbil-poo/blob/30fe206fcdf93c21d94ad00682a26150cf7a321a/strong-components.ss#L721][POO compact SCC traversal]] marks a lowered discovery word with one
flag bit. On postvisit the active parent link is read before a vertex
becomes a follower or retires. A leader retires its eligible followers,
and retired vertices cannot lower an active discovery word. The ASCENT
repair traversal uses the same state transitions for list suffixes and
packed row offsets. The condensed Session walks its existing packed rows
and keeps the current dense ordinals.

A verified reverse bridge deletion or restoration copies the adjacency
vector header and edits only the affected origin row. Every other row
and the sorted vertex labels remain owned by the prior publication.
Deleting a non-self edge within a component leaves both endpoints
incident to the graph. The repair borrows those vertices and rebuilds
the quotient from the changed rows. Quotient edges run from earlier to
later components because sink-first retirement is prepended.

Checkpoint calls cover root probes, each arc, postvisits and follower
retirement. The Session keeps the next index private through closure
construction, fact limits and the owner's acceptance check. Existing
Results retain their path witnesses; the repaired Result issues its
own version. A one-way bridge between existing components stays on the
incremental quotient path.

The =BorrowedAdjacency= section of =SccState.lean= checks the low-word representation, the
direction of retirement ranks, unchanged adjacency rows and refusal
before publication. The native graph oracle checks the complete mutual
reachability partition and quotient order independently of the
implementation's discovery state. These obligations do not constitute a
proof of the complete SCC implementation.

** Quotient construction and first-origin cost

The SCC traversal in =core/dependency-graph.ss= inspects the admitted
adjacency with cancellation checkpoints. Its result supplies a dense
owner for each vertex. In =program/condensed-closure.ss=,
=condense-adjacent= then constructs direct component masks, closes them
in reverse topological order, and indexes runs of ordered labels. Those
are separate costs. =source-slot-packed-extra= checks the full ordered
one-edge edit before either graph stage.

=QuotientConstruction= in =packages/proofs/lean/ComponentClosure.lean=
connects the direct-mask changes to concrete edges. A partition with
one component and a nonempty adjacency has exactly one direct bit. A
nontrivial component has an internal edge, so its self bit can be seeded
once. Singletons still require an explicit loop. An inter-component
edge contributes the same bit whether it is the first or a subsequent
concrete edge between its owners. The cost model counts a quotient
arc probe per stored edge for a multi-component rebuild, and zero for
a one-component rebuild. The latter still runs the partitioner and
still checks the token, label order, fact limits and publication.

The first single-origin visit goes through =gerbil-ascent-visit-snapshot!=
and =parts= to the retained run index or the deferred per-group target
list. The ordered-run route pays one mask probe per run and visits each
selected label once. An unchanged binding emits each visited label. =ordered_runs_select_exact= and
=single_origin_run_cost= capture the selected order and number of
emissions. On the global restoration workload, all 3,200 labels belong
to one run. That route performs no deferred target sort. A native
source benchmark also includes the client callback and scheduler time.
Record wall, process CPU, allocation and GC for the same query sample
before attributing a tail to any of those costs. A source-loaded versus
compiled client control holds the production provider fixed and
changes only the client module, including its visitor call site and
callback. The retained Result's witness still traverses that
publication's original adjacency.

The local reference packs 71 cliques of 64 vertices in a one-way chain.
A return edge between the final two cliques changes only their SCCs.
The independent count is the sum of the triangular chain rectangles
plus one rectangle of 64 squared rows when the edge is present. It has
10,469,376 and 10,473,472 logical rows respectively. This case compares
global rebuild cost with an update whose affected component membership
is small, even though reachability has a large predecessor cone.

Local partition repair would restrict traversal to the 128 affected
vertices and their 8,065 or 8,066 internal edges. Reusing an unchanged
component also requires preserving its outgoing edge summary and
relating its owner ordinal to the next version. A local partition by
itself leaves whole-cut validation, source replacement and remapping
the reachability masks outside that region in place. Measure these
costs separately before choosing the update path.

** Versioned single-edge edits

Open the Session with =gerbil-ascent-open-condensed-actor-session= and
run its initial source. Submit an edit as
=(gerbil-ascent-session-edit-edge! session current-result 'edge 'delete left right)=
or use ='insert=. The call returns the next published Result.
The owner compares the caller's completed Result with the current
publication and admits an edit only on an idle, clean condensed Session.
Deletion removes one existing edge. Insertion appends one
absent edge to the source order. Endpoints must be in the admitted
vertex dictionary. A persistent ordered source journal shares the
original owned source and retains the surviving additions in insertion
order. The worker edits a private adjacency row and publishes only on
owner acceptance. Input, derived and output limits keep their existing
meaning. A Result and its witnesses retain the source cut they captured.

An intra-component delete partitions only the old component. A path
between two of its members cannot leave and return through the acyclic
old quotient. An insertion that closes a quotient cycle merges exactly
the intersection of the old forward cone of the destination and the
old reverse cone of the origin. A retained component's immutable member
list supplies its identity across cuts. Dense mask ordinals are local
to each cut. The next cut translates the retained direct masks, scans
the old component's changed members and resolves incoming targets
that refer to the split component. Merges map the old ordinals to one
new owner without reading their internal concrete arcs. The resulting
acyclic quotient supplies the next reachability masks.

The =VersionedEdgeEdit= section of =ComponentClosure.lean= checks the
induced path, merge cone, direct destination translation, source
selection and refusal properties. The source keeps cancellation checks
at the restricted SCC walk, affected edge and quotient traversals and
owner publication. Native tests check the integrated Session, including
stale edits, source order, aliasing, resource exhaustion and replay.

** Live roots during a full-component split

A published result carries its own admitted source and the index used
by its witness. During an edit, the Session also keeps the last
completed result until the worker passes owner acceptance. The
source journal shares its numeric base, and the two adjacency headers
share every unchanged outgoing row. The full-component benchmark
holds the caller's original fact list through the edit. A bound
first-origin visit follows the retained index without constructing
the whole logical closure.

The phase observation uses the SDK's post-collection hook with counters
only. Matched retained-root controls hold the loaded test, caller list,
source slots, adjacency, or completed Results across collections. The
controls identify differences in accounted live bytes and GC time.
The runtime does not tag scanned bytes with Scheme ownership or retain
an object census for an earlier pause.

The condensed index owns packed successor rows. Only dense ordinals
below 8,192 occupy the unsigned 16-bit cells, and the ordered label
table keeps caller labels at their original width. The shared SCC
walker resumes a packed row by an offset with the same meaning as
the previous ordered list suffix. =splice-neighbor= copies the
changed row, and the edit borrows every unchanged row through its
new adjacency header. The previously published index remains available
for witness replay and rollback. Public row and witness lists keep
their existing ownership and order.

The packed-row theorems in =SccState.lean= check the ordinal round trip,
cursor suffix, splice order and unchanged rows. The same model counts
201,713 successor pairs across the fixture's two initially held
adjacencies and 3,201 buffers for the packed form. The latter store
unboxed ordinals. Neither object count measures collector scan bytes.

** Timing a versioned Actor edit

The public call enters =request= in =program/actor-session.ss=. It
captures the authority and reply completion, takes the lifecycle
mutex, and sends one envelope. The owner takes the envelope in
=dispatch-request!=, checks the completed Result, and prepares the
prospective source cut. =start-resident!= makes the job visible to
the resident worker. The worker takes the job and computes the next
index and Result in its own dynamic extent.

The worker sends the outcome back to =finish-resident!=. The owner
accepts and publishes in =finish!=, after checking epoch, worker,
completion and authority. Completion posting then makes the reply
available to the original caller. The boundary between publishing
and delivery is distinct from the boundary between finishing
evaluation and the owner taking the outcome.

A diagnostic can place monotonic marks before both sends, at both
receives, at evaluator entry and exit, at owner publication and at
completion delivery. Additional marks separate mutex acquisition,
enqueue return and completion posting. =edge_edit_clock_partitions=
proves the principal intervals sum to an individual edit. Process
CPU and GC counters at the same marks help distinguish work from
wall time outside measured CPU. Interval percentiles are considered
separately and are never added into an end-to-end percentile.

The operating-system diagnostic optionally reads the current task's
runnable counter alongside the Scheme marks. On Darwin that counter
aggregates runnable thread time in Mach clock ticks, including CPU
time. Counter updates can straddle an interval boundary. It cannot
identify a competing task or assign the entire elapsed gap to one
thread. Keep this diagnostic out of the acceptance run.
[[https://github.com/apple-oss-distributions/xnu/blob/main/osfmk/kern/task.c#L6386-L6434][XNU task accounting]]

During evaluator admission, =gerbil-ascent-condensed-closure-view=
determines the number of target vertices in each reach mask before
accepting the derived and output counts. The sum is the population of
the mask times a common component size, plus the signed deviations of
selected components from that size. =centered_target_count= proves the
equality, including negative deviations. An edit without an external
work meter can use this count when checking the deviations costs less
than walking the selected components. It still checks cancellation
before each mask and while traversing deviations. An edit with a work
meter keeps the original per-target work checkpoints. Query order,
source ownership, and witness traversal use the same packed index.
