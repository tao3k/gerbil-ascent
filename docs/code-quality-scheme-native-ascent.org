#+title: Code Quality: Scheme-native Ascent

* Source picture

#+begin_example
syntax                   declaration analysis         execution
program/syntax.ss ------> program/planning.ss -------> program/evaluate.ss
program/scheme-language.ss       |                            |
         |                        v                            v
         +----------------> program/funs.ss              table/funs.ss
                           strata and terms             row indexes
#+end_example

The two syntax surfaces have different contracts. The historical
=ascent= form admits general Scheme expressions and patterns and is
kept for the Rust-oracle qualification path. It is not re-exported by
=program/interface.ss=. The native public =relational-program= form has
a checked scalar grammar and an admission boundary. Shared machinery
must preserve that distinction. =program/analysis.ss= caches immutable
declaration plans, while =program/evaluate.ss= owns mutable relation
state and retained-session behavior.

* Feature: lattice rows and term binding

=program/funs.ss= extracted a lattice key with two reversals and a
lattice value with another reversal. It now uses =butlast= and =last=,
with an explicit nonempty check for the private key helper. The
evaluator also calls key and value separately in some paths, so a
single extraction at the caller is a possible later measurement target
without adding a new public helper.

=gerbil-ascent-bind-row= is a compact state machine. Its invariants are
repeated-variable equality, pattern result arity, and shadowing order
of newly bound variables. A =match= rewrite is desirable only if those
invariants become easier to see and the errors stay stable.

Relevant qualification: repeated-variable, lattice, pattern, rule,
and invalid-program fixtures. Record values, row order, and errors.

** Checked binding and identity storage

=program/objects.ss= now retains raw atom terms for admission and
index-key planning, and prepares a separate binding-term list. A
=fresh-variable= term is permitted only when the name is absent from
earlier clauses and earlier terms of this atom. At row time that term
conses its binding directly. Repeated variables, pattern outputs,
expressions, and externally bound names retain the original checks.
This removes environment searches for first variable occurrences;
it does not change the public term grammar.

A separate experiment bypassed identity storage wrapping for the exact
built-in Set Provider without field callbacks. It was reverted because
matched whole-solve measurements did not qualify a stable gain. The
retained evaluator changes only the three atom-binding calls to use
prepared terms. Storage admission, duplicate accounting, budgets,
custom Providers, and field callbacks keep their original paths.

The frozen binder and evaluator in =t/qualification/= come from
=74f0046bb6137b4fce22db5ae398b9812734c137=. The evaluator oracle
uses original raw binding terms, while both evaluators share current
declaration metadata. The finite binder comparison covers 99,999
combinations of term shape, binary rows, and prior environments,
plus pattern, expression, false-value, and error goldens. Source
admission qualification covers duplicate order/counts, row mutation,
nullary facts, budgets, custom Providers, and stateful callbacks.

Performance qualification uses =just binding-benchmark= with identical
optimizing compilation and 1000 alternating old/new pairs per case.
It excludes cold declaration construction. Wide binding kernels
require at least 900 paired wins and median nonregression;
individual solves are median nonregression controls.
The initial individual projection measurements failed the experimental
900-win gate (854/1000 and 882/1000 in the last initial run). An
eight-evaluation batching experiment also failed at 705/1000 wins for
width 16 and timed out before completing width 32. Neither experiment
supports a retained whole-solve optimization. No stable
individual-solve speedup or tail-latency improvement is claimed.
The original SS 1000-sample, 2 ms p95 gate remains unchanged.

* Feature: indexed relations

=table/funs.ss= builds bucket order by reversing the current relation
snapshot once and then prepending each row. This is intentional.
=hash-update!= with an empty-list default passed the index qualification
but was reverted after a broader test hit a time budget. The same
time budget failed after the revert, so that test does not attribute
the anomaly to either hash implementation. The existing standard
=hash-ensure-modify!= remains the clearer bounded choice here.
=gerbil-ascent-index-key= uses =list-ref= for each selected column;
its cost grows with both row width and selected columns. A single
pass over the row could help wide composite keys, but arbitrary
column order must be preserved. Use the existing index-program and
BYODS cases plus a matched wide-row probe before choosing an algorithm.

* Feature: stratification and dependency cycles

The initial implementation used stratum relaxation and repeated
reachability searches for strict-cycle diagnostics. The second round
below replaces it with SCC condensation while preserving minimum
strata, diagnostic kind, and encountered-edge ordering. The rule
summary and relation stratifier share Tarjan traversal but retain
their different vertices and output contracts.

* Feature: finite selection and admission

=program/operator.ss= lowers =select-eq= into a singleton source relation
plus an equality join. A direct literal term in the body and head was
tried locally. It removed one relation and allowed a smaller source
budget, and it passed the finite selection and operator qualifications.
A paired native probe then compared the original declaration order and
source handles with the literal version, under equal budgets and with
independent expected-row checks. At 64 and 256 source rows, most
alternating admission-plus-solve samples for the literal version were
much slower, despite noisy host timing. The experiment was reverted;
the singleton join remains the implementation. Do not infer a runtime
gain from the smaller rule shape.

=program/scheme-admission.ss= used to copy Core relation rows before
calling =relational-source=, which checks and copies them again. The
snapshot now delegates that single copy to =relational-source=. A
mutable Core input-row test changes the caller's list after admission
and confirms the admitted result stays unchanged. Retained replacement
and append paths had the same duplicate =relational-source= validation
after =relational-copy-rows= had already checked scalar values, arity,
and copied the row lists. They now send that checked copy directly to
the native session. Append uses the existing single-row validator and
copier directly, without building a temporary one-element list.
Existing replacement rollback and isolation cases,
plus a new append isolation and non-scalar case, protect the contract.
These are fewer copies at the boundaries; their runtime benefit still
needs a matched measurement rather than an inference from shorter
source.

The reproducible boundary probe is =just admission-copy-benchmark=. It
runs the old and new operations in one Gerbil process, checks equal
rows and independent list spines after every sample, warms both paths,
and alternates their order for eight pairs per case. Bulk admission
and replacement use 512 two-column rows, 20 repetitions per timed
sample; single-row append uses 1000 repetitions. Timing starts inside
the loaded process, so Gerbil startup is excluded. This measures row
copy and validation work only; it does not measure a complete retained
solve, rollback, or application latency.

* Feature: syntax boundaries

=program/syntax.ss= and =program/scheme-language.ss= both lower atoms,
negation, and reducers. Their generated objects and error paths must
be compared production by production before sharing code. Keep
lexical fragment handles hygienic, preserve source locations and
diagnostics, and never broaden the public checked scalar grammar
to accept arbitrary callbacks. An extra macro that hides one runtime
call would make the layer harder to read.

The current =relational-atom= and =relational-atom/lexical= expansions
look alike but quote a relation spelling versus evaluate a lexical
handle. That difference is the ownership boundary, so a common
expander would need to keep it visible. =relational-copy-row= and the
operator project constructor use =map identity= to copy list spines
before retention; these are intentional copies, not redundant maps.
The contract in =docs/native-library-acceptance.org= also keeps the
historical =ascent= syntax on the test path, so deleting or folding it
into the native language would be a separate interface change.
The same snapshot-copy pattern appears in =candidate/reasoning.ss= and
=program/scheme-admission.ss=. Its presence across those boundaries
is evidence of an isolation rule, not a reason for a blanket rewrite.

* Second round: SCC stratification and reusable graph analysis

The installed Gerbil Compiler gives three concrete lessons for this
implementation. =compiler/optimize-xform.ss:16= registers handlers by AST
form with =defcompile-method=; =compiler/optimize.ss:27= creates pass-local
mutator and type tables before traversal; =compiler/optimize-call.ss:43=
specializes calls after resolving their operators and checking safety.
The applicable pattern is to move declaration work into checked planning
and keep mutable execution state local. The compiler's method hierarchy
and unchecked-call machinery are not needed for this graph algorithm.

Previously =program/funs.ss= relaxed every dependency edge until the
strata stopped changing. A reverse-ordered strict chain required one
pass per relation, giving worst-case =O(V*E)= work. Cycle diagnostics
then searched reachability separately for strict edges.

=program/graph.ss= now owns the Tarjan implementation formerly embedded
in =program/summary.ss=. Both the rule summary and relation stratifier
use it with their own vertices and edge metadata. A strict edge within
one SCC is rejected, selecting the first invalid dependency in the old
ordering to preserve aggregate, negation, and lattice-projection error
messages. Every positive SCC receives the maximum incoming level; a
single source-before-consumer pass propagates the minimum strata.
Graph analysis and propagation take =O(V+E)= work. Programs containing
only positive dependencies use stratum zero without building SCCs.

The frozen relaxation oracle in
=t/qualification/ascent-strata-fixture.ss= comes from commit =74f0046=.
The qualification test compares 6,656 three-node graph configurations,
including single strict edges, mixed strict kinds, and lattice
projections. Additional checks cover a positive SCC with a strict
incoming edge, empty declarations, and duplicate dependencies. All
strata and concrete cycle diagnostics matched the oracle.

=just strata-benchmark= compiles current planning and the oracle into one
isolated output directory with identical optimizing =std/make= settings.
It alternates old/new execution for
1000 samples per case, checks exact strata outside every timed span,
and retains all samples plus source hashes. The 32-relation positive
case batches 32 calls per sample to resolve sub-microsecond differences;
strict chains use one call per sample. The matched gate requires no
median regression and at least 900/1000 wins for strict chains.

Two consecutive runs passed all four matched cases. Strict-chain
planning medians improved from 5 to 3 us at 32 relations, from 59 to
10 us at 128 relations, and from 235/230 to 20 us at 256 relations.
Each strict-chain case favored the candidate in 972--985 of 1000
pairs. The positive-case median also improved.
=t/performance/strata/README.org= records the
protocol and links the retained raw samples and source manifests.

These receipts measure planning over prebuilt lowered rules. They
exclude declaration construction, POO admission, fixed-point solving,
and process startup. They do not establish a full evaluator speedup.
The existing =ascent-indexed-joins= SS fixture still uses 1000 samples;
a local run completed in 28 s with correct rows but p95 =10.372 ms=,
which failed its unchanged =2 ms= gate under heavy host load.

An earlier experiment cached selected atom terms alongside index
columns. The literal/expression/variable regression passed, but there
was no matched full-solve gain, so the production and fixture changes
were reverted. The retained row-key implementation and index plans
remain as at =74f0046=.
