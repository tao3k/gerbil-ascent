* Representation and execution

- Complete uniform keys reuse the captured membership schema. Candidate routing
  retains descriptor order and a scalar point visitor publishes exact stored
  representatives without binding vectors, query records or singleton lists.
- Long axes probe the four values exposed by the existing five-cell shape test,
  then fall back to exact frozen owner routing. Short axes use membership scans.
  Tail and absent controls prohibit replacing owner routing with full long scans.
- Selected materialization constructs only its scalar or product collector.
  Nonpoint queries enter the product flow once, avoiding repeated schema checks.
- At most two descriptors use constructor-local identity associations. A scoped
  =defrule= binds that profile once; the large path keeps native identity tables.
- Tiny cuts do not build multi-owner ordinal plans. Other cuts first use
  =hash-find= to establish that a multi-owner plan is needed, then bind private
  tables immutably. Published tables remain read-only.

These choices follow actual installed Gerbil sources: compiler
=optimize-base.ss= (constructor-owned fields and =!class-method-table=), runtime
=hash.ss= (=hash-find=), and =std/list/list-builder.ss= (scoped collectors).
Conditional initialization must not turn hot table bindings into mutable
closure boxes; that rejected implementation is retained below.

* Fixed study

Twelve scenarios, 20 alternating natural-GC CPU pairs, 20 ASP admissions,
five allocation pairs and eight consumers per sample are fixed before final
qualification. The grouped target requires CPU <=0.9 and at least 16 paired
wins; grouped and tiny-capture allocation require <=0.8 with zero absolute
allowance. All other CPU controls retain <=1.1 plus 20us and allocation <=1.1.
Repeated-small retains all 4096 queries in the existing four 1024-query
allocation legs; negative counters and failed legs are errors. CPU is unsplit.

Tail/absent points are explicit controls. Capture is measured separately from
prepared query consumption. Exact ordered Cartesian answers and counts are
checked outside sampling for both arms. Input and source bytes are frozen for
each run; all generated artifacts remain under ignored =.cache/=.
