#+title: Scheme Coding Style: Data representations and lookup results

[[file:../scheme-coding-style.org][Coding Style index]]

* Applied: private proof expression and binding flow

=candidate/proof-frame.ss= follows Gerbil's compile-before-execution pattern and
invocation-local facts. Closed term operations become private final records and
ordered continuations; relation/variable names are resolved during preparation.
Public proof values retain their existing protocol. Preparing syntax does not
validate an external predecessor, source row, digest or answer.

One fresh dense frame owns a linear rule derivation. Absence uses a private
marker distinct from #f. Successful prefixes prove first/repeated bindings;
fixed computation still refuses a bound output, and following atoms check its
computed value. Pure guard facts belong only to that prefix. Failed checks
discard the frame rather than publishing partial bindings to another node.
The independent verifier never borrows producer membership or verdict caches.

The complete six-consumer A/B and negative variants are recorded in
[[file:../../t/performance/proof-verification/README.org][proof verification qualification]]. Target improvements are 19.3%/19.9% CPU
for wide/mixed verification. The small control adds 3us and 7840 bytes; private
preparation overhead remains part of the full consumer, not hidden from timing.

* Upstream source patterns

The installed Gerbil =2591dcd= compiler makes fixed record fields visible:

- =compiler/base.ss:89-96=: =symbol-table= names its =gensyms= and =bindings=,
  with fresh tables allocated by its initializer.
- =compiler/base.ss:295=: =compile-executor= names its =submit= and =close=
  operations. Code reads the role of each field rather than a numeric slot.
- =compiler/compile.ss:1501-1512=: =meta-state= and =meta-state-block= name the
  source, phase and code fields used by generation.
- =compiler/optimize-base.ss:63-76=: =!class= names its hierarchy, fields,
  constructor and method metadata, while preserving the record's own identity.

The standard library also makes absence explicit:

- =std/hash/misc.ss:104-121=: =hash-ref/default= and =hash-ensure-ref= use
  =absent-value=; a present false value does not invoke the default thunk.
- =std/hash/misc.ss:250-256=: =hash-ensure-removed!= returns both the value
  and a presence flag, so a removed false value differs from a missing key.

These representation choices follow field meaning and observable contracts.

* Representation choices in ASCENT

| Role | Representation | Reason |
|------+----------------+--------|
| Fixed storage-state fields | Private named records | Field meaning and mutation ownership are explicit |
| Dense graph vertex tables | Vectors | Numeric vertex addressing is the algorithm's representation |
| Certificate wire projection | Ordered lists with explicit field projection | Historical bytes and protocol versions are observable |
| Candidate variable bindings | Association entries | Entry presence is distinct from the bound scalar value, including false |

The certificate and binding boundaries retain their current formats. A
truthiness-based default cannot replace an entry-presence test when false is
a legal row value. Dense algorithm vectors retain their numeric addressing.

The storage indexes have a narrower value domain: component objects, true
membership markers or neighbor lists. Their existing =hash-get= lookups retain
an unambiguous missing result. Candidate bindings inspect association-entry
presence separately from a potentially false scalar value. Each lookup follows
its actual value domain.

* Applied: named private storage state

=table/eqrel.ss= previously encoded each shared component as a two-slot vector.
It now declares =eqrel-component (members size)=. The component's identity still
unifies all of its member index entries. Union-by-size reads the named size;
only the small component's keys are rebound, and member order is unchanged.
The cached size remains part of the same component object.

=table/trrel.ss= previously returned a three-slot vector from its state factory.
Its private =trrel-state (known predecessors successors)= record names the
membership and directional indexes. The factory allocates three fresh tables
per provider run. The record accessors are private to the module; consumers use
the existing state factory and extension functions. Raw vector indexing is no
longer a supported way to inspect this opaque provider state. Repository
consumers already treat it as opaque and require no migration.

Budget preflight, row publication, component merge order, reflexive/nonreflexive
semantics and provider dispatch retain their existing code. Provider entry
points retain their signatures and each provider run owns its mutable state.

Existing native Unit Tests independently model the closures and check ordered
publication, grouped isolation, budget rejection/retry, retained sessions,
concurrent runs and custom composite indexes. These tests exercise the public
provider contract. No measured
performance gain follows solely from changing the representation.

* Local verification

Against source baseline =c8ddcd3=, native BYODS invariants pass seven Cases,
complete BYODS programs twenty-four, and custom BYODS indexes two, for 33 Cases
in total. Every module has final native/module/harness markers and exits 0.
Original budgets and timeouts remain unchanged. Source comparison, mapping
record constructors/accessors back to their prior vector operations and
excluding comments, confirms that all remaining algorithm forms are unchanged.

Production source policy exits 0 with =findings=2 errors=0=. Both existing
warnings belong to =program/finite-arithmetic.ss=; the changed storage modules
introduce none. Coding Style links, paired Org blocks and diff formatting pass
static checks. Logs stay in ignored =.cache/ascent/storage-state-records/=.
These focused local checks do not establish a whole-suite, matched SS timing,
AOT application or remote CI result.

* Study: prepare applicability, independently replay, then project

=temporal/lens.ss= uses one private final =temporal-binding= to name invocation
coordinates, the admitted cut and its fresh content-bound snapshot. It follows
the installed compiler's named metadata fields and applicability-before-
transformation pattern. The public POO answer remains extensible; a private
record is not exposed as its extension model.

=prepare-binding=, =complete-receipt?= and =answer-projection= express the whole
flow shared by solve and verification. Exact finite replay already establishes
closure/query truth, so verification consumes that established fact directly.
It still rebuilds the current cut, binds every coordinate, checks founded
proofs for nonempty answers, preserves total output limits and compares the
whole projected answer. It no longer needs to produce and validate another
certificate merely to validate the caller's existing certificate. Fork and
comparison compose this same checked boundary. A POO kind tag or a detached
wire projection alone never permits reuse.

[[file:../../t/performance/temporal-replay/README.org][Matched complete consumers]]
qualify this semantic flow. CPU evidence from verification is not an initial
solve or general execution throughput claim.

* Study: resolve canonical construction, then admit one complete root

=program/operator.ss= applies the private inert declaration extent to both
Program and Fragment publication. The final POO receiver supplies relation,
rule and terminal constructors. One applicability check compares all three
procedures with the canonical implementations before selecting the publication
receiver; inheriting a method does not prove that a child's constructors are
canonical. Any customized stage retains the ordinary immediate declaration
contracts. A constructor wrapper is a custom stage even when it eventually
calls the canonical constructor.

=program/objects.ss= owns the construction extent and root receivers. Native
=call-with-values= restores ordinary checks before recursively admitting the
complete Program or Fragment, including exceptional exits. Intermediate
canonical children cannot escape to a supplied callback in this extent; graph
admission still precedes construction. No declaration shape, source occurrence,
lexical binding, generated handle or public generic method is replaced.

This follows Gerbil =1cfb032= =compiler/optimize-call.ss:45-63=: establish
applicability before specialization and retain the ordinary call when that
applicability is unknown. The concrete study and complete consumer gates are
in =t/performance/operator-publication/README.org=. Validation savings in this
flow require complete root consumption; they are not a general solver claim.

The same private publication now refines POO responsibilities in
=program/types.ss=: one fresh positive membership table owns generated Term
shape checks. Atoms, rules and roots still traverse all their responsibilities;
nonatom clauses use the original contracts. Ordinary public contracts remain
unchanged. This is shape admission inside one immutable construction, not a
cache of descriptor/scoped validation, lexical bindings or evaluation results.

A derived native Contract must explicitly retain its parent's =proto=. Gerbil
POO inherited slots evaluate against the final receiver; inheriting the parent's
=proto: (.o)= constructor creates another prototype, which cannot classify
objects already constructed with the parent's prototype. Preserve ancestry,
then refine the responsibility map. New native Cases compare every root slot
and prototype, independently validate published roots with original contracts,
reject malformed Terms, test guard clauses without invoking callbacks, and
recheck a previously published Term identity after mutation in a later root.

* Prepare group-local expressions across a complete proof flow

Gerbil =1cfb032= resolves operation applicability before call specialization in
=compiler/optimize-call.ss:45-63=. Its native table updater in
=runtime/table.ss:440-464= hashes/probes once and invokes a synchronous callback.
The lesson here spans finite replay, proof production and independent checking.

=candidate/reduction-plan.ss= separates constrained row matching from aggregate
operand reading. The successful rule prefix fixes outer bindings; variables
introduced only inside a reduction are local to that group. They need checks for
repetition and literals, but unused locals need no runtime binding pairs.
=candidate/stratified-plan.ss= resolves ordered atom/scalar/reduction operations
and fuses checked head rendering. Private final records carry syntax operations;
each independent consumer prepares its own instance without retaining rows or
verdicts. All original row-probe and proof budget charges stay at their callers.

Exact independently verified closure membership proves scalar shape and arity.
The external proof checker can reuse that invariant, while separately rejecting
variable-looking symbols and wildcards required by the stricter proof grammar.
One private native hash updater consumes distinct rows in the original charged
order. None of these changes trusts producer indexes or a cached verdict.

The complete six-scenario native qualification includes cold, forged, small and
source controls. Target verification/production CPU improves 16.2%/20.7%, with
63.8%/58.7% less allocation; cold/small add bounded preparation overhead.
Failed CPU and allocation stages remain rejected. See
[[file:../../t/performance/stratified-replay/README.org][the frozen complete study]] for fixed gates, all control results and independent semantics.
