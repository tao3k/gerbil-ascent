* Replacement-valued lattice proof ownership (2026-10-07)

LatticeProjection owns keyed update/fold/publication and last-column row encoding
laws. Abstract map growth is distinct from inclusion of current tuple rows:
min updates can remove the old materialized tuple. Monotone-gamma ProviderIteration
therefore retains its admission scope rather than silently covering every lattice.

Quint owns settled publication and held-snapshot ownership for one finite min-map
transaction. Native tests own actual multi-field false/true keys, repeated same-key
updates, strict ordinary projection, retained append/replacement and old results.
Seven protocol faults distinguish the expected rejection conditions; raw checker
errors are not counterexamples. General join purity/laws, hash/key extraction,
universal native vector/SCC/hash extraction and asynchronous lattice execution
retain separate obligations. Typed strict-edge and functional pending-key
contracts are refined in the following section. See [[file:../../scheme-trrel-uf-design.org][the design]] and
[[file:../../evidence/scheme-provider-views-20261007/keyed-lattice-projection.json][the projection receipt]].



* Weighted compilation and pending roster ownership (2026-10-07)

StrictDependencies extracts exactly every reading-clause/head edge and proves
that the native global false preflight implies valid all-zero levels. Strict
cycles have no Nat labeling; lattice-to-ordinary reads require a later level.
SCC normalization preserves lower bounds using mutual reachability, and a
completed valid propagation is minimal. The completeness premise is visible;
these laws are not a universal proof of native mutable Tarjan output.

PendingKeys proves roster support equals pending-table domain after arbitrary
effective writes, and that materialization observes the final value per key.
Its representation contract separates logical membership from native visited
hash-table list order and deduplication. Quint handles dirty-key publication and
held snapshots, with two added faults for lost and repeated changed keys.
Scheme independently enumerates admissible three-node labels and rechecks the
existing native lattice session cases. No additional weighted-graph Quint model
repeats the Lean algebra. See
[[file:../../evidence/scheme-provider-views-20261007/strict-dependencies-pending-keys.json][the receipt]]
for source identities, fault witnesses and the acceptance boundary.



* Effective-write extraction and budget defect discovery (2026-10-07)

LatticeAdmission connects the branch before PendingKeys: pending-first lookup,
merged value, unchanged skip and effective key write. Arbitrary finite replay
and touched-key publication equal the full update fold. Seventeen laws retain
mathematical merge/equality premises; growth uses the existing JoinLaws contract.
Pending-slot cost follows fresh effective key support rather than event count.
The runtime cumulative derived-work/output budgets are not allocator bounds.

Quint explores exhausted, single-key and full two-key remaining capacity. Refused
private staging cannot publish; earlier held cuts remain stable. The three new
faults must fail BudgetBound, RefusalSound and RefusalStable with exit 12 and
actual behavior states. A checker evaluation exception encountered during model
construction was repaired and excluded from accepted defect evidence. These
faults concern temporal admission/publication, while Lean owns static replay
and support laws. No duplicate Quint proof of the Lean fold equations is added.

Native tight-budget cases check repeated-key acceptance, exact typed refusal,
held-result stability, and replacement/reconstruction against a fresh solve.
They passed; no newly discovered native defect is claimed. The design and
receipt distinguish this typed component closure from universal native hash,
callback/SCC extraction and full paper application/cost replication. See
[[file:../../evidence/scheme-provider-views-20261007/effective-lattice-admission.json][the receipt]].
