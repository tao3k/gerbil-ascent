* Source picture

program/syntax.ss ------> program/planning.ss -------> program/evaluate.ss
program/scheme-language.ss       |                            |
         |                        v                            v
         +----------------> program/funs.ss              table/funs.ss
                           strata and terms             row indexes

The two syntax surfaces have different contracts. The historical
=ascent= form admits general Scheme expressions and patterns and is
kept for the Rust-oracle qualification path. It is not re-exported by
=program/interface.ss=. The native public =relational-program= form has
a checked scalar grammar and an admission boundary. Shared machinery
must preserve that distinction. =program/analysis.ss= caches immutable
declaration plans, while =program/evaluate.ss= owns mutable relation
state and retained-session behavior.

* Feature: declaration compilation and ordered stratum grouping

The installed compiler makes pass ownership visible in its entrypoints.
=gerbil/compiler/optimize.ss:27= scopes mutation and local-type tables to one
=optimize!= invocation; =compile.ss:57= declares the syntax handlers for binding
collection explicitly. =optimize-base.ss:24= names optimizer metadata with a
structure instead of spreading its field interpretation across callers.
These are concrete ways to expose invariants to a reader and to the compiler.
They do not establish that every upstream implementation is faster.
For diagnostics, =base.ss:97= passes the current compile context and source
syntax to =raise-syntax-error=. ASCENT's corresponding boundary keeps the
rule/body/head or program-dependency path and re-raises the original exception
after the optional diagnostic callback observes it.

ASCENT now has one declaration compilation entrypoint,
=gerbil-ascent-prepare-program= in =program/planning.ss=. It accepts relations,
rules, a validated schema and the diagnostic callback. It resolves atoms,
checks body/head variable bindings, computes strata and groups active rules.
It neither reads source rows nor invokes storage or rule callbacks.
=program/evaluate.ss= requests this result through the existing declaration
cache, then constructs its own execution metadata, variable frames and timers.

#+begin_example
relations + rules + validated schema
                  |
                  v
planning: resolve -> bind/check -> strata -> ordered active rules
                  |
                  v
analysis cache: immutable declaration plan
                  |
                  v
engine: owned rows, indexes, variable frames, budgets and timers
#+end_example

The earlier active-rule construction scanned every rule's heads once per
stratum. The replacement groups each rule's heads in one traversal, prepends
the resulting active rule to its stratum, then reverses the accumulators.
Hash iteration order cannot change rule order: a rule contributes at most one
group to each stratum, and each stratum reverses the same source-rule traversal.
Head order and duplicate heads are retained. Delta positions and diagnostic
paths still use the original lowering functions.

The private plan vector layout and public POO declarations remain identical.
Source admission still precedes declaration compilation inside engine creation,
preserving the existing error and provider-callback order. This change removes
declaration compilation from the large engine closure without moving callbacks
into a different phase. It does not claim a measured solve-time speedup.

Qualification adds two Cases to the existing =ascent-rule-program-test.ss=:
storage and guard callbacks remain idle during compilation and execute during
evaluation; a multi-head rule spanning two strata retains repeated heads,
source-rule order and the correct delta positions. Existing language diagnostic,
negation, aggregate, lattice and retained-session tests cover the other seams.

checks 42 modules with findings=0 and errors=0; =just test= passes 50 modules

ignored =.cache/ascent/planning-*.log=. These are local receipts, not remote CI
or a paired declaration-compilation benchmark.

* Feature: checked scalar calling conventions

=gerbil/compiler/optimize-call.ss:43= resolves procedure information before
optimizing an application; its treatment of known procedures and lambda calls
depends on actual bindings and effects. The transferable lesson is to check
generated calls and measured behavior instead of assuming a source form creates
the desired calling convention.

The checked language supports unary =even?= and =identity=, and binary =<=
and =+=. Their operand descriptors are validated at construction and rebuilt
at admission. The old callback interpreted those descriptors again on every
row, assembled a reversed argument list and invoked =apply=.
=program/scheme-checked.ss= now specializes the six variable/literal calling
conventions at construction. A small hygienic =checked-call= rule expands the
runtime parameter check into a short list match and calls the already checked
operator directly. Numeric validation still executes at row time, including
literal-only operators. The original argument-mismatch error is retained.

this installed toolchain generated a rest-argument lambda, a length check and
=apply=. In the complete paired run it won only 797, 730 and 546 of 1000 pairs
for right-literal, left-literal and unary-literal inputs. These failed the
unchanged 900-win admission criterion. The explicit-match variant generates
pair/null checks followed by the operator call in its successful path.

* Feature: prepared general index key terms

=gerbil/compiler/optimize-call.ss:88= checks mutable bindings before substituting
lambda arguments. The relevant principle is to move only work whose inputs
are stable, while preserving observable evaluation. ASCENT's physical index
columns and admitted term descriptors belong to immutable declaration plans;
expression results and environment bindings do not.

=program/objects.ss= now records ordered key terms in the same traversal that
selects indexed columns and prepares binding terms. The private atom vector
contains relation position, raw terms, columns, binding terms and key terms.
The first four fields retain their meanings. Key terms refer to the same term
descriptors; they never retain computed expression values or engine buffers.
Selection still uses bindings from earlier clauses, rather than names first
bound within this atom. This costs one additional list spine per atom key in
the declaration cache, proportional to the number of selected columns.

After index construction, the general evaluator calls
=gerbil-ascent-index-key/terms= with that prepared list. It visits only the key
terms instead of repeatedly walking the full term list with =list-ref=.
Expression callbacks still run in column order on every lookup. Dynamic column
key construction and prepared key construction share one value operation for
literals, expressions and variables; missing bindings retain the same error.
The positive slot-based path continues to use its existing prepared slot terms.

The real index qualification module compares results and the complete
build/expression/lookup trace against the frozen evaluator. It also verifies
that declaration planning does not evaluate expressions, fresh variables are
excluded from key columns, and false values and missing-variable errors retain
their semantics. No provider callback is bypassed.

* Feature: local name indexes throughout declaration lowering

The installed Gerbil compiler's =compile.ss:1115= creates a local
=make-hash-table-eq= while walking imports. Its continuation records an
expander context only once and keeps the original traversal order. ASCENT
can apply that representation to admitted names; compiler context identity
and ASCENT variable scope remain different semantic contracts.

=program/objects.ss= and =program/planning.ss= now share an admission-local
membership predicate. Small scopes use =memq=. For scopes with at least 32
names, the 32nd query builds one identity index. Multiple heads share that
snapshot after body lowering. A bounded 32-cell probe avoids a full length
scan. The threshold limits allocation for short query sequences; it is an
implementation choice, not an optimal threshold proven for every workload.

Wide atoms separately index the growing same-atom scope. Freshness is read
before inserting the current name; repeated variables and names introduced
by patterns still compare row values. Physical key eligibility consults
only the prior clause scope. Pattern-output collision checks retain their
list representation and remain a second phase after expression-input validation.
Wide generator and aggregate outputs use indexed collision checks; wide
aggregate input queries use a variable-only atom index. Checked fixnum
operations apply only to the probe and query counter bounded by 32.

Custom clause planners still receive the original bound-name list. Result
vectors, declaration order and diagnostic priority are unchanged. Scratch
tables and lookup closures disappear after admission; immutable plans retain
no variable frames, engine rows, global name cache or new metadata fields.

Three binding Cases check 31/32/33/128-name boundaries with uninterned
symbols, fresh and repeated variables, prior-scope index eligibility,
callback timing, ordered pattern outputs and expression-error priority over
pattern collisions. Four whole-program Cases exercise multi-head atoms,
tuple generators, aggregates, patterns and head expressions, preserving
=#f= values and ordered output columns across the same boundaries.

* Research: rejected positional selection during positive slot compilation

=optimize-call.ss:43= resolves known procedure types before selecting a
specialized call path; unknown or nullable types retain the generic transform.
The transferable lesson is to specialize from an established representation
and keep the general behavior outside that boundary. Gerbil's call optimizer
does not implement ASCENT column selection or prove its cost model.

After applicability checks in =program/positive.ss=, all atom terms have been
lowered to ordered slot actions. The baseline compiler selects every indexed
column with =list-ref=, repeatedly scanning prefixes. For an atom with =W=
terms and =K= selected columns, selection can cost =O(W*K)=; a full ordered
composite key costs =O(W^2)=. A temporary vector permits =O(W+K)= selection,
but introduces allocation and branch costs on the complete compilation path.
A candidate used a vector when =K>=8=, retaining list selection for short
keys and later specializing empty/singleton keys with native =match=.

The experiment measured complete slot compilation, including applicability,
slot allocation, body actions, key selection and head actions. The reference
compiler was frozen from =53980e4= and compiled inside the benchmark unit;
the candidate used the production export. Each shape retained 1000 alternating
pairs of eight compilations, with input construction and exact plan comparison
outside the intervals. Wide targets required 900 strict wins and nonregressing
medians; controls required nonregressing medians.

With collection every 20 pairs, the first candidate's 128-column target had
reference/candidate medians =176/122= jiffies and 940 strict wins. The
512-column target had =1388/542= but only 884 wins, and the 64-of-512 target
had =668/512= but only 800. The one-column control regressed =502/521=.
After removing a local selector call, medians were =169/117=, =1360/516=
and =669/499= with =924/917/864= wins; the one-column control remained
=484/486=. Neither version qualified.

Collecting before every batch exceeded the native 120-second deadline,
including an isolated narrow shape, and is discarded. Collecting once per
pair completed the isolated narrow shape with =13/16= median jiffies and
503 wins, still failing its gate. Wide shapes were not rerun under this
last protocol after the control failed. The candidate and its experimental
performance module were removed from the tracked tree. Source snapshots,
patches and raw logs remain under ignored =.cache/ascent/slot-selection/=.

These results do not establish a stable production slowdown or a full-solve
speedup: GC protocols differ, and the frozen local reference and production
export have different module call boundaries. Future work should first
calibrate the unchanged production export under an identical call boundary
and retain a bounded benchmark protocol. Reduced asymptotic selection cost
alone is insufficient evidence to replace the existing implementation.

Three retained Cases strengthen the existing positive-plan qualification.
They assert independently specified fresh/bound slot sequences, slot counts,
forward/reverse/duplicated key order, action identity, repeated variables,
literals, wildcards and callback rejection at 7/8/9/32/128-column widths.
The real composite Join compares custom provider key traces and ordered
output rows against the existing independent evaluator, including =#f=.
There is no copied slot compiler in the retained tests. Production code,
build entrypoints, scheduling, original deadlines and sample counts remain
unchanged by this research slice.

* Second round: SCC stratification and reusable graph analysis

The installed Gerbil Compiler gives three concrete lessons for this
implementation. =compiler/optimize-xform.ss:16= registers handlers by AST
form with =defcompile-method=; =compiler/optimize.ss:27= creates pass-local
mutator and type tables before traversal; =compiler/optimize-call.ss:43=
specializes calls after resolving their operators and checking safety.
The applicable pattern is to move declaration work into checked planning
and keep mutable execution state local. The compiler's method hierarchy
and unchecked-call machinery are not needed for this graph algorithm.

Previously =program/funs.ss= relaxed every dependency edge until the
strata stopped changing. A reverse-ordered strict chain required one
pass per relation, giving worst-case =O(V*E)= work. Cycle diagnostics
then searched reachability separately for strict edges.

=program/graph.ss= now owns the Tarjan implementation formerly embedded
in =program/summary.ss=. Both the rule summary and relation stratifier
use it with their own vertices and edge metadata. A strict edge within
one SCC is rejected, selecting the first invalid dependency in the old
ordering to preserve aggregate, negation, and lattice-projection error
messages. Every positive SCC receives the maximum incoming level; a
single source-before-consumer pass propagates the minimum strata.
Graph analysis and propagation take =O(V+E)= work. Programs containing
only positive dependencies use stratum zero without building SCCs.

* Study: compiler phase contracts and higher-order normalization

This study reads the installed Gerbil compiler Scheme directly, rather than
inferring quality from an optimization result. Three concrete structures matter:

- =compiler/optimize-top.ss:21-86= declares separate visitors for top-level
  types, declarations, expression types, complete type collection and mutators.
  The operation determines the visitor, while the AST representation stays
  shared. ASCENT already separates descriptor validation from lowering inside
  =relational-typed-compile=; the appropriate improvement is to state their
  different obligations, rather than introduce another visitor framework.
- =compiler/optimize-base.ss:15-29,492-503= names optimizer, local and path
  contexts separately. Type lookup searches path facts, then local facts, then
  the optimizer table; alias resolution delegates to this lookup. The mutable
  optimizer tables are fresh in the optimizer-info constructor. ASCENT's
  compile counters, source tables and domain accumulator likewise belong to
  one invocation. Reified closure environments use descriptor identity and
  lexical bindings; source-name equality cannot replace that relation.
- =compiler/optimize-top.ss:182-194,213-268= still visits an expression when its
  binding type is already known. Lambda and let handling establish the local
  environment around the body traversal. Known metadata therefore does not
