* Delivery decision

The next delivery is one usable Scheme-native reasoning lifecycle:

#+begin_example
Scheme program / fragment / inert candidate + copied source snapshot
  -> whole-program admission -> native fixed point
  -> completed result + bounded snapshot-relative evidence
  -> atomic source update / withdrawal -> next completed result
  -> rejected or cancelled work preserves the last completed result
#+end_example

The MVP uses the public =program/interface.ss= API and the separately restricted
=candidate/reasoning.ss= boundary. It does not expand candidate grammar to
match trusted Scheme construction. No preset model instructions, answer
prefills, response extraction or repair are required for this lifecycle.
The actual composed scenario already exists in
[[file:../t/qualification/scheme-library-contract-test.ss][the native Library contract]]: recursive paths, exclusion, checked
filter/computation, grouped sum, fragments, inert candidates, evidence and
atomic multi-source replacement share an independent finite matrix model.
We will deliver and extend this path before adding another isolated feature.

This document controls MVP sequencing. The [[file:scheme-design-framework.org][design framework]] and
[[file:scheme-paper-closure.org][paper closure matrix]] retain the broader R1--R7 and full-replication
obligations. An MVP pass does not close those obligations.

The structural problem is delivery organization: independent passing receipts
do not form a current-head release. We also have material open work: no general
native refinement, no complete BYODS application replication, no established
general model or runtime benefit. These are not repaired by adding more
isolated tests or renaming a version.

* One native acceptance entry

Run in the repository's declared Gerbil environment:

#+begin_src sh
just test 2
#+end_src

In the owning development workspace, run this through its captured
=.devenv/devenv-profile-exec= environment. The existing =just test= recipe runs
=t/harness/run.ss= and discovers the full native qualification suite. Scheme
owns module admission, semantic verdicts, source/carrier hashes, child isolation
and drain decisions. Python remains process supervision only. The Scheme
runner preserves admitted parallel and exclusive lanes. The MVP obligations
are covered by these existing modules within that full suite:

| Module | Obligation |
|--------+------------|
| scheme-library-contract | Composed direct/fragment/candidate lifecycle and independent complete sets |
| scheme-closure-contract | Whole-program rejection, finite-domain and budget boundaries |
| scheme-session-deletion | Source replacement/withdrawal, cyclic and alternative support, rollback |
| ascent-finite-evidence | Snapshot-relative positive/stratified evidence and replay |
| ascent-positive-nonmembership | Completed finite absence; bounded/unsupported is not absence |
| ascent-actor-session | Generation ownership, cancel/drain, detached inputs and publication |
| ascent-byods-invariants | Built-in storage/frontiers, SCC structure and refusal atomicity |

Acceptance requires Scheme parent exit status zero, actual Case and module
verdicts, and unchanged source/carrier identity. Building with continuous real
progress may exceed 180 seconds; child watchdogs retain their existing limits.
The same =just test= entry runs in CI. Exact-head Scheme, oracle, formal and
performance gates remain required for release. MVP delivery uses this existing
native execution path and adds no Shell wrapper or separate success marker.

* Finish in three integrated deliveries

| Order | Deliverable | Required exit evidence | Dependency |
|-------+-------------+------------------------+------------|
| 1 | Usable native lifecycle and central capability contract | The composed path and all eight boundary modules pass with explicit parent success and frozen source/carrier identity; full exact-head Scheme/oracle/formal CI succeeds | Existing implementation; correct failures before expanding scope |
| 2 | Application and architecture qualification on that lifecycle | One representative composed workload with insertion, withdrawal and cancellation; identical complete outputs in fresh/retained/actor or serial Provider arms; paired initialization-inclusive CPU/wall/allocation results and negative results retained | Native acceptance; reuse the same workload rather than independent microbenchmark promotion |
| 3 | Model comprehension and consumer admission | Frozen real Scheme source/tasks, raw acceptance and complete-set correctness, no prompt scaffolding or repair; authorized external calls and paired benefit; ABI status/ownership/resource parity before Rust Runtime | Deliveries 1 and 2, explicit model call authorization; R7 remains last |

For delivery 2, select the workload and controls before optimization. Retained
and fresh arms must see identical snapshots and budgets. Actor admission must
use actual VM capacity; requesting four workers does not establish four-CPU
execution. BYODS does not inherit parallel support from the Set path. Record
the UF fixture's approximately 57--78 percent greater cumulative allocation as
an open regression; do not claim its selected CPU gain as an application win.

Formal work follows this same scenario: connect source update/publication,
SCC scheduling and Provider frontier laws to actual native transitions and
their discriminators. Finite TLC fixtures are exploration scopes, not runtime
generation ceilings. General native refinement remains separately tracked.

* Release receipt and claim discipline

The [[file:evidence/scheme-trrel-uf-20261005/receipt.json][existing full native qualification receipt]] records its own frozen
source and full-suite result. Preserve that evidence boundary; it does not
certify later commits. MVP sequencing introduces no new formal, performance
or model result. Final-head GitHub CI remains a separate release gate.

Use one release summary for the admitted MVP, with the exact GitHub PR head,
capability boundary, scenario identity, source/carrier binding, explicit native
parent status, independent comparison result, same-head CI URLs, formal
premises, paired costs and remaining gates. Historical JSON receipts remain
source-bound references; they are not silently regraded as current evidence.
Do not upload raw =*.log= files. This sequencing change modifies no runtime
semantics and performs zero model calls. A complete native MVP must be described as such;
full ASCENT/BYODS replication and model usefulness require their own evidence.
