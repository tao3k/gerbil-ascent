#+title: Invocation-owned finite model lookup for stratified proofs

* Production ownership and Gerbil study

Gerbil revision =2591dcd= uses fresh symbol identity tables in
=compiler/compile.ss:1113-1127= for one import traversal and in
=compiler/optimize-spec.ss:121-130= for one specialization target. Its
=optimizer-info= record (=optimize-base.ss:24-29=) names table responsibilities.
Lookup indexes belong to the analysis invocation; stable source order remains
separate from hash iteration. The applicable pattern is state lifetime and
lookup representation, not manually forcing every expression to inline.

=candidate/closure-index.ss= privately owns relation metadata over the
independently replayed verified closure. Symbol identity selects relations;
structural row equality implements the former =member= membership semantics.
Original ordered rows remain responsible for enumeration and every charged
proof-search/check step. Only the checker supplies source occurrences; their
vector preserves exact positions, including duplicates. All indexes are fresh
per call. No metadata survives certificate/generation changes.

The producer still calls the separate checker, and each still independently
replays the finite model. Neither indexes nor caller certificates bypass
verification. Source labels, node/root order, backward dependencies, explicit
budget boundaries and invalid/bounded/unsupported verdicts remain unchanged.
=build.ss= adds only the library module; test and benchmark work stays in =t/=.

* Frozen baseline and public ASP entry

Run =just performance-stratified-model=. Project modules compile against the
installed SDK without rebuilding Gerbil. Explicit arguments select scenarios,
library and receipt paths. Logs, native artifacts and raw receipts live only
under ignored =.cache/ascent/stratified-model/=.

Both reference modules freeze =5e549ce8d17c3fd942cdb50eb36cee825c06f795=.
The checker is byte-identical. Only the producer's checker import is redirected
to the frozen checker; restoring that path reproduces its original file.
The timed baseline therefore includes the old producer and old checker.

=benchmark.ss= was created with public =make-benchmark-fixture=.
=benchmark-run/result= owns 50 alternating checked pairs and its standard
wall/heap receipt. Additional process CPU and cumulative allocated byte deltas
measure each inner call. Inputs, finite certificate and expected rows are
prepared before timing; each timed producer call includes independent replay,
proof search and its complete internal checker/replay. Both ordered proof
data and root rows must match outside the timed span. Both external old/new
checkers must accept the proof. A collection precedes each leg.

* Fixed gates and retained negative results

Large source/derived proofs require at least 20% CPU improvement and 35/50
paired wins. All large/control scenarios permit at most 25% extra allocation
plus 8 KiB. Controls allow 5% CPU plus 30 microseconds; small permits at most
8 KiB extra bytes. All gates were fixed before sampling. Standard pair wall
p95 is diagnostic; this does not establish whole-query latency improvement.

The initial separate source-position map passed large CPU gates but allocated
10,400 extra bytes for four source rows, failing the small allocation gate.
Capacity hints alone still failed (10,624 extra bytes). The final relation
record owns ordered rows, structural membership and optional source positions
together, removing the additional relation map. No size cutoff or admission
gate relaxation was introduced. Both failed raw logs remain in local cache.
