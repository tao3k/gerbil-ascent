* Audit decision

The [[file:research/scheme-dsl/index.org][DSL source ledger]] contains eight papers: A22, F16, H13, F20,
S20 and L25 concern the language/kernel; H18 and B22 add deletion and
incremental-maintenance constraints. These are distinct from the separate
[[file:research/agent-inference/index.org][agent-inference collection]]. The next step is to connect paper assumptions
to admitted Scheme IR and observable transactions. Adding syntax, quoting a
paper or passing an abstract proof is insufficient for design closure.

The current checked subset has a coherent division: Scheme constructs program
values; admission exposes domains, lexical captures and dependencies; the native
core owns evaluation; retained Sessions own source/result publication; bounded
evidence binds a specific program and snapshot. No paper establishes the safety
of arbitrary host closures. Therefore unrestricted callback admission, silent
domain clamping and hidden dependencies are excluded from the checked subset.
Trusted host construction remains outside the proof boundary.

Audit baseline: GitHub PR #1 head =bb4f58a826ac37e85974c66ce504ba1a7c7b57da=.
The 13-Suite / 138-Case receipt binds native source =0e1141e=; its later
documentation child does not expand that semantic scope. Historical negative
performance results and the failed three-arm measurement remain failures or
negative evidence. They do not become benefit claims through this proof audit.

Generation has no maximum in either protocol's =Init/Next/Spec=. It ranges over
=Nat= and can keep increasing. =ExplorationDepth= and =ExplorationBound= exist
only for TLC state-space exploration; configuration values do not limit runtime
or constitute an all-generations theorem. Repeated source cuts are allowed,
so a stale job cannot become current merely because source bytes return to an
earlier value (ABA). Lean publication theorems quantify over all natural-number
generations, but still prove the abstract publication function, not Gerbil.

Safety is not liveness. Neither TLA model claims a solver eventually finishes,
or a transaction eventually wins against continuous competing publication.
A fairness/termination claim needs an explicit scheduling assumption and a
separate proof. Abort preservation is encoded as a required action contract;
model checking does not establish that native exceptions implement it.

Previously GitHub's =formal= job ran Lean only. It now executes the common
[[file:../packages/proofs/check.sh][proof gate]], including both TLA models and the two intentional faults. TLC is
pinned to the official 1.7.4 jar and verified by SHA256. The gate accepts
=ASCENT_PROOF_EXPLORATION_DEPTH= independently of protocol semantics; GitHub
uses 4, the default exploration configuration uses 2. Counterexample checks
require both TLC's violation exit code and the expected violated property;
parse/tool crashes cannot count as successful fault detection.

* Ordered implementation plan and exit conditions

| Order | Work package / owner | Concrete next deliverable | Exit condition |
|-------+----------------------+---------------------------+----------------|
| 1 | Compiler semantics: =program/higher-order.ss= | Formal descriptor AST and environment interpretation matching actual source/variable/lambda/apply/fix/union/join/project/select/map branches; per-phase relation to normalized positive IR | Structural typing, substitution and lowering preservation proven for the stated subset; source-domain/cardinality lemmas discharge finite-height premises; native phase discriminators still pass |
| 2 | Transactions: Session/admission/reuse/update-selection | Map accepted logs, pending sources, private engines and frozen results to formal state; record every publication and failure point, including single-source partial/resume and explicit atomic batches | Native interruption/domain/budget/stale controls preserve the specified visible state; reused relations equal fresh solve. Do not force the single-source pending-work API into the batch atomic model |
| 3 | Evidence algebra: support graph / stratified provenance | Specify complete finite alternative graph versus one founded witness; define negative/group observations and stratum-relative replay | Independent finite enumeration, cycles, tamper, size exhaustion and duplicate supports pass; absence only from a completed closed model. Arbitrary semiring valuation and lattice history require separately specified algebras |
| 4 | Optimization and benefit: native evaluator / Session | First diagnose the failed retained measurement's first expensive stage with actual stage output and profiling; then matched solve-only/fresh-update/retained receipts | All groups pass existing semantic/progress gates; lifecycle operation counts plus CPU/wall/allocation distributions recorded. A negative result closes the measurement question, not a positive-benefit claim |
| 5 | Actual model comprehension: native scoring + Python byte transport | Freeze current Scheme source/tasks after compiler and publication stabilization; discriminate raw acceptance, semantics, reasoning and genuine post-response feedback | Paid calls require new exact-source authorization; every timeout/raw rejection stays in denominator; no semantic Prompt, answer-prefill, repair or truth-guided extraction. No historical score transfers to this source |
| 6 | MRR Rust binding | Byte/status/ABI conformance against the accepted native grammar and publication contract | Native, model and architecture gates reviewed first; Rust must preserve bounded/unsupported/failure versus completed/absence. No semantic authority migrates into transport |

Steps 1–3 can make independent progress, but compiler proof claims must bind
the same admitted grammar and proof assumptions used by transaction/evidence
tests. Optimization changes require renewed semantic qualification. S20-style
function-delta work follows current lowering preservation; a general DBSP
conversion is not a shortcut around the deletion contract.

* Closure report requirements

For each work package publish: exact source identity, admitted grammar, paper
premise used, theorem/model identifier, executable discriminator, raw outcome,
counterexample controls, cost boundary and remaining obligations. Abstract Lean
success, bounded TLC success, native semantic qualification, remote CI and real
model benefit are separate entries. No new real-model call belongs to this audit.

The [[file:scheme-design-framework.org][acceptance matrix]] remains the closure authority. This plan refines R1–R7;
it does not mark them all closed. The [[file:evidence/scheme-proof-audit-20261004/receipt.json][formal receipt]] records this patch's proof and
model-checker results and identifies the checked files and toolchain. Execution
