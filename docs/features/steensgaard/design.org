** Capability extraction before selected matching

A native counterexample exposes a custom three-argument visitor entering the
admitted canonical path and raising a part-visitors type error. Nested mixed
unions can also retain a part-visitors record whose admitted field is false.
Testing only the outer record shape is therefore insufficient.

=gerbil-ascent-admitted-row-parts?= recognizes the actual callable admission.
The extraction invariant is structural: built-in rectangles carry admission;
custom visitors do not; a union carries it iff both children do; binding and
ordered export preserve the captured capability. The private index owner
requires this capability and the canonical index receiver before evaluating
the key or invoking the consumer. Declined access returns false without a
consumer call, preserving the generic full matcher for custom candidates.
An explicit unsupported admitted call raises a typed diagnostic.

The new native control checks custom, mixed, nested and rebound cuts, retained
checked traversal, zero callbacks on decline and successful all-built-in union
access. The red receipt fails at the actual native dispatch before the fix.
These controls connect the native representation seam to the existing ordered
lookup premise. They are not a universal extraction theorem for Gerbil hashes,
foreign callbacks or compiled vectors.

** Complete Steensgaard rules and current scale obligation

[[file:../../../applications/steensgaard.ss][The application constructor]] returns the ordinary POO Program declarations;
it owns no storage, session, configuration environment or compatibility layer.
It includes allocation and assignment injection plus the full store/load/field
join. Its explicit arm includes symmetry/reflexivity and transitivity rules.
The rule source is pinned at
[[https://github.com/s-arash/ascent/blob/03f4f792442ecaf9e4f178a6a1b5840eab526388/byods/ascent-byods-rels/examples/steensgaard/main.rs][the upstream Steensgaard application]].
B23 Section 5.2 motivates this application; its paper timings are not Scheme
measurements.

Scheme's independent partition saturation and Rust's independent undirected
graph saturation do not use the production compiler or equality Provider.
Rust compares the complete implicit and explicit programs with 33 application
inputs, including empty input, duplicate allocations, missing equivalence,
field mismatch and a second load/store saturation wave. Native controls also
cover false/true host values, append, withdrawal, held old results, explicit
actor cancellation and retry. Worker-capacity comparisons do not assert that
custom eqrel storage executes concurrently.

Paired application calls include solve and full vpt export, with warmed programs
and alternating order. The VM allocation counter is thread-local: cross-thread
subtractions can be negative and are excluded; caller allocation is admitted
only for serial arms. CPU/elapsed measurements retain their workload scope.

The pinned OpenJDK files are alloc (737,392 bytes), assign (13,102,621 bytes),
load (1,088,142 bytes), and store (88,661 bytes). The complete Rust implicit application and independent partition model both
count 440,438,706 implied pairs, with a largest class of 20,956 members. This
qualifies full-input cardinality agreement in the Rust reference, not full
Scheme solving, tuple-by-tuple full-data correspondence or continuous peak memory. Inspection identifies a concrete
architecture gap: current eqrel component state still emits expanded pairs into
the engine's eager row buffers. B23's linear storage argument requires retaining
implicit total/delta equivalence views, not merely fewer closure rules. The
current complete rule program and finite speed measurements do not establish
that memory bound. Compressed eqrel publication, source recovery and ordered
consumer correspondence precede OpenJDK benefit claims; Polonius, LLVM and
lattice PageRank remain later application gates in the same closure matrix.

** Compressed eqrel implementation contract

The next implementation must retain equivalence semantics, rather than treating
an injection as directed transitive reachability. Each frozen total represents
one disjoint square per active component; its count is the sum of squared
component sizes. An insertion frontier consists of newly active diagonal facts
and the two cross-component rectangles, and its count must equal the old
extension's preflight =needed=. Duplicate injections emit zero facts.

Admission remains before mutation. A failed budget or field callback retires
only the staged owner, and replay reconstructs it from the source log. Published
member segments and selection indexes must not reference a mutable component
record; append, withdrawal/replay, cancellation and retry must preserve held
old cuts. Native selected-coordinate routing must return stored representatives
for equal-but-distinct keys, preserve false/true members, and isolate groups.

The current =program/view-state.ss= export journal is UF-specific. Eqrel needs
its own ordered source/derived replay so legacy total and delta order remain
exact. A new view carrier alone does not close the eager engine-buffer gap:
initialization, frontier staging, count budgets, routing and publication must
all select it through the canonical eqrel Provider identity. Custom Providers
retain their existing checked contract.

Admission requires per-injection truth and exact ordered output against the
existing eager eqrel implementation, multi-producer delta joins, rejected
updates with recovery, and old-cut retention through Session withdrawal and
actor cancellation. The full OpenJDK run then compares the 440,438,706 count
without forcing a full export; peak-memory and end-to-end costs are measured
separately from the count observation. This contract is design, not a claim
that the compressed eqrel route is implemented.
