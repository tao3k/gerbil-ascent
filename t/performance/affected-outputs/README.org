* Native selection and activation phase

ASP Scheme benchmark API runs 50 alternating old/new pairs. Immutable heads,
body, compiled plans, initial activations and affected bitmap are prepared before
measurement. Each call selects all rule strata, activates partial rules and
consumes every selected head into a relation-ID checksum. Baseline parity and
an independent affected-ID sum are required for every pair. This consumption
checks selected heads; separate semantic qualification checks compiled outputs,
plan sharing and frame ownership. It does not execute a public session or solve.

GC precedes each sample. CPU is process user/system time and allocation is
Gambit allocated bytes. Timing lanes do not overlap local builds or qualification.
The full-survivor target was declared before execution: CPU <=90% of baseline
and at least 40 faster pairs. Controls allow 110% CPU +20 microseconds;
allocation allows 110% +4096 bytes. No gate was relaxed.

* Semantic qualification

The added suite compares every four-relation affected mask against the frozen
reference and a direct ordered-head oracle, including repeated and reordered
head IDs. It checks compiled output order, full rule/plan/frame identity,
first/middle/last rejection, mutation of every projected spine pair without
altering the caller, private partial frames, shared actions, missing-plan
lowering and empty/excluded strata. Existing selected-activation and positive
component suites cover update/append/resume flows. Root =build.ss= is unchanged.

Final local qualification: three Suites, 32 Cases, final =OK= and exit zero.
The source-loaded selection/activation pipeline also passed. Native policy
completed with 30 advisories and zero errors; the repository is not claimed
warning-free. The first qualifier build was rejected because other Scheme
sources changed during compilation; its log was retained and the subsequent
build passed source-snapshot admission. Local receipts do not establish
completed remote CI.
