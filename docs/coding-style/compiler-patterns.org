* Study: descriptor ownership and shared lexical analysis

Gerbil revision =2591dcd= separates compiler phases into modules. Its
=compiler/optimize-base.ss:24-29= gives one optimizer-info record ownership
of identity tables. =std/list/list.ss:24-33= provides linear identity-aware
deduplication when supplied an eq table, with an explicit first-occurrence
policy. The applicable lesson is to retain analysis once per compilation
and distinguish node identity from the number of paths reaching it.

Our former 691-line =program/operator.ss= combined builders, validation,
scope analysis, lowering, interpretation and counters. Production ownership
now follows these boundaries:

| Module | Responsibility |
|--------+----------------|
| =operator-descriptor.ss= | finite builders and descriptor identities |
| =operator-analysis.ss= | graph admission, owned rows, free parameter sets |
| =operator.ss= | lexical instances and rule emission; stable public facade |
| =operator-reference.ss= | independent bounded set interpretation |
| =operator-measurement.ss= | public dynamic interpreter counters |

The facade is 299 lines. A shared union DAG formerly duplicated parameter
entries once per path, and lowering recomputed validation's free lists.
Analysis now deduplicates parameters by identity in first traversal order;
lowering retains the same invocation's analysis record. Binding-dependent
memoization still uses the actual relation handles for every free parameter.
Every public call revalidates mutable descriptors. No analysis cache crosses
calls, and no contract checks or row ownership copies are bypassed.

Tests stay in =t/qualification/= and =t/performance/=. Production counters
remain public reference/change functionality. Deep sharing, escaped bindings,
pointer cycles, mutable rows and independent transformation instances are
semantic controls. The frozen matched compile benchmark and its negative
14-level result are described in
[[file:../../t/performance/operator-scope/README.org][operator scope qualification]].

* Study: admitted callback arguments and ordered pattern extension

The installed compiler's =optimize-call.ss:90-131= only substitutes lambda
arguments after proving equal arity and stable bindings; other operands retain
explicit lexical bindings. =compile.ss:557-628= separately lowers fixed/rest
case-lambda dispatch. The transferable rule is to specialize a proved calling
shape while preserving operand evaluation, rather than assuming that =apply=
or a shorter source expression will disappear in native code.

=core/rule-bindings.ss= applies this at the admitted rule boundary. Zero,
one and two input names use direct calls; larger callbacks retain =apply= and
an ordered argument list. All names are resolved before invoking user code,
missing-name diagnostics retain their first failing input, and a bound =#f=
is a value. No user callback becomes an unchecked call or a cached value.
The evaluator shares this operation for guard, binding and generator clauses;
expressions use the same core owner. Aggregate input tuples still require
lists and use its ordered projection helper.

The compiler's =generate-meta-define-values%= (=compile.ss:1446-1469=)
constructs only its owned output and preserves publication order. Our pattern
operation combines finite output-name traversal, result arity validation and
fresh binding construction. It produces two fresh pairs per output rather
than the old map-plus-append's three, retains output order and the caller's
original environment tail, and never mutates callback-owned tuples. A cyclic
or improper callback result is bounded by the admitted output count and still
raises the original pattern diagnostic. Row and aggregate patterns share it.

Baseline =02d84463482a266c9dcc0196a0d2da0c5b5dfb9f= is frozen in
=t/performance/rule-bindings/=. Runtime functions are verbatim source extraction (final newline normalized);
the positive runner and full evaluator differ only in import routing to that
baseline. All mutable relation/index/result machinery is shared symmetrically.
=just performance-rule-bindings= compiles both graphs and verifies native
=.ssi= resolution plus =.o1= presence before sampling. Scenario, library prefix
and ignored receipt path are explicit command arguments.

* Feature: checked scalar calling conventions

=gerbil/compiler/optimize-call.ss:43= resolves procedure information before
optimizing an application; its treatment of known procedures and lambda calls
depends on actual bindings and effects. The transferable lesson is to check
generated calls and measured behavior instead of assuming a source form creates
the desired calling convention.

The checked language supports unary =even?= and =identity=, and binary =<=
and =+=. Their operand descriptors are validated at construction and rebuilt
at admission. The old callback interpreted those descriptors again on every
row, assembled a reversed argument list and invoked =apply=.
=program/scheme-checked.ss= now specializes the six variable/literal calling
conventions at construction. A small hygienic =checked-call= rule expands the
runtime parameter check into a short list match and calls the already checked
operator directly. Numeric validation still executes at row time, including
literal-only operators. The original argument-mismatch error is retained.

An initial =case-lambda= variant was rejected. With its variadic error fallback,
this installed toolchain generated a rest-argument lambda, a length check and
=apply=. In the complete paired run it won only 797, 730 and 546 of 1000 pairs
for right-literal, left-literal and unary-literal inputs. These failed the
unchanged 900-win admission criterion. The explicit-match variant generates
pair/null checks followed by the operator call in its successful path.

The native =t/performance/ascent-checked-call-performance-test.ss= freezes the
old calling convention from =a97762d=. Both implementations are natively
compiled; each shape uses 1000 alternating old/new pairs of 256 calls, identical
inputs and type checks, with GC outside timed samples. All six shapes must win
at least 900 pairs and retain median nonregression. This is a calling-kernel
benchmark: construction, admission, environment lookup and full solves are
excluded. It does not measure individual-call tail latency.

* Feature: syntax boundaries

=program/syntax.ss= and =program/scheme-language.ss= both lower atoms,
negation, and reducers. Their generated objects and error paths must
be compared production by production before sharing code. Keep
lexical fragment handles hygienic, preserve source locations and
diagnostics, and never broaden the public checked scalar grammar
to accept arbitrary callbacks. An extra macro that hides one runtime
call would make the layer harder to read.

The current =relational-atom= and =relational-atom/lexical= expansions
look alike but quote a relation spelling versus evaluate a lexical
handle. That difference is the ownership boundary, so a common
expander would need to keep it visible. =relational-copy-row= and the
operator project constructor use =map identity= to copy list spines
before retention; these are intentional copies, not redundant maps.
The contract in =docs/native-library-acceptance.org= also keeps the
historical =ascent= syntax on the test path, so deleting or folding it
into the native language would be a separate interface change.
The same snapshot-copy pattern appears in =candidate/reasoning.ss= and
=program/scheme-admission.ss=. Its presence across those boundaries
is evidence of an isolation rule, not a reason for a blanket rewrite.

* Study: compiler phase contracts and higher-order normalization

This study reads the installed Gerbil compiler Scheme directly, rather than
inferring quality from an optimization result. Three concrete structures matter:

- =compiler/optimize-top.ss:21-86= declares separate visitors for top-level
  types, declarations, expression types, complete type collection and mutators.
  The operation determines the visitor, while the AST representation stays
  shared. ASCENT already separates descriptor validation from lowering inside
  =relational-typed-compile=; the appropriate improvement is to state their
  different obligations, rather than introduce another visitor framework.
- =compiler/optimize-base.ss:15-29,492-503= names optimizer, local and path
  contexts separately. Type lookup searches path facts, then local facts, then
  the optimizer table; alias resolution delegates to this lookup. The mutable
  optimizer tables are fresh in the optimizer-info constructor. ASCENT's
  compile counters, source tables and domain accumulator likewise belong to
  one invocation. Reified closure environments use descriptor identity and
  lexical bindings; source-name equality cannot replace that relation.
- =compiler/optimize-top.ss:182-194,213-268= still visits an expression when its
  binding type is already known. Lambda and let handling establish the local
  environment around the body traversal. Known metadata therefore does not
  authorize skipping traversal or changing scope. In ASCENT, validation,
  lowering visits and conservative finite-height expansion keep their original
  budget charges even when source lowering reuses an existing source node.

The complete =program/higher-order.ss= owner now carries adjacent polymorphic
and domain signatures for all 21 definitions, including its three representation
constructors. Comments state the distinct relation/arrow field meanings, source
spine ownership, builder-once construction, identity-based lexical bindings and
full graph validation before lowering. These signatures describe runtime checked
contracts; they do not install a static type checker or change function bodies.
Removing comment lines from the module yields exactly the previous source bytes.

Two independent native regression Cases specify domain publication order across
three successive compiles and the existing flatmap normalization budget boundary:
limit five rejects and limit six accepts. They include false and character atoms
and retain all previous closure, domain, native Session and rollback tests.

A separate candidate replaced repeated accumulated-domain copy/deduplication
with an invocation-owned table of each atom's latest position and representative,
then sorted only at publication. Inspecting =std/list/list.ss:21-30= was necessary:
=delete-duplicates/hash= keeps the latest occurrence by default, so first-seen
insertion order would silently change observable domain declarations. The candidate
passes all 17 native higher-order Cases, including the new order and budget goldens.

are timed; descriptors are constructed outside timing, and published finite

* Study: operator traversal and local rule emission

The installed Gerbil compiler's =optimize-top.ss:244-291= uses named local
=collect-e= procedures inside =collect-type-let-values%= and
=collect-type-letrec-values%=. The local procedure handles one binding's type;
the enclosing procedure owns traversal order and the dynamic local environment.
Ordinary let expressions are compiled before the body environment is installed.
Recursive bindings are compiled inside their environment, in two explicit
passes. The useful lesson is to keep scope and ordering visible in the driver
while moving a separate responsibility into a small local procedure.

=program/operator.ss= now applies this structure to =lower-operator-graph=.
Named local definitions replace the manual letrec/lambda binding list.
=emit= owns graph traversal, active lexical bindings, closed-node memoization,
fixed-point placeholders and projected-join fusion. =emit-operation-rules!=
receives already lowered inputs and owns ordinary union, join, selection,
projection and finite mapping rule emission. Both close over one compilation's
relation/rule/source accumulators; no public interface or shared context is
added. The public compilation contract is adjacent to its actual definition.

Free-parameter validation still precedes memo lookup. Fixed-point relations
are allocated before their bodies, transformer input graphs are emitted before
their bound bodies, and ordinary inputs are lowered before their output and
private sources are allocated. The operation clauses and scope traversal match
the preceding revision after whitespace normalization. Rule construction,
gensym order, final publication reversal and budget enforcement are preserved.

A native Unit Test exercises a shared selection/project/flatmap pipeline consumed
by nested unions. It checks that private sources are emitted once, explicit
sources retain traversal order, union rules retain both shared consumers in
order, and solved rows agree with the independent descriptor interpreter.
Existing lexical-escape, fixed-point, projected-join, nullary and fragment tests
remain semantic gates. This is a responsibility refactor; no speedup is claimed.

* Study: one finite type algebra for symbolic and bounded arithmetic

Gerbil's installed =optimize-xform.ss:17-48= reuses traversal handlers such as
=apply-body-lambda%=, =apply-body-let-values%= and =apply-operands= across
expression operations. The mutation collector specializes assignment handling;
expression substitution supplies reference and assignment handlers on the basic
transform traversal. The shared structural walk has one owner, while each
operation supplies its interpretation and state.

ASCENT's higher-order compiler had separate symbolic and bounded implementations
of finite type cardinality and height. Both described relation powersets and
pointwise arrow lattices. =type-cardinality= and =type-height= now own those
structural recursions once. The symbolic height API supplies constructors for
=expt= and =*= expressions; bounded fixed-point lowering supplies its existing
saturating power and product operations. These procedures remain private to the
module that owns the finite type representation.

Relation height remains =domain-size^arity=, relation cardinality remains two
to that height, arrow cardinality remains output cardinality raised to input
cardinality, and arrow height remains input cardinality times output height.
The bounded interpreter retains the expansion-limit-plus-one cap and repeated
squaring; it does not allocate complete powersets or function spaces. Validation,
domain accumulation, lexical environments and normalization visit accounting
are unchanged. No memoization or sample-based termination is introduced.

Native Unit Tests extend the exact symbolic-expression golden to nested arrow
types. They also solve function fixed points over empty domains at arities zero
and one, and require the precise height-budget rejection for an arity-128
two-atom relation. Existing finite-seed closure, recursive function and exact
normalization-budget checks remain regression gates. This change consolidates
the mathematical ownership; it makes no performance claim.

Focused native =just test-file= qualification passes the higher-order module's
20 Cases and model-closure module's 27 Cases. Both invocations exit 0 and have
complete native/module/harness/final markers, with no Case errors. The selected
production-source policy audit exits 0 with =findings=0= and =errors=0=.

* Study: pass-owned symbol maps and whole-cut graph preflight

The installed compiler's =compile.ss:1113-1127= collects runtime imports using
a local =make-hash-table-eq= and a small =K= continuation. Each context identity
is handled once before adding its load path. =optimize-spec.ss:121-130= similarly
allocates method-call and slot-reference tables for one specialization target.
Collection state has one enclosing owner; the helper handles one identifier.

The installed Gerbil =2591dcd= compiler provides two concrete state lifetimes:
=optimize-base.ss:24-29= constructs the optimizer's symbol-identity tables,
while =optimize.ss:27-30= creates fresh mutator/local-type maps at the optimizer
entry point. Shared optimizer information and per-pass traversal state have
separate owners. The transferable technique is to choose the map's equality
from the identifier protocol, and allocate mutable traversal state at its call
boundary rather than retaining it in source declarations.

ASCENT's temporal solve previously checked every parent edge by recomputing
reachability from its target. Each reachable level scanned the complete edge
list and performed list-membership checks. Cycle rejection is a property of
the whole cut, so the repeated closures did unnecessary work even when the
root or valid-time window excluded those events.

=temporal/graph.ss= now owns the symbolic-to-dense graph adapter. Its fresh
=make-hash-table-eq= preserves the existing =memq= symbol identity. Both endpoints
are interned, including parents without event data. The adapter rejects self
edges and detects larger cycles via =core/dependency-graph='s SCC traversal.
After indexing, the graph pass is linear in vertices and edges; expected hash
lookup cost governs indexing. Source edge lists remain immutable.

=temporal/lens.ss= retains cut selection, time/order checks, rejection priority,
horizon/frontier publication and evidence binding. The cycle check still runs
on the entire selected cut before window/root filtering. It does not consult
the candidate oracle, reuse a receipt, or cache across generations. No measured
end-to-end speedup follows solely from the traversal change.

Native tests compare all 512 directed three-vertex graphs, including self edges,
against an independent Boolean matrix closure, repeat with reversed edge order,
and check long graphs at the 512-parent-edge bound and isolated missing-parent
cycles. Lens integration covers disconnected/out-of-window cycles, absent event
data, self loops and preservation of a previously verified answer. Current
verification results belong in [[file:qualification-history.org][qualification history]].
