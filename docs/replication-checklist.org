#+TITLE: ASCENT 0.8.0 complete replication checklist
#+STATUS: open

* Completion contract

Target the pinned Rust =ascent= and =ascent-byods-rels= 0.8.0 implementations,
the [[https://s-arash.github.io/ascent/cc22main-p95-seamless-deductive-inference-via-macros.pdf][CC 2022 paper]], and the [[https://kmicinski.com/assets/byods.pdf][BYODS paper]].
Implement the corresponding behavior through Gerbil modules, Scheme macros,
POO contracts and Foundation Providers. Rust token spelling and Rust ownership
rules are not Scheme requirements. Where pinned Rust contradicts the paper's
fixed-point semantics, retain a pinned Rust probe, an independent model and a
documented difference. The [[file:rust-parity.org][parity matrix]] gives the detailed current evidence.

An item is checked only when its named evidence runs on the same source head.
An example or finite corpus is evidence for its stated domain; it does not
close a whole feature family. All required items below must be checked before
calling the replication complete or the PR safe to squash. Keep new Agent
research and broader POO Flow integration outside the replication claim.

* P0: Inventory and language surface

The pinned =ascent= crate exports five macros with its default =par= feature:
=ascent!=, =ascent_run!=, =ascent_source!=, =ascent_par!= and
=ascent_run_par!=. =include_source!= is a form inside the program macros.
The current executable map is:

| Rust form | Scheme boundary | Evidence and remaining gap |
|-----------+-----------------+----------------------------|
| =ascent!= | =ascent= declaration plus =gerbil-ascent-open-session= | Selected declarations, runs and retained updates pass; result =relation-sizes= matches the generated Rust summary on selected inputs; SCC diagnostics remain open |
| =ascent_run!= | lexical =ascent= plus =gerbil-ascent-evaluate-program= | =module_session.rs= compares local input and closure; broader local capture diagnostics open |
| =ascent_source!= / =include_source!= | Gerbil module =ascent-fragment= / =(include name)= | =syntax.rs= compares recursive closure; Rust token-copy resolution and wider invalid cases open |
| =ascent_par!= / =ascent_run_par!= | Same program/result boundary | =module_session.rs= compares selected output sets at one and four workers, including Rust =#![inter_rule_parallelism]=; Scheme intra-program scheduling and failure semantics open |

- [X] Pin =ascent= and =ascent-byods-rels= 0.8.0 in =rust/ascent-oracle/Cargo.toml= and keep the oracle under =rust/=.
- [X] Put Scheme implementation in module namespaces and Scheme qualification under =t/=; expose the =ascent= form and POO program/session APIs. See =program/=, =interface/= and =docs/scheme-syntax.org=.
- [ ] Inventory every pinned Rust macro family (=ascent!=, =ascent_run!=, =ascent_source!=, =include_source!=, =ascent_par!=, =ascent_run_par!=), declaration, rule clause, attribute and generated public API. Map each to a Scheme form or a justified language-specific difference, then execute at least one same-input probe per family. The static =summary()= rule SCC loop flags and dynamic relation sets now have a same-declaration probe in =syntax.rs= and =ascent-scc-summary-test.ss=; lowered rule text, SCC order and runtime SCC timing remain open. Evidence: =rust/ascent-oracle/tests/integration/= and =t/qualification/=.

Pinned Rust 0.8.0 panics during macro expansion for the unbound aggregate input; Scheme reports the missing dependency at admission. This remains a starting receipt, not exhaustive coverage.

* P1: Fixed-point semantics

- [X] Establish a composed differential baseline: 778 fresh Rust/Scheme programs with multi-head recursion, negation, aggregation, disjunction and product lattice, plus three-phase Scheme retained sessions. Evidence: =composed_corpus.rs=.
- [ ] Cover arbitrary relation arity, repeated variables, rule/head order, recursive SCC topology, and body-clause order with same-input differential and invalid cases. The three-relation SCC corpus compares complete Rust/Scheme outputs under two rule and body-clause orders for all 64 loop-free three-node graphs. =arity_repetition.rs= covers every directed three-node graph, a nullary source gate, unary repeated-variable filter, ternary through five-column joins, recursive closure, and two rule/body orders. A two-head self-loop rule reverses its head order between variants. Its 2048 snapshots compare fresh Rust, retained Scheme source replacement and an independent finite model. Arity beyond five, interacting multi-head recursion and invalid cases remain.
- [ ] Close guards, bindings, iterable generators, negation and aggregation across empty, duplicate, recursive, grouped and invalid inputs. The =clause_composition.rs= corpus compares 512 directed three-node graph subsets plus seven duplicate-edge cases: bound-dependent two-value generation, guard, =let= score, derived blocking, negated filtering, recursive closure, grouped count and a custom maximum aggregator that emits no row for empty groups. Fresh Rust, retained Scheme source replacement and an independent finite model agree on every public derived row. The same declared Scheme rules now compare all rows with fresh Rust and an independent graph model at 1,000 and 10,000 edge/root pairs. Wider iterator shapes, invalid cases and timing/memory gates remain.
- [ ] Close lattice laws and interactions: minimum, set union, product and another nontrivial partial order; source plus derived values; recursive joins; negation and aggregation downstream; cycles that require strict strata. =divisibility_lattice.rs= covers the non-total divisibility order with Standard Library =lcm= join, recursive propagation, a later negated stratum and aggregate count over every directed three-node graph. =byods_lattice_timeout.rs= composes =eqrel=, recursive minimum, a later negated stratum and aggregate count on all 512 directed three-node graphs; fresh Rust, retained Scheme and independent models agree. Direct lattice source combinations, law violations, broader strata and other lattice families remain. Check an independent finite fixed-point model where Rust 0.8.0 differs.
- [ ] Close finite-model checks for termination, stratification and rule ordering on bounded graph families; document the boundary of each enumeration. =arity_repetition.rs= checks all 512 subsets of ={0,1,2} × {0,1,2}=, with both nullary-gate states and two rule orders; Floyd-Warshall supplies an independent closure model. This does not cover negative strata, larger graphs, or termination outside the finite family. Evidence belongs in =rust/ascent-oracle/tests/integration/= and =t/qualification/=.

* P2: State, storage and execution

- [X] Compare selected repeated-run append/replace, timeout/resume, BYODS =eqrel=/=trrel=/=trrel_uf=, and indexed relation cases. Evidence: =session_corpus.rs=, =timeout.rs=, =byods.rs= and =lattice_index.rs=.
- [ ] Close retained state for all supported source changes: ordinary and lattice append, replacement and withdrawal, duplicate input, failed update rollback, prior snapshot stability, multi-relation producers, and interaction with later strata. The =multi_source_session.rs= corpus checks two ordinary sources through nine mixed updates, including retraction through negation, downstream aggregation, a failed replacement and earlier snapshot stability, against fresh Rust and an independent finite closure model. The =byods_session.rs= corpus checks two producers feeding binary =eqrel=, =trrel= and =trrel_uf= through nine mixed updates against fresh Rust and independent component/closure models. =grouped_eqrel_session.rs= checks retained grouped equivalence through nine mixed updates, with the pinned Rust split-producer discrepancy isolated by a single-producer baseline. =byods_lattice_timeout.rs= now checks =eqrel= with recursive minimum and later strata through eight retained states, including duplicate append, source withdrawal, invalid replacement and earlier snapshot stability. Broader Provider and lattice source combinations remain.
- [ ] Close generated timeout behavior across recursion, lattice, BYODS, replacement and resumed strata, with a documented unit/API mapping for Scheme. =timeout.rs= compares a recursive chain feeding a later negated stratum at the first zero-budget round and at completion against pinned Rust 0.8.0 and an explicit finite expected set. =byods_lattice_timeout.rs= checks two zero-budget calls followed by completion at each retained phase of the composed =eqrel=/lattice/later-stratum program; fresh Rust and an independent model check the completed rows. Scheme's zero duration is a cooperative round budget; the selected partial states are not claimed as Rust wall-clock timeout parity. Bounded cancellation within a large round, wider Rust differential coverage and timeout scale remain. Prove bounded cancellation and failure atomicity.
- [ ] Close BYODS Provider contract: default hash, custom index, =eqrel=, =trrel= and =trrel_uf= across multiple producer partitions, update sequences, error paths and larger relation sizes. Binary two-producer =eqrel=/=trrel=/=trrel_uf= and grouped =eqrel= retained update and malformed replacement corpora are covered; =ascent-byods-index-test.ss= checks a custom composite index with grouped =eqrel= through append and replacement. =byods_lattice_timeout.rs= checks =eqrel= with downstream lattice/negation/aggregation at 1000 and 10000 disjoint edge pairs. Other custom index/Provider combinations, wider partitions and connected-component scale remain. Exercise POO Provider slots rather than introducing parallel storage abstractions.
- [ ] Implement and qualify the pinned parallel macro execution semantics or document precisely which intra-program behavior Scheme exposes. Compare serial/parallel results, worker failures and contention; independent program reentrancy alone does not close this item.

* P3: Scale and admission

- [X] Use ASP's standard SS profile with 1000 samples and Foundation Observability memory/duration guards; retain the existing budgets. Evidence: =just performance= and =t/scenarios/performance/=.
- [ ] Measure each completed feature family at representative 1000- and 10000-row/key scales where applicable. Other families and connected-component scale remain.
