#+TITLE: Affine page window synthesis

* Source correspondence

The Actor page transaction validates the destination and row budget
before staging. The ordinal worker clips a certified affine window to
the space left in the page. The current private scratch, initial pair,
stride, and clipped row count suffice to generate that part of the
page. The caller still receives the same checked copy at the existing
second checkpoint.

The C compilation target carries both signed fields in one unsigned
two-lane vector. Each lane adds the same stride; the store writes one
pair. Blocks write four pairs, then a scalar-counted tail writes the
remaining zero to three pairs. Source loading and subwindows larger
than 512 rows use the existing Scheme recurrence. Ordinary row
visitation, complete mutable-list export, publication identities,
the 256 KiB two-buffer geometry and cancellation checks stay on their
existing paths. A client does not compile its DSL.

=carried_affine_word_exact= identifies the carried unsigned word with
the mathematical affine recurrence modulo 2^64, including a negative
stride. =carried_affine_word_writes_admitted_value= removes the modulus
at each admitted field. =affine_copy_four_row_partition= and
=affine_window_chunk_cells= cover the four-pair blocks and tail
within the already validated scratch extent. The compiled expression
uses constant-size unaligned-safe copies and does not call back into
Scheme while holding a scratch pointer. The emitted macOS code has
two-lane adds and 16-byte stores.

* Validation

The guarded Lean inventory passed all 196 jobs. The native interface,
Actor Session, and condensed Session suites passed with the candidate.
The added case compares ascending and descending cuts with labels
near the maximum fixnum, partial final pages and an odd caller-buffer
offset. The standard interface case still exercises cancellation
between staging and copy. Source loading with =gxi= ran a separate
ordered-page prefix check against a literal expected sequence.

* Uninstrumented qualification

Each width and arm used 40 matched shards, 25 requests per shard.
The first four pairs were retained in the same distributions, and
the remaining shards completed once with the frozen candidate and
reference binaries. The original per-field oracle checked each row.
All 160 processes passed; the longest took 4.116 s under the original
90-second watchdog.
