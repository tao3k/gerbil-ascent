#+TITLE: Native retained replacement benefit measurement

* Question and executable boundary

Does checked dependency reuse reduce native work and elapsed time relative to
a fresh solve of the identical prospective input? Run =just build-dsl-closure=
then =just check-retained-benefit=. The native entry uses the same compiler,
dependency prefix, DSL and evaluator for both paths. Scheme verifies source
and binary hashes and admits the artifact. Just launches the native process
directly with a 1 GiB heap and the existing 120-second runtime deadline.
Compilation uses std/make completion and exit status, then source/owner/binary
binding before artifact publication. The Python output/CPU supervisor has been
removed from these recipes. Historical deadline failures below remain failures
under their original policy.

* Workloads and independent truth

The original receipts measure a twelve-edge chain plus an independent
singleton source and its copied output. The current entry also measures a
48-edge chain. Each condition has thirty groups of three timed arms; all six
order permutations occur five times. Batch sizes are 16 for twelve edges and
4 for 48 edges, with a distinct completed base Session for every update.
Declaration, completed initial solve/check and completed timed-arm markers
report actual work outside timers; they are not periodic heartbeat output.

| Condition | Source transaction | Expected active native plans, fresh / retained |
|-----------+--------------------+------------------------------------------------|
| independent | Change the singleton 7 to 8 | 3 / 1 |
| recursive | Remove edge 0->1 | 3 / 2 |
| all-inputs | Both changes together | 3 / 3 |

Scheme verifies completion and every row of all four relations before
publishing a sample. Its independent model checks x<y membership, rejects
duplicates and checks the complete triangular cardinality. After deletion
node 0 is isolated; the lower bound becomes 1. This establishes exact closure
without comparing one evaluator output with another as the sole oracle.

* Timing contract

Each batch opens and completes distinct base Sessions. Initial construction,
initial solves, forced GC and independent row checking are outside the timers.
Three separately named arms preserve the distinction between solve and update:

| Arm | Timed work |
|-----+------------|
| solve | evaluate-program on the preconstructed prospective program: engine admission, computation and publication |
| fresh-update | Construct a prospective source snapshot from base declarations and ready replacement rows, then full evaluate-program |
| retained | replace-sources!: snapshot, replacement admission, dependency invalidation, computation and publication |

The fresh-update snapshot preserves the base rules/providers/declarations and
overrides source rows through the same POO prototype mechanism used by Session.
Both update arms therefore start with base declarations and ready replacement
rows and include candidate construction. The solve arm remains a diagnostic
control, whose time must not be relabeled as the cost of a complete update.
The original Session setup cost is therefore excluded explicitly: these are
update measurements for an already retained session, not cold-start claims.

Raw samples report per-operation batch means for current-jiffy wall seconds,
cpu-time process CPU seconds, native allocated bytes and active-rule-count.
The result vectors, loop index lists and two-element f64 counter buffer are
allocated before timing. Gambit's native =##get-bytes-allocated!= implementation
was checked against installed compiler commit
[[https://github.com/gambit/gambit/blob/dcd677cd3e40860bdd27dfbdbf5e3ce46ab03813/lib/_kernel.scm#L4126][dcd677cd3e40860bdd27dfbdbf5e3ce46ab03813]]. Allocation is not live heap or peak RSS.
Active plans are a dependency-selection observation,
not counts of every rule invocation, join, allocation or instruction. No
speed threshold turns a slower but correct sample into an omitted result.
Shared-host interference remains possible even with counterbalancing.

* Fresh-update construction correction

The former fresh-update helper used =relations: relations=. In a POO object
expression the field name is an implicit self-field binding; the right-hand
reference therefore recursively read the candidate field instead of the
lexically computed replacement list. A minimal native reproduction with an
empty program exited 70 with heap overflow; the full measurement failed with
stack overflow. This was a defective comparison-arm construction, not evidence
that retained source invalidation failed.

The private =fresh-replacement-program= helper now names the lexical list
=replacement-relations=. The native regression checks replacement rows, empty
source withdrawal, inherited rules/providers/budgets, and an unchanged original
program against explicitly enumerated closure results. Actual arm-start
markers are outside the timers; they identify which operation is executing
without relaxing the five-second runtime progress rule.

The [[file:evidence/scheme-fresh-update-20261004/receipt.json][construction receipt]] and structured samples bind the integrated
source, artifact, qualification and all three measurement arms. No execution
logs are published. These measurements qualify this finite workload only;
they do not establish general speedup, proof refinement or model benefit.

All 13 native modules and 141 Cases passed on source =b8c695d= plus the
published construction patch. The unchanged measurement gate completed 180
groups and 5,400 independent native verdicts. Each table entry is the median
of thirty paired retained/fresh-update ratios; it is not a ratio of medians.
A ratio below one denotes lower cost for retained replacement.

| Condition | Edges | Wall ratio | CPU ratio | Allocated-byte ratio |
|-----------+-------+------------+-----------+----------------------|
| independent | 12 | 1.234 | 1.444 | 1.803 |
| independent | 48 | 0.526 | 0.525 | 0.814 |
| recursive | 12 | 2.231 | 1.745 | 1.844 |
| recursive | 48 | 1.084 | 1.237 | 1.180 |
| all-inputs | 12 | 2.322 | 2.254 | 1.841 |
| all-inputs | 48 | 1.074 | 1.074 | 1.179 |

Only the 48-edge independent-source condition shows lower measured costs in
all three metrics. The other conditions retain a management-cost penalty.
Every group, including slower retained samples, is published in
[[file:evidence/scheme-fresh-update-20261004/samples.json][samples.json]]. No speed threshold or significance test is an acceptance
criterion. Shared-host interference and the limited workload remain explicit;
these data do not establish a general crossover policy. Allocation counts are
not peak or retained memory. Formal compiler refinement and model reasoning
gain remain open.

On source 7103f87 the native dynamic model module completed all 24 tasks,
including the two actual function-valued fixed points (independent bitmasks

The first result establishes computation agreement only; neither invocation
replaces the accepted AOT preflight or authorizes a model accuracy claim.

The architecture must qualify a cost crossover before selecting
reuse on performance grounds. Next evidence needs larger independent and
fully affected components, batch duration above the timer resolution, separate
setup/update accounting, and profiling of admission/snapshot/native solve
allocations. Any cost-based choice must preserve the same atomic publication,
failure recovery, budgets and independent result checks. Counting fewer plans
alone cannot authorize a claim of runtime savings.

This finite chain experiment cannot establish general runtime benefit, memory
benefit, provenance cost or model reasoning gain. R5 also needs per-operation
memory/allocation distributions, larger and varied workload families and
reproducible measurements on an isolated host. R6 still requires a newly
frozen actual-source plan and explicit source-disclosure/cost authorization.
No paid model calls belong to this experiment. MRR integration remains gated.

* Initialization-inclusive composed lifecycle

The existing =scheme-library-contract-test= extends the checked recursive
program through nine source cuts: alternative/final-support withdrawal,
blocker and weight changes, a recursive cycle and removal of its last base
support. Fresh constructs a new program and Session for every cut; retained
constructs its first program and Session, then applies atomic four-source
replacements. Both arms create identical inert-candidate receipts and check
snapshot binding, finite replay and stratified replay at every cut. Initial
construction, solve, updates, publication, receipt generation, replay and
identical completed-cut progress output are inside the timer. AOT compilation,
process startup, forced pre-sample GC and independent model checks are outside.
Rejected-transaction checks follow timing; no failure/cancellation latency
claim is made.

An independent three-node Boolean matrix model supplies all eight native
relation sets, including sources, recursive paths, excluded paths, weighted
rows and grouped sums. Twenty-four arms across twelve alternating pairs check
1,728 native relation sets, 216 candidate =summary= answer sets and 192 relation
sets after rejection: 2,136 complete-set comparisons. Earlier saved snapshots
are checked after the whole sequence and rejected update. Candidate evidence
has separate binding and replay checks; its query does not cover every native
relation. The [[file:evidence/scheme-application-lifecycle-20261005/receipt.json][lifecycle receipt]] retains every raw pair, source binding,
formal source hashes and the discarded test-wrapper error. The focused native
module passed six Cases in 22 seconds with parent exit status zero.

| Whole nine-cut workflow | Fresh median | Retained median | Median reduction | Retained wins |
|-------------------------+--------------+-----------------+------------------+---------------|
| CPU | 867.716 ms | 492.522 ms | 43.24% | 12/12 |
| Wall | 885.737 ms | 494.673 ms | 44.15% | 12/12 |
| Cumulative allocation | 1,520,942,240 bytes | 849,843,028 bytes | 44.12% | 12/12 |

These are complete workflow medians, not per-update latency. Retained amortizes
initial construction over nine cuts. Cumulative allocation includes reclaimed
objects and is neither live heap nor peak RSS. No speed threshold, selected
retry or significance claim was used. Shared-host interference remains possible;
timings from parallel CI are not automatically new qualified cost receipts.

The support-withdrawal and cyclic cases connect H18's support distinction to
the admitted source-update path; they do not implement DRedc or DBSP signed
circuits. =SourceUpdateFrame.source_frame= / =completed_reuse= retain
=readsMatch= and completed-fixed-point premises. Rejection and old-snapshot
checks discriminate the publication contract modeled by
=SessionTransaction.AtomicSnapshot= and
=NativeSessionPublication.CommittedSnapshot= / =NoPrematurePublication=.
Those unchanged formal results do not establish native heap refinement.

This finite canonical-Set workflow does not establish production-scale or
general runtime benefit. Timed actor/cancellation, specialized BYODS Providers,
larger applications and real-model comprehension remain open. This run made
zero model calls. Final-head GitHub CI remains a separate release gate.
