#+TITLE: Lexical instance resolution and identity union publication

* Production flow
=program/operator-lowering.ss= resolves and validates each free parameter once
before instance memo lookup. Parameter emission consumes that checked value.
The invocation-local association list remains the lexical environment; no
mutable scope table, new runtime option or public receiver was introduced.

Ordinary and fixed-point union producers now share a private publication
protocol. Each producer emits resolved relation handles in its original order.
The publisher constructs one copy rule per distinct handle, suppressing
repeated handles before allocating variable terms and atoms. A first handle
uses an inline slot; an identity table is allocated only when a second distinct
handle appears. Different relation handles remain distinct even if their source
rows are equal. Private output relations, lexical instances and source labels
are preserved. Constructor calls for semantically duplicate rules are removed;
unique-input constructor ordering remains unchanged.

Gerbil SDK 1cfb032 =src/gerbil/compiler/optimize-call.ss:43-80= resolves a receiver
once and carries the checked result through dispatch. The lowering resolver
uses that same checked-result flow. The union publisher uses native eq tables
and a synchronous producer/consumer contract, matching the ownership pattern
of =src/std/list/list-builder.ss=. It is a private compilation protocol rather
than another public generic receiver hierarchy.

* Evidence scope and retained negative result
The initial experiment only combined repeated binding checks. Complete lowering
with production relation and rule constructors measured CPU 890338 -> 883496us
(0.8%), 25/50 wins; allocation was essentially unchanged. It failed the 20%
performance gate. The raw receipt is retained in ignored
=.cache/ascent/binding-resolution/binding-only-failed.ss=. This small change
alone is not claimed as a performance improvement.

Final A/B fixtures exercise the complete lowering flow, including graph
admission, lexical analysis, memoization, scope resolution, production POO
relation/term/atom/rule construction and result publication. Only fixture
creation and comparison are outside timing. Both compiled lanes use identical
flags. Every relation, source label and output handle is alpha-normalized;
every rule preserves rule-local variable sharing. Since the optimization
intentionally removes duplicate rules, the comparison removes duplicate
normalized baseline signatures while retaining first occurrence order. Raw
rule-count and distinct-source unit tests qualify that normalization boundary.
