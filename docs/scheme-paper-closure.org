* 收口结论与判据

目标保持完整的 ASCENT 行为与 BYODS 设计覆盖。当前不能宣布整体完成。
已通过的原生用例、有限 Rust 差分、抽象 Lean 定理、有限 TLC 状态探索，
分别回答不同问题。用例数量或某个 CI 绿灯不能替代缺失的论文功能与证明。
本表将原矩阵、最近 actor 实现和证明目录对齐；既有收口范围保持明确，
未实现或未证明的项目不能从表中删除后再宣布“完整复刻”。

每项只有在以下证据均匹配时才能收口：
1. 论文定位、接受的 Scheme 行为和实现 owner 明确。
2. 独立真值、Rust 差分或明确记录的上游差异覆盖该项及其交互。
3. Lean/TLA+ 证明命题与实际实现之间有明确对应；尚需假设不能当作结论。
4. 正负对照、失败/超时行为和资源约束均有当前源码绑定的执行结果。
5. 该项声称的性能收益有同输入、同语义、交替顺序的测量；负结果保留。
6. 最终 GitHub 提交的 CI 和消费者 pin 验证通过。

论文来源：[[https://thomas.gilray.org/pdf/seamless-deductive.pdf][A22]]、[[https://kmicinski.com/assets/byods.pdf][B23]]。
2026-10-05 重新读取。A22 的并行化在原文是未来工作；当前 actor 设计
是后续工程义务。B23 的自定义数据结构接口与论文应用实验需要分别验收。
原论文性能数字不构成 Scheme 性能证据。

* ASCENT 行为覆盖

下表“已有验证”引用现有 [[file:rust-parity.org][Rust 0.8.0 差分矩阵]] 和代码，
不是本轮重新执行全部 Rust 差分的宣称。证明目录链接列出相关命题，
不是这些命题已经证明整条 native evaluator 的宣称。

| 功能 | 实现 / 已有验证 | Lean / TLA+ 对应 | 尚未闭合的验收义务 |
|------+-----------------+------------------+----------------------|
| 声明、任意 arity、类型、无效程序 | program/types、schema；arity_repetition、compile-fail 差分 | DescriptorScope / AtomicBinding 的抽象语法与匹配 | 所有接受的 native 声明对应、剩余 attribute/API/诊断类别；Scheme host predicate 不等同 Rust 静态类型 |
| 绑定、重复变量、join、wildcard、多头 | core/rule-bindings、rule-semantics；clause_composition、composed_corpus | AtomicBinding / LexicalLowering 的局部 sound/complete | native 标量相等、向量编码、任意已接受 body 组合与规则执行 correspondence |
| guard、let、for、disjunction、嵌入宏 | program/syntax、core clauses；原生及 Rust fixture | 有界已接受语法的 lowering 命题 | host callback 和 iterator 行为不是形式证明前提自动成立；其错误/不终止必须保持 typed 状态 |
| SCC、semi-naive、strata、最小不动点 | planning、component-plan/worker、evaluate；递归/组合差分 | RuleGraphClosure、RecursiveLowering、FiniteHeight | 编译 adjacency、实际 delta 选择、执行步骤与 consequence operator 的完整 refinement；一般 host 程序终止不可默认 |
| negation 与 aggregate | program/strata、aggregation；有限交互语料 | StratifiedNegation、PositiveNonmembership | 实际分层读图、aggregate 行编码与 completed-stratum 对应 |
| lattice 与下游普通关系 | table/storage、evaluate；min/union/product/LCM 有限语料 | 抽象有限高度及单调性命题 | 任意用户 join 法则、部分序/domain/native 值对应；lattice 不可套用普通 Set 的 delta 命题 |
| indexes / physical plan | table/provider、program/index；hash/alist/composite 与 scale 差分 | AtomicBinding indexed_atom_iff；RoundAdmission.ComponentIndex 顺序扩张 | 原生 bucket/key 编码 refinement、用户 lookup 完整性、更多 scale/成本结果 |

* BYODS 设计覆盖

B23 §3 的 concretization 与 total/delta 条件、§4 接口以及 §5 的数据结构
和应用，必须各自有验收项。不能用三类内置 closure Provider 代替整篇覆盖。

| 验收项 | 已有实现 / 证据 | 本轮形式与原生补强 | 剩余缺口 |
|--------+------------------+----------------------+------------|
| 自定义 index / storage 接口 | POO Provider、hash/alist、Set/eqrel/trrel/trrel_uf | frontier 接口义务明确列出 | 任意 caller Provider 的 monotone concretization、lookup 完整性及 emitted frontier 无法由接口声明证明 |
| 内置 eqrel/trrel/trrel_uf 的 concrete rows | 三/四/八节点、两 producer 分区、分组隔离与 scale 语料 | 每次插入后的独立 concrete difference，512 图 × 3 Provider × 正反两个顺序 | 更大分组 arity、一般图上的 native 算法 refinement、规模/内存与复杂度收益 |
| delta 可见性 | 独立闭包及 split-producer discriminator；Rust eqrel 缺漏差异保留 | ProviderFrontier Lean：concrete partition、fresh fact 必须交付、二元 join 分解；TLA eqrel 注入/消费与两个遗漏负对照 | B23 Theorem 3.5 的完整任意 body/迭代证明及 native frontier 到抽象 gamma 的对应；本轮三个局部定理不冒充该定理 |
| 重复输入、budget、失败原子性、保留更新 | 原生 preflight/retry、byods_session 与 timeout 差分 | 每步 frontier 同时检查无重复与不遗漏 | Provider external state 与 timeout/换源/分层交互的完整模型/refinement |
| index sharing (ind_share) | 当前 solve-private index cache/增量扩张 | 无论文 index-sharing 算法验收 | 尚无 B23 对应索引共享设计、共享布局/选择算法和端到端应用证据；不能把普通缓存称作完成 |
| 用户定义格与并发 Provider | serial lattice 有有限差分；actor 只接受限定纯 Set 路径 | 不将 Set frontier 定理扩展为 lattice theorem | 一般格/递归聚合契约、并发访问/迭代/合并协议与 race/失败/refinement |
| 论文应用与收益 | 当前有 closure 与选定 Rust 包示例 | 保留现有负性能结果 | Steensgaard、Polonius、PageRank、LLVM/index-sharing 对应完整程序与可复现数据、成本/内存测量尚未验收；当前不能宣称论文实验全部复现 |

* 其他论文与证明链

[[file:scheme-research-proof-audit.org][研究/证明总审计]] 是 F16/S20 单调类型及有限高度、H13 binding、
F20/L25 embedding、H18 deletion、B22 change maintenance 和 provenance 的
对应表；它列出的 native refinement、任意语法/host value、一般维护算法
及语义收益缺口继续有效。新增 ProviderFrontier 不能替代这些命题。
目前 proofs 下的模型均为命名契约或有限状态探索，不是整个 native Scheme
代码自动生成/验证的程序证明。所有 Nat generation 保持无界；有限 TLC
节点集合只是探索 fixture。没有增加 Prompt、repair、模型调用或 Rust runtime 接入。

* 落地顺序与终验门槛

1. 先闭合 admitted DSL → native row/binder/index/rule-step → consequence operator
   的 refinement，连接现有局部命题；输入能力/退出状态和 semantic budgets 同步。
2. 连接内置 Provider gamma、逐步 emitted frontier 与任意 body/迭代，完成
   semi-naive/naive 等价链；格与普通关系分别定义语义。
3. 实现并验证论文对应 index-sharing 及用户 Provider 并发协议，保留 owner、
   取消和发布隔离；不能以限制测试规模替代这些实现。
4. 补齐论文应用程序、组合交互、数据集与性能/内存对照，记录上游差异。
5. 在全部收口项有当前源码、native/Rust/Lean/TLA+、负对照及收益证据后，
   完成最终 head 和 consumer pin CI，才宣布 ASCENT/BYODS 整体收口。
